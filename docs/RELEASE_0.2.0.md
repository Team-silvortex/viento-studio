# 0.2.0 版本记录

2026-10-24。本版收录 0.1.9 之后的六轮动画增量：状态进入触发来源、按事件回看、手动事件试算、连续试算、可复用用例及内置 JSON 用例编辑。运行观察可以追到实际消息或完成通知；编辑时可以独立试算、记录路径，并保存用例供改表后再次检查。

## 变更

- **状态进入的触发来源**：区分初始化回调、项目事件、动画完成和直接进入。事件来源显示实际事件值及订阅关系，完成来源关联实际片段记录；旧记录明确标示来源未记录。来源反映进入入口，不推测命中了哪条条件分支。
- **按事件回看投递与进入**：选择一条消息，逐订阅查看投递状态和确证关联的状态进入，再跳到对应控制器历史或冻结来源。平铺列表筛选不裁剪回看选择。同名消息、多绑定和不同场景访问各自关联；投递已处理但无进入记录，只表示当前记录未采集到进入，不据此判断条件失败。
- **手动事件试算**：在新建或重新编辑状态表时，选择当前状态、事件载荷和固定共享值，查看候选顺序、逐项比较和全部／任一短路，并定位转换字段。沿用既有 Rust 严格比较；缺失键、类型不同和未求值分别显示。手动样本不参与作者表、源码审阅或普通保存。
- **连续事件与完成试算**：先试算，再通过“记录并继续”采用预测目标；可串联下一事件或假定动画完成，查看步骤详情、撤回并恢复该步的原始输入。没有匹配时也能记录保持状态的一步，自循环独立保留。完成样本假定控制器有效、所选片段完成通知已送达，不模拟播放器和进入失败。
- **可复用手动用例**：已采用路径可导出为独立 JSON，再导入并在当前状态表上明确重跑。每步只对照预期目标状态和是否发生转换，首个不符后停止，后续步骤显示未运行；同目标的不同分支不被视为不同预期。导入和回放不覆盖当前手动路径，错误文件保留已载入用例及有效结果。
- **内置用例 JSON 编辑**：可从当前路径建立待应用草稿，或编辑载入用例；“检查 JSON”“应用用例”和“取消编辑”分别操作。检查成功后输入再次改变会撤销应用资格，无效或超限文本原样保留。编辑期间暂停冲突文件与回放操作，迟到读取不能覆盖草稿；明确应用后才替换载入用例并清除旧回放，重跑仍需单独操作。“导出载入用例 JSON”与原路径导出分别保留各自内容。

以上界面提供中、英、日文案。语言切换保留输入、选择与焦点；用例编辑支持窄屏换行和取消入口，输入法使用 Escape 时保留编辑，普通 Escape 只取消子编辑。

运行观察入口见[项目事件](PROJECT_EVENTS.md#按事件回看投递与动画进入)及[动画进入来源](SCENE_ANIMATION.md#查看状态进入的触发来源)。手动检查入口见[事件试算](SCENE_ANIMATION.md#手动试算事件分支)、[连续试算](SCENE_ANIMATION.md#连续试算事件与完成转换)、[用例保存与重跑](SCENE_ANIMATION.md#保存与重跑手动试算用例)和[内置用例编辑](SCENE_ANIMATION.md#在-studio-内编辑试算用例)。

## 格式与兼容

当前系统仍为 **22 模块／43 项声明能力**；工作流图谱为 **151 功能／449 实现／654 绑定／2616 评分单元／114 工作流**。产品升版不修改既有成熟度评分。

Godot 适配器由 0.1.9 发布时的 0.18.0 更新为 **0.19.0**。新构建的严格状态控制器项目使用 **protocol 10／清单 11**；普通动画项目保持 protocol 7，无动画项目保持 protocol 4。旧协议 1–9 及旧工程按各自精确形状读取，不为旧记录补猜来源。需要新来源观察的工程应重新生成，不自动迁移已有派生工程。Bevy 数据适配器 **0.3.0**、Rust 适配器与模板 **0.2.0** 保持。

作者状态表、v1–v5 源码生成器、既有 Rust/WASM 接口及字节保持。真实来源采集由独立运行包装及派发作用域承担；手动试算在独立领域模型内复用既有 Rust 比较。运行协议与手动用例格式各自管理。

用例格式为 `viento.animation-state-trial-case` 第 1 版，只包含起始状态和逐步规范化输入／手动预期，不含作者表、运行权限或可信运行报告。完整文件先验证，再允许回放；重复键、未知字段、非法标量、矛盾的无转换预期及不支持版本会被拒绝。容量限制分别为：

- 连续手动路径最多 32 步，可导出的用例须含 1–32 步；规范化样本合计最多 64 KiB。单次试算在路径记录预算用完后仍可使用。
- 用例 JSON：UTF-8 原文最多 128 KiB；编辑入口优先使用可读缩进，超预算时使用紧凑表示，输入期间不自动格式化或截断。
- 连续试算的撤回缓冲：原始输入累计最多 256 KiB，包含隐藏的未完成输入；超限时拒绝记录该步，仍保留输入及单次试算。

应用标识、用户数据路径、作者文档、稳定编号、元数据关系与素材保持；产品升版没有批量作品迁移。用例当前通过显式 JSON 导出持久保留，尚未登记为工程资产。

## 修复与交互保护

- 修正 Godot 首次 `_ready` 内部已被标为就绪时的初始化来源识别，后续直接调用仍与首次初始化区分。
- 严格检查待投递消息的队头关系和已退休事件订阅，拒绝把不属于当前实际派发的消息当作进入来源。
- 修复控制回放暂存清单误混资源 URL 的问题，保持生成资源和临时运行文件分开管理。
- 加固试算、用例及编辑会话的失效处理：已观察到过期的待采用结果或报告不能在恢复旧值后重新生效；旧详情与迟到文件不覆盖新选择。
- 保留大状态表的刷新边界，历史条件详情按需展开；新增用例面板不因空历史反复读取整张作者表。

## 交付边界

本说明对应 **0.2.0 源码**；源码升版、构建产物与已安装程序分别管理。本轮完成 0.2.0 源码升版，未提交推送、创建标签或 GitHub Release，也未制作新安装包或更新本机安装。最近保留的 [Linux 安装验收](test-results/native-installed-0.1.1/README.md)仍为 0.1.1 工作树，不能作为 0.2.0 的安装验收。

状态进入来源不记录真实条件逐项求值或未进入原因。进入接受、命令执行、自然完成和末态各有独立记录；事件投递成功不证明发生转换或播放成功。手动试算使用假定当前状态及每步固定共享值，不模拟脚本副作用、片段绑定、播放时钟或进入失败，也不读取运行历史生成预期。

当前动画仍使用每场景共享播放头。逐实例播放头、混合、骨骼、3D 与 Bevy 动画、运行条件追踪和标准语言服务仍分别推进。Godot 字符串 NUL 的原生表示限制继续适用。工程 ZIP 需要对应引擎工具，尚非独立游戏发行程序；本次源码验证不外推到安装版、Android 或其他桌面设备。
