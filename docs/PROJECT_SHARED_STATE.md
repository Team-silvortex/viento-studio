# 项目会话共享状态

本页能力已纳入源码交付；开发证据保留执行时的 0.1.3 工作树身份，安装及目标设备范围以[当前状态](STATUS.md)为准。

已收录 [0.1.4 源码](RELEASE_0.1.4.md)。在[项目组装与场景切换](PROJECT_ASSEMBLY.md#运行中切换场景)之上，Godot 行为可以在一次项目运行中共享少量值，例如已取得钥匙、关卡进度、分数和对话分支。场景退出不会清空这些值；重新运行、重新启动导出的工程或恢复冻结工程后再次运行，都会从空状态开始。

这是运行状态，不是作者文档或游戏存档。宿主会把观察结果记入本机运行会话记录，便于审阅，但下一次运行不会从该记录恢复状态。[项目事件发布与订阅](PROJECT_EVENTS.md)与[行为声音控制](PROJECT_AUDIO_CONTROLS.md)已独立接入；磁盘存档、事件留存重放和实时调试修改尚未接入。

## 在 Studio 中使用

1. 打开 **新建脚本**，选择 **Godot / 共享状态**，审阅后进入普通原文草稿并保存。
2. 将脚本绑定到组装成员场景的实例。起始内容在该行为就绪时累加 `visit_count`；同场景多个绑定会分别调用，同一实例的多条行为也分别计数。
3. 保存行为、检查并重新构建组装，然后运行。**构建与运行 → 会话共享状态** 显示全局修订、当前键值、各键最后来源，以及最后一次写入或删除。
4. 按状态键筛选，或点击 **打开状态来源** 返回冻结构建对应的行为声明。该面板只读取观察结果，没有修改游戏状态的按钮。

中英文和日文界面只翻译操作标签，作者的键、字符串和文件名称保持原样。切换场景保留当前筛选；换运行任务清空筛选和旧快照。删除最后一个键后仍能查看最后删除来源。旧项目协议没有此状态快照时，面板不把它当作一个已经完成观测的空状态。

## 行为接口

仅项目运行注入 `viento_project` 访问接口，普通单场景运行不注入。每个接口属于发起行为及本次场景访问；场景退出后，即使脚本保留了接口引用，也不能读取或修改后续场景的状态。

```gdscript
extends Node

func _ready() -> void:
    if not has_meta("viento_project"):
        return
    var project = get_meta("viento_project")
    var previous = project.read_state("visit_count")
    var count := 0.0
    if previous is int or previous is float:
        count = float(previous)
    project.write_state("visit_count", count + 1)
```

| 方法 | 语义 |
| --- | --- |
| `read_state(key)` | 返回当前值；键不存在或访问已过期时返回 `null` |
| `write_state(key, value)` | 成功返回 `true`；相同类型和数值的重复写入返回 `true`，不产生新修订 |
| `erase_state(key)` | 删除已有键返回 `true`；键不存在或访问已过期时返回 `false` |

值支持布尔、有限数字和字符串，不存储 `null`，从而明确区分缺失键。数字的整数／浮点表示统一为数值语义，`1` 与 `1.0` 是同值；`true` 与 `1` 是不同类型。空字符串、`false` 和 `0` 都是有效的已存值。

可以先写入再调用 `request_scene`；同一回调中排队的切换不会立刻销毁场景，写入在真正退出前仍属于当前访问。目标场景的行为就绪时可读取这些值。返回同一场景会创建新的场景实例，但共享值仍属于本次项目会话，不恢复旧场景节点或坐标。

## 范围与失败处理

| 限制 | 范围 |
| --- | --- |
| 键 | 区分大小写，1–64 个 ASCII 字符，以字母开头，后续允许字母、数字、下划线、点和连字符；禁止 `constructor`、`prototype`、`__proto__` |
| 数字 | 有限且绝对值不超过 1,000,000,000 |
| 字符串 | 有效 Unicode，UTF-8 至多 4096 字节 |
| 同时存在的键 | 至多 64 个 |
| 总容量 | 至多 16384 字节：键按 ASCII 字节计，布尔值计 1、数字计 8、字符串按 UTF-8 字节计 |
| 单次运行的有效变更 | 至多 1024 次；同值写入和删除不存在的键不消耗修订 |

每次变更先校验完整候选，再原子更新状态、修订和事件。活跃接口的非法输入或超额会报告对应行为错误并使运行失败，未批准的候选不成为新状态；旧访问调用则直接失效。原有项目访问次数、事件、输出和运行时间限制继续适用。

## 中间层和兼容

项目协议 2 在就绪时声明空状态修订，状态事件只传当前访问、场景、绑定、实例、对象、操作、键值和连续修订。状态来源位置由通用核心从冻结行为声明推导，执行事件不能引入文件路径。结束事件必须匹配已准入的最终修订；当前对象筛选不会删除项目共享状态。

纯契约、事件准入、观察查询、Godot 存储与界面分开。界面接收已校验快照，不直接读取进程输出或执行写状态命令。Godot 适配器声明 `project.shared-state`；这不代表其他后端已经支持该能力。

作者组装 schema 1、项目计划 1 及旧单场景协议保持，纯读取器显式兼容项目协议 1／2／3。当前新工程使用 Godot 适配器 0.11.0 和项目协议 4，保留协议 2 的状态语义与协议 3 的事件记录，再增加独立实际声音命令记录；生成 `assembly.json` 为 schema 5。适配器指纹改变后，旧本机构建需要重新构建，不绕过来源或生成字节校验。此前导出的独立工程保留自己的生成代码和语义。声音命令不自动修改共享状态，也不把状态值解释为播放器当前状态。

工程 ZIP 包含协调器、成员行为与素材，接收方使用 Godot 启动后也会从空状态开始；状态不会作为当前游戏进度打进包内。使用与交付边界见[后端工程](BACKEND_PROJECTS.md)，本轮实际验证见[共享状态验收](test-results/project-shared-state/README.md)。
