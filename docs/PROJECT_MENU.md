# 项目运行菜单

运行菜单已收录于0.3.0源码，本机安装仍为0.2.0。菜单沿普通TXT、行为参数、审阅和保存链启用；它与[只读HUD](SCENE_HUD2D.md)分别负责，不改变旧HUD格式。真实浏览器作者、实际窗口键鼠、场景重开与离线工程已分别验证；完整结果与来源范围见[验证回执](test-results/project-menu/README.md)。

## 配置入口

1. 在项目组装中保留开始、游玩、结果等明确成员；按需保存输入映射。菜单使用引擎既有Tab／方向键导航、Enter／Space确认及鼠标左键，不代建玩法输入映射。
2. **新建脚本 → Godot / 运行菜单** 创建普通TXT并保存，在需要菜单的场景关联脚本并新增行为绑定。每场景的每种模式最多一份菜单绑定，默认只提供“Exit”，命令和目标必须由作者明确填写。
3. 在 **编辑场景行为 → 脚本参数接口 → 补齐缺失参数** 加入 `title`、`items_json`、`display_mode` 三个String参数，沿 **检查 → 审阅 → 应用原文草稿 → 普通保存** 提交。应用不会自动保存；取消不写入。
4. 检查并构建完整组装，打开实际窗口。暂停菜单还须在同场景关联一份官方[暂停控制器](PROJECT_PAUSE.md)，它负责暂停动作及失焦规则；菜单不提升作者节点的处理权限。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `title` | `Menu` | 菜单标题，作者可填写中英日文字 |
| `items_json` | `[{"id":"finish","label":"Exit","command":"finish"}]` | 1–8项明确按钮与命令 |
| `display_mode` | `scene` | 正常场景菜单；`paused`用于暂停菜单 |

普通参数仍受既有每String最多4096 UTF-16单元的限制；菜单JSON另限制8192 UTF-8字节，不扩大旧作者格式。标题和标签为1–160个Unicode标量，不含C0/C1控制字符。参数助手仅识别完整官方正文的LF／统一CRLF、各可有一个开头BOM；构建能力与专用预检只认原始官方正文，不扫描自定义脚本。

## 按名称连接菜单按钮

在 **编辑场景行为** 选择已绑定的官方菜单脚本，先补齐三个String参数，并把 `display_mode` 明确设为 `scene`。下方的 **按场景名称连接菜单按钮** 复用已保存的场景／组装目录：

1. 点击 **读取菜单目标目录**，明确选择包含当前场景的项目组装；不会自动选择第一个组装或目标。
2. 修改已有 `scene`／`retry` 按钮时，选择按钮和目标成员，再点击 **填入所选按钮目标**。只能选择其他成员；按钮的命令、文字及 `values` 原样保留。
3. 新增时填写唯一按钮标识、显示文字，选择 `scene` 或 `retry` 及目标成员，再点击 **追加跳转按钮**。新 `retry` 明确写入 `values:{}`，不猜测分数、生命等初始值；如需复位，请在原JSON中填写实际键值。
4. 修改仅进入当前 `items_json` 输入框，继续 **检查 → 完整审阅 → 应用原文草稿 → 普通保存**。读取、选择和取消不改参数或审阅；改值后重新审阅。

写入前再次读取并核对当前场景正文来源与整个保存态目录；脚本识别依据当前会话的参数接口，最终检查仍重新核对全部脚本依赖。正文、绑定、参数、组装或来源修订改变时保留输入并要求重读。无效旧JSON、重复／缺失参数或暂停模式保留原文供手动编辑，不自动补修。目标替换只改对应字符串，追加保留全部既有条目的原文字节，包括转义、数字表示、换行和初值。仍受8项、4096 UTF-16单元及8192 UTF-8字节限制。

这是独立作者辅助，不增加脚本执行权限、宿主接口或后端协议；通用String参数参考仍保持原用途。三语、保存重开与真实Godot范围见[验证记录](test-results/menu-target-authoring/README.md)。

## 菜单项与命令

每项包含唯一的 `id`、`label`、`command`；`id`为小写字母开头的1–48个ASCII字母／数字／下划线。命令只接受下表各自字段，未知字段、重复JSON键和无效Unicode被拒绝。

| 命令 | 附加字段 | 适用模式 | 行为 |
| --- | --- | --- | --- |
| `scene` | `targetSceneId` | `scene` | 导航到不同的冻结组装成员，保留共享值 |
| `retry` | `targetSceneId`、可选 `values` | `scene` | 导航到不同成员，按明确键覆盖初始值 |
| `restart` | 可选 `values` | `scene` | 当前场景新访问，复用[原地重启](SCENE_RESTART.md) |
| `resume` | 无 | `paused` | 请求恢复，沿原暂停层等待全部注册动作释放 |
| `finish` | 无 | 两种模式 | 正常结束本次有限运行 |

`targetSceneId`必须是完整小写UUID，属于当前冻结组装且与当前场景不同。`values`至多16键，键为原共享状态的合法ASCII标识；布尔、有限数值及Unicode字符串仍按共享状态规则校验。菜单使用中立载荷预算：所有ASCII键长度加标量字节合计最多4096，数值固定8字节、布尔1字节、文本按UTF-8计数。字符串不含C0/C1控制字符，避免后端JSON读取或输出修复造成语义丢失；原共享状态和旧重试文本合同不变。该预算与JSON打印风格无关，`1`、`1.0`和`1e0`表示相同数值。

当前Godot读取器有一项独立数值限制：部分极小的非零Double会被其解析器读成零，菜单配置会明确拒绝，且不占菜单槽、不改状态或预算。通用数值合同不因此收窄；作者原文保留供修改。全零尾数（包括带巨大指数的零）仅在临时解析副本中规范为零，原 `items_json` 不重写。正常数值和这些拒绝案例见[后端对照](test-results/project-menu/checks/README.md)。

例如暂停菜单：

```json
[
  {"id":"resume","label":"继续游戏","command":"resume"},
  {"id":"finish","label":"结束本次运行","command":"finish"}
]
```

开始／结果页使用 `scene` 或 `retry`，把目标和初始值填入普通参数；没有任意函数名、回调路径或动态脚本命令。暂停中的导航／重开本轮明确拒绝，不能先唤醒旧玩法再切换；后续需独立的受控事务。

## 焦点、输入与生命周期

内置控制器持有真实按钮、屏幕层和键盘焦点。首次显示及重新聚焦须等待全部已注册动作与鼠标键释放，再接受新按下；长按、重复键和旧访问中的按钮不能反复提交。Tab／上下切换焦点，Enter／Space或鼠标左键选择；长文字和多个按钮在窄窗中滚动。

按钮选中后先禁用菜单，等待焦点和全部注册动作／鼠标键释放，再重新核对当前访问、菜单项、目标与队列安全点并调用既有端口。失焦会取消尚未执行的选择，恢复焦点不会自动提交。拒绝保留状态和预算；受理仍沿原场景访问、重试和重启事务，不生成新运行协议。

`scene`菜单是正在运行场景的UI：GUI消费事件不等于清除InputMap或停止普通脚本轮询，作者应把标题／结果页作为独立成员。要冻结玩法应使用 `paused`菜单与暂停控制器；暂停菜单显示时替代基础暂停提示，等待恢复时按钮禁用。离场、结束和中止撤销菜单和端口，释放旧焦点；旧按钮不控制下一访问。

## 构建与迁移

精确绑定官方菜单脚本显式要求 `project.menu` 与 `project.pause`，成员、组装、后端与生成输出分别检查。Godot当前描述符0.49.0；菜单工程在完整0.48.0暂停层外叠加0.49.0可选菜单层，保留并认证所有原入口／设置／时钟设置。无菜单的暂停工程仍生成0.48.0，无暂停工程仍生成0.47.0。既有后端GD／文本、业务协议4／7／10／11、作者格式和事务日志不升级。

菜单属于作者普通脚本与参数，完整作品迁移使用 `.viento.zip`；生成工程使用 `.viento-build.zip`，仍需Godot工具。Bevy与ns-nova尚未接入，未从Godot能力推断对等。实际验证范围见[本轮记录](test-results/project-menu/README.md)。从空白完整创作、暂停中的重开、持续运行、存档、字体闭包、独立发行及候选安装仍按[路线](ROADMAP.md)与[0.5.0门槛](MILESTONE_0.5.0.md)推进。
