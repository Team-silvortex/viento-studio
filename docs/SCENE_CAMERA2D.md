# 二维运行主相机

0.2.10 源码支持在 Godot 项目组装中为每个 Scene2D 配置一个运行主相机。编辑器的画布平移、缩放、全部取景和选择聚焦仍是临时编辑视图，详情见[世界工作平面](PROJECT_BUILD.md#世界工作平面与运行视口)。相机只改变运行取景，不改实例世界坐标、物理求解或动画视觉变换。主编辑画布的边框仍是默认 viewport 的参考范围，不叠加运行相机取景框；相机设置内另有独立的逻辑构图示意。实际画面仍通过构建后的窗口预览查看。

## 设置与保存

1. 保存 Scene2D 场景，在“构建与运行”中选择该场景，点击“运行主相机”。当前要求具有稳定实例 UUID 的 Scene2D 2／3。
2. 首次创建时选择文档类型和项目正文目录内的 `.json` 路径。默认固定在该场景 viewport 的中心，缩放为 1。
3. 选择“固定中心”，填写世界坐标 X／Y；或选择“跟随实例”，从目录选择完整实例 UUID，再填写世界单位偏移。共用同一 OC 定义的多个实例可分别选择。
4. 点击“审阅相机设置”，核对完整作者 JSON。点击“保存相机设置”才写入；“取消修改”和“返回构建”可放弃表单。首次保存同时建立正文、登记和场景引用；后续保存只更新相机正文。
5. 选择包含该场景的项目组装，重新检查计划、构建，再进行窗口预览。已有冻结工程不会自动改写。单独构建含相机的场景会提示需要项目组装。

相机中心和偏移每轴为 −100000～100000；统一缩放为 0.125～8，数值越大，可见世界范围越小。例如 viewport 为 800×480 时，缩放 2 对应 400×240 世界单位。跟随使用目标实例的最终逻辑节点；不跟随动画视觉子节点，也不跟随共用 OC 的其他实例。

需要限制运行取景时，勾选“启用世界边界”，填写左、上、右、下四条世界坐标边界。首次勾选前填入的范围来自当前场景设计 viewport，不根据演员位置自动推断；只有审阅并保存后才启用。取消勾选并保存会显式移除边界并降回作者格式 v1，不自动修改其他文档或已有冻结工程。

表单保存采用相机源版本和场景源版本双重检查，写入前再核对登记和依赖。外部修改、目标删除、切换场景或关闭后返回的旧响应不能继续应用。响应失联时只重新读取工程核对，不自动重复提交；仍无法核实时，可返回后重新打开检查。

## 相机设置内的逻辑构图

“相机构图示意”按当前表单绘制橙色取景框和场景实例的逻辑矩形。固定模式的期望中心来自表单中心；跟随模式的期望中心来自所选实例的保存态逻辑位置加偏移，按完整 `instanceId` UUID 区分共用 OC 的多个实例。橙框的世界尺寸为所选视口尺寸除以运行相机缩放。未启用边界时，期望中心就是实际中心；启用后按下节规则计算实际取景。示意不读取图片、视频或音频字节，不显示材质、动画视觉偏移、物理运动或实时游戏状态，也不启动引擎。

“构图视口参照”默认选择当前场景自己的设计 viewport。目录还可列出包含该场景的合法已保存项目组装，使用各自入口场景的 viewport 作为参照；这与当前 Godot 工程采用入口视口的规则一致，但不表示该组装已通过完整构建或运行检查。选项显示来源路径，组装选项另标明入口场景路径。切换参照只改变本地示意，不修改当前场景、组装入口或相机表单，也不发送新的网络请求。灰色框始终表示当前场景设计 viewport，不裁剪框外对象。

构图画布获得焦点后，可使用以下操作：

| 操作 | 效果 |
| --- | --- |
| 在橙框内拖动，或按方向键 | 调整固定中心或跟随偏移；Shift＋方向键每次移动10世界单位 |
| 在空白处、按住Alt或使用中键拖动 | 平移示意视图 |
| 滚轮、＋／－ | 缩放示意视图，不改变运行相机缩放 |
| Home／“适配相机取景” | 适配当前取景框 |
| 0／“查看全部构图” | 同时适配实际取景框与全部逻辑对象；启用边界时另包含边界框和期望中心点 |
| Esc／“取消取景拖动” | 取消进行中的手势；不撤销已经回填的表单修改 |

拖动期间只显示临时取景框；正常结束后才向父表单提交候选中心或偏移。父表单复核当前相机、场景会话和来源，接受后使旧审阅失效，仍须“审阅相机设置”及“保存相机设置”才能写入。取消、失去指针捕获、切换来源或关闭设置会取消尚未完成的手势。构图组件不持有保存票据，也不修改场景对象或主编辑画布。

构图上下文来自本次相机读取使用的同一个 World 快照。逻辑尺寸、位置和颜色通过共享场景模型解析，包含投影继承的有效值；不会用原始声明中缺失的尺寸拼出默认矩形。上下文最多128个实例、32条组装参照，另保留当前场景设计参照；局部来源诊断最多64条，目录截断会明确提示。视口参照分别携带其所有者与入口场景的身份、路径和修订。

几何或可选参照损坏时，相关参照会省略，或隐藏构图示意并显示局部提示；数字表单保留原有编辑与保存流程。这不绕过原相机声明、跟随成员、来源版本和保存校验。需要更新保存态几何或参照时，使用“重新读取工程”。逻辑构图本身只增加编辑视图与只读上下文；下面的世界边界由作者显式选择 v2 声明，仍不改变事务日志或运行协议版本。

## 世界边界与期望中心

边界为 `{left,top,right,bottom}`，每个值必须是 −100000～100000 内的有限数，支持小数和负坐标；要求 `left < right`、`top < bottom`。固定中心或跟随目标加偏移先形成期望中心，再根据每轴 `viewport / zoom / 2` 的可见半尺寸夹取实际中心，使正常尺寸的取景框留在边界内。若某轴可见范围大于世界边界跨度，该轴放在边界中点；此时画面仍可能看到边界外，边界不裁剪像素，也不限制演员移动或物理求解。

构图中青色框表示世界边界，橙色十字和橙框表示实际中心与实际可见范围，粉色圆点表示期望中心，两中心之间显示连线。拖动橙框和方向键仍修改声明的中心或跟随偏移，保持边界、缩放与目标 UUID；不会将夹取后的实际中心反写成作者值。即使实际框已贴边，期望中心仍可继续变化；“查看全部构图”会包含该点，便于找回越界意图。“适配相机取景”只适配实际框。

构图按所选视口参照计算；Godot 运行则按当前真实 Viewport 的可见尺寸计算，窗口尺寸变化后重新夹取。世界边界不扩展 Scene2D 设计 viewport，也不修改组装入口。 实际取景、恢复与包迁移的独立验收见[世界边界专题](test-results/scene-camera2d-limits/README.md)。

## 作者格式与关系

相机声明独立保存，UTF-8 上限 16 KiB；其引用的 Scene2D 正文在相机保存、构建和资源包语义验证中上限为 128 KiB。创建／恢复可以冻结更大的场景证据（最高 8 MiB），这个恢复预算不提高相机运行支持的正文上限。固定中心示例：

```json
{
  "format": "viento-scene-camera2d",
  "schemaVersion": 1,
  "sceneObjectId": "11111111-1111-4111-8111-111111111111",
  "camera": { "mode": "fixed", "center": [400, 240], "zoom": 1 }
}
```

跟随时，`camera` 改为：

```json
{
  "mode": "follow",
  "targetInstanceId": "22222222-2222-4222-8222-222222222222",
  "offset": [0, -40],
  "zoom": 2
}
```

v1 禁止 `limits` 字段；只有显式启用边界才使用 v2，且 v2 必须有完整 `camera.limits`。例如固定模式：

```json
{
  "format": "viento-scene-camera2d",
  "schemaVersion": 2,
  "sceneObjectId": "11111111-1111-4111-8111-111111111111",
  "camera": {
    "mode": "fixed",
    "center": [400, 240],
    "zoom": 2,
    "limits": { "left": -1000, "top": -500, "right": 3000, "bottom": 1500 }
  }
}
```

跟随模式保留上面的 `targetInstanceId`、`offset` 和 `zoom`，同样添加 `limits` 并使用 v2；移除边界时显式降为 v1。

两种模式的字段分别严格检查，不混用 `center` 与 `offset`，未知字段、重复 JSON 键、无效 UUID 和非有限数值会被拒绝。表单编辑替换 `/camera` 值，仅在启用或禁用边界时同时精确替换 `/schemaVersion`；两个值以外的 BOM、换行、字段顺序与数字原写法保留，语义无变化时保留完整原文；全文仍可用普通原文编辑器修改，构建和资源包导入导出独立验证语义。

场景登记以 `references`、`slot: "camera2d"` 指向相机登记；创建会在相机登记写入 `references`、`slot: "scene"` 指回场景；纯依赖验证要求恰好一条指回该场景的 `references`，不会强制该反向引用的 slot 值。每个场景最多选一个主相机。首次创建走 `camera2d.create` 三文件事务，事务日志 v13 支持中断恢复；不自动迁移已有作品或旧事务。相机本身不增加场景实例数量，也不升级 Scene2D 作者格式。

## 构建、迁移和接替边界

冻结计划中的可选 `camera2d` 保存相机作者声明和登记来源，子计划包装仍为 v1；基础能力为 `scene.camera2d`，作者 v2 还必须同时要求 `scene.camera2d.limits2d`。单场景、组装能力并集及实际生成器均独立检查，不能通过删掉能力标记将边界静默降级。没有选中相机时，不生成此字段和能力，沿原运行生成路径。Scene2D 作者格式、项目运行协议和创建恢复日志 v13 均不因边界改变。

相机边界增量引入时的 Godot 执行描述符为 0.44.0；当前描述符见[执行中间层](BACKEND_MIDDLEWARE.md)。相机内部生成层仍按内容区分：仅 v1 相机为 0.43.0，含任一 v2 相机为 0.44.0；不据此推断项目最外层生成器版本。同一组装可以混合两种相机：仅 v2 场景增加独立边界脚本和完整 v2 旁文件；其历史 v1 相机声明作为基础投影保留，两份声明由库存验证成对核对。运行先计算世界期望中心再夹取，原生相机 offset 置零，避免跟随偏移在夹取后再次移动画面。场景退出时释放相机，重新进入时重新绑定本次访问的逻辑实例。

旧场景、演员、物理与动画脚本不被边界层改写；未启用边界的 v1 生成文件与 `sourceMap` 保持。实现源码、准入规则和适配器源码参与构建指纹，源码变化会改变相关 fingerprint／SHA，文件保持不表示旧指纹也相同。新生成的边界工程同样接受脚本、基础／完整声明及额外旁文件的严格库存核对，未知、缺失或不配对内容会拒绝运行准备。

选择式[资源包](RESOURCE_PACKAGES.md)按登记和正文依赖带走场景、相机及其余完整依赖，保留 UUID 和原文。导入时即使 ZIP 校验和正确，也必须复核场景反向引用与跟随实例；引用目标工程已有场景时，会对该实际目标内容重新核对。生成工程则通过[工程交付](BACKEND_PROJECTS.md#交付生成工程)导出，仍需 Godot 工具执行。

当前相机模块不提供多活动相机、平滑／死区／震屏、相机旋转或镜头时间线；Bevy 尚未声明相机能力。屏幕文本与数值条由独立[场景 HUD](SCENE_HUD2D.md)提供，不属于相机坐标。作者规则、冻结合同、事务、界面与 Godot 适配分离；未来 ns-nova 原生 Studio 接替时保留语义、稳定身份和验收样例，不要求保留当前 JS 或 Tauri 实现。运行能力的环境与验收范围见[相机专题](test-results/scene-camera2d/README.md)；设置内的逻辑构图、恢复和实际取景核对另见[构图专题](test-results/scene-camera2d-composer/README.md)。
