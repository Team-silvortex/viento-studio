# 项目组装与启动场景

本页能力已纳入源码交付；开发证据保留执行时的 0.1.3 工作树身份，安装及目标设备范围以[当前状态](STATUS.md)为准。

2026-10-15，已收录 [0.1.4 源码](RELEASE_0.1.4.md)。项目组装把 **1–32 个已保存的 Scene2D** 组织为一个可构建目标，明确选择启动场景。当前由 Godot 4 适配器实现；Bevy 两条通道明确拒绝项目计划。安装包与设备范围见[当前状态](STATUS.md)。

## 从当前场景开始

在 **构建与运行** 中选择已保存的二维场景，点击 **用当前场景创建组装**。编辑器重新读取工程目录，核对场景身份后，把它放入新组装草稿，并设为启动场景。可继续添加其他场景，也可只保留这一个成员。

名称和 JSON 保存位置会预填；默认路径为 `documents/projects/assembly-<场景 UUID>.json`（正文根目录随工程配置），遇到目录内已有组装时追加数字。名称、位置、文档类型仍可修改；文档类型默认遵循工程目录，请选择适合工程组织方式的分类。其他文件占用路径时，保存事务仍会拒绝覆盖。

点击 **审阅组装** 核对完整 JSON，再点击 **保存组装**。保存确认后，构建目标切换到新组装，返回构建面板继续 **检查计划 → 构建项目 → 无头测试／窗口预览**。打开入口、审阅、取消均不会创建文档或执行任务；离开未保存的预填草稿时会确认丢弃。

这是从场景进入项目的作者入口。项目端口与[逐实例动画](SCENE_ANIMATION.md#为正式运行选择播放范围)沿既有项目运行路径执行；原场景、动画和行为文档继续独立维护。当前场景在目录中消失、作者会话／场景选择变化或草稿尚未保存时，不能继续应用旧选择。**项目组装** 仍可手动新建或编辑已有组装。

本轮操作与实际 Godot 验证见[从场景创建组装验收](test-results/scene-assembly-entry/README.md)。独立 Scene2D 的逐实例动画构建仍要求项目组装，作者格式、运行协议与执行后端契约保持。

项目的 **检查计划** 也会检查已保存生成状态控制器的动画绑定。缺失片段、错误参数、缺少场景动画或实例轨道会在启动工具前报告，可直接定位原文并普通保存修正；见[操作和边界](SCENE_ANIMATION.md#构建前检查状态片段绑定)。

## 在编辑器中使用

1. 先保存各场景及其需要的对象、投影、行为和声音。组装成员必须已经登记；片段配方先[生成独立 Scene2D](SCENE_COMPOSITION.md#从配方创建运行场景)。
2. 打开 **构建与运行 → 项目组装**。选择可添加场景，点击 **加入项目**；通过 **上移／下移／移除成员** 维护顺序，并选择 **启动场景**。
3. 填写组装名称、工程正文目录内的 JSON 保存位置和文档类型。点击 **审阅组装** 查看完整候选，再点击 **保存组装**。仅审阅或取消不写入作品。
4. 返回构建面板，已保存组装会成为当前构建目标。执行 **检查计划 → 构建项目 → 无头测试／窗口预览**。构建包含全部成员的一个工程；运行从指定入口开始。
5. 在后端工程详情核对组装来源、启动场景、各成员修订、资源和生成文件，再按[工程交付](BACKEND_PROJECTS.md#交付生成工程)生成 `.viento-build.zip`。

选择已有组装后再次打开 **项目组装** 可调整成员与入口；也可在窗口中载入其他组装，或新建独立组装。多个组装可以引用同一个场景。修改成员列表不会删除场景原文；成员顺序只表示项目中的保存顺序，不隐含自动切换。

原文、元数据或成员在审阅后变化时，保存会拒绝旧修订并保留输入。重新读取工程后需再次审阅；已存在的目标路径不会被新建操作覆盖。通信中断导致保存结果不明时，重新读取会按原文、路径、稳定身份和修订核对，未确认前不自动重复写入。

## 作者数据与依赖

组装是普通已登记的 JSON 作者文档，不含生成路径或引擎对象：

```json
{
  "format": "viento-project-assembly",
  "schemaVersion": 1,
  "title": "双场景作品",
  "entrySceneId": "eeeeeeee-eeee-4eee-8eee-eeeeeeeeeeee",
  "sceneIds": [
    "dddddddd-dddd-4ddd-8ddd-dddddddddddd",
    "eeeeeeee-eeee-4eee-8eee-eeeeeeeeeeee"
  ]
}
```

文档至多 32 KiB，名称 1–160 个 UTF-16 单元；成员为 1–32 个互不重复的小写 UUID，入口必须包含在成员内，成员不能是组装自身。成员支持现有 Scene2D v1／v2／v3，按原场景的规则继续解析对象、投影、图片、行为与声音。需要的脚本后端必须与当前宿主兼容。

`sceneIds` 是成员关系的权威。无须手动再创建一份同义 metadata 关系。资源包目录从组装正文派生成员依赖，递归收集其对象、脚本和素材；导入再次校验声明与依赖闭包。原有显式登记关系仍按原规则保留。完整作者工程迁移使用 `.viento.zip`；选定资源迁移使用[资源包](RESOURCE_PACKAGES.md)；生成工程交付使用 `.viento-build.zip`。

## 构建和运行边界

项目计划沿用 `viento-build-plan` 封装，以 `kind: "project"`、`schemaVersion: 1` 区分；它包含组装来源、入口 UUID、原样子场景计划及去重后的资源／能力并集。不把项目伪装为一个场景，也不把各场景实例合并到同一空间。现有单场景计划和静态预览保持原格式。

一次 World 观察与提交屏障冻结全部成员。资源按 UUID 去重并核对实际字节；任何成员或共享素材变化都使旧快照批准失效。每份资源至多 32 MiB、资源总计至多 128 MiB，组装联合资源清单至多 128 项；生成文件仍受现有构建预算约束。

Godot 适配器 `0.11.0` 生成一个 `project.godot`、可读的 `assembly.json`（schema 5） 和 `scenes/<场景 UUID>/` 子目录，共享图片、WAV 与作者脚本按稳定身份保存。只调整宿主生成模板中的固定路径；作者 GDScript 内容保持原字节。脚本不应依赖生成器内部的根 `scene.json`／`runtime.gd` 路径，这些不是作者接口。

后端工程清单 v2 明确记录组装身份、入口和所有成员来源；单场景继续使用 v1。持久目录兼容混合新旧工程，恢复后仍需显式选择运行工程。工程 ZIP 携带全部成员及去重素材，接收方仍需 Godot；作者快照、运行报告和缓存不随工程 ZIP 交付。

运行从启动场景开始，已绑定行为可请求进入其他成员；当前对象观察随场景变化，任务和工程身份仍指向组装。项目目标不显示单场景布局、行为、声音和控制回放／验收入口；需要修改成员时选择对应单场景。[跨场景共享状态](PROJECT_SHARED_STATE.md)、[项目事件](PROJECT_EVENTS.md)和[行为声音控制](PROJECT_AUDIO_CONTROLS.md)已接通；状态存档、事件留存重放、连续调试、组装级回放以及独立发行程序尚待接入。窗口预览保留现有五分钟上限。

## 运行中切换场景

这是 0.1.3 后工作树的第二步，接在组装保存与构建之后。Godot 适配器声明 `project.scene-switching`；Bevy 仍不接收项目组装，组装作者格式和原有单场景计划没有升级。

1. 在 **新建脚本** 中选择 **Godot / 场景切换**，审阅后进入原文草稿，再普通保存。
2. 给源场景的实例添加该行为；在行为参数里设置字符串 `target_scene_id`，值为目标成员的场景 UUID。可从组装审阅原文的 `sceneIds` 取得。只有支持行为的 Scene2D v2／v3 能绑定脚本，目标成员可使用已有场景版本。
3. 保存行为并重新构建组装。运行到该行为就绪时，会请求切换。窗口中的 **场景访问记录** 显示实际顺序，**当前场景** 与对象信息随成功进入的场景变化；访问记录中的原文入口只做导航。

起始内容使用仅在项目运行时注入的窄接口：

```gdscript
extends Node

@export var target_scene_id: String = ""

func _ready() -> void:
    if target_scene_id.is_empty() or not has_meta("viento_project"):
        return
    get_meta("viento_project").request_scene(target_scene_id)
```

`request_scene` 只接受当前组装已冻结的成员 UUID，不接受文件路径或引擎节点。请求延迟到当前回调结束后执行；退出前停止该场景处理、关闭声音并撤销旧访问的接口，再创建目标场景。返回同一场景会创建新的场景实例，不恢复旧坐标。每个接口绑定发起行为与访问编号，退出后持有的旧引用不能切换新访问。

同场景、已经有待执行请求或过期引用返回 `false`；非成员目标会报告行为错误并停止运行，可从问题列表定位绑定。当前每次运行最多进入 64 次场景，循环触发超过预算会明确失败。起始内容在就绪时请求切换，双向引用需自行设置触发条件，不能把两个无条件跳转脚本作为持续游戏循环。

无头测试仍使用整个项目合计两步、每步 0.25 秒的有限移动／声音检查；切换不会重置总预算。它会处理就绪时及步进之间的请求；脚本提前关闭导致累计时间不足时，本次测试明确失败。时长要求由 Godot 适配器提供，通用读取器只校验约定和引擎报告，不构成任意作者脚本的完整时间模拟。窗口运行保留正常 Godot 回调；工程 ZIP 含协调器、成员、脚本和资源，在另一处启动也采用同一切换接口。

运行中间层当前使用独立 `VIENTO_PROJECT:` 协议 4，按项目就绪、场景进入、带访问身份的原场景事件、共享状态变更、事件发布与投递、实际声音命令、场景退出及项目结束校验。纯读取器仍支持显式协议 1／2／3；本机旧工程按冻结适配器指纹守护，升级后需重新构建。每次访问重新建立原协议 1／2／3 的对象与行为校验；声音保留独立子协议 1。对象来源与成员列表来自冻结计划，切换间隙立即撤销旧坐标，A→B→A 的迟到导航也不能写回新访问。切换首轮证据见[场景切换验收](test-results/project-scene-switching/README.md)，状态首轮见[共享状态验收](test-results/project-shared-state/README.md)，协议 3 首轮见[项目事件验收](test-results/project-events/README.md)；当前声音控制范围见[专题指南](PROJECT_AUDIO_CONTROLS.md)。

## 行为声音与场景退出

当前访问中的行为可用 `play_audio(trackId)`／`stop_audio(trackId)` 请求控制本场景已声明的音轨，也可在项目事件回调中调用。场景初始化及零时刻提示完成后，先处理项目事件，再执行声音请求，两类队列排空才切场景或正常结束。离场统一停止旧播放器，历史命令不能控制新访问。**声音控制记录** 保留实际回执及行为／音轨双来源；预算、空提示和失败规则见[行为驱动场景声音](PROJECT_AUDIO_CONTROLS.md)。

## 命令行与接口

```sh
node scripts/project-build.mjs --command plan --root /path/to/workspace --target <assembly-uuid>
node scripts/project-build.mjs --command build --root /path/to/workspace --target <assembly-uuid> --tool /path/to/Godot --output /outside/source/build
node scripts/project-build.mjs --command run --build /outside/source/build --tool /path/to/Godot
```

`--target` 接受登记 UUID 或工程内来源路径；旧 `--scene` 仍可用于单场景，两者互斥。运行和检查只接受冻结构建目录，不重新读取作者正文。

本机构建 API 的 `plan/build` 新增 `targetId`；旧 `sceneId` 只准入单场景。作者窗口使用 `assembly-list`、`assembly-load`、`assembly-save`，保存需 World 与原文修订。运行查询 `inspect` 可按当前实例或对象筛选，项目任务同时返回当前场景与访问记录；查询不会返回已离开场景的旧对象。HTTP 不接收工具路径、输出目录或超时覆盖。领域校验、作者存储、窗口和执行适配器各自独立，系统能力为构建模块的 `project.authoring.assembly`。

实现与实测见[本轮记录](test-results/project-assembly/README.md)、[功能图谱](FUNCTION_ATLAS.md#build.project_assembly)。
