# ZIP 归档双头一致性修复

2026-11-04，0.2.8 之后的源码安全修复。

[上游告警 GHSA-m665-v7pm-7grj](https://github.com/advisories/GHSA-m665-v7pm-7grj)将 zip ≤9.0.4 列为受影响，修复版为 9.0.5。问题在于 ZIP 的中央目录和本地文件头可声明不同名称，使用不同读取方式的工具可能对同一个包作出不同判断。

本项目的正常导入始终按清单、安全路径与摘要恢复文件；新增测试证明旧依赖仍会接受双头不一致包，不据此声称本项目已复现远程代码执行。修复同时升级依赖并显式调用上游严格校验，拒绝歧义包，再进入既有桌面／移动导入流程。

两个入口在文件数量限制之后、清单读取与恢复目录创建之前验证全部头信息；后续仍核对文件路径、大小、SHA-256、登记与作品身份。zip 9 的可失败文件名解码也显式处理。合法的旧归档继续支持，格式、正文、素材、UUID 及关系不迁移。

宿主 Rust 最低版本改为 1.88，与修复版依赖要求一致；推荐稳定版。本机已安装程序和已生成的旧安装包需要重新构建、更新后才包含修复。本次源码修复不升级应用版本，也不改写历史发布证据。

复现、错误包拒绝、正常迁移与测试环境见[独立验收记录](test-results/zip-security-2026-11-04/README.md)。
