# 后端工程管理

基础工程管理已随 0.0.10 源码交付，当前 0.1.0 之后的工作树另增加生成工程交付包。作者工程与后端生成工程分别管理，现有安装版的覆盖见[当前状态](STATUS.md)。Godot、Bevy 共用清单与宿主管理接口，具体生成格式和执行命令仍由[可信后端适配器](BACKEND_MIDDLEWARE.md)负责。

## 作者内容与生成工程

作者工程保存 OC 定义、投影、场景、行为正文和资源引用。它是完整迁移包的权威内容。构建保存这些输入的冻结快照，再在作者目录和实际素材目录之外生成后端工程；生成文件不会回写作者正文，也不自动进入作者工程包。

| 后端 | 当前生成内容 | 使用方式 |
| --- | --- | --- |
| Godot 4 | `project.godot`、场景、运行脚本、图片副本；行为场景另含冻结的 GDScript 输入 | 由锁定的 Godot 工具导入、检查与运行 |
| Bevy | `scene-data.json` 场景数据包 | 由锁定的可信 Bevy 无头运行程序检查与运行；当前不生成可编辑的 Cargo / Rust 作者工程 |
| ns-nova / yalivia | 尚未接入 | 管理契约与具体后端分开；不把未来原生运行能力标成现有功能 |

同一作者场景在不同后端生成的工程有各自的构建 UUID、后端身份、工具身份和库存。查看详情与选择运行工程是两个明确操作。

## 在编辑器中查看

打开“构建与运行”，切换到“构建任务”。“后端工程”列出当前服务创建的产物及持久索引登记的历史成功工程，按所选场景与后端筛选。成功工程可打开“工程详情”，查看冻结来源、工程入口、生成文件、资源副本、适配器和工具身份，以及保留规则。失败或取消的输出在当前服务列表保留，其部分输入用于诊断，不能作为成功工程执行；本轮索引只登记成功构建。

重启后历史工程显示“待检查”，当前运行工程为空。点击“设为运行工程”后，宿主重新检查冻结来源、当前适配器、生成文件、清单摘要和原目录身份，成功才改变运行目标。仅查看详情不会选择，也不会启动引擎。普通运行、有限方向控制、验收用例与验收组都使用明确选择的同一份冻结工程；运行时仍单独检查本机工具身份。选择失败保留原运行目标，过期请求不会覆盖后来的选择或新任务。

重启时作者目录离线或原场景不再存在时，可以显示“仅冻结工程”的场景入口；已观察过的场景保留原缓存列表，由明确的来源离线提示阻止新作者操作。可以查看、选择和运行已经保存的工程；新设计检查、构建、场景编辑及读取作者验收组仍要求可读取的作者内容。作者路径仍可读取时，宿主另外核对小型作品清单中的 workspace UUID，另一个作品替换同一路径不会继承旧工程。

详情核对的是该份冻结工程，当前作者草稿或后续修改不会替换它的输入。页面按路径、大小和 SHA-256 展示生成文件，按稳定 UUID 展示资源与冻结来源。作者文件清单覆盖冻结的作者输入，不能把全部文件都理解成所选场景的最小依赖闭包。目录只供查看，网页不能传入任意本机路径来检查或删除文件。

检查不会启动工具进程，因而工具未安装、作者目录暂时离线时仍可查看已拥有的成功工程。锁定工具身份是构建事实；检查结果不代表目前本机工具已经通过身份检查。运行前仍需核对工具与适配器，生成文件被修改时应从作者工程重新构建。管理清单不成为脚本输入：当前创建宿主仍按既有写入凭据与冻结运行规则准入；恢复工程另以索引锁定的清单精确摘要作为身份守护，不把列表条目或一次检查结果当成持续执行许可。

刷新会重新读取索引，合并其他宿主登记的新工程；历史登记被移除或变更时，撤销对应选择并要求重新检查。正在执行的任务保留已准入的冻结输入直至结束。当前服务的真实写入凭据不会因索引中缺少条目而丢失。索引损坏或写入失败显示独立提示，当前构建仍可成功使用，已有记录和产物不会被覆盖。

## 交付生成工程

在成功工程的 **工程详情** 完成核对后，点击 **交付工程**。入口要求已有真实登记清单及其精确摘要；旧产物派生的只读详情不能直接交付，需重新构建取得登记。当前服务还须明确支持交付能力。查看、选择运行和交付各自独立，交付不会更换运行目标或启动工具。

先核对生成文件、素材副本、来源 ID 和工具依赖，再 **准备交付包**。服务按构建 ID、预期快照和清单摘要重新核对，逐文件读取与复查后生成 `viento-<构建 ID>.viento-build.zip`：

```text
viento-<buildId>.viento-build.zip
  project/       # 仅清单登记的生成文件、素材与所需脚本副本
  README.md      # 中英日使用说明与工具要求
  manifest.json  # 交付格式、来源清单、文件大小与 SHA-256
```

包使用 `viento-build-delivery` v1；来源清单保留构建、场景、后端、工具和证据摘要，摘要引用不表示把证据文件也打包。原始作者快照、`build.json`、`snapshot.json`、`source-map.json`、运行日志、缓存、工具程序和额外目录均不进入 ZIP。详情中发现的额外文件也不会自动加入包；登记文件变化、路径不安全或最终复核失败会阻止发布。

Godot 包需要兼容的 Godot 打开入口；Bevy 包是供对应可信运行程序消费的 `scene-data.json`，没有 Cargo 作者源码。此包用于迁移和交付派生工程，尚非独立游戏发行；包校验不授予导入、运行、删除或回写作者工程的权限。完整作者数据仍通过 `.viento.zip` 保存和迁移。

准备期间与构建、运行及工具检查共用服务任务位置，直到 ZIP 写入及最终核对结束才释放。完成后下载使用已经冻结的包，不再依赖生成目录的后续状态，也不阻止继续创作。未下载时关闭窗口会释放包；浏览器已发起下载则交由服务到期回收。桌面保存窗口期间保持任务，先完成或取消文件选择；取消可保留同一包重试。准备取消、迟到回执与场景／会话／后端变化不能替换当前审阅。操作及临时空间见[导出](EXPORT.md#生成工程交付包)，本轮证据见[交付专题](test-results/backend-project-delivery/)。

## 磁盘清单与只读检查

新成功构建保存以下布局：

```text
<build-directory>/
  backend-project.json  # 统一后端工程清单，schemaVersion 1
  build.json            # 构建状态、工具、执行适配器与生成文件库存
  snapshot.json         # 冻结作者输入与中立场景计划
  source-map.json       # 运行声明到冻结作者来源的映射
  project/              # 后端生成文件与资源副本
  sessions/             # 运行后留下的小型会话记录；临时运行工程结束时删除
```

`viento-backend-project` 清单复用原构建身份与库存，记录来源、后端、执行适配器、工具、入口、文件角色、资源 UUID 到生成路径的映射及生命周期。三份证据文件另以精确字节摘要锁定；清单不包含本机工具路径，不授予执行权限或磁盘所有权。原 build-record / snapshot 格式不升级。Godot 导入为已知脚本／图片产生的 `.uid` / `.import` 辅助文件按可信输入路径清理，在运行临时副本中重新产生，不作为未登记文件留在生成工程里。本轮 Godot 执行适配器代码指纹因此变化，旧构建须按既有规则重建；生成器与原运行协议不变。

命令行可以检查已知目录，包括前一次服务或 CLI 创建的输出：

```sh
node scripts/project-build.mjs --command inspect --build /absolute/build-directory
```

检查恢复冻结计划，重新生成预期文件，核对生成器／适配器、源映射、库存与实际字节。旧成功构建没有统一清单时可以派生只读详情，结果 `inspection.recorded=false`；不会为它补写文件。记录文件或库存被篡改会报错。额外文件与会话目录会单独列出，`complete=false` 不把这些文件冒充受管理生成物，也不执行或删除它们。

`inspect` 只接受 `--command`、`--build` 和可选 `--backend`，无需作者工程、工具配置或运行参数。`run` / 验收组未显式选后端时按冻结工程选择后端，同时选择该后端对应的本机工具配置，不再误用默认 Godot 工具。

## 缓存与保留规则

编辑器输出位于应用缓存的 `builds/editor/<author-root-hash>/<backend-id>/<job-uuid>/`。同一后端目录下的 `backend-project-catalog.json` 是宿主恢复索引，保存已成功创建工程的相对子目录、稳定来源身份、目录设备／inode 和清单摘要，单独绑定目录范围与后端。列表只读取这份登记，不扫描或认领陌生目录。CLI 默认使用 `builds/<build-uuid>/`，也可选择全新输出目录；已有目录拒绝覆盖，CLI 输出和本轮以前未登记的输出继续通过上面的 `inspect` 检查，不自动加入界面。

索引以最多 256 条／1 MiB 限制读取和发布，跨进程独占锁串行合并更新，原子替换前后核对文件身份与精确字节。损坏、链接、目录替换或锁占用会报独立诊断，不静默重建、驱逐旧记录或删陌生锁。关闭面板后任务继续；关闭服务取消任务并等待检查／执行退出，已有输出和索引保留。索引是本机宿主状态，不进入作者迁移包；作者根路径或缓存位置变化后不会自动迁移或重新认领，已知产物仍可 CLI 检查。

当前服务保留最近三份可自动回收的输出。每次清理先核对创建时保存在内存的目录身份、精确文件字节和目录树；清单本身不能授予删除权限。以下情况保留工程，并在列表说明原因：

- 生成文件或记录被修改、缺失，或目录身份被替换。
- 增加了文件、空目录、链接或特殊文件。
- 工程已有运行会话报告。
- 清理未能完成。

普通输出首次核对通过后会先移到同父目录的随机 `.viento-prune-<uuid>` 路径，再完整复核后删除；复核发现新改动时保留这个目录，详情展示实际新位置，避免恢复时覆盖用户后来新建的原路径。该规则防止检查期间的常见改动误删，不提供对同一用户持续并发写入的事务锁。

这些保留项不占后续三份普通输出的回收额度，因此列表可以超过三份。失败构建保留部分生成输入，只有内容与宿主写入凭据完全一致时才按同一规则回收。恢复的上一服务工程统一标为保留，即使重新选择运行也不会获得本服务的删除凭据。CLI 输出、工具缓存、作者正文和素材也不在这个自动清理范围中。

当前不支持在生成目录里编辑后再回导作者工程、跨路径自动迁移／陌生目录认领、工程独立发行或任意缓存批量删除。构建与场景工作流见[构建与运行](PROJECT_BUILD.md)，后端能力边界见[Bevy 后端](BEVY_BACKEND.md)与[场景行为](SCENE_BEHAVIORS.md)。清单与回收原验收见[管理专题](test-results/backend-project-management/results.json)，持久恢复与运行对接另见[本轮验收](test-results/backend-project-catalog/results.json)。
