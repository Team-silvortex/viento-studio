## 实测修复及保留记录

- 既有来源导航按逻辑行数估算滚动，现与行号导航共用完整文本排版测量；词中位置不会因截断文本而改变折行。
- 来源激活中的多次提前焦点已改为延迟交接。焦点前后均检查来源、弹窗和忙碌状态；后续用户操作优先，旧回调不能覆盖新文档或新选区。实际宿主新增 11 项回归。
- 初次窄屏实测 `browser-1791863122055` 发现诊断面板被压到一行，日语正文也过小。现在面板保持可用高度，内容区可纵向滚动；最终三语面板为 125／130／130px，源码区约 461px。
- `browser-1791863096227` 是实测脚本自身的换行转义问题，修正后独立测量通过。
- 首次完整检查 `full-check.log` 发现旧行为诊断测试仍期待两个参数，已补上新增标量描述并继续完整核对原定位数据。中途隔离 VM 对象比较失败记录也保留，最终比较已统一为普通数据快照。

- 后续完整检查 `full-final.log` 暴露既有模拟崩溃测试的竞争问题：工作进程仅等待未完成 Promise，约 4.85 ms 后自行以 13 退出，提前释放锁。现通过保活维持检查点，父连接断开即退出；测试确认等待 100 ms 后仍持锁，并确实由父进程终止。生产事务代码不变，22 项事务测试通过；修复前后证据见 `crash-worker-before.json`、`crash-worker-after.json` 和 `transaction-worker-fixed.log`。

- 最终复核补上创建行为后的窗口关闭交接：异步读取仍校验发起方，窗口正常关闭后焦点由当前源码编辑会话接管。`author-focus-before.log` 保留复现，`author-focus-fixed.log` 的 36 项实际宿主测试通过。其后两条浏览器流程均重新运行并匹配最终源码。
- `full-integration-pass.log` 为最后一处修正整合期间的完整通过记录；源码冻结后再次运行的 `full-verified.log` 用作最终验收。
