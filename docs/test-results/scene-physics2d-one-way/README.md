# 静态单向平台：编辑、原生运行与工程交付

2026-10-25，**0.2.3 之后的开发工作树**。在物理观察、角色运动和作者事件之上增加静态单向平台。源码版本保持0.2.3，本机安装仍为0.2.0；本轮验证使用隔离作者工程，未更新安装或日常作品。操作见[配置静态单向平台](../../SCENE_PHYSICS2D.md#配置静态单向平台)。

## 实现与范围

- 物理schema 4新增静态矩形专属 `oneWay: { margin: 1 }`，有限范围1–64。Rust/WASM提供独立检查操作和标记；旧schema 1／2／3检查保持各自范围。
- 现有物理编辑器提供“静态碰撞方式 → 单向平台”，中英日齐全。首次创建保持普通流程；启用需检查、审阅、应用草稿与普通保存。关闭删除字段但不降格式；空间偏移与尺寸编辑保留平台和角色参数。
- 中立计划按实际字段要求 `physics.one-way-platform2d`。没有单向字段的schema 4复用旧生成输出；缺少能力的后端和生成回执明确拒绝，两条Bevy通道尚未接入。
- Godot0.26.0包装只在原生静态形状建立后、作者行为就绪前设置 `one_way_collision` 和margin。旧13份生成／运行文件保持；原求解只运行一次，项目wire与观察协议不变。角色落地继续驱动普通作者事件、动画和声音。
- 独立helper、逐场景声明、库存和原runtime随生成工程交付。没有运动平台、斜坡策略、可配置朝向或主动向下穿透；较大margin可能推出初始重叠角色，不保证任意巨大单步无穿透。

## 发现与修正

1. 原生独立探针发现margin为0时常规下降可漏碰，0.01／0.1也存在特定步长漏碰。因此正式声明、UI和生成库存统一限制为1–64，默认1；保留[初始](backend-probe-initial.log)、[范围](backend-probe-margins.log)、[正数边界](backend-probe-positive-margins.log)记录及[最终探针源码](backend-probe.gd)。这些开发探针不视作完整防穿透保证。
2. 首次完整原生测试错误要求排除平台碰撞的角色在30步内回到下层地面Y180。实际末位置为 `[160.033081,173.278458]`，仍在下降且平台接触为零；飞行时间较长，尚未落到下层。只修正测试为中心已穿过平台、仍下降且无额外landed，定向复验通过，产品源码未因该失败修改。
3. 首次完整app-only共8171项，7748通过、422条件跳过、1失败；唯一失败为适配器指纹测试的独立文件清单漏列两个新增后端文件。补齐清单及逐项排除断言后，[适配器复验](adapter-retest.log)13通过、2原生条件跳过；生产指纹正确且没有修改。最终完整检查另行保存。
4. 后端补丁审阅发现两条指纹文件条目被误插到无物理的control replay暂存数组；应用前移除，实际生产与回归均使用修正后的补丁。

首次完整应用检查启动后仅修正上述测试断言与测试指纹预期，生产代码保持冻结。专项之间及与完整应用检查存在重叠，不能相加作为覆盖率；条件跳过不计为通过。
