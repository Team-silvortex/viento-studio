# 菜单后端检查与诊断证据

本目录只记录本轮检查、历史诊断及复现源文件。完整应用回归和真实键鼠／离线工作流验收由本主题其他证据记录。

- `backend-tests.tap.log`：菜单 8 项（含真实 Godot 数值回归）、原暂停 7 项、原重开 6 项，共 **21/21 通过**。
- `final-capability/report.json`：最终冻结菜单运行层的 **87 个接受／拒绝案例符合预期**。其中 **84 个共同结果**；另外 **3 个值在通用 Double 合同中合法，但 Godot 无法保真读取，最终后端明确拒绝**，原因是 `godot-number-underflow`。这是能力限制检查，不代表全部数值逐位一致。
- `numeric-loss-diagnostic/report.json`：修复前 **22 个数值的 IEEE Double 字节与序列化诊断**，保留发现静默归零的原始失败结果。`String.to_float()` 存在相同限制；`-0` 的序列化归零另属于既有共享状态零值归一规则。
- `initial-admission82/`：修复前 **82 个接受／拒绝初检**，当时全部相同；该检查没有比较数值字节，不能代替后续诊断或最终能力报告。
- `wm-environment/report.json`：原版／定制 Godot × 运行／暂停 × 未预建／预建标准 X11 原子的 **8 项独立窗口矩阵**。未预建原子的 4 项不接收关闭消息；启动前保持 X 连接并预建标准原子的 4 项都收到真实关闭通知和窗口信号，正常退出。该诊断定位了无窗口管理器 Xvfb 的环境缺项，没有放宽真实关闭验收，也不需要修改产品运行层。

最终数值检查拒绝 `5e-324`、`2.2250738585072014e-308`、`1.2345678901234567e-300`，避免把非零值静默变成零。全零尾数的 `0e9999`、`-0.000e9999`、`0e-9999` 只在解析副本中归一化；作者原文和冻结配置字符串保留。真实回归同时验证失败不占菜单槽、不写共享状态、不消耗预算。

最终运行层 SHA-256：`477231c332608e3fa0fc9860663b2f6f3101e8dbdf4c882e452a6c636e3f5b62`。

各目录保存当时的探针与驱动源码，保留其原始临时路径；复现时应先在临时副本中准备对应目录与工具链。历史初检和数值诊断源依赖修复前运行层，不能在最终版本中放宽校验来重现历史结果。`wm-environment` 同时保存 8 项最小项目、每项报告及日志；未保存早期窗口标题不匹配的无效探针。
