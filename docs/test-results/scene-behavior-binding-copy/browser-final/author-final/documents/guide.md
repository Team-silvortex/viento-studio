# 俯视收集：从空白工程到可运行初稿

这是本轮作者样例的操作草案，记录现有入口如何组合成一款小关卡，尚未作为逐步界面实测通过记录。具体文件名、参数和值以正式样例保存的作者原文为准；构建和运行结果应另行留证。

## 玩法与操作

方向键移动薄荷色玩家，收集地图上的三簇金色晶体。收集齐三簇后，青色出口解锁；进入出口通关。红色尖刺是危险区，玩家初始有三点生命，生命归零后进入失败页。墙壁阻挡移动。

开始页按 **Enter** 开始；通关页或失败页按 **Enter** 开始新的尝试。跨场景时需先释放 Enter，再重新按下。鼠标不控制玩家，屏幕文字和生命条只负责显示。**Escape 会结束本次预览，不是暂停。**

## 准备工程和素材

1. 使用当前源码提供的 Studio，在首页选择 **新建作品库**，创建独立的空白工程。空白模板不会自动生成此关卡。本机旧 0.2.0 安装的支持范围与当前源码不同，不据此假定它已经具有全部入口。
2. 切换到 **编辑** 模式，在 **项目类型与模板** 中确认可用的文档类型；可按需增加设定、投影、场景、行为、脚本及各类场景声明的分类。分类用于工程组织，不会自动产生玩法。
3. 通过编辑器的素材入口导入本样例的玩家、晶体、出口、尖刺、墙壁 SVG，以及拾取、受伤、通关 WAV。先完成素材登记；场景和声音表单选择已经登记的素材。`floor.svg` 是可选装饰，单用场景背景色也可。
4. 新建设定原文并普通保存，分别说明玩家、晶体、出口、危险区和墙壁的含义。选择角色后可在 **世界与对象 → 创建投影** 使用现有 RPG 玩家／NPC 子模板：玩家使用方向键输入和移动速度，静态物件使用无输入、零速度。审阅配置再保存；投影中的数值不会自动实现伤害或收集规则。

## 布置场景和碰撞

1. 从 **构建与运行 → 创建场景** 建立开始、关卡、通关和失败四个已保存的 Scene2D。场景中的行为载体、玩家、三个晶体、出口、尖刺和墙壁均保留独立实例身份；重复物件可复用设定或投影。
2. 关卡使用深色背景 `#101b29`。布置玩家起点、三处可到达的晶体、危险区、出口和边界墙。尺寸、位置与显示顺序以场景原文为准；先用静态场景预览检查摆放，它不证明碰撞或玩法已经运行。
3. 在关卡的 **场景物理** 中创建角色体；审阅并 **保存物理与关系**。再打开物理原文，通过 **编辑二维物理** 为墙设置静态障碍，为晶体、危险区和出口设置触发区。角色可选择沿碰撞面滑动；静态物件和触发区保持无输入、零速度。检查完整原文，应用草稿后仍须主编辑器普通保存。
4. 通过 **运行主相机** 设置固定中心或跟随玩家；需要世界边界时显式开启并保存。编辑画布的缩放、拖动和取景不会代替这份运行相机配置。

## 保存玩法、状态和声音

1. 在 **新建脚本** 中选择 Godot 空 Node 或适用的现有起始内容，创建普通 TXT 草稿。在内置原文编辑器写入样例的完整行为源码，然后普通保存；也可先新建 TXT 文档再编辑。不要修改构建目录中的生成文件。
2. 玩家、晶体、危险区和出口的普通行为共同负责收集、计分、生命、出口条件与胜负事件。三个晶体必须分别记录是否已拾取，同一个晶体不能重复计分；通关和失败由实际玩法触发，不能用测试专用按键代替。
3. 选择已保存场景，使用 **添加场景行为** 明确选择 Godot／GDScript、实例和已登记脚本，审阅后 **保存行为与关系**。已有行为文档则通过 **管理已有行为** 补充脚本引用，再用 **编辑场景行为** 配置绑定、带类型参数及信号。检查后应用到原文草稿，最后普通保存。脚本参数不会自动从源码发现。
4. 在关卡的 **场景声音设置** 中选择拾取／受伤 WAV，建立由行为事件触发的两条音轨，审阅后 **保存声音与关系**；通关 WAV 则放在胜利场景，以 0.05 秒时间提示播放。如脚本使用音轨参数，可在行为编辑器 **读取场景音轨** 后显式填入编号。轨道和时间提示以各自已保存声明为准，单纯导入声音不会自动触发播放。
5. 在 **场景 HUD** 添加操作说明、已收集数量和生命值／生命条。状态键与玩法脚本一致，生命条范围设为 0–3；用临时示例检查版式，再审阅并保存。示例不会初始化游戏状态。本轮运行文字优先使用 ASCII 英文；尚未接通自定义字体交付，不把开发机字体视为随包资源。

## 接通开始、结果和重试

1. 在 **项目组装** 加入四个已保存场景，把开始页设为启动场景。审阅完整组装再保存。另创建并保存项目键盘映射，本样例为 `start_retry → Enter / Space`，在组装中选择该映射并再次保存；新建脚本不会自动创建动作。
2. 开始页和结果页使用 **Godot / 按动作重试关卡** 的普通脚本。关联脚本后，在行为编辑器显式添加 String 参数：`action_name` 选择对应的动作名，`target_scene_id` 使用本组装的关卡身份，`state_values_json` 设置为 `{"score":0,"health":3,"door_open":false}`。三枚晶体的去重记录保存在控制器／触发区的局部状态中，重建关卡时自然清空，不需要额外的共享收集键。未声明的其他共享状态仍会保留。
3. 关卡使用 **Godot / 按事件切换场景** 订阅玩法发布的通关／失败事件，分别指向相应结果场景。当前目标仍保存为完整 UUID 字符串，可从组装审阅或来源原文核对；这里不假定尚在规划中的场景参数选择器已经可用。修改参数后检查完整行为原文、应用草稿并普通保存。
4. 保存全部作者文档，返回组装目标执行 **检查计划 → 构建项目 → 窗口预览**。构建诊断优先回到对应作者来源修正，再重新构建。Godot 工具置于作者工程之外；窗口预览需有图形环境。

## 本轮应留下的验证结果

这是待执行的验收清单，不能因文件存在或静态检查通过而标记完成。

- 从开始页按 Enter 进入关卡，方向键移动、墙壁阻挡；三处晶体各只计一次，未收集齐时出口不能通关。
- 集齐三簇后出口可通关；接触危险区会扣血，生命归零进入失败页，HUD与相应声音符合保存的行为。
- 分别从通关页和失败页按 Enter 重试：位置、三点生命、收集记录与出口状态全部复位；长按 Enter 不连续跳过页面。
- 保存、关闭重开后仍能检查与构建；将作者工程导出为完整 `.viento.zip`，在新根目录恢复，原目录移离后重新检查、构建和运行。
- 拾取／受伤／通关声音需要实际播放检查。后端播放回执不等于扬声器出声证据；静态画布、无头测试与窗口操作分别记录。

## 当前边界和素材许可

本轮是完整游戏工作流的第一份可运行初稿，不代表 0.3 或 0.5.0 门槛已经通过。现有窗口预览仍受约五分钟及访问／事件／状态／媒体累计预算限制，反复重试不会重置会话预算。尚不包含暂停／恢复、同场景即时重启、跨启动存档、30 分钟持续游玩或独立游戏发行。

`.viento.zip` 是可继续编辑的作者工程；`.viento-build.zip` 是生成的 Godot 工程交付，运行仍需 Godot 工具。两者均不等于不依赖引擎工具的游戏发行程序。

本样例的六份 SVG 和三份短 WAV 为此次原创素材，采用 **CC0-1.0** 许可，可复制、修改和再分发，无需署名。SVG不含脚本、字体或外部引用；声音由数学波形生成，无外部录音或采样。素材登记应保存最终文件的真实大小和 SHA-256，不因改名而重新假定内容摘要。
