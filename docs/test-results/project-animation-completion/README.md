# 动画自然完成与片段衔接验收

应用版本仍为 **0.1.7**，基线提交 `bc463a2f0365493decdf4fddf5ca857ae951b27f`；本目录记录之后的未发布源码。用户已明确允许新含动画项目升级为 protocol 7／Godot 适配器 0.16.0，以接通自然完成；没有修改作者数据格式或安装程序。

## 本轮范围

- Rust 既有显式时钟 transport 核验自然结束，独立完成账本核对冻结动画、片段和接收行为来源；循环、停止或手动定位不冒充自然完成。
- Godot 先捕捉完成，再在安全点投递。有新动画命令、离场或结束请求时跳过旧通知；同访问仍有效的订阅可在下一轮继续使用。独立预算限制完成、订阅和投递，回调失败保留诊断。
- 普通“Godot / 动画完成后衔接片段”脚本及两个字符串参数复用现有创建、片段选择、审阅和保存；真实攻击完成后衔接循环待机。
- 独立三语完成面板显示完成与投递状态，分别回源到动画、片段和订阅行为；旧命令、声音、事件与共享状态面板保持。

首轮 [Chrome 记录](browser-authoring-1792494737042/browser.json)验证了前两条来源；其说明残留旧模板的“command/time参数”措辞，最终脚本已改为 finished_clip_id／next_clip_id 并重跑第三条订阅来源。保留首轮原始证据，不将其计作额外覆盖。初始 [保存流程失败日志](authoring-workflow-initial.log)来自协议7尚未接入外层后端描述符准入，已修复并由最终8项回归覆盖。

初次 [应用回归](app-check-initial.log) 的两处失败为旧“未知协议”数组仍列入 7，改为 8，并显式覆盖合法 1–7 后，[29 项定向回归](protocol-admission-fixed.log)通过，再复跑完整应用。统一 Godot 组的单项失败为旧完整动画状态断言漏 `clipId: null`，实际运行与协议核验已成功；修正后定向重跑通过，不将原始失败日志改写成全绿。

首批 [16 项完成回归](native-completion-initial.log)通过；[扩展首轮](native-completion-extra-initial.log)中浮点反例因 GDScript 十进制字面量舍入失真而失败。改用相同 IEEE 754 位模式构造时间后，确认并修复新桥接的末端判断，独立反例及最终统一组均通过。旧生成器对应的 GDScript 文件没有改写。

## 验收边界

Chrome 的运行样例在测试前预置，GUI 新建的脚本另验普通保存；新保存脚本到执行由独立 HTTP 工作流贯通，不拼成一次从空工程全 GUI 的结论。实际 Chrome 使用本机 HTTP 编辑服务，Godot 使用无头工具；未安装 Tauri、未验收 Android 或其他桌面平台、未检查硬件 GPU／游戏窗口画面。作者 schema、Rust 源码和 WASM 没有变化，本轮不重跑 Rust 原生全量。状态机、混合、骨骼、3D、Bevy 动画及独立游戏发行不在本轮范围。

完成记录的“已处理”只代表同步回调返回成功，衔接命令是否执行应另查动画命令记录。旧安装程序、已登记真实作品、历史示例和旧测试目录都不属于本轮写入目标。
