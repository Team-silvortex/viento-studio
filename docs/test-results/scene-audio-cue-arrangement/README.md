# 声音提示换轨与顺序验收

2026-10-16，基线 `cc4e5aa3`／0.1.4 后未发布工作树。已有声音编辑器支持为提示更换目标音轨，以及上移／下移；同一表单可组合增删、时间／动作与轨道设置。步骤见[声音提示编排](../../SCENE_AUDIO.md#调整提示目标轨道与顺序)。

## 实现与边界

新 `createSceneAudioTimelineProposal` 接受完整提示编排，复用 Rust 校验／采样和既有来源宿主。两种旧 API 继续各自的严格契约：叶编辑保持定长、身份与绑定；增删 API 只允许移除及末尾追加，固定既有绑定与相对顺序。私有提案模式在应用时重算，不因共享宿主放宽旧调用。

只换轨时修改对应 `trackId` 叶 token；增删／重排只重建 `/cues`，按 UUID 复用保留项原片段。提示身份、轨道／资源声明及未修改原文保持。播放先按时间排序，同一时刻才按列表顺序执行；移动不同时间的提示不会修改秒数。界面保留未完成输入，进一步编辑撤销旧审阅；检查后仅应用到普通草稿，再普通保存。

轨道增删、素材替换与即时播放不在此表单范围。声音 schema、Rust ABI、模块／能力和后端协议不变；未增加 JS 语义替代层、保存事务或后端权限。

## 保存与交付

临时副本中的两条既有提示换轨，三条提示由 A／B／C 调整为 C／B／A。新顺序为：0 秒音效播放，0.25 秒音乐停止，随后同为 0.25 秒的音乐播放。Rust 最终采样确认音乐为播放状态；Godot 命令顺序一致。审阅、取消和应用草稿均不写磁盘，普通保存只改变声音 JSON，保存重开保留身份与目标。

Chrome 下载 **58,458 字节**工程 ZIP；独立校验 **8 个文件／1 份 WAV**，异地导入和运行产生相同声音事件。归档 SHA-256：`c0f57791beddab9fa1389105bbc83961c048579271a3eb9f34936311e552064c`。这是需要 Godot 的源工程交付，不是独立游戏发行。

**7516** 份旧示例／历史／证据和已安装 AppImage 保持，2136 个旧评分对象完整保留。浏览器、临时工程和解包目录由验收脚本回收；[清理记录](cleanup.json)只移除本轮新生成且核对过的桌面资源副本，既有移动副本保留。未升版、提交推送或更新安装，也没有将本轮结果外推到物理声卡、Android 或其他桌面系统。
