## 实际工作流

Chrome从GUI规划、生成并运行一个v5组合条件控制器：首个事件不满足条件，没有进入记录；第二个事件值3触发进入，随后自然完成，再由脚本直接进入。四条记录保留`initial/event/completed/direct`，分别关联准确消息／完成编号；8条动画命令仍独立记录。中英日、390px、键盘选择、筛选、绑定及脚本原文定位通过，作者文件哈希保持，最终实现快照未变化。

Godot覆盖v1–v5、同帧重复、共享源码多绑定、跨绑定直接调用回调不借用事件身份、手工再次_ready、拒绝play、接受后执行失败，以及旧p9真实重放。v4/v5独立ZIP含BOM/CRLF作者源码，移走作者和原构建目录后仍可运行。Studio中的旧缓存继续受既有适配器版本／指纹检查约束，使用新适配器需重新生成；这不代表自动迁移旧工程。

## 发现与修复

- 实际Godot在_ready内部已返回就绪状态；改用包装器首次树内_ready作用域，避免初始化误标direct。
- [独立审阅](review.json)确认并修复：pending来源不能越过队头，已撤销事件token不能借后续排队消息记录进入。完成skipped的语义保持独立。8项独立探针通过。
- 完整回归发现控制回放的暂存列表误混入指纹资源URL；移除误插项，并断言执行中目录仅有三份预期暂存文件。23项真实Godot／Bevy及清理测试通过；[适配与库存审阅](review-adapter.json)另列。
- 同步旧测试中的未知协议哨兵、适配器版本与VM依赖注入；p9回看保留旧字段形状。

[首轮全应用日志](app-check-initial.log)保留14项失败（控制回放3项，旧测试集成／预期11项）；旧读取形状的[首次失败](legacy-reader-initial.log)与[修复后47项](legacy-reader-fixed.log)、旧原生夹具漏资源和版本预期修正也分别保留。最终通过不能倒填为初次通过。

## 边界与保留

来源表示实际进入入口，不记录具体转换边、逐项条件值或未进入原因。已接受进入不等于排队命令已执行；pending回调可在中止后保留，不能冒充handled。此观察不是对作者GDScript私有调用的安全沙箱。

[保留审计](preservation.json)核对8986个既有文件：示例、旧验收／历史／发布、五个作者生成器、旧p9采集资源和版本文件全部不变；Rust/WASM及已安装程序不变。新证据不外推到安装版、Android、其他桌面平台、Bevy动画或每实例播放头。功能图谱增量和既有评分保留见[评分复核](score-review.json)。
