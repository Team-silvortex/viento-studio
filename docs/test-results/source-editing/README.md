# 通用原文缩进验证

本轮接入“普通源码／脚本草稿 → 缩进单位与选区 → 增加或减少缩进 → 原生撤销／重做 → 普通保存”。纯文本规则、DOM 原生事务和宿主草稿分别负责自己的范围；模块仍为 19 个、声明能力 36 项，版本保持 0.1.0。

## 真实浏览器与保存

最终证据为 [浏览器记录](browser-1791856760717/report.json)，`passed: true`、浏览器错误 0、5 张截图。所列生产与测试源码摘要均与最终候选相同。环境为报告记录的 Linux 本机编辑服务、Chrome 与 Node。

实际操作覆盖：

- 正文先有真实键盘输入，再用真实鼠标对反向多行选区缩进；原生撤销／重做保留先前输入。一次缩进通过一个原生文本事务完成；浏览器可发出多个原生 input，不人为压缩原生事件，也不额外重复派发。
- Ctrl / ⌘ 方括号操作、选区终点在下一行开头、首行 BOM、制表符及 2／4 空格；原文之外的空白与尾部保持。
- 切换中／英／日后，正文、选区和原生历史保留。390px 收起目录后，工具条和源码可见且无遮挡；测量之外检查实际截图。
- 显式输入法组合、组合键标记与 legacy 229 不改原文；真实 Tab 只移动焦点。未验证操作系统输入法完整候选界面。
- 所有普通保存之前的操作均不写作者文件。普通 Save 只发送一次文档请求，仅目标 TXT 从原字节变为预期的 88 字节，BOM 及 CRLF 保持，登记、模板、素材均不变化；完成后草稿清洁。
- 现有“新建脚本”将含制表符的起始内容交到普通草稿，缩进单位随新来源重新识别；弹窗关闭后工具条可用，不会提前创建文件。

## 排查与验证范围

首个 [原生事务探针](browser-1791856457306/report.json) 独立验证浏览器输入历史。[首次完整运行](browser-1791856628729/report.json) 暴露新脚本窗口关闭后工具条仍禁用的问题：刷新发生在弹窗尚打开时，而关闭没有触发刷新。最终实现监听源码获得焦点及捕获 dialog close，在不改变原文的情况下重新核对可用性；对应两条控制器回归覆盖新脚本与设置窗口。首轮窄屏截图侧栏未收起，不作为最终视觉通过证据。

首次全量回归中的一个失败来自旧场景来源测试仍按内联输入回调的文本位置截取函数。回调已提取为 `handleSourceInput`，测试同步改为验证真实绑定并执行提取后的函数；保留其脏状态／独立视图刷新和无写权限断言。记录见 [修正前全量日志](full-check-before-fixture-update.log)，最终结果另见下文。

本轮原生撤销以 Chrome 为实测范围，未声明 Tauri WebKit、Android 实机或安装包验收。工具不含语法高亮、自动格式化、LSP、引擎执行或作者关系修改；已有保真序列化对未修改前后行保持字节，对改动区域沿用首个换行风格，并不承诺将所有混合换行逐行原样保留。
