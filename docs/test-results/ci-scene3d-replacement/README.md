# CI：3D 导出替换测试

2026-10-18，源码 0.1.5 工作树。修复[远端运行 38850008923](https://github.com/Team-silvortex/viento-studio/actions/runs/38850008923)中 application 作业唯一失败；该次 compatibility 作业成功。原错误见[节选](remote-failure-excerpt.log)。

原测试删除生成文件，再按原路径写回相同字节，假定系统会分配新 inode。实际 100 次实验中，`/tmp` 复用 0 次、项目所在文件系统复用 99 次。将临时目录放到后者后，未修改的原测试也出现相同的 Missing expected rejection，见[实验](inode-reuse-experiment.json)与[失败复现](local-before.log)。

现在先把旧文件移到生成目录之外、临时夹具之内，保留旧 inode，再排他创建同字节的新文件。测试明确断言旧身份保留、新身份不同、字节相同；内容修改、身份替换、硬链接分为三项，分别要求具体拒绝码，并确认工具连版本识别都没有启动。生产逻辑、CI 工作流与产品版本保持。

一次额外的全量文件系统试验把临时目录置于本仓库之内，导致无扩展名的模拟工具继承仓库 ESM 设置，并使一个固定 `/tmp` 路径的测试遇到跨设备重命名；45 项失败保留于 `application-nested-temp-diagnostic.log`。这是该临时验证环境改变了已有夹具语义，未作为产品回归结果。最终全量恢复正常系统临时目录，问题文件系统另以三项专项连续验证。

验证结果：问题文件系统连续 10 轮 × 3 项全部通过；完整导出 18 通过、2 个真实 Godot 条件测试跳过。`npm run core:test` 实跑 342 项通过；完整应用按正常 CI 命令及系统临时目录运行，5718 项中 5549 通过、169 条件跳过、零失败，951 个 JS 及版本／API 预检通过。范围有重叠，不相加。见[完整日志](application-final.log)、[核心日志](core-test.log)、[导出日志](scene3d-export-final.log)及[结构化摘要](summary.json)。

7891 份已有示例、历史及报告字节保持，前轮动画／声音工作保留。独立复核确认拒绝原因和零工具执行断言没有弱化。未提交推送或触发新远端 CI，旧失败记录不会因本地修复改变；未更新安装。
