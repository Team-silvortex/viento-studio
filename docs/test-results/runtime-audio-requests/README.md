# 音频排队请求与共用观察层

2026-10-28，0.2.5之后的开发工作树。音频请求现以独立观察链路记录接受、实际后端调用回执和中止清理；动画与音频复用分帧、FIFO、留存、时钟和异常收尾机制，领域模块分别核对各自目标与业务回执。Godot适配器描述符为0.36.0；含音轨项目生成0.36.0，无音轨含动画为0.35.0，其余项目保持0.34.0。原项目协议4–11、作者格式和应用版本保持。

## 合同

`VIENTO_AUDIO_REQUEST:` 协议1提供 accepted、applied 和 discarded。accepted为单会话内的音频请求分配身份，记录真实Engine idle／physics帧对、动作、绑定来源及声明轨道；来源与音轨资源均从冻结计划派生。applied只在匹配同一FIFO队首、已准入业务回执、commandSequence、executionFrameIndex和帧对后确认。它证明后端调用有回执，不证明物理扬声器发出声音。discarded在abort清理循环移除FIFO队首前同步输出，表示已观察清理标记，不推断该请求曾播放或执行失败。

动画与音频各自维护单调请求ID、256次会话接受预算及64条未决上限，互不借用编号或额度。各自默认保存最近128条终态和全部未决；进程取消或回执标记缺失时pending表示证据不完整，不能推断命令尚未执行。业务账本和预算总量不裁剪、不重置。读取器每域最多512次观察前缀尝试、单行16KiB UTF-8（去掉行尾）和128条诊断；正常业务、失败、取消以及消费者异常均保留已准入事实，不重放缓冲。`session.json.audioRequests` 和任务同名快照提供来源、时刻、统计与保留量。

Godot生成层仅转换已知音频队列的副本，保留原GDScript模板与作者文件。固定helper、sidecar、原始副本和转换结果逐字核验；旧库存只接收已核对的固定音频队列副本。当前生成器指纹有所变化，旧冻结构建需显式重建，不能绕过完整backend和产物校验。

## 首次失败与修复

[首次音频原生运行](native-new.log)与[首次旧动画运行](native-animation-regression.log)均在实际运行前被新库存拒绝；定向mock构建未触发真实Godot导入，因此未覆盖这一情况。[独立真实导入复现](import-uid-reproduction.json)确认导入成功后自动生成 `audio-request-emitter.gd.uid`，新库存把这个文件误判为孤儿。修复只允许该固定UID文件，验证其是受限大小的普通文件且内容符合UID格式；没有sidecar、未知UID、链接、超长和篡改仍拒绝，UID不进入可执行脚本清单。[修复后库存验证](backends-uid-fix.log)及最终原生组通过。修复前完整检查8624项虽通过，但其原生测试被跳过，不作为修复后的最终检查。
