## 工作流与实际证据

Chrome分别操作新建和重编辑入口。事件样本采用后idle→attack，假定匹配片段完成采用后attack→idle；仅试算不推进。撤回恢复上一步状态和输入，未知事件可记录保持状态的一步。完成模式忽略隐藏的未完成数字输入。步骤详情按需展开，三语390px保留输入身份、焦点和选择，旧定位按钮不能跨作者表修改生效。

重编辑用一个未使用状态取得真实源码审阅，所有转换规则与保存态相同。试算和撤回保留审阅资格；最后取消整个作者表草稿，不写入未使用状态。真实字段改变清除旧路径，重新打开表单也清空。20份源码和36份临时作者文件前后字节一致。

随后从GUI规划、构建、运行保存态原脚本，真实Godot记录idle→attack→idle，与显式采用的手动路径对照；真实回执仍独立于试算。原始v1–v5控制器另验证100个连续步骤及40次不匹配片段完成通知忽略，生成源码指纹保持。请求被拒或控制器失活时，真实状态与手动采用预测目标明确不同，不混称为成功播放。

## 边界、容量与保留

不可变序列和待采用结果有独立品牌；结果只属于精确前序，截取前缀或撤回后不能重用旧结果。32步／64KiB规范化样本仅限制记录，单次试算继续可用；UI另限制用于撤回的原始输入缓冲，超限原子拒绝而不截断旧输入。历史只读且不重算旧条件，完成步骤不读取事件样本或要求标量比较能力。

完成试算假定控制器有效、所选片段通知已送达。它不模拟绑定片段、循环、播放时钟、脚本副作用或失败进入；每步共享值是独立固定样本。NUL的原生表示限制仍按[上一轮验收](../animation-state-event-preview/README.md)记录。
