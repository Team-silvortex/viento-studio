## 实际操作与断言

真实Godot运行发布两条同名事件。第一条投递给3个订阅，结果为handled／handled／skipped，均无动画进入；第二条只有控制器订阅确证关联到进入记录2，普通观察回调仍无进入。初始化、自然完成和直接进入均不会误归入事件。

Chrome由GUI规划、构建和运行项目；事件回看经显式按钮进入已有控制器历史，两种列表筛选隐藏所有行后仍保留独立选择。中英日390px无横向溢出，语言切换保留选择和焦点；发布及订阅来源按钮打开精确冻结声明范围。再次真实运行清除事件与控制器选择。27份相关源码前后指纹一致，36份临时作者文件字节保持。

领域测试另覆盖pending已有进入、handled无进入、同脚本多绑定、跨访问、旧p3–p9明确不可关联、畸形来源拒绝、深冻结品牌与预算。UI检查覆盖迟到来源、编辑器草稿、选择/任务/访问/来源变化及独立来源票据。自审发现并修正“已移除订阅旧按钮可能命中新行”的对象身份问题，有专门回归；[交叉审阅](review.json)另列领域与宿主结果。

## 架构与边界

纯模型仅用已准入的事件序号／订阅编号关联；独立事件视图由宿主端口连接已有控制器回看，不操作运行或写入作者文件。投递成功不等于发生状态转换或动画已执行。没有进入只能说明当前快照未采集，不能推断条件失败、命中分支或未执行行为；逐项条件值、每实例播放头、混合与Bevy动画仍未接入。
