# 逐角色单向平台下穿 → 原有事件与媒体 → 工程交付

2026-10-26，**0.2.4之后的开发工作树**。入口为 **新建脚本 → Godot / 单向平台下穿**，绑定到开启重力与跳跃的角色，默认按向下键穿过当前支撑自己的静态单向平台；操作见[物理指南](../../SCENE_PHYSICS2D.md#从单向平台主动下穿)。本轮使用隔离作者工程，未升版、提交、推送或更新本机0.2.0安装。

## 实现与边界

- Godot执行适配器 **0.29.0** 新增可选 `physics.character-drop-through2d`。仅同场景存在重力角色和静态单向平台时，给相应角色行为注入本次访问的 `viento_character_drop` 端口：`protocol_version() -> int` 返回1，`request_drop() -> bool` 请求下穿，无新信号。
- true只表示排队，下一物理步重新核对行为、角色着地和上一次真实移动返回的向上支撑。返回的普通／未知支撑或已有双向碰撞例外会拒绝；**不是几何接触全集查询**，本次未被返回的相邻实体仍由下一次原生求解阻挡。
- 只为请求角色和对应平台添加自己管理的碰撞例外，清除着地使同一步跳跃不会覆盖下穿。其余角色继续站在平台上。下落由原重力及原生移动完成，不传送、强设速度或增加求解。
- 以真实 CollisionShape2D 全局包围盒、平台容差和安全边距判断完全分离，随后恢复碰撞。低重力、厚平台或紧邻下层障碍可推迟恢复，没有固定时限保证；同时仅有一个排队或进行中的请求。关闭清除自己持有的例外，旧访问端口失效。
- 普通TXT模板仅导出 `drop_action`，默认 `ui_down`，只在新按下时请求；启动时已按住和持续按住不会反复触发。false为正常未受理，退出停止处理。所有18个旧模板完整记录保持。
- 新薄桥委托冻结0.28采集层和独立下穿控制器；没有适用场景时保留旧生成结果。保存的采集原脚本、新helper／port／桥及场景清单精确校验，拒绝遗漏、孤儿、篡改和符号链接。作者schema、Rust／WASM、项目运行和观察协议保持。
- 下穿的实际落地和接触反馈由已有事件脚本发布，动画和音轨沿既有订阅链消费。未新增持续接触查询、移动平台、动态刚体或Bevy物理；生成工程ZIP仍需相应Godot工具，不等于独立游戏发行程序。

## 首次失败与修正

- 初次原生首例两次失败均因夹具继承了旧smoke默认向右输入，角色仍有水平速度，却断言全过程只垂直移动。第二次先误判为浮点差放宽至1e-4仍失败；随后将隔离下穿夹具的水平speed明确设为0，保留arrows以验证同一步跳跃，[第三次首例](native-third.log)通过。生产实现未改；[首次](native-first.log)和[第二次](native-second.log)证据保留。
- 首轮完整矩阵[18项中16过2失败](native-matrix-first.log)：一个非运动端口探针超过既有“最多8个来源脚本”预算，改为同一脚本绑定三个实例；另一个低重力夹具在固定第6步尚未被原生移动报告为着地，拒绝请求是正确行为。最终低重力案例在真实grounded后申请，再验证形状未完全分离期间保留例外。[定向修复](native-repair-focus.log)及[低重力复验](native-low-gravity-focus.log)分别保留，最终19项全过。中间定向修复3项为2过1失败，仍因低重力的固定请求时刻早于真实接地；完整过程见[原生汇总](native-summary.json)。
- 带媒体的原生退出出现两项ObjectDB泄露提示，旧0.28同夹具对照也有相同提示。本轮没有把该既有提示当作下穿新增故障或已修复项；真实执行、样本和事件断言另行验证。
