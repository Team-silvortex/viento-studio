# 项目事件发布与订阅验收

2026-10-15，0.1.3 之后的未发布工作树。在多场景组装、切换和共享状态之上，增加项目会话内事件发布与订阅。使用方法见[项目事件](../../PROJECT_EVENTS.md)。本轮未升版、提交、推送或更新安装。

## 完成范围

- 引擎中立的事件账本、显式协议 3 和完整有界观察 DTO；发布方和订阅方分别解析到冻结绑定来源，事件不能注入路径。旧项目协议 1／2 和单场景协议保持。
- Godot 0.10.0 增加独立事件模块。发布捕获当前收件者，延迟 FIFO 处理；撤销后跳过，嵌套发布排到队尾，排空后才切场景或正常关闭窗口。新访问撤销旧订阅，新运行从空会话开始。
- 回调属于同一行为实例，同步返回严格布尔 true 才记为处理成功。错误、无返回值、异步及失效回调明确失败，不回滚此前作者副作用，也不伪造成功回执。
- 独立只读中英日面板显示载荷、发布方、订阅方和处理状态；筛选及两类回源分别受身份保护。内置起始脚本、原生窗口运行和工程 ZIP 交付均接通。

## 检查点与修正

旧检查点原样保留，不改标为通过：

- [启用 Godot 的完整检查点](application-godot-checkpoint.log)为 5228 项、5150 通过、77 条件跳过、1 失败。唯一失败是旧运行取消测试固定六秒后要求已收到就绪，在并行真实引擎负载下不成立；改为按就绪信号取消，真实定向结果见[project-build-cancellation.log](project-build-cancellation.log)。最终常规全应用重跑另记，不把这次失败覆盖掉。

- [闭包修复前](godot-closures-before-fix.log)与[本机探针](godot-callable-probe.log)证实，该 Godot 的原生 Callable 比较会将不同绑定参数误判为同一回调。去重现在额外比较解绑数量、绑定参数类型与身份，不遍历作者容器；同一数组引用可复用，相同内容的不同数组分别登记。
- [边界检查点](godot-boundaries-checkpoint.log)、[补充检查点](godot-additions-checkpoint.log)及[生成指纹检查点](godot-closures-fingerprint-checkpoint.log)保留开发期失败。包含测试使用了错误的单场景参数、在回调中释放自身的测试方式不适用，以及并行修改导致冻结指纹按预期拒绝；另有一项早期无运行记录的检查未保存底层拒绝原因，保留为原因未知；最终完整组合修正后重跑通过。
- [首轮真实 Godot](godot-initial.log)、[首轮宿主](host-checkpoint.log)及[宿主中间检查](host-workflow.log)保留；最终宿主以 `host-final.log` 为准。
- 核心 [121 项检查点](core-results-checkpoint-before-max-origin.json)和[124 项检查点](core-results-checkpoint-before-retired-token.json)保留。最终 126 项覆盖最大完整来源及大合法子观察，并验证已跳过编号不得被新发布捕获、此前已排队者仍可跳过。无发布／回执交错信息的独立 DTO 只拒绝可证明不可能的结果，不推断缺失时序。
