# 导出诊断指标的 CI 竞态修复

失败来源为 [GitHub Actions 40077294228](https://github.com/Team-silvortex/viento-studio/actions/runs/40077294228)，提交 `4cf75a65`（0.2.1）。application 任务通过；compatibility 任务在导出 Range 诊断用例失败，原始结果为87项中86通过、1失败，见[失败日志](ci-failure.log)。本轮修复仍在工作树，尚未推送或重新运行远端任务。

## 根因及修复

`export.test.mjs` 假定客户端读取响应体完成后，`GET /api/export` 指标必然已经登记。实际上 `sendFile` 还需异步关闭文件句柄，导出服务随后完成下载记账；路由只在整个处理器的 finally 中登记指标。下一次指标请求可以更早返回，因此 route 桶暂时不存在，直接读取 `lastStatusCode` 会失败。原生工具构建与归档功能并非本次报错来源。

测试现在在5秒截止时间内等待导出完成次数达到当前序号，再严格断言206／416、状态计数和完整200重试；不等待某个期望状态码出现，以免掩盖错误记账。生产指标生命周期及下载实现保持。新增 `export-metrics-lifecycle.test.mjs` 通过真实HTTP、真实ZIP和真实指标服务，在响应发送之后主动阻塞下载收尾，稳定验证“客户端已经读完，但指标尚未登记”的时序；解除阻塞后确认一次记账、原状态码、可完整重试和作者原文保持。新用例已加入兼容性工作流的显式测试列表。
