# 业务回执的精确引擎帧

2026-10-26，0.2.5之后开发工作树。Godot执行适配器与项目生成外层 **0.34.0** 以独立封套记录每个业务回执输出当时的真实引擎帧对，保留最近128条紧凑位置，接通会话及任务接口。应用版本、作者格式、项目协议4／7／10／11和有限累计预算保持；本机Studio仍为0.2.0，本轮未提交、发布或更新安装。

## 已实现的范围

新能力 `runtime.execution-frames` 通过 `VIENTO_EXECUTION_FRAME:` 协议1传递连续index、真实idle／physics计数及原业务DTO；旧项目DTO不增加字段，新构建不重复输出裸项目帧。可移植读取器组合原业务、物理和预算观察读取器，只有原准入成功才保留位置。`executionFrames` 的128条尾部独立于 `executionClock` 的32个预算窗口；零成本业务帧不制造预算窗口，旧因果锚点也不自动获得已移出位置的时钟。

宿主保存并复制实时／最终DTO；没有换行的尾帧、取消和观察者异常保留已准入事实，失败标为incomplete。独立clock观察者异常仍可完成原有收尾通知；业务回调已准入后抛错则隔离原缓冲，防止重复消费。原始事件、语义状态、位置尾部与因果投影分开保存。

严格库存验证新helper、sidecar、全部原协调器副本及重新推导的转换字节；同时改副本与hash也不能伪造已知源码。运行宿主完整对比重新生成的backend描述，并从其能力选择读取器，防止修改build记录降低校验。旧GDScript模板保持原字节；预算和clock的JavaScript库存接口变动会改变生成指纹，旧冻结构建应显式重建，不能绕过hash检查。

## 首次失败与修复

[首次定向](targeted-first.log)发现两项回归：指纹fixture漏列新模块，以及新外层在clock尾部观察者抛错后提前封闭，漏发原有终态通知。前者补齐真实指纹输入；后者修正新wrapper收尾状态，允许独立clock收尾重试，同时继续阻止业务缓冲重放。最终定向与原生13案在修复后冻结源码上通过。

[元数据修复前](backend-metadata-before.log)另证明宿主只比协议和sha时，build记录中的能力／版本可被改写；现在完整核对重生成backend，三种变体均在执行前拒绝。当前生成器的原生fixture补齐能力参数；历史p9用旧生成器产生旧协议，不能篡改新sidecar来冒充历史工程。

[新原生首次尝试](native-first.log)在受限执行环境中仅报告测试worker文件级退出，没有子案例结果；[记录](native-first-exit.json)确认源码未变，但未确定退出原因，也不计为任何用例通过。改用实际宿主环境及TAP报告后，同一冻结源码的1案和3案全部通过。另有 [命令启动日志](targeted-initial.log)记录一次PATH含空格未引用导致的启动失败，该次未执行测试。

## 边界与复现

本轮不新增排队请求身份、接受／应用双时刻、完整账本裁剪或continuous模式；原4096准入、事件／媒体／状态／访问、输出及时限继续生效。128条位置尾部不保存所有历史因果锚点的精确位置。没有新增UI、Rust／WASM或Bevy功能，真实无头结果不替代窗口、扬声器、设备或安装验收。

接口和库存见[中间层](../../BACKEND_MIDDLEWARE.md#业务回执的精确引擎帧)，复现命令与证据环境变量见[验证指南](../../TESTING.md)。下一步应定义排队请求身份和接受／应用位置，再讨论未决引用跨尾部保留与实时准入。
