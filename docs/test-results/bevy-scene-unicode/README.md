# 场景标题 Unicode 与 Bevy 控制链验证

本记录对应 0.2.6 发布后的开发工作树，并非已安装桌面版本的验收。此前可复现的问题是：JSON 场景标题可以通过转义包含单独的 UTF-16 高或低代理项，旧的场景规划与 Bevy 生成器接受该数据，但真实 Bevy 数据运行程序在检查生成 JSON 时拒绝它。修复后，常规场景计划在 `/title` 报告 `build_scene_title_unicode`，两条 Bevy 生成边界也独立拒绝无效标题；没有自动替换字符或修改作者文档。历史场景登记／恢复仍保留原数据。

## 环境

- Linux `7.0.0-42-generic`，`x86_64`；Node.js `v24.21.0`。
- 真实 Bevy 数据运行程序：`viento-bevy-runtime 0.3.0 bevy 0.19.1`，从本机已安装工具目录调用。
- 控制链对照还使用本机 Godot `4.7.2-viento-audiofix1`。

## 结果

- [Unicode 定向回归](unicode-regression.log)：116 项，115 通过、1 条条件跳过、0 失败。覆盖中立场景源定位和登记恢复、两种 Bevy 生成器、中文／日文／组合字符／emoji 原样保留、160 UTF-16 代码单元上限及孤立高／低代理项；覆盖场景创建的中英日提示，以及预览和构建诊断的源位置跳转。真实 Bevy 数据通道检查了无效标题在生成输出前被拒绝，以及合法标题的实际构建。
- 同一回归中，真实 Rust 作者行为 Cargo 测试因未设置 `VIENTO_BEVY_RUST_TEST_CARGO` 而跳过；测试只验证 Rust 生成 DTO 的边界与合法文本，不声明该通道的本轮编译或运行实测。
- [双引擎控制链审计](bevy-control-audit.log)：26 项全部通过。该审计在 Unicode 修复前执行，覆盖真实 Bevy／Godot 的场景计划、无头运行、相同冻结场景、实例独立输入、离线回放和取消；不能作为修复后重新运行的证据。

有效字符不会被规范化。若旧场景包含无效标题，打开诊断指出的原文，删除或重新输入该字符并保存，再重新检查计划和构建。修复改变 Bevy 生成器摘要，旧冻结 Bevy 构建须显式重建；作者格式和已安装运行程序不自动迁移。
