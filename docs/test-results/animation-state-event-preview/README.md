## 实际操作

Chrome检查新建与重新编辑两条入口。重编辑先在临时表添加一个未使用状态，取得真实非空源码审阅；随后修改手动样本，审阅文本与应用资格保持。事件转换规则始终与保存态相同，最后取消整个表单，不写入新增状态。覆盖缺失共享键、严格类型、有序选择、all/any短路、兜底、未知合法事件、无效数字、字段定位及旧定位按钮失效。三语390px保留输入节点、焦点和选择，无横向溢出；桌面及中英日截图已人工查看。

同一保存态原脚本再通过界面规划、构建和真实Godot运行。发布器写入combat.enabled=true并发布action数字3，实际进入idle再到attack；手动试算也选择attack。真实回执独立保存，不把试算冒充历史。19份源码与36份临时作者文件前后指纹一致。

## 原生标量边界与初次失败

真实Godot对照原始v1–v5脚本的目标、逐项比较及共享键读取顺序，包含未匹配、有序兜底、混合all/any、缺键、类型错误、极小数字，以及选中分支进入失败后不再尝试后续分支。87份生成源码指纹保持。

[初次原生日志](godot-initial.log)保留3个NUL样本差异（加父项共4失败）。最小[构造探针](nul-probe.log)确认Godot的String.chr(0)产生U+FFFD，部分字节解码则截断。最终测试给每个实际载荷／共享值记录字节，再与相同实际值的手动语义对照；仍明确断言4组输入发生替换，其中原先3组结果与原始NUL手动样本不同，另核验7条构造路径。没有删除原样本、修改生成器或声称NUL可以完整往返；旧限制见[原条件验收](../animation-state-conditions/README.md)。

[首次浏览器报告](browser-1792804101946/browser.json)因测试错误地等待无变化表的应用按钮失败；[第二次报告](browser-1792804230432/browser.json)因测试CDP表达式缺少包装失败。修正后第三次报告完成全部步骤。最初UI日志[另行保留](ui-initial.log)，最终结果以上表为准；交叉审查及开发修复见[审查记录](review.json)。
