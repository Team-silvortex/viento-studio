# 角色起跳与落地 → 作者事件 → 动画与声音

2026-10-25，**0.2.3 之后的开发工作树**。本轮在已完成的物理观察、角色重力／跳跃之上接通真实运动事件与普通作者脚本。源码版本未变，本机安装仍为0.2.0；本专题不替代安装、Android、Bevy物理或扬声器验收。

作者入口及参数见[物理指南](../../SCENE_PHYSICS2D.md#用角色运动事件驱动动画与声音)。

## 实现与边界

- Godot 0.25.0独立包装提供 `physics.character-events2d`；每份角色行为在 `_ready` 前获得自己的 `viento_character_motion` 端口，`protocol_version()` 为1，`jumped`／`landed` 为零参数信号。
- 起跳钩子位于运动器实际接受起跳的分支；着地来自原生接触的未着地→着地，**包含首次接地**。步末发送，运动只执行一次；退出先撤销端口，音频仍沿继承的清理路径关闭。
- 新角色模板经自己的项目端口发布实例UUID。新声音模板纯订阅 `event_name` 并播放 `track_id`，可用 `instance_id` 过滤；动画使用已有状态表／事件片段。物理层不直接选择动画或音轨，观察流的256条预算不控制玩法。
- 脚本是普通TXT，需普通保存、登记、关联和显式绑定参数。现有15项模板保持；普通GDScript参数不自动发现。默认事件动画操作整场景，不能从发布者UUID推导逐实例目标。
- 原0.24运动生成器与运行模板，以及更早8份物理生成／运行文件保持。本轮不改Rust、作者schema、项目运行协议或物理观察协议；仅新运动构建包含新包装及独立库存。旧生成工程须重新构建才能取得新接口。
- 没有新增离地／持续接触、平台策略、动态刚体或有限控制回放。测试驱动脚本显式注入按键；不等于实体键盘或完整玩法验收。

## 失败与修正记录

三个失败Chrome目录和原始 `browser-run-1.log`～`browser-run-3.log` 均保留：

2. [第二次](browser-1792923463955/browser.json)：服务已结束，但界面轮询尚未收到最终事件序号；改为等待同一运行的最终序号再断言。
3. [第三次](browser-1792923513322/browser.json)：测试总断言漏计取消未应用表单触发的两次已确认提示；改为精确核对两条预期文案，没有放宽任意对话框。
4. [第四次](browser-1792923577290/browser.json)通过。这三处均为验收脚本修正，产品源码没有因此改变。

新原生首次运行已成功导入、检查脚本并产生预期运动事件，但测试误要求旧事件来源对象含不存在的脚本字段。改为沿冻结行为绑定解析脚本身份后通过；[首次输出转存](backend-attempt-1.log)来自工具返回值复制，并非当时直接重定向的原始文件，[开发说明](backend-attempts.log)是人工记录。最终[完整日志](backend-native.log)为本次命令直接输出。

旧运动ZIP首次失败来自测试显式使用0.24生成器构建、检查却采用默认0.25注册表；检查也传入同一冻结生成器后通过。新0.25工程交付由本轮新矩阵独立验证，不用旧生成器通过结果替代。
