# 行为驱动场景声音验收

2026-10-15，0.1.3 之后的未发布工作树。行为及事件回调现在可以请求播放／停止当前场景已声明的音轨。使用方法见[行为驱动场景声音](../../PROJECT_AUDIO_CONTROLS.md)。

## 完成范围

- 通用核心增加命令账本与显式项目协议 4，分别保留控制行为和音轨声明的冻结来源；旧项目协议 1／2／3 与声音子协议保持。
- Godot 0.11.0 使用独立有界队列，在音轨就绪后执行，事件和声音请求排空后再切场景或正常关闭。旧访问失效，错误归属调用行为；失败和取消不制造未执行命令的回执。
- Rust 支持 0–64 条提示，允许声音仅由行为触发。原有非空时间线保持，新接口不改变声音文档、音量或循环配置。
- 中英日只读记录可筛选音轨／资源，分别打开控制来源和音轨声明；起始脚本、窗口运行和独立工程 ZIP 均接通。

机器摘要见 [summary.json](summary.json)。浏览器从隔离副本的已保存场景开始，A→B→A 产生八条声音命令，顺序为播放、停止、播放／播放、停止／播放、停止、播放；六次事件发布与共享状态修订 8 同时保持。第二次运行从序号 0 开始。两份声音文档使用同一音轨 UUID，来源仍各自独立；音轨回源精确选中 `/tracks/0`，行为回源没有文本范围时仅打开完整文档。

真实混音采集峰值为 **0.0146488891914487**，越过 WAV 长度后循环仍在播放；停止及零音量的采样峰值均为 **0**。测试采集引擎内部输出，不声称用户物理设备实际可听。

实际导出 ZIP 为 **116,997 字节、28 个文件、2 份媒体资源**。SHA-256 为 `0d7554dd321cb4abc3548261619586ef07e4b5402c288d8e89c8fd2b42f91444`。换目录导入运行后，八条声音命令、场景访问、事件和状态变更与原运行一致。

## 检查点与边界

- [核心检查点](core-results.json.checkpoint-210829)保留 148／149 的结果。唯一失败来自测试模块加载器并发导入出两个独立核心实例；加载器改为在读取前缓存 Promise，并在模拟浏览器内部复制纯 JSON。最终 149／149 另记，没有放宽产品校验。
- [准备副本检查点](prepared-check.log.checkpoint-source-key)记录验证脚本误读 `documentId`；实际来源使用 `objectId`，修正检查脚本后通过，产品未变。
- Rust 汇总以原始日志的 286 项单元和 49 项集成为准，共 335 项；进度消息中的 345 为算术误计，未计入最终报告。
- 子代理环境不能执行部分原生进程／本机服务，真实引擎、浏览器和完整应用由主进程执行；界面专项关闭测试文件隔离，完整应用另用正常隔离通过。
- [首轮宿主](host-checkpoint.log)保留；最终以八项组合为准。各专项并非所有操作系统或已安装客户端的完整验收。

原 **7364** 个样例、历史与旧证据文件以及已安装 **0.1.1 AppImage** 字节保持。[清理记录](cleanup.json)只删除本轮新生成的桌面准备副本，原有移动资源保留。图谱只新增 36 格，旧 2100 格完整保持；当前为 127 功能／352 实现／534 绑定／2136 评分单元／90 工作流。
