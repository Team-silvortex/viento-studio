# ADR 0005：正文与登记一并创建

日期：2026-09-27。状态：采用于 V-M2 / V-M3 创建纵切，沿用 experimental semantic v1 和 workspace v2 / v3。

## 决策

`object.create` 使用调用者提供的新 UUID、已知工程类型、正文路径与精确原文。可移植 Core 检查世界基线、身份／路径冲突和可解析性，计算只增一个对象的投影及预计 revision；Node 适配器检查真实文件系统并取得现有登记锁，在锁内重读全部条件。预览不能分配磁盘记录。创建后的属性仍由正文提供，不复制到独立对象数据库。

扩展 [ADR 0004](0004-recoverable-source-changesets.md) 的事务执行器：version 1 继续表示现有文档的属性替换；version 2 只表示两个原本不存在的文件——正文和同一 UUID 的文档登记。登记镜像必须精确匹配来源、类型、解析配置和空关系／绑定结构；不接受任意元数据写入。将缺失编码为 `null`，不能把空文件当成缺失。

提交按正文、登记顺序排他发布；提交前回退按登记、正文反序撤回，只删除匹配本事务 after 摘要的文件。提交标记存在时，恢复只补齐完整 after 状态。全部镜像与目标必须先验证，再开始任何恢复写入；外部冲突保留日志。恢复中再次退出可重入。新建目录同步父链，回退保留空目录，避免递归删除外部内容。

GUI、CLI、HTTP 共用创建命令。界面保留一个稳定身份，输入变化使预览失效；不与暂存属性队列混用。保存事实与索引重建结果分离，恢复不自动重发草稿。`undoMode: none` 明确尚无删除反向命令；崩溃回退不等于用户撤销历史。

## 兼容与边界

不改变已有 workspace / document / archive schema。新执行器能恢复旧 version 1 日志；0.0.3 旧执行器看见 version 2 会保持屏障并拒绝恢复，不允许降级绕过 `active`。完成后的数据经已有原生归档和移动存储往返验证。Android 不声明该语义写入能力。

旧新建文档流程不在本次替换范围；新保证限定语义创建入口。混合 ChangeSet、模板选择器、关系／资源变更、垃圾回收、持久 UI 草稿、长期回执与 Build 快照后续分别设计。本轮在合成项目验证，不改官方作品。

使用及验收见 [对象创建](../WORLD_OBJECT_CREATE.md)。
