# ADR 0004：现有文档的可恢复批量提交

日期：2026-09-27。状态：采用于 V-M3 第一条纵切，继续使用 experimental semantic v1 和 workspace v2 / v3。

## 决策

先在已登记文档的标量属性上实现多源事务，再扩展对象创建、关系与资源命令。`prepareChangeSet` 属于可移植 Core，只规划和验证；Node 宿主负责登记锁、前后镜像、日志发布与恢复。首版限定最多 32 个对象，每个对象一个属性，不改登记文件、资源文件或作品清单。

逐文件原子替换不足以使多个文件成为一笔提交。因此在私有目录发布不可变意图和镜像，在任何原文变化之前设立 `active` 读取屏障；独立的提交标记决定恢复回退还是前进。确认整批源状态后发布回执，再退役屏障。所有镜像和目标先整体校验，发现第三方内容就保留现场。恢复期间再次中断可重入；临时源文件也有可恢复名称。

`proposed` ChangeSet 仍是提案；持久回执使用独立 Schema，包含批次 ID、提案 ID、World ID、前后 revision 和提交／回退状态。只保存最后一次回执，不把它宣传为永久审计日志或撤销栈。写入完成后的索引失败不能改写保存结果。CLI 与 HTTP 失败不自动重试未知结果，GUI 保留待提交队列供核对。

读取屏障接入现有 World、登记、文档读取、缓存索引、静态原文及 Node／Rust 导出。前后回执 token 防止提交／回退期间的读取被误当成一个稳定版本。现有写入方共用登记锁；批量执行器不会反向取得文档队列。启动恢复置于登记和构建之前，恢复命令使用既有写鉴权。

## 取舍

保留旧工程的原文权威及词法精度，代价是保存前后镜像并限制批量大小。源与私有目录必须支持所需的原子改名、文件同步和目录同步；不支持时在发布原文前拒绝执行。恢复保证以当前应用的协作读写方和本机进程崩溃为边界，不涵盖旧版本、任意外部写入者、硬件断电或恶意并发替换目录。

暂存和退役目录是私有垃圾，不参与恢复，也不会归档；异常退出留下的此类目录尚无通用垃圾回收器。UI 未提交队列只在当前页面内存中保留。Android 无能力声明，不借用 Node 的通过结果声称原生事务已实现。

操作协议、故障边界和验证入口见 [可恢复批量提交](../WORLD_TRANSACTIONS.md)。
