# 场景导航：等待动作与事件

0.2.10 源码新增两个普通 Godot 行为脚本起始内容：**Godot / 按动作切换场景** 和 **Godot / 按事件切换场景**。它们复用已有项目场景请求、输入映射、项目事件及作者保存流程，把只读 HUD 与“开始→游玩→结果”的交接连起来。新增内容不是可点击 HUD 按钮、暂停系统或完整游戏胜负规则。

## 在内置编辑器中设置三个场景

1. 保存开始、游玩、结果三个 Scene2D，加入同一[项目组装](PROJECT_ASSEMBLY.md)，把开始场景设为入口。挂行为的源场景需要 Scene2D v2／v3 的稳定实例；目标可以是组装内任何受支持的已保存 Scene2D。开始／结果场景可保留一个 `controls: none` 的实例承载行为。
2. 在[场景 HUD](SCENE_HUD2D.md)为开始场景写“按 Enter 开始”，结果场景写“按 Enter 返回”；游玩／结果 HUD 可读取 `score` 等项目共享状态。HUD 仍只负责显示，编辑器中的示例值不会进入游戏。
3. 创建并普通保存[输入映射](PROJECT_ASSEMBLY.md#项目键盘输入映射)，如 `menu_confirm → Enter`；再在组装中选择该输入映射并保存。这是两次明确保存，创建脚本不会自动创建按键映射。
4. 在 **新建脚本** 选择 **Godot / 按动作切换场景**，审阅完整源码，创建 TXT 草稿并普通保存。在开始场景的行为编辑器中关联脚本，手动添加 String 参数，把 `action_name` 设为 `menu_confirm`，把 `target_scene_id` 设为游玩场景 UUID。检查完整行为修改，应用到原文草稿，再普通保存。
5. 结果场景复用同一脚本，独立填写 `action_name: menu_confirm` 与开始场景 UUID。长按 Enter 进入新场景时不会立刻跳过，需要释放并再次按下。
6. 游玩场景使用 **Godot / 按事件切换场景**，关联并保存后，设置 `event_name` 和结果场景 UUID。事件由真正的玩法行为发布，例如[物理触发区](SCENE_PHYSICS2D.md)的 `entered_event` 设置为 `game.complete`，导航行为订阅同名事件；`payload_filter` 可填写玩家实例 UUID，只响应该玩家进入。导航模板不自行产生通关事件。
7. 保存所有来源后，对组装 **检查计划→构建项目→窗口预览**。在实际窗口按键，观察场景访问记录；输入映射、行为、脚本或 HUD 改动都要重新构建。无头固定两步测试不等于键盘菜单交互验收。

目标 UUID 可从组装审阅中的 `sceneIds` 或场景来源取得。行为仍复用现有参数表与普通原文保存，没有隐藏的场景跳转配置、自动建立的跨场景关系或对生成工程的手工修补。

## 参数与触发规则

| 模板 | 参数 | 规则 |
| --- | --- | --- |
| 按动作切换场景 | `action_name` | 默认 `ui_accept`，非空文字；运行时必须已在 Godot 注册。优先使用当前组装明确引用的输入映射 |
| 两个模板 | `target_scene_id` | 必填完整小写 UUID，必须是当前组装的另一个成员；不支持直接重启当前场景 |
| 按事件切换场景 | `event_name` | 默认 `game.complete`，沿用项目事件名称规则：1–64 字符，以字母开头，其余字母、数字、点、横线、下划线，保留名禁止 |
| 按事件切换场景 | `payload_filter` | 默认空字符串，接受全部载荷；非空时只接受完全相同的字符串，区分大小写与类型，最多4096 UTF-8字节 |

动作模板进入场景时观察当前按键：已经按住则等待释放。只有新的、非重复、未被界面处理的动作按下才发请求；同一个动作映射到多个按键时，在全部释放前不因另一个键重复触发。失焦清理候选，重新聚焦后重新等待已释放状态，再接受新的按下。不会创建输入动作，也不会轮询重发请求。

请求受理后，该访问停止重复请求；普通 `false` 拒绝不自动重试，但释放后新的按下或之后新的匹配事件可以再次明确尝试。事件模板在就绪时只订阅，不直接跳转；不匹配的载荷、重复事件及同批请求竞争不会使正常回调返回失败。事件回调保持同步，并在退出时取消订阅。

场景切换仍由已有宿主排队，在当前回调和必要队列处理完后执行。脚本不直接释放场景树，也不把 HUD 元素冒充行为绑定。新访问重建行为和 HUD；旧访问的端口、输入候选与订阅不控制后续访问。非布尔端口结果、无效配置或端口失效会明确报错。

## 构建前检查与问题回源

组装检查只对**与这两个官方起始内容完全相同**的源码推导导航参数：目标为空、不是小写 UUID、不在组装内或就是当前场景均阻止构建；参数类型／范围错误也会报告。诊断定位到行为文档及具体绑定参数，缺省值定位到最近的参数容器。最多256条，超限保留明确省略计数。 若成员场景、资源或其他原始声明先有错误，先返回这些原始诊断，不用不完整的规划成员集推断导航目标，避免把合法成员误报为组装外目标。

动作模板另复用输入映射建议：自定义 `action_name` 未出现在项目映射中会给出非阻断提示；`ui_*` 保守保留，因为 Godot 或作者代码可能另行注册动作。提示不证明该动作实际可用。改写后的自定义脚本不再按官方导航语义推断，其行为由作者负责；原有就绪即跳转模板保持原规则。

一次行为文档可以被多个组装复用；目标可能只属于其中一个组装，所以检查的是本次真实组装成员。不会为了一个字符串参数自动扩展组装或把外部场景加进资源包。导出组装并包含依赖时，全部成员、脚本、HUD、输入映射和资源按既有闭包收集；换根目录恢复后重新检查、构建。

从失败页重新进入关卡并显式复位计分、生命等状态，见[关卡重试](SCENE_RETRY.md)。普通导航继续保留全部共享值，不自动复位。

## 边界与验证

两脚本是普通可编辑 TXT 作者数据，使用既有 GDScript 行为绑定和 visit-scoped `viento_project` 端口。应用版本为0.2.10，关卡重试层使新组装执行描述符为0.46.0；导航本身的作者格式、事务、运行协议及已有GD／文本不变。执行适配器源码指纹包含新模板和预检模块，旧冻结构建应重新构建，不自动修改已安装程序或作者工程。

当前窗口预览仍受既有五分钟及访问／事件／状态预算限制。Escape 沿用宿主结束运行行为，不是“返回”或“暂停”。本轮不提供当前场景重启、全会话状态重置、持久存档、鼠标菜单或独立发行；它们继续按[0.5.0 验收门槛](MILESTONE_0.5.0.md)分别推进。

实际作者、原生窗口输入、迁移与回归范围见[场景导航验证](test-results/scene-navigation/README.md)。原生窗口中的 XTest 合成按键与直接脚本注入分别记录，不视为真实物理键盘设备测试。
