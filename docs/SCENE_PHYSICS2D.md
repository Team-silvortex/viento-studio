已有声明的共同保存顺序是 **修改表单 → 检查物理修改 → 审阅完整原文 → 应用到原文草稿 → 主编辑器保存 → 重新检查项目计划**。图形手势不跳过这条路径；首次创建则使用下节独立的正文与关系事务。

## 从现有场景开始

1. 准备已保存的 Scene2D v2／v3。角色、墙和触发区各有稳定 `instanceId`；可以共用同一设定对象。角色保留现有 `controls: "arrows"` 和 `speed`；墙和触发区使用 `controls: "none"`、`speed: 0`。
2. 打开 **构建与运行 → 场景物理**。选择场景实例、文档类型和正文目录内的 JSON 路径，设置第一个物理体的种类、形状、偏移、层和检测掩码。默认角色体、32×32 矩形、零偏移、层与掩码均为 1；所有参数可修改。
3. 点击 **审阅二维物理**，核对完整 JSON 和双向关系，再点击 **保存物理与关系**。一次操作创建物理正文、登记 UUID，并更新场景的 `references / physics2d` 关系；物理文档同时引用场景。三处文件共同提交并支持中断恢复，场景正文及素材保持。
4. 点击 **打开二维物理原文**，进入 **编辑二维物理**。面板可增删碰撞体、选择实例、切换矩形／圆形、修改尺寸和层掩码；检查并审阅后先应用原文草稿，再普通保存。也可使用通用字段表或直接编辑 JSON。
5. 将场景加入[项目组装](PROJECT_ASSEMBLY.md#从当前场景开始)，检查计划、构建，再用无头测试或窗口预览运行。构建页静态画布只展示场景；物理面板另有[场景空间图](#在场景空间中查看与选择碰撞体)，显示碰撞范围但不运行物理求解。

### 首次创建的保存边界

首次创建入口需要已登记、有稳定实例的 Scene2D v2／v3；不要求安装引擎或已有动画、声音、行为。审阅只读取，取消不会创建文件。已有物理声明时直接提供原文入口，不重复创建。保存结果未确认时先 **重新读取工程**，用文档身份、精确原文和关系核对结果，不再次发送创建命令。

创建时验证声明规则、已保存场景实例归属、世界及来源修订；静态体和传感器的有效控制必须为 `none`、速度为 `0`，这些投影后的运动条件仍由构建预检负责。新建表单不会替用户改变场景运动设置。创建后沿用同一个物理字段编辑器及普通保存，不引入第二份持久配置。

也可手工新建 JSON 并使用 [World 对象关系](WORLD_RELATIONS.md)：物理文档引用场景，场景引用物理文档且用途为 `physics2d`。这条手工路径继续可用，两个关系分别保存，不具备新创建命令的三文件事务。首次创建的开发验证见[首次创建记录](test-results/scene-physics2d-creation/README.md)。

## 编辑已有物理声明

面板只编辑当前已存在的 JSON 原文，不创建文件、登记对象或修改场景关系。先保存符合上例格式的物理文档，再进入原文编辑；打开面板时会读取当前草稿，包括尚未保存的原文修改。JSON 语法或声明规则无效时，返回原文修复后重新打开。识别到物理格式并不意味着它已经登记或关联到场景。

1. 点击 **编辑二维物理**，在“碰撞体”中选择要修改的条目。场景 UUID 和已有碰撞体 UUID 保持原值。
2. 选择目标实例，或手动填写其 UUID；可从[已保存场景目录](#按名称选择已有场景实例)按名称选择，或从场景原文的 `actors[].instanceId` 复制。选择 `static`、`character` 或 `sensor`，再编辑矩形宽高或圆形半径、X/Y 偏移、层与掩码。
3. **添加碰撞体** 会生成一个新的碰撞体 UUID；仍需显式选择或填写目标实例。**移除碰撞体** 只修改当前表单，至少保留一个条目。已有条目保留相对顺序，新条目追加在末尾。
4. 点击 **检查物理修改**。通过后查看变化的 JSON 路径、修改前后完整原文，以及所选碰撞体的局部形状示意。继续改动表单会撤销审阅，需重新检查。
5. 点击 **应用到原文草稿**。若以目录检查过目标，会先重读并核对该目录；变化或读取失败时保留表单，刷新后重新检查。应用成功后面板关闭并返回主编辑器，此时仍未保存；原有未涉及的草稿内容保留。最后点击主编辑器的 **保存**，才会写入作者文件。
6. 保存后从项目组装 **检查计划**。这里进一步核对场景登记、双向关系、实例成员及有效运动属性，再进入构建／运行。

| 面板内容 | 含义与编辑范围 |
| --- | --- |
| 场景 UUID、碰撞体 UUID | 已有身份只读；新增碰撞体单独分配 UUID，不重建整个声明 |
| 实例 UUID | 选择或手动填写当前场景的稳定实例编号；一个声明中不能重复使用同一实例。名称只供选择，原文保存 UUID |
| 物理类型 | 静态障碍、角色体或触发区；静态／触发区的场景运动条件由构建检查 |
| 碰撞响应 | 仅角色体可选停止或沿碰撞面滑动；选择滑动需审阅作者格式升级 |
| 平台运动 | 静态矩形可选水平往返，终点偏移与速度独立；显式启用审阅schema 5 |
| 静态碰撞方式 | 仅静态矩形可选普通碰撞或单向平台；启用时审阅 schema 4 与穿透容差 |
| 角色运动 | 自由平面或重力与跳跃；重力、起跳速度、最大下落速度与碰撞形状分开配置 |
| 形状及尺寸 | 矩形完整宽高或圆形半径；切换形状只替换该条目的形状对象 |
| X/Y 偏移 | 相对实例根的局部偏移，不是场景世界坐标 |
| 层与掩码 | 0–65535 的整数位掩码，多个层按位组合 |

形状示意把局部原点、形状和偏移一同缩放到可见区域；矩形与圆形保持比例。它不读取场景、运行碰撞求解或显示其他碰撞体，也不会改变作者数值。示意来自已检查的声明，表单变化后清除，重新检查后再显示。

**取消修改**、**返回编辑器** 或 Escape 会关闭面板；有未应用表单变化时先确认是否丢弃。取消只丢弃这次表单，不覆盖打开面板前已有的原文草稿。检查或应用期间关闭后，迟到结果不能继续写入。若切换文档、原文被修改、保存基线变化或核心不可用，旧审阅失效，需重新打开。

声明检查复用 Rust 的身份、形状、数值及 64 KiB 预算规则。可选的只读目录另行核对已保存场景、关联和实例身份；未取得目录时，手填流程只验证声明参数。投影继承后的 `controls`／`speed` 和完整工程条件始终由保存态构建前检查负责。字段面板不创建关系、自动迁移或执行物理回放；空间图手势见[偏移](#在空间图中调整碰撞偏移)与[尺寸](#在空间图中调整碰撞尺寸)两节。

来源补丁保留 BOM、行尾和未修改的原文字节；标量修改只替换相应 token，形状切换和增删条目分别限制在形状对象或碰撞体数组内。目录增量沿用这些补丁与普通保存规则，不改变作者格式、Rust 规则、后端版本或运行协议。

## 选择角色的碰撞响应

以下功能已收录 **0.2.3**。在首次创建表单或已有物理字段编辑器中，把物理类型设为 **角色体**，选择 **碰撞后停止** 或 **沿碰撞面滑动**。滑动适合沿障碍移动的俯视角角色；斜向遇墙时保留沿墙方向的剩余位移。

- 旧声明默认停止；只打开、检查或保存其他字段不会升级格式。首次创建也默认停止，继续生成原 schema 1。
- 显式选择滑动后，旧格式会升级至至少 `schemaVersion: 2`，已有更高格式保持；审阅同时显示该角色的 `collisionResponse: "slide"`。已有文档仍沿 **检查 → 完整原文审阅 → 应用草稿 → 普通保存**；首次创建沿正文与关系事务保存。
- schema 2 的角色允许 `collisionResponse: "stop" | "slide"`，缺省为停止。切回停止不会降低作者格式；已有显式停止字段在编辑其他字段时保留。静态体和触发区不接受响应字段，切换种类时会在审阅中移除它。
- 参数改变会使旧审阅失效；取消不改原文。核心缺少目标 schema 所需的检查能力时，对应修改不可用；schema 4 使用独立单向平台检查能力，不要求旧响应标记。旧格式的原有编辑流程保持。

Godot 根据每次项目物理步给定的位移执行碰撞；滑动把未走完的位移投影到碰撞切面，最多继续四次。自由平面模式没有隐式重力、地板／斜坡策略或速度积分；下节的显式角色运动单独启用重力与跳跃。动态刚体、弹跳和摩擦仍未接入。空间图仍只展示作者几何，不能预演滑动；正式结果从保存后的项目构建与运行查看。验证入口见[碰撞响应专题](test-results/scene-physics2d-response/README.md)。

## 配置角色的重力与跳跃

以下能力已收录 **0.2.4**。先按上面的流程创建并打开物理声明，在角色体中把运动模式选为 **重力与跳跃**。编辑器会同时选择滑动响应；重力朝场景正 Y 方向，水平移动速度继续取场景实例的 `speed`。

1. 设置重力、起跳速度和最大下落速度，点击检查并审阅完整原文。显式启用会把旧物理作者格式升级至至少 **schema 3**，已有更高格式保持，加入下面的角色字段；应用草稿后仍需主编辑器普通保存。
2. 准备静态地面：它必须有匹配的碰撞层／掩码，场景实例保持 `controls: "none"`、`speed: 0`。首次运行先下落，真正接触地面后才能起跳。
3. 重新检查项目计划、构建并打开窗口。`controls: "arrows"` 时左右方向键移动，空格或 Enter（Godot 默认 `ui_accept`）的新按下触发一次跳跃；长按不自动连跳，空中再次按下不会二次跳。上下方向键不再直接移动该角色。
4. `controls: "none"` 时仍受重力，但不接收内建移动或跳跃；起跳速度为 0 时禁止内建跳跃。切回自由平面会移除 `characterMotion`，保留当前滑动响应和文档格式；不会自动降低作者格式。
5. 无头测试继续使用半秒、30 步，可在[物理观察](#查看角色的物理步与碰撞)核对请求／实际位移与碰撞法线。测试默认只提供原有水平输入；要验证起跳，可由明确的测试行为发出 `ui_accept`，或在窗口实际操作。默认参数的完整跳跃可能超过半秒，不能据此宣称烟测覆盖完整跳跃周期。

```json
"collisionResponse": "slide",
"characterMotion": {
  "kind": "platformer",
  "gravity": 980,
  "jumpSpeed": 360,
  "maxFallSpeed": 1200
}
```

| 参数 | 单位与范围 |
| --- | --- |
| `gravity` | 场景像素／秒²，1–20000 |
| `jumpSpeed` | 场景像素／秒，0–4000；0 禁止内建跳跃 |
| `maxFallSpeed` | 场景像素／秒，1–4000 |

运动对象只允许出现在角色体且要求 `collisionResponse: "slide"`；静态体／触发区或与停止响应组合会被拒绝。Rust 的独立 `scenePhysics2D.inspectMotion` 检查格式 3，原格式 1／2 的操作与可选能力保持；旧核心不能把新声明当作已支持。原文编辑保留未修改的数字写法、转义键、BOM 和行尾，空间偏移／尺寸编辑只改几何字段。

Godot 用显式物理步长积分速度、限制下落速度，再执行最多四次原生滑动碰撞；碰撞清除朝向表面的速度，法线 Y ≤ −0.7 的接触作为下一步可起跳依据。每次场景访问重新建立速度与按键边沿状态。基础运动层没有跳跃缓冲、土狼时间、地面吸附、移动平台或完整斜坡策略；静态单向平台由下节独立启用，起跳／落地事件通过后续独立作者脚本接入。观察协议 1 继续展示移动和接触，不把法线显示冒充正式的着地状态接口。

中立计划只在实际存在 `characterMotion` 时要求 **`physics.character-motion2d`**。基础运动包装保持 **0.24.0**，新运动构建的事件包装保持 **0.25.0**，当前执行适配器为 **0.32.0**；独立运动脚本和参数随生成工程交付。未启用运动的旧生成器继续使用原版本，关闭模式后保留当前格式（schema 3或4）的声明也可构建。项目运行协议、作者场景／组装格式和观察协议均保持，Bevy 两个通道明确拒绝此能力。验证见[角色运动专题](test-results/scene-physics2d-character-motion/README.md)。

## 配置静态单向平台

以下能力已收录 **0.2.4**。平台只允许静态矩形；角色可以从下方穿过，再从上方落在平台上。承重面固定朝向场景坐标的上方（−Y），视觉动画的旋转或缩放不会改变平台方向。

1. 先按普通流程创建并保存静态矩形，或在已有声明中添加静态矩形后保存。平台实例仍须为 `controls: "none"`、`speed: 0`，并配置与角色匹配的碰撞层／掩码；首次创建不会自动启用单向设置。
2. 打开 **编辑二维物理**，选择该静态矩形，在 **静态碰撞方式** 中选择 **单向平台**。**穿透容差（场景单位）** 默认为 1，允许有限数值 **1–64**，包含小数；它影响原生单向碰撞判定，不修改 `box.size` 声明的矩形高度。
3. 点击 **检查物理修改**，审阅 schema 升级和平台字段，再 **应用到原文草稿 → 主编辑器保存**。首次启用显式升级为物理 **schema 4**。未完成、越界或不合法输入不产生可应用的提案。
4. 改回 **普通碰撞** 会删除 `oneWay`，保留 schema 4。改为圆形、角色或触发区时，单向字段不再参与候选声明；仍需检查、审阅和普通保存。未涉及的几何、角色运动与原文写法保持。
5. 重新检查项目计划、构建并运行。可结合上节重力／跳跃角色检查下方穿越、上方下降承重，再从物理观察和既有作者事件核对接触；空间图只展示形状，不预演单向碰撞。

静态矩形原有字段之外增加：

```json
"oneWay": { "margin": 1 }
```

较大容差会加厚单向碰撞的判定范围，原生参数见 [Godot CollisionShape2D](https://docs.godotengine.org/en/stable/classes/class_collisionshape2d.html#class-collisionshape2d-property-one-way-collision-margin)。起始重叠的角色可能被推出到平台上方；默认使用 1，增大容差不保证任意巨大单步都不会穿透。

`oneWay` 严格只含 `margin`，不能写成布尔值。省略该对象时保持普通碰撞；schema 4 同时容纳已有角色滑动和 `characterMotion`，不要求每个物理体启用新功能。独立 `scenePhysics2D.inspectOneWay` 和可选标记检查完整 schema 4，旧格式 1／2／3 的检查操作保持原范围。编辑器只修改 `margin` 叶或相应可选字段，空间偏移／尺寸操作保留平台参数。

中立计划仅在实际存在 `oneWay` 时要求 **`physics.one-way-platform2d`**。Godot **0.26.0** 独立包装把字段应用到静态矩形的原生碰撞形状，复用既有运动、起跳／落地作者事件和来源。关闭全部单向设置后，schema 4 仍可构建并复用旧生成分支。该0.26平台切片不含移动／旋转平台或可配置方向；0.2.5 收录的[水平往返](#配置水平往返平台)与[主动下穿](#从单向平台主动下穿)分别见下节；项目协议、物理观察协议和作者场景／组装格式均不变，两个 Bevy 通道明确拒绝。验收范围见[单向平台专题](test-results/scene-physics2d-one-way/README.md)。

## 配置水平往返平台

**0.2.5 源码**已收录水平往返平台，适合横向渡台和周期移动的落脚点。平台轨迹独立于角色输入、场景实例的速度与视觉动画；物理空间图仍显示保存的起点和形状。

1. 按普通流程创建一个**静态矩形**，场景实例保持 `controls: "none"`、`speed: 0`；角色另行开启重力与跳跃。打开物理原文的 **编辑二维物理** 并选择该平台。
2. 在**平台移动方式**中选择**水平往返**。设置终点的水平偏移与平台速度；正偏移向右、负偏移向左，起点来自本次场景访问的实例位置。偏移绝对值为1–8192场景单位，速度为1–2000单位／秒，默认120和60。
3. 检查并审阅完整原文，明确启用后升级至 **schema 5** 并增加 `platformMotion`。应用草稿后仍需主编辑器保存；取消不改变作者文件。关闭只移除运动字段，保留schema 5。切换到非静态类型或圆形时，审阅会移除不适用的平台字段。
4. 保存、重新检查计划、构建并运行。平台以恒定速度在起点与终点间往返；每次重新进入场景从起点重新开始。普通实体平台及已有 `oneWay` 单向平台都能使用同一轨迹。

```json
"platformMotion": {
  "kind": "horizontal",
  "offsetX": 120,
  "speed": 60
}
```

角色承载取最近一次真实原生移动返回的向上支撑；只有重力角色会被携带，自由平面角色继续原碰撞方式。平台在已有项目物理时钟中前进，把本步水平位移合入各个受支撑角色的原运动请求，再由原碰撞求解处理墙体等障碍。观察里的 `requestedMotion` 因而包含输入／重力及平台承载的总请求，不等于纯输入。它不会额外驱动视觉动画或模拟另一套角色运动。

角色实际起跳的当步，或下穿请求在下一物理步复核通过并执行时，停止平台承载，脱离后不继承平台水平惯性；其他角色继续独立处理。支撑仅来自实际返回结果，不是几何接触全集；同一步返回其他普通／未知支撑或多个移动平台时，不推断应跟随哪一个。平台自身按作者轨迹移动，不会自动避开障碍；首版不定义垂直／旋转平台、侧向推挤、挤压伤害或刚体惯性。

新增独立核心检查域 `scenePhysics2D.inspectPlatformMotion` 与WASM能力标记；旧格式1–4保持，旧核心继续编辑其支持的旧声明。实际声明运动时才要求 `physics.platform-motion2d`，Godot **0.30.0** 通过独立轨迹与承载控制器实现；无运动字段的schema 5仅把冻结计划副本投影为schema 4后沿既有生成分支，原计划及作者原文保持。Bevy尚未实现，计划检查会明确拒绝。原项目运行和观察协议保持，新增清单与脚本随生成工程交付。验证见[水平往返平台专题](test-results/scene-physics2d-platform-motion/README.md)。

## 用平台端点事件驱动动画与声音

**0.2.5 源码**已收录 **Godot / 平台端点事件** 普通起始脚本。先保存水平往返平台，再在**新建脚本**中选择该项，普通保存为TXT并登记；通过现有行为编辑流程加入脚本引用，绑定到该移动平台的实例。它不应绑定到乘客角色、静止障碍或传感器。

两个文本参数分别是 `origin_event`（默认 `physics.platform_origin`）和 `destination_event`（默认 `physics.platform_destination`）。空名称禁用对应发布；载荷始终是本平台实例UUID。声音订阅可填写相同事件名和实例过滤，动画沿已有事件片段脚本订阅。修改参数仍经过检查、完整审阅、应用草稿和普通保存；创建脚本不会自动建立绑定、音轨或动画。

行为局部端口 `viento_platform_events` 版本1提供零参数 `origin_reached`／`destination_reached` 信号。它们表示**本次项目步内曾抵达该端点**：每个平台、每端、每步最多通知一次。初始已经在起点不通知，零时长不通知；恰好到端点计入本步，下一步不重复。若速度很高、路径很短而一步跨过多个端点，重复同端合并；两端都到过时按本步首次抵达顺序通知。它不是逐次穿越计数或逐端点时间线；负偏移只改变方向，起点／终点名称保持。

事实由实际轨迹步产生，在原有运动、碰撞和角色事件完成后派发，不从截图位置或有界测试trace推断。每个行为各有端口，场景关闭、退出及重入不保留旧连接，也不补发完成事件。发布来源回到普通行为绑定；物理声明来源继续通过物理观察或编辑入口查看。

**普通项目事件仍有每次运行128次累计发布等预算**，达到上限会明确失败，不因离开场景或队列排空而清零。原生端点信号自身不受这个累计发布预算，但起始脚本把信号转成项目事件后仍受[既有预算](PROJECT_EVENTS.md#有界数据与中间层)约束。当前接通的是有限验收与玩法接线；长期持续交互需要独立拆分执行预算和观察留存，见[路线](ROADMAP.md#内置创作到交付的推进顺序)。

Godot **0.31.0** 声明可选 `physics.platform-events2d`，独立薄桥与场景包装复用0.30轨迹，新增端口、清单与脚本进入严格工程库存。作者物理schema 5、Rust／WASM、项目运行和观察协议保持，Bevy未接入。验证见[平台端点专题](test-results/scene-physics2d-platform-events/README.md)。

## 从单向平台主动下穿

**0.2.5 源码**已收录 **Godot / 单向平台下穿** 普通脚本。先为角色保存重力与跳跃，为静态矩形保存单向平台，再把两者加入同一项目场景。默认使用向下键发起下穿；其他角色仍能站在同一平台上，普通实体地面继续阻挡。

1. 点击 **新建脚本 → Godot / 单向平台下穿**，创建TXT草稿并普通保存。通过 **管理已有行为** 显式关联脚本，绑定到要下穿的角色实例。
2. 可显式添加文本参数 `drop_action`，默认 `ui_down`。它是Godot已存在的输入动作名，脚本不会创建新的按键映射；就绪时已按住的键不会自动触发，释放后再次按下才请求，长按不重复。
3. 参数仍沿 **检查 → 完整原文审阅 → 应用草稿 → 普通保存**。重新构建后，在角色真正站上单向平台时按下该动作。空中，或本次原生碰撞返回的支撑包含普通地面时不会受理。
4. 下穿继续由原重力和移动求解完成。已有 **角色起跳与落地**、**角色移动碰撞** 脚本可发布实际运动结果，动画和声音继续订阅这些项目事件；下穿脚本本身不把请求成功当成已经落地。

后端提供独立行为局部 `viento_character_drop` 端口：`protocol_version()` 为1，`request_drop() -> bool` 的true仅表示请求已排队，下一物理步执行前仍要复核。端口只属于该行为绑定的角色和本次场景访问，同一实例同时最多一个待执行或进行中的请求；重复请求返回false。只有场景同时具有重力角色和静态单向平台时才提供此可选能力，自由平面、静态体和传感器不获得端口。

支撑来自最近一次真实移动结果及运动器的着地状态，本次返回的所有向上支撑都必须对应已声明的单向平台。这里不补做接触全集查询；没有被这次移动报告的相邻实体仍由下一步原生求解阻挡。执行时只为请求角色添加与这些平台的碰撞例外，并清除着地标志，防止同一步跳跃覆盖下穿；不传送、不强设下落速度，也不改变其他碰撞层或平台形状。

恢复使用实际碰撞形状的世界边界，包含平台容差与安全边距，完全脱离后只移除本功能添加的例外；已有作者例外不会被接管。边界矩形检查不发起另一轮物理查询。**很低的重力／落速、很厚的平台，或紧贴下方的实体障碍，都可能延长忽略时间。** 如果没有足够空间脱离，例外会保持到角色移开或本次场景关闭；不会按固定计时器提前恢复并把角色弹回。关闭、离场和重入分别清理旧请求与旧端口。

当前执行适配器为 **0.32.0**，通过 `physics.character-drop-through2d` 声明可选脚本能力。薄桥复用0.28移动采集钩子并委托独立下穿控制器，旧求解及事件采集源文件保持；新脚本清单与摘要随生成工程交付。作者物理格式、Rust／WASM、项目运行及观察协议保持，Bevy尚未接入。验证见[下穿专题](test-results/scene-physics2d-drop-through/README.md)。

## 用角色运动事件驱动动画与声音

以下能力已收录 **0.2.4**。先为角色保存上述重力与跳跃配置，再使用普通脚本与行为绑定接线。新构建的 Godot 项目提供实际运动事件；重新打开旧生成工程不会自动加入此接口，需重新构建。

1. 点击主编辑器 **新建脚本 → Godot / 角色起跳与落地**，选择 TXT 路径、创建草稿并普通保存。回到场景的 **添加行为** 或 **管理已有行为**，关联该脚本并绑定到启用重力与跳跃的角色实例。
2. 默认发布 `physics.jumped` 和 `physics.landed`，载荷是发布角色的实例 UUID。需要改名时，在行为编辑器显式添加文本参数 `jumped_event`／`landed_event`；空字符串禁用对应发布。普通 `@export` 参数不会自动填入表单。
3. 动画可绑定已有 **Godot / 事件动画片段**，把 `event_name` 设为 `physics.jumped` 或 `physics.landed`，用现有目录选择 `clip_id`。该模板默认操作整场景播放头；多角色共用事件名时须在作者脚本中按载荷过滤，或使用不同事件名。逐实例动画另按其明确目标契约配置，不能仅凭发布者 UUID 推导播放目标。
4. 声音可新建 **Godot / 项目事件播放声音** 并绑定。显式添加文本参数 `track_id`，从已声明音轨目录填入编号；`event_name` 默认 `physics.landed`。`instance_id` 留空接受该事件的全部合法载荷，填写时仅响应载荷等于该实例 UUID 的事件；它不认证发布者身份。就绪时不会自行发布或播放，也不替用户创建音轨。原 **Godot / 事件声音** 示例继续保留原有 `sound`／布尔载荷用法。
5. 参数修改仍沿 **检查 → 完整原文审阅 → 应用草稿 → 普通保存**。重新检查项目、构建并运行后，在[项目事件](PROJECT_EVENTS.md)查看发布与投递，分别打开作者绑定来源；动画和声音执行结果从各自的观察入口核对。

`jumped` 只在运动器实际接受本次起跳时产生，长按、空中重复按键或禁用跳跃不会产生第二次起跳。`landed` 在实际接触使角色从未着地变为着地时产生，**包含首次接触地面**；持续站立不会逐帧发布。碰顶和着地分别判断，接受起跳后同一步碰顶仍可产生起跳事件。没有提供离地、持续接触或任意碰撞生命周期事件。

事件端口在作者行为 `_ready()` 前注入到该行为的 `viento_character_motion` metadata：`protocol_version()` 为 1，`jumped`／`landed` 是无参数信号。运行层收集本步真实事实，在所有角色移动完成后发送；普通作者脚本再通过自己的 `viento_project.publish_event()` 发布。端口只属于本次场景访问，关闭时撤销，重入建立新端口；绑定目标不支持运动端口时模板明确报错。它不读取有界物理观察流，也不会让256样本限制影响正式玩法。

Godot 的独立 **0.25.0** 事件包装声明 `physics.character-events2d`，保持原运动生成器和脚本文件。此能力是新后端提供的可选脚本接口，不扫描任意作者 TXT 来推断需求，也不新增物理作者字段；物理 schema 3、项目协议及观察协议保持。没有行为订阅时仍只运行运动。验证与实际工具边界见[角色运动事件专题](test-results/scene-physics2d-character-events/README.md)。

## 用角色移动碰撞驱动项目事件

0.2.4 已为启用 `characterMotion` 的角色提供此接口；**0.2.5 源码**将它扩展到自由平面角色的停止／滑动响应。它报告角色在每步原生移动中遇到的阻挡实例。`started` 表示上一步未报告而本步报告该对方，`ended` 表示上一步报告而本步不再报告该对方；同一角色与对方在一步内重复碰撞只记一次。它与触发区进入／离开、起跳／着地是独立语义：例如贴墙后停止向墙移动，本步没有该墙的碰撞结果，也会结束；这不能证明几何已经分离。

1. 为场景实例保存角色碰撞体，自由平面角色可沿用停止或滑动响应，无需启用重力／跳跃。按普通脚本创建流程选择 **Godot / 角色移动碰撞**，将TXT保存并登记，再通过已有行为管理入口关联脚本并绑定到该角色实例。
2. 在行为参数中显式填写 `started_event`、`ended_event`，默认分别为 `physics.contact_started`、`physics.contact_ended`，单项留空不发布该事件。`other_instance_id` 留空接受所有对方，填写有效实例UUID则只接受该对方；这里填的是场景实例编号，而非OC／投影对象编号或碰撞体编号。
3. 检查、审阅并保存行为声明，重新构建项目。事件来源保留发布角色和绑定身份，载荷是**对方实例UUID**。两个实例共用同一设定时仍分别识别；运行层依据原生碰撞节点与冻结声明匹配身份，不从任意节点metadata认领对方。
4. 沿用已有事件动画或项目事件播放声音脚本订阅这些名称。声音模板的 `instance_id` 过滤载荷，因此此处可填写被碰撞对象的实例UUID；模板不会把发布角色与对方混为一谈。动画默认订阅同名事件而不按载荷过滤；多个来源需由作者显式区分事件名或脚本过滤。
5. 从项目事件、动画／声音控制记录分别确认发布、投递与执行，再使用来源按钮返回相应行为绑定。取消未应用设置、查看记录和来源导航不会写作者文件。

新构建提供独立的行为局部 `viento_character_contacts` 端口：`protocol_version()` 为1，`started(body_id: String, instance_id: String)` 与 `ended(...)` 各传递两个稳定编号。每步先结束旧集合差项，再开始新集合差项，按身份稳定排序；在原有运动及起跳／落地回调完成后派发。每个行为获得本次场景访问的独立端口，关闭或退出时撤销连接与集合，不补发结束事件。未知原生碰撞体不冒充登记实例，也不产生该作者事件。

0.2.4使用的Godot **0.27.0** 包装仅支持重力／跳跃角色，原验证保持在[移动碰撞事件专题](test-results/scene-physics2d-contact-events/README.md)。0.2.5 交付时的执行适配器为 **0.32.0**：从已有运动与单向平台生成层组合一套统一的碰撞集合收集器，自由平面和重力角色使用同一行为端口，复用原 `physics.character-contacts2d` 可选能力。纯平面场景另有薄运行层，让交互运行也经过已有移动返回值；不启用无头观察，不增加碰撞查询或第二次求解。

不扫描作者脚本文本推断计划能力，不新增作者格式、项目事件载荷或运行／观察协议。没有角色的场景继续旧生成分支；静态体和传感器不获得此端口，Bevy尚未接入。已有普通碰撞脚本可继续用于新构建，作者文件不自动改写；需重新构建才能使用0.28接口。自由平面验证见[独立专题](test-results/scene-physics2d-planar-contacts/README.md)。

## 查看角色的物理步与碰撞

以下能力已收录 **0.2.4**。重新构建含二维物理的 Godot 项目，在构建工作台运行现有 **无头测试**，即可查看独立的物理观察面板；窗口截图测试也会采样。作者声明无需升级，测试仍使用原来的半秒、30 个物理步。

1. 先保存物理声明和场景，重新检查项目并构建。旧冻结工程需重新构建，才包含观察脚本与库存。
2. 无头测试结束后，在物理观察面板按实例筛选，再选择访问和步样本。每条样本显示角色移动前后位置、请求位移、实际位移与停止／滑动方式。
3. 有碰撞时查看对方实例、接触位置、法线及本次碰撞前已走过／剩余的位移。可分别打开角色和对方的物理声明；来源来自这次构建的冻结计划，存在未保存草稿时沿原导航保护处理。
4. 改作者参数并普通保存后，重新构建／测试再比较。观察面板只读，不把运行位置回写场景或替换现有运行对象面板的坐标样本。

样本记录的是 **内建角色移动完成时的碰撞结果**：停止最多一次，滑动最多四次。接触位置使用场景全局坐标，法线来自后端实际求解；`moving` 仍表示输入意图，判断阻挡应比较请求与实际位移。引擎的安全距离修正可能在零输入时产生很小位移，不应把它当作新输入。

每次测试最多保留 **256 条角色样本**；达到限制后明确标为部分记录，游戏继续执行。中断保留已接收样本并标记不完整；无角色、尚未采样和该样本未碰撞分别显示。脚本自行创建的未登记碰撞体标为未映射，不猜测 UUID 或作者路径。记录不覆盖持续窗口运行、自定义脚本的所有位移、触发区重叠、着地状态或持续接触生命周期，也不能用于有限控制回放。

中间层使用独立的 `VIENTO_PHYSICS2D` 协议 1 和 `viento-physics2d-observation` 快照 1；宿主保存到运行 `session.json` 的 `physics` 字段。物理观察包装生成器为 **0.23.0**，能力为 `physics.observe2d`；当前执行适配器为 0.32.0，显式角色运动与单向平台各套独立包装。观察本身不要求作者格式升级，项目协议 4／7／10／11和既有动画契约不变。验证范围及结果见[物理观察专题](test-results/scene-physics2d-observation/README.md)。

## 按名称选择已有场景实例

以下操作已收录 **0.2.2**。编辑宿主支持 `scenePhysics2DTargets` 时，打开物理面板会自动读取一次已保存场景；目录显示来源路径。它只列该场景已有的实例，名称来自实例引用的设定对象；共用一个设定的多个实例可以同名，每个选项同时显示完整实例 UUID。场景草稿不会进入目录。

1. 在碰撞体详情的 **按场景实例名称选择** 中选择目标。选择只更新本次表单的实例编号，不修改场景、不生成新实例；手填框始终保留。已删除或不在目录里的旧编号会显示提示并保持原值，需显式修复。
2. 点击 **检查物理修改**。目录可用时核对所有碰撞体的目标；未选中条目里的缺失实例也会阻止通过。仍由 Rust 检查重复实例、参数与预算，不能将两个碰撞体指向同一实例。
3. 场景在其他位置保存后，点击 **刷新场景实例**。刷新保留表单及未完成输入，但撤销旧审阅。重新检查、审阅后应用；应用前宿主还会重读目录，若来源或成员发生变化则不写草稿。
4. 目录不可用、读取失败或关联尚未补齐时，可以继续手动填写并检查参数；面板明确显示 **目标尚未验证**。目录读取过程中可继续编辑字段，检查需等待这次读取完成。修好关联后可刷新重试，构建仍核对完整保存态工程。

目录服务使用独立只读 `POST /api/scene-physics2d-targets`。它从一次保存态 World 快照检查 Scene2D v2／v3、稳定实例、定义登记及物理文档的双向引用，并将目录绑定到当前草稿与保存基线。即使某个旧碰撞体引用了已删除实例，只要声明本身有效，目录仍可用于修复。它不执行脚本、不读取素材内容，也不借用动画目录或构建后端。

目录是检查时的保存态快照；应用前重读不构成跨文件事务，也不会锁住场景直到普通保存。后续保存或构建时仍需按各自规则复核。物理形状示意继续只使用已检查的声明，不把目录当作世界坐标或运动模拟。三语切换保留当前输入、选择与审阅；取消后重开时，旧目录响应或旧关闭事件不能改动新会话。

## 在场景空间中查看与选择碰撞体

以下功能已收录 **0.2.2**。宿主支持 `scenePhysics2DSpace` 时，打开物理面板会自动读取已保存 Scene2D v2／v3；面板的 **场景中的碰撞形状** 显示视口、实例逻辑范围、根位置及已检查的碰撞体。角色、静态体和触发区域使用不同颜色；所有图形保持比例，视口外的实例和碰撞体也计入显示范围。这里不加载图片或播放动画。

1. 点击碰撞形状，或用下方的按钮列表及键盘选择碰撞体。它只切换当前条目和字段，不修改声明，不产生未保存改动；同名实例用完整实例 UUID 与碰撞体 UUID 区分。重叠或过小的形状可通过列表选择。
2. 修改形状、尺寸或偏移后，图形清除并提示先检查。点击 **检查物理修改**，通过后才显示候选形状，并进入既有完整原文审阅。碰撞中心为 **已保存实例位置 + 声明偏移**，尺寸直接使用声明；偏移仍相对实例根，图上位置不回写为偏移。
3. 场景在其他位置保存后，可点 **刷新场景位置**。它更新空间参考并保持当前选择、未完成数字和已检查审阅；与会撤销审阅的 **刷新场景实例** 分开。空间读取不验证应用权限；目录辅助审阅的应用仍通过原有目标目录重读，场景发生变化时需重新检查。
4. 碰撞体引用的实例不在场景中时，仅列在缺失目标列表，不绘制猜测位置，也不删除原声明。选中后用已有实例选择器或编号字段修复，再检查。
5. 沿 **应用到原文草稿 → 主编辑器保存** 写入声明。点击形状、读取或刷新空间都不写作者文件；取消保留原文草稿。

空间服务为独立只读 `POST /api/scene-physics2d-space`，只接受场景 UUID，使用既有会话认证和同源校验。它复用保存态 World 快照及场景投影模型，只返回有界几何与来源信息；不依赖已有物理登记、图片字节、动画／声音／行为声明或引擎构建。空间读取失败或宿主不支持时，字段编辑、局部形状示意与目标目录仍按原能力可用。场景草稿不包含在空间图中。

空间图不提供碰撞求解、自由平移或运行轨迹；偏移拖动、尺寸手柄及缩放／聚焦工具见[偏移调整](#在空间图中调整碰撞偏移)与[尺寸调整](#在空间图中调整碰撞尺寸)。动画视觉变换不会改变物理根参考。表单、保存态空间、目标身份检查与引擎执行各自独立。中英日切换保留选择、输入及焦点；旧请求不能跨文档、能力变化或关闭重开覆盖新会话。完整验证见[空间图专题](test-results/scene-physics2d-space/README.md)。

## 在空间图中调整碰撞偏移

以下功能已收录 **0.2.3**。打开 **编辑二维物理**，等待保存态空间图加载，选择已有碰撞体，再点击 **调整碰撞偏移**。默认仍是查看与选择；调整模式只改变碰撞体相对实例根的 X/Y 偏移，不移动场景实例。

1. 可先使用 **放大空间图**、**缩小空间图**、**显示全部** 或 **聚焦选中碰撞体** 调整查看范围。这些操作不修改参数、原文草稿或审阅结果。选中形状在调整模式中显示在其它碰撞体上方，重叠条目仍可通过列表选择。
2. 拖动已选中的形状，查看临时轮廓和偏移；抓取点保持，不把碰撞中心吸附到指针。松开后才将有效新偏移交给参数表。触控也使用同一单指路径；未选中形状的首次操作用于选择。
3. 也可用四个方向按钮微调；每次 **1 单位**，按住 **Shift 为 10 单位**。空间图获得焦点时支持方向键，普通参数输入框保留自己的键盘操作。每次接受调整后，重新点击 **检查物理修改** 才会显示新形状并允许下一次调整。
4. 检查通过后审阅完整原文。变化限制于所选碰撞体的 `offset`，其身份、尺寸、其它物理体与场景位置保持。点击 **应用到原文草稿**，最后在主编辑器 **保存**。对完整工程的关系、成员和运动检查仍由已有流程负责。

拖动途中按 **Escape** 取消临时位移并保留面板；没有拖动时 Escape 继续沿原面板关闭规则。失去指针捕获、第二根手指、窗口失焦、切换选择／模式、场景刷新或关闭重开也会取消未完成手势。任何检查／应用中的旧回调、过期视图或未检查输入均不能更新参数。

偏移范围仍为 **−8192～8192**。越界拒绝并保留原输入和审阅，不把值截断到边缘；移回有效范围可以继续拖动。零位移不生成修改，未变化轴保留其输入数字写法。尚未找到场景目标的碰撞体只能选择并修复实例编号，不能猜测一个位置后拖动。

检查或刷新导致空间图重新生成时，查看范围重新适配全场景。视图仍不提供自由平移、场景实例移动或物理求解；尺寸手柄见[下一节](#在空间图中调整碰撞尺寸)。手势、参数表和作者源码分开管理；完整验证见[偏移编辑专题](test-results/scene-physics2d-space-edit/README.md)。

## 在空间图中调整碰撞尺寸

以下功能已收录 **0.2.3**。选择已检查、目标存在的碰撞体，点击 **调整碰撞尺寸**。该模式与 **调整碰撞偏移** 互斥，再点当前模式按钮返回查看；切换不会改参数或已检查审阅。

- **矩形**：右侧手柄调整宽度，下侧手柄调整高度，右下角手柄同时调整宽高。中心固定，因此边缘移动 1 单位时，完整宽或高变化 2 单位；对边会围绕中心同步伸缩。
- **圆形**：右侧手柄沿水平方向调整半径，中心固定，半径增量等于水平场景位移。拖动始于实际抓取点，不会把轮廓边缘吸附到指针。
- **精确微调**：使用减小／增大宽度、高度或半径按钮，每次 1 单位，Shift 为 10 单位。空间图获得焦点时，矩形左右键减／增宽、上下键减／增高；圆形左／上键减半径、右／下键增半径。参数输入框保持自己的按键操作。

拖动中只显示待确认轮廓和数值，松手才交接参数表。只更新发生变化的宽、高或半径字段，保持未变化数字写法、形状类型、偏移、其它碰撞体和场景实例位置；零变化不撤销审阅。每次接受调整后点击 **检查物理修改**，审阅完整原文，再 **应用到原文草稿 → 主编辑器保存**。

矩形完整宽高范围仍为 **1～8192**，圆形半径为 **0.5～4096**。越界拒绝，不截断为边界值、不翻转形状；无效临时轮廓不会显示，移回有效范围可继续。按 Escape 取消手势并保持面板；多指、失焦、丢失捕获、视图／模式改变或关闭也会取消。旧会话、未检查输入、检查／应用等待中和缺失目标不能接收尺寸提案。

缩放、显示全部和聚焦选中只调整查看范围；检查或刷新重建空间图后重新适配场景。手柄有固定屏幕命中范围，较小或重叠形状也可先聚焦，或改用按钮及原参数字段。此编辑使用已保存场景参考，不运行碰撞求解；端到端证据见[尺寸专题](test-results/scene-physics2d-space-resize/README.md)。

## 字段与映射

| 声明 | 规则与当前运行含义 |
| --- | --- |
| `static` | 默认是 Godot `StaticBody2D` 固定障碍；声明水平往返时映射为 `AnimatableBody2D`，按独立轨迹移动 |
| `character` | Godot `CharacterBody2D`，自由平面按方向输入移动；默认遇障碍停止，schema 2 可选滑动，schema 3 可显式启用重力与跳跃 |
| `sensor` | Godot `Area2D`，检测身体进入／离开；不阻挡身体，不提供区域之间的事件 |
| `box.size` | 完整宽高，各为 1–8192；与场景坐标使用相同单位 |
| `circle.radius` | 半径 0.5–4096 |
| `oneWay.margin` | schema 4 静态矩形的可选单向碰撞容差，1–64；编辑器启用默认 1，省略 `oneWay` 为普通碰撞 |
| `offset` | 相对实例根位置的碰撞形状偏移，各分量在 −8192–8192 内 |
| `layer` / `mask` | 0–65535 的整数位掩码；例如层 1 用数值 1，层 2 用数值 2，同时两层用 3。触发区 mask 与身体 layer 相交才检测它 |

正文不超过 64 KiB，每份 1–128 个物理体；一个实例最多一个物理体。原有字段必须完整，不接受未知字段；schema 2 定义角色可选 `collisionResponse`，schema 3 增加可选 `characterMotion`，schema 4 增加静态矩形的可选 `oneWay`，schema 5 增加水平往返 `platformMotion`。省略这些字段保持原有默认行为。未声明物理体的实例沿用原移动路径。

碰撞尺寸不由图片大小自动推断。视觉动画只变换独立视觉子层，物理根位置和碰撞形状由物理运行维护；改变视觉缩放、旋转或偏移不会移动碰撞体。`idle`／`moving` 仍表示输入运动意图，受墙阻挡时可以仍是 `moving`，应通过实际位置判断阻挡。

## 从接触到项目事件和动画

在“新建脚本”中选择 **Godot / 物理触发区**，审阅并普通保存，再用[场景行为](SCENE_BEHAVIORS.md)把脚本绑定到 `sensor` 对应的实例。

起始脚本连接真实 `Area2D.body_entered` 和 `body_exited`，默认发布 `physics.entered`／`physics.exited`。可通过普通行为参数 `entered_event`／`exited_event` 改名，空字符串禁用相应事件。载荷是接触身体的实例 UUID；发布来源是触发区的真实行为绑定与实例。

其他行为可按[项目事件](PROJECT_EVENTS.md)订阅，动画控制器也可将同名事件配置为状态转换触发器，动作片段自然完成后返回待机。运行页已有事件与动画来源观察可回看这条链路。离场时脚本断开信号且项目端口失效，旧访问不能向新访问继续发布。

无头测试在真实物理帧之间推进半秒逻辑时间，前半段按住右方向、后半段松开，允许触发区被实际检测。它是有限冒烟运行；具体物理交互仍可用窗口预览检查。Godot 的区域重叠在物理步更新，信号检测和立即修改位置不同步，参见 [Area2D 文档](https://docs.godotengine.org/en/4.7/classes/class_area2d.html)；运动调用见 [PhysicsBody2D 文档](https://docs.godotengine.org/en/4.7/classes/class_physicsbody2d.html)。

## 构建、交付与边界

Rust 核心负责声明规则；中立计划负责绑定场景身份、保存态来源和能力需求；Godot 适配器负责原生节点和时钟。声明没有 Godot 节点名、事件绑定号或渲染尺寸。schema 1 使用既有可选核心入口 `scenePhysics2D.inspect`；schema 2／3／4／5 分别使用独立 `scenePhysics2D.inspectResponse`／`inspectMotion`／`inspectOneWay`／`inspectPlatformMotion` 与各自可选标记，不改变主 ABI。物理子计划为 `viento-physics2d-plan` v1，挂在场景计划 `physics` 字段；旧场景作者格式不变。

执行能力为 `physics.bodies2d`，按声明种类追加 `physics.character2d`／`physics.sensors2d`；按实际字段追加 `physics.character-slide2d`、`physics.character-motion2d` 、`physics.one-way-platform2d` 或 `physics.platform-motion2d`。Godot 提供这些能力，两个 Bevy 通道明确拒绝。当前执行适配器为 0.32.0；原 0.21.0 物理、0.22.0 响应、0.23.0 观察、0.24.0 运动及 0.25.0 事件生成层保持，实际单向平台再套 0.26.0 包装，当前含角色的场景从这些层组合 0.28.0 统一移动碰撞收集器，保留但不叠加旧 0.27.0 收集器；同时存在重力角色和单向平台时再由0.29.0薄桥提供独立下穿控制；显式水平往返由0.30.0独立平台控制器合入角色请求，保存并严格校验旧运行原文；项目运行协议继续按已有动画范围与控制器内容[选择](PROJECT_BUILD.md#当前项目协议选择)，没有新的物理线协议。只在选择物理声明时加入原生物理运行文件；没有选择的场景不产生空物理计划。

成功工程经现有[交付工程](BACKEND_PROJECTS.md#交付生成工程)导出，包内含物理声明、运行脚本、行为和已冻结素材；解包后可独立用 Godot 导入运行。`physics-project.json` 是受校验的生成文件清单补充；schema 2 另附 `physics-response-project.json` 登记响应场景与底层停止脚本，它们都不是作者配置。实际单向平台另附 `one-way-project.json`、各场景 `one-way.json`、原运行脚本与独立原生形状设置脚本，并由库存核对后参与交付。水平往返另有平台场景清单、参数、旧运行原文及独立控制器，纳入严格库存；完整作者迁移仍使用 `.viento.zip`。

更新 Studio 执行适配器会改变执行指纹：旧冻结构建仍可读取，但在新版 Studio 中再次运行或按现行适配器核对交付，需要重建，不能跳过旧执行凭据检查。已导出的独立 Godot 工程不依赖 Studio 的执行指纹。

当前未提供动态刚体、力／冲量、垂直或旋转平台、关节、物理材质、3D 或 Bevy 物理；局部偏移和尺寸拖动见上述独立空间图。单场景构建提示先创建项目组装；旧有限控制回放明确拒绝含物理工程，避免把直接位置回放当成物理验证。静态预览、普通源编辑与错误修复不依赖物理构建成功。
