# 二维物理声明与运行

0.2.2 源码支持项目组装中的静态障碍、受碰撞约束的方向键角色和触发区。可从场景首次创建物理声明与双向关系，在独立面板按实例名称选择或修复目标，并通过场景空间图查看和选择碰撞体；检查、审阅、应用草稿和普通保存分别管理。物理声明独立于场景、视觉动画及行为脚本，Godot 将它映射为真实物理节点。见[版本记录](RELEASE_0.2.2.md)与[发布检查](test-results/release-0.2.2/README.md)；本机已安装程序仍为 0.2.0，各开发专题保留原验证时点。

## 从现有场景开始

1. 准备已保存的 Scene2D v2／v3。角色、墙和触发区各有稳定 `instanceId`；可以共用同一设定对象。角色保留现有 `controls: "arrows"` 和 `speed`；墙和触发区使用 `controls: "none"`、`speed: 0`。
2. 打开 **构建与运行 → 场景物理**。选择场景实例、文档类型和正文目录内的 JSON 路径，设置第一个物理体的种类、形状、偏移、层和检测掩码。默认角色体、32×32 矩形、零偏移、层与掩码均为 1；所有参数可修改。
3. 点击 **审阅二维物理**，核对完整 JSON 和双向关系，再点击 **保存物理与关系**。一次操作创建物理正文、登记 UUID，并更新场景的 `references / physics2d` 关系；物理文档同时引用场景。三处文件共同提交并支持中断恢复，场景正文及素材保持。
4. 点击 **打开二维物理原文**，进入 **编辑二维物理**。面板可增删碰撞体、选择实例、切换矩形／圆形、修改尺寸和层掩码；检查并审阅后先应用原文草稿，再普通保存。也可使用通用字段表或直接编辑 JSON。
5. 将场景加入[项目组装](PROJECT_ASSEMBLY.md#从当前场景开始)，检查计划、构建，再用无头测试或窗口预览运行。构建页静态画布只展示场景；物理面板另有[场景空间图](#在场景空间中查看与选择碰撞体)，显示碰撞范围但不运行物理求解。

### 首次创建的保存边界

首次创建入口需要已登记、有稳定实例的 Scene2D v2／v3；不要求安装引擎或已有动画、声音、行为。审阅只读取，取消不会创建文件。已有物理声明时直接提供原文入口，不重复创建。保存结果未确认时先 **重新读取工程**，用文档身份、精确原文和关系核对结果，不再次发送创建命令。

创建时验证声明规则、已保存场景实例归属、世界及来源修订；静态体和传感器的有效控制必须为 `none`、速度为 `0`，这些投影后的运动条件仍由构建预检负责。新建表单不会替用户改变场景运动设置。创建后沿用同一个物理字段编辑器及普通保存，不引入第二份持久配置。

0.2.1 发布基线仍使用普通新建 JSON 和 [World 对象关系](WORLD_RELATIONS.md)：物理文档引用场景，场景引用物理文档且用途为 `physics2d`。这条手工路径继续可用，两个关系分别保存，不具备新创建命令的三文件事务。首次创建的开发验证见[首次创建记录](test-results/scene-physics2d-creation/README.md)。

以下编号仅演示结构，需换成当前工程的场景和三个实例 UUID；各物理体 `id` 也应有独立稳定 UUID。

```json
{
  "format": "viento-scene-physics2d",
  "schemaVersion": 1,
  "sceneObjectId": "11111111-1111-4111-8111-111111111111",
  "bodies": [
    {
      "id": "44444444-4444-4444-8444-444444444441",
      "instanceId": "22222222-2222-4222-8222-222222222221",
      "kind": "character",
      "shape": { "kind": "box", "size": [20, 20] },
      "offset": [0, 0], "layer": 1, "mask": 1
    },
    {
      "id": "44444444-4444-4444-8444-444444444442",
      "instanceId": "22222222-2222-4222-8222-222222222222",
      "kind": "static",
      "shape": { "kind": "box", "size": [10, 100] },
      "offset": [0, 0], "layer": 1, "mask": 1
    },
    {
      "id": "44444444-4444-4444-8444-444444444443",

      "offset": [0, 0], "layer": 2, "mask": 1
    }
  ]
}
```

## 编辑已有物理声明

面板只编辑当前已存在的 JSON 原文，不创建文件、登记对象或修改场景关系。先保存符合上例格式的物理文档，再进入原文编辑；打开面板时会读取当前草稿，包括尚未保存的原文修改。JSON 语法或声明规则无效时，返回原文修复后重新打开。识别到物理格式并不意味着它已经登记或关联到场景。

1. 点击 **编辑二维物理**，在“碰撞体”中选择要修改的条目。场景 UUID 和已有碰撞体 UUID 保持原值。
2. 选择目标实例，或手动填写其 UUID；0.2.2 可从[已保存场景目录](#按名称选择已有场景实例)按名称选择。0.2.1 发布基线仍需从场景原文的 `actors[].instanceId` 复制。选择 `static`、`character` 或 `sensor`，再编辑矩形宽高或圆形半径、X/Y 偏移、层与掩码。
3. **添加碰撞体** 会生成一个新的碰撞体 UUID；仍需显式选择或填写目标实例。**移除碰撞体** 只修改当前表单，至少保留一个条目。已有条目保留相对顺序，新条目追加在末尾。
4. 点击 **检查物理修改**。通过后查看变化的 JSON 路径、修改前后完整原文，以及所选碰撞体的局部形状示意。继续改动表单会撤销审阅，需重新检查。
5. 点击 **应用到原文草稿**。当前工作树若以目录检查过目标，会先重读并核对该目录；变化或读取失败时保留表单，刷新后重新检查。应用成功后面板关闭并返回主编辑器，此时仍未保存；原有未涉及的草稿内容保留。最后点击主编辑器的 **保存**，才会写入作者文件。
6. 保存后从项目组装 **检查计划**。这里进一步核对场景登记、双向关系、实例成员及有效运动属性，再进入构建／运行。

| 面板内容 | 含义与编辑范围 |
| --- | --- |
| 场景 UUID、碰撞体 UUID | 已有身份只读；新增碰撞体单独分配 UUID，不重建整个声明 |
| 实例 UUID | 选择或手动填写当前场景的稳定实例编号；一个声明中不能重复使用同一实例。名称只供选择，原文保存 UUID |
| 物理类型 | 静态障碍、角色体或触发区；静态／触发区的场景运动条件由构建检查 |
| 形状及尺寸 | 矩形完整宽高或圆形半径；切换形状只替换该条目的形状对象 |
| X/Y 偏移 | 相对实例根的局部偏移，不是场景世界坐标 |
| 层与掩码 | 0–65535 的整数位掩码，多个层按位组合 |

形状示意把局部原点、形状和偏移一同缩放到可见区域；矩形与圆形保持比例。它不读取场景、运行碰撞求解或显示其他碰撞体，也不会改变作者数值。示意来自已检查的声明，表单变化后清除，重新检查后再显示。

**取消修改**、**返回编辑器** 或 Escape 会关闭面板；有未应用表单变化时先确认是否丢弃。取消只丢弃这次表单，不覆盖打开面板前已有的原文草稿。检查或应用期间关闭后，迟到结果不能继续写入。若切换文档、原文被修改、保存基线变化或核心不可用，旧审阅失效，需重新打开。

声明检查复用 Rust 的身份、形状、数值及 64 KiB 预算规则。当前工作树可选的只读目录另行核对已保存场景、关联和实例身份；未取得目录时，手填流程只验证声明参数。投影继承后的 `controls`／`speed` 和完整工程条件始终由保存态构建前检查负责。面板不提供碰撞拖拽、关系创建、自动迁移或物理回放。

来源补丁保留 BOM、行尾和未修改的原文字节；标量修改只替换相应 token，形状切换和增删条目分别限制在形状对象或碰撞体数组内。目录增量沿用这些补丁与普通保存规则，不改变作者格式、Rust 规则、后端版本或运行协议。

## 按名称选择已有场景实例

以下操作已收录 **0.2.2**。编辑宿主支持 `scenePhysics2DTargets` 时，打开物理面板会自动读取一次已保存场景；目录显示来源路径。它只列该场景已有的实例，名称来自实例引用的设定对象；共用一个设定的多个实例可以同名，每个选项同时显示完整实例 UUID。场景草稿不会进入目录。

1. 在碰撞体详情的 **按场景实例名称选择** 中选择目标。选择只更新本次表单的实例编号，不修改场景、不生成新实例；手填框始终保留。已删除或不在目录里的旧编号会显示提示并保持原值，需显式修复。
2. 点击 **检查物理修改**。目录可用时核对所有碰撞体的目标；未选中条目里的缺失实例也会阻止通过。仍由 Rust 检查重复实例、参数与预算，不能将两个碰撞体指向同一实例。
3. 场景在其他位置保存后，点击 **刷新场景实例**。刷新保留表单及未完成输入，但撤销旧审阅。重新检查、审阅后应用；应用前宿主还会重读目录，若来源或成员发生变化则不写草稿。
4. 目录不可用、读取失败或关联尚未补齐时，可以继续手动填写并检查参数；面板明确显示 **目标尚未验证**。目录读取过程中可继续编辑字段，检查需等待这次读取完成。修好关联后可刷新重试，构建仍核对完整保存态工程。

目录服务使用独立只读 `POST /api/scene-physics2d-targets`。它从一次保存态 World 快照检查 Scene2D v2／v3、稳定实例、定义登记及物理文档的双向引用，并将目录绑定到当前草稿与保存基线。即使某个旧碰撞体引用了已删除实例，只要声明本身有效，目录仍可用于修复。它不执行脚本、不读取素材内容，也不借用动画目录或构建后端。

目录是检查时的保存态快照；应用前重读不构成跨文件事务，也不会锁住场景直到普通保存。后续保存或构建时仍需按各自规则复核。物理形状示意继续只使用已检查的声明，不把目录当作世界坐标或运动模拟。三语切换保留当前输入、选择与审阅；取消后重开时，旧目录响应或旧关闭事件不能改动新会话。

## 在场景空间中查看与选择碰撞体

以下功能已收录 **0.2.2**。宿主支持 `scenePhysics2DSpace` 时，打开物理面板会自动读取已保存 Scene2D v2／v3；面板的 **场景中的碰撞形状** 显示视口、实例逻辑范围、根位置及已检查的碰撞体。角色、静态体和触发区域使用不同颜色；所有图形保持比例，视口外的实例和碰撞体也计入显示范围。这里不加载图片或播放动画。

1. 点击碰撞形状，或用下方的按钮列表及键盘选择碰撞体。它只切换当前条目和字段，不修改声明，不产生未保存改动；同名实例用完整实例 UUID 与碰撞体 UUID 区分。重叠或过小的形状可通过列表选择。
2. 修改形状、尺寸或偏移后，图形清除并提示先检查。点击 **检查物理修改**，通过后才显示候选形状，并进入既有完整原文审阅。碰撞中心为 **已保存实例位置 + 声明偏移**，尺寸直接使用声明；偏移仍相对实例根，图上位置不回写为偏移。
3. 场景在其他位置保存后，可点 **刷新场景位置**。它更新空间参考并保持当前选择、未完成数字和已检查审阅；与会撤销审阅的 **刷新场景实例** 分开。空间读取不验证应用权限；目录辅助审阅的应用仍通过原有目标目录重读，场景发生变化时需重新检查。
4. 碰撞体引用的实例不在场景中时，仅列在缺失目标列表，不绘制猜测位置，也不删除原声明。选中后用已有实例选择器或编号字段修复，再检查。
5. 沿 **应用到原文草稿 → 主编辑器保存** 写入声明。点击形状、读取或刷新空间都不写作者文件；取消保留原文草稿。

空间服务为独立只读 `POST /api/scene-physics2d-space`，只接受场景 UUID，使用既有会话认证和同源校验。它复用保存态 World 快照及场景投影模型，只返回有界几何与来源信息；不依赖已有物理登记、图片字节、动画／声音／行为声明或引擎构建。空间读取失败或宿主不支持时，字段编辑、局部形状示意与目标目录仍按原能力可用。场景草稿不包含在空间图中。

当前空间图没有碰撞求解、拖拽、缩放／平移工具或运行轨迹；动画视觉变换不会改变物理根参考。表单、保存态空间、目标身份检查与引擎执行各自独立。中英日切换保留选择、输入及焦点；旧请求不能跨文档、能力变化或关闭重开覆盖新会话。完整验证见[空间图专题](test-results/scene-physics2d-space/README.md)。

## 字段与映射

| 声明 | 规则与当前运行含义 |
| --- | --- |
| `static` | Godot `StaticBody2D`，作为固定障碍，不按输入移动 |
| `character` | Godot `CharacterBody2D`，方向输入乘原速度与物理步长，`move_and_collide` 遇障碍停止；尚无贴墙滑动、跳跃或重力 |
| `sensor` | Godot `Area2D`，检测身体进入／离开；不阻挡身体，不提供区域之间的事件 |
| `box.size` | 完整宽高，各为 1–8192；与场景坐标使用相同单位 |
| `circle.radius` | 半径 0.5–4096 |
| `offset` | 相对实例根位置的碰撞形状偏移，各分量在 −8192–8192 内 |
| `layer` / `mask` | 0–65535 的整数位掩码；例如层 1 用数值 1，层 2 用数值 2，同时两层用 3。触发区 mask 与身体 layer 相交才检测它 |

正文不超过 64 KiB，每份 1–128 个物理体；一个实例最多一个物理体。字段必须完整，不接受未知字段或隐式默认值。未声明物理体的实例沿用原移动路径。

碰撞尺寸不由图片大小自动推断。视觉动画只变换独立视觉子层，物理根位置和碰撞形状由物理运行维护；改变视觉缩放、旋转或偏移不会移动碰撞体。`idle`／`moving` 仍表示输入运动意图，受墙阻挡时可以仍是 `moving`，应通过实际位置判断阻挡。

## 从接触到项目事件和动画

在“新建脚本”中选择 **Godot / 物理触发区**，审阅并普通保存，再用[场景行为](SCENE_BEHAVIORS.md)把脚本绑定到 `sensor` 对应的实例。

起始脚本连接真实 `Area2D.body_entered` 和 `body_exited`，默认发布 `physics.entered`／`physics.exited`。可通过普通行为参数 `entered_event`／`exited_event` 改名，空字符串禁用相应事件。载荷是接触身体的实例 UUID；发布来源是触发区的真实行为绑定与实例。

其他行为可按[项目事件](PROJECT_EVENTS.md)订阅，动画控制器也可将同名事件配置为状态转换触发器，动作片段自然完成后返回待机。运行页已有事件与动画来源观察可回看这条链路。离场时脚本断开信号且项目端口失效，旧访问不能向新访问继续发布。

无头测试在真实物理帧之间推进半秒逻辑时间，前半段按住右方向、后半段松开，允许触发区被实际检测。它是有限冒烟运行；具体物理交互仍可用窗口预览检查。Godot 的区域重叠在物理步更新，信号检测和立即修改位置不同步，参见 [Area2D 文档](https://docs.godotengine.org/en/4.7/classes/class_area2d.html)；运动调用见 [PhysicsBody2D 文档](https://docs.godotengine.org/en/4.7/classes/class_physicsbody2d.html)。

## 构建、交付与边界

Rust 核心负责声明规则；中立计划负责绑定场景身份、保存态来源和能力需求；Godot 适配器负责原生节点和时钟。声明没有 Godot 节点名、事件绑定号或渲染尺寸。独立可选核心入口 `scenePhysics2D.inspect` 不改变主 ABI。物理子计划为 `viento-physics2d-plan` v1，挂在场景计划 `physics` 字段；旧场景作者格式不变。

执行能力为 `physics.bodies2d`，按声明种类追加 `physics.character2d`／`physics.sensors2d`。当前 Godot 提供三项，Bevy 明确拒绝未提供的能力。含物理的新生成工程使用适配器版本 0.21.0，项目运行协议继续按已有事件／动画内容选择，没有新的物理线协议。只在选择物理声明时加入原生物理运行文件；没有选择的场景不产生空物理计划。

成功工程经现有[交付工程](BACKEND_PROJECTS.md#交付生成工程)导出，包内含物理声明、运行脚本、行为和已冻结素材；解包后可独立用 Godot 导入运行。`physics-project.json` 是受校验的生成文件清单补充，不是作者配置。完整作者迁移仍使用 `.viento.zip`。

更新 Studio 执行适配器会改变执行指纹：旧冻结构建仍可读取，但在新版 Studio 中再次运行或按现行适配器核对交付，需要重建，不能跳过旧执行凭据检查。已导出的独立 Godot 工程不依赖 Studio 的执行指纹。

当前未提供动态刚体、力／冲量、重力、关节、物理材质、3D、Bevy 物理或场景画布中的碰撞体拖拽编辑。单场景构建提示先创建项目组装；旧有限控制回放明确拒绝含物理工程，避免把直接位置回放当成物理验证。静态预览、普通源编辑与错误修复不依赖物理构建成功。
