**已有物理声明编辑的独立边界**：`engine/scene-physics2d-edit.mjs` 负责当前原文的有界捕获、局部补丁和品牌化审阅，完整声明仍由既有 Rust `scenePhysics2D.inspect` 校验。`app-scene-physics2d-source.js` 只通过 source5、generation 和摘要守护当前原文，在最终所有权检查后同步写入草稿；普通保存单独拥有持久化权限。独立视图持有表单、选择、局部形状示意和取消票据，不读取场景目录或执行后端。

新增 `org.viento.scene-physics2d` 只依赖文档模块，贡献 `scene.authoring.physics2d`；0.2.1 源码为 **23 模块／44 项声明能力**。缺少端口或显式关闭时保持旧编辑器装配，Rust 可选能力只控制物理入口。格式识别不证明元数据登记，手填实例成员、关联与继承后的运动属性仍由构建前检查。没有新 HTTP 接口、Rust/WASM 规则、作者版本或运行协议；见[使用指南](SCENE_PHYSICS2D.md#编辑已有物理声明)和[本轮验证](test-results/scene-physics2d-editor/README.md)。下列历史专题的模块数和验收条件保留当时范围。

**二维物理为独立可选层**：`scenePhysics2D.inspect` 在 Rust 校验形状、身份和预算；`engine/scene-physics2d.mjs` 将显式 `references`／`physics2d` 关系解析为带来源的物理子计划，按种类声明执行能力。Godot 包装器只为含物理项目替换运动根与时钟，视觉动画仍留在独立子层；触发区通过普通作者行为发布现有项目事件，不伪造绑定身份。旧生成器与主核心 ABI 保持，执行适配器指纹更新仍要求旧构建重建。见[二维物理](SCENE_PHYSICS2D.md)。

只读 3D 预览通过独立来源端口取得有效模型和可选的受守护光标定位。名称／UUID 检索、画布点选及选中边缘提示共享稳定实例身份；单对象和全场景聚焦只改变临时相机。数学、GPU 适配与界面不取得作者补丁、World、保存或执行后端接口。全场景取景使用实际旋转角点和画布比例，作者 schema、源字节及后端协议保持。操作见[3D 指南](SCENE3D.md)，交付与实际验收边界见[0.1.0 记录](RELEASE_0.1.0.md)。

当前工作树的标准方向仍在预览边界内：纯数学显式表达临时 `up` 与局部轴轨道，GPU适配器通过可选 `setViewDirection(direction)`原子取景并撤销旧手势，界面仅提交固定方向标识。绘制、几何命中与聚焦使用同一相机基底；作者schema与Rust解析、宿主端口、系统能力和后端工程保持。见[标准方向契约](SCENE3D.md#标准观察方向010-之后的工作树)。

临时镜头平移进一步划分了三层职责：`panCamera` 只消费相机、CSS 位移和绘图比例，返回冻结的相机或拒绝结果；渲染器的 `setDragMode` 及手势状态机决定旋转／平移、撤销旧手势并守护 Float32 上传和失败回滚；界面只切换固定模式并守护当前只读会话。相机目标与位置一起变化，聚焦范围、作者模型与持久化接口不转移给手势层。详见[平移操作与边界](SCENE3D.md#临时镜头平移010-之后的工作树)。

正交观察继续复用同一视图边界：`cameraProjection4` 只返回投影矩阵，`lookAt4` 仍单独负责相机基底；单对象与整景取景接受投影模式。渲染器将私有 `projectionMode` 与作者模型分开，可选 `setProjectionMode` 在矩阵与实际 Float32 上传预检后切换，失败恢复原模式并清理不完整命中帧。UI 只接收固定模式与成功回执，点选、边缘提示和绘制复用相同的实际矩阵。作者格式、Rust 解析、保存及后端导出不消费此临时状态，见[正交边界](SCENE3D.md#正交观察010-之后的工作树)。

坐标方向提示另以观察接口分离绘图和显示：纯 `orientationAxes` 把世界三轴投影到当前相机基底；渲染器的可选 `onViewChange` 只在成功帧之后发布冻结的临时相机／投影回执，失效时发布 `null`。独立 `scene3d-orientation.js` 仅维护自身 SVG 和翻译说明，预览入口负责当前渲染实例与会话守护。没有轮询、原文重解析或保存路径，观察者异常不改变绘图结果，详见[方向提示边界](SCENE3D.md#坐标方向提示010-之后的工作树)。

双指导航复用相同视图边界：纯 `touchCamera` 只接收临时相机、两组 CSS 触点、画布尺寸／绘图比例及当前距离界限，以目标平面中心锚点合成缩放与平移；不取得 DOM 或设备状态。渲染器负责明确的两触控升级、移动阈值、每次成功后的基准更新、捕获生命周期与取消，双指输入在同一浏览器动画帧内合并最新坐标，完整候选经过 Float32 预检后只绘制一次并更新基准。正常抬指提交末批有效位移，取消或视图变更撤销排帧；晚回调检查手势归属。只有输入触发排帧，没有轮询；无帧调度的适配环境保留同步处理。界面只消费 `supportsTouchNavigation === true` 这一渲染器本地提示来显示三语操作说明，不注册新系统能力。来源、保存、作者变换和后端接口保持，详见[双指边界](SCENE3D.md#双指导航010-之后的工作树)。

当前源码还把[运行对象观察](RUNTIME_OBJECTS.md)置于可移植引擎层：从验证后的冻结计划取得稳定身份和来源，只消费适配器已准入的既有生命周期／状态事件。宿主保存并提供当前任务的只读观察，工作台负责显示、检索与原文导航；没有将具体 ECS 句柄、节点路径或反射方法提升为作者契约。

当前再增加[有限控制回放](RUNTIME_CONTROL.md)：可移植层验证有界方向数据与 trace 顺序；schema 1 为全局，schema 2 仅按冻结 plan 2 实例 UUID 独立输入，提前检查目标与输入行预算，具体后端在每步释放未列实例。宿主冻结程序、绑定 SHA-256 和独立会话，适配器负责暂存驱动／数据，Godot 与 Bevy 自己执行移动。步骤位置只更新同一只读对象观察；没有引入引擎反射、Entity 或实时命令通道。

已交付的[工具身份检查](BACKEND_MIDDLEWARE.md#工具身份检查未发布增量)另把纯状态 DTO、宿主探测和界面显示分开。宿主显式复用各适配器的工具识别；普通轮询只观察文件，缓存只在当前服务内存。工具路径和进程输出不进入可移植状态，检查结果不替代构建／运行时的完整身份校验。

已交付的[运行验收用例](RUNTIME_CASES.md)组合已有控制程序与步骤采样：纯模块负责用例／实例准入和位置／状态比较，通用宿主负责真实完成事实与独立记录，界面负责显式输入和逐行结果。仅无行为冻结 plan 2；用例不含引擎标识、路径或句柄，评判不模拟移动。运行成功与断言失败分别记录，取消和缺样本标未完成。旧作者／计划／trace、适配器指纹及 Rust／WASM 保持。

包装文档 `viento-runtime-case-document` 单独保存场景 UUID 与原用例，纯模块负责绑定和依赖校验；Node 作者文档服务复用登记锁、原子正文写入、原文及场景修订保护，GUI 独立控制器负责显式载入／保存与草稿归属。资源包从正文派生必要场景和可选子内容，不复制关联权威到元数据；目录迁移保留作者字节和实例身份。执行仍消费纯用例及已验证场景绑定，不把文档路径带进运行 DTO。

本轮另接[有序验收组](RUNTIME_CASE_SUITES.md)：纯数据层定义同场景成员、联合预算与汇总，共享作者写入保护；Node 一次捕获全部成员，再按顺序复用原无头执行器。GUI 只编辑成员与显示结果；读包／导入复用场景准入，已知坏场景不会因成员正文延期而绕过。任务分配前重查构建归属，每成员重新核对冻结身份；取消等待进程退出。无新引擎协议、Rust／WASM 或作者格式升级。

行为创作的 `scene-behaviors-edit.mjs` 仅持有严格声明、稳定绑定身份和保真文本补丁；共用 `json-source.mjs` 由 JSON.parse 准入，再扫描词元记录范围与重复键，不依赖浏览器第三方解析包。只读依赖服务沿已有 World 快照与关系规则生成选项及依赖摘要，私有提案不持有 IO 或工具句柄。文档来源宿主在异步摘要和依赖重验后再次核对会话，并同步替换内存；独立 UI 只调用来源／检查／草稿端口。普通保存仍拥有持久化与外部冲突处理，具体运行能力仍属于原执行适配器。此链路是可移植 JS 实现，没有新增 Rust ABI、作者格式或运行权限。

首次创建另由 `world-behavior-create.mjs` 规划 `behavior.create`，复用 World／场景修订、声明及依赖规则，派生新行为登记并保真追加场景的唯一 `behavior` 边；通用 `relation.add` 的种类保持。稳定 UUID 由调用者持有，预览不分配磁盘文件。Node 宿主以登记锁和完整 World 再检查执行固定三文件事务，v9 日志区分两个新建目标与一个既有登记，按摘要验证后整体回退或补齐。恢复使用单独冻结的场景／脚本／角色定义证据验证，不解析当前只读依赖原文，也不恢复或覆盖这些依赖文件。构建区中的创建控制器只取得只读目录、该命令及已保存原文导航接口；创建不启动后端，后续参数编辑仍走独立草稿模块。


0.1.2 后增量的 `engine/scene-behavior-create-plan.mjs` 接收明确的场景、后端／语言以及已分配身份的绑定列表，调用既有 `inspectSceneBehaviors` 生成普通行为 JSON 和排序去重的脚本身份。它不读取文件、DOM、宿主或后端状态，也不分配 UUID。独立视图持有新增项身份和逐项表单，在切换、增删、重检时保护其余内容；一次审阅固定完整清单及依赖，事务仍负责同时写入新正文、新登记和原场景登记。一个实例可有多份行为，一份脚本可被多个绑定引用；参数与信号的后续修改继续经过原行为草稿宿主。已有绑定文档新增脚本引用另走独立管理入口，首次创建规划不取得既有登记的任意关联写权限。

已有行为目录由 `scripts/lib/scene-behavior-directory-service.mjs` 从一次受读取屏障保护的 World 快照取得：输入仅为场景 UUID，沿唯一显式 `behavior` 边核对完整清单和依赖，返回身份、相对路径、修订及脚本使用关系，不返回正文。没有关联时明确为空，多个关联、缺失或无效依赖阻止操作；不调用构建计划、渲染器或模板来猜测后端。候选是至多 256 份、每份至多 64 KiB 的已登记 TXT；实际绑定仍为 1–32 条、最多 8 份源码。

`engine/scene-behavior-directory.mjs` 捕获严格冻结目录，规划既有 `relation.add` 的 `references` 请求并核对命令回执，无文件、DOM、宿主读取或后端调用。独立 `app-scene-behavior-links.js` 只管理选择、审阅与结果确认；Node 事务保真追加一份行为登记，打开原文另经来源修订与编辑会话守护。随后绑定编辑只应用内存草稿，普通保存才持久化正文。该关联管理阶段保持当时的 20 模块／37 项声明能力，未新增 World 命令、模块、声明能力、作者格式或运行协议。

## 创作与交付的接口

脚本创建由 `engine/script-authoring.mjs` 的已知起始内容和私有提案、独立 `app-script-create.js` 界面及正文宿主 `scripts` 端口组成。`getContext` 提供文档会话、正文目录和类型目录；`createDraft` 重新核对提案品牌及完整上下文后同步建立普通 TXT 内存草稿。纯模块返回语言与后端标识，不读取文件、分配 UUID、执行源码或生成关系；持久登记继续走普通保存。该入口不改项目类型模板，不把 TXT 后缀当成 GDScript 语法识别，也不扩充现有 `behavior.create` 事务。

产品主路径为 **设定 → 投影 → 场景实现 → 组装打包 → 工程交付**。文档／字段编辑器、OC 投影表单和场景作者区负责基本创作；各自以来源身份、修订与候选检查衔接，磁盘持久化仍由普通保存或明确的作者事务负责。已保存 Scene2D 经中立计划、冻结输入和后端适配生成工程，交付只消费成功构建的登记清单。Composition 通过独立场景生成入口接到此链路：共享 Rust 展开、可移植创建规划与界面分离，现有 `scene.create` 负责新正文及登记事务。配方本身与 Scene3D 仍不直接进入 Scene2D 构建目录。

`engine/backend-project-delivery.mjs` 定义无 I/O 的审阅 DTO，绑定完整后端清单与精确摘要。Node 交付适配器重新检查登记、文件身份和字节，只生成清单登记的 `project/*`、`README.md` 与 `manifest.json`；独立校验器核对归档成员和校验和。清单中的原快照和运行证据摘要只是来源引用，原始输入、`build.json`、运行日志、缓存、工具与额外目录均不随包复制。包校验不创建作者工程、不认领缓存，也不取得运行或删除权限。

构建服务按构建 ID、预期快照与清单摘要准入，持有现有执行槽直到 ZIP 写入、最终复查及取消收尾结束，避免与构建回收并发。导出服务拥有临时包、读取者和到期回收；生成后下载只读冻结包，作者可以继续编辑。独立 `app-backend-project-delivery.js` 仅通过来源上下文、准备、检查下载和释放端口工作；它守护场景／会话／后端归属及原生保存结果，不取得作者保存接口。父构建面板只负责装配和忙碌状态，详情核对、选择运行与交付互不替代。

外部 IDE 与 LSP 将通过独立文档接口接入，当前没有实际 LSP 客户端或服务。后续契约需要明确文档 URI、语言、版本、来源范围、诊断以及带来源和版本前置条件的 `applyDraft`；内置视图和外部工具共同遵守作者草稿与保存边界。生成工程的外部修改不自动回写作者数据，语言服务也不取得任意文件或进程权限。

## 数据权威与生命周期

新建 v3 工程用 `workspace.json` 声明类型与布局，默认保存 `documents/`、`templates/`、`metadata/`、`assets/`。旧 v1／v2 工程继续走兼容读取与原有保存规则，不因应用升级自动改名或重排正文。

| 数据 | 权威来源与保留规则 |
| --- | --- |
| 文档内容 | 原文是标题、字段、叙事和场景声明的权威来源；布局、索引和 World 属性是解析投影 |
| 身份、关系与素材登记 | `metadata/` 保存稳定 UUID、逻辑路径、类型、归属／引用和资源用途绑定；名称和路径不充当身份 |
| 类型和起始模板 | 创建工程时复制完整定义与模板，实例此后自行维护；模板不会自动重写旧正文 |
| 素材字节 | 由登记中的逻辑存储定位；正文使用相对逻辑路径或 `asset:<UUID>`，本机外置位置留在 `.viento/local.json` |
| 派生索引 | 受管理工程的标准化文件和索引位于 `.viento/cache/`；Android 索引即时生成，均不作为作品权威内容 |
| 恢复状态 | `.viento/world-transactions/` 等意图和恢复记录参与一致性保障，不能当作普通缓存清理；活动事务阻止不一致的读取或导出 |
| 构建输出 | 写到作者工程和实际素材目录之外，默认使用应用构建缓存；保存输入摘要、生成物、工具版本和会话记录 |
| 本机偏好与草稿 | 与工程分开；Android 恢复草稿不等于作品备份，也不会自动进入完整迁移包 |

角色背景仍由角色正文或有明确 `part-of` 归属的附属文档承载；共享故事可以多归属。不能为对象化另建一份与原文竞争的可写属性库。

物理默认布局在 `scripts/lib/workspace-layout.json`，起始模板目录在 `scripts/lib/project-templates.json`。桌面和移动端创建工程时选择模板包，复制类型／模板并记录版本与摘要；缺少原始包不妨碍打开已创建工程。这些仍是文档实例模板，尚无可执行工程类型插件或模板包升级框架。格式与迁移见 [通用项目](GENERIC_PROJECTS.md)、[工作流](PROJECT_WORKFLOW.md) 和 [作品布局](WORKSPACE_LAYOUT.md)。

## 文档编辑与宿主存储

桌面作品库启动内置 Node 和 `scripts/desktop-server.mjs`，服务绑定本机随机端口，以每次启动的会话 Cookie、Host 和 Origin 校验隔离编辑器。浏览器编辑入口由 `scripts/ops/site.mjs` 启动；独立浏览服务不开放正文写入、项目配置写入和构建操作。

```text
工程清单 + 正文 + 登记
  → 标准化与静态索引 → 阅读器和列表

源码／分段／字段草稿
  → 文档接口 → engine/document-store.mjs
  → node-document-storage.mjs 或 Android Rust 存储
  → 修订检查、原子写入与登记 → 刷新视图
```

可编辑目录来自已验证的工程定义。桌面静态索引入口 `data/index.json` 与实时文档接口 `/api/index` 是不同读取路径；两者共享原文及登记约束。正文保存与索引刷新分开：保存成功后即使刷新失败，也保留保存结果并允许重试。版本冲突保留草稿，字段修改只替换可证明对应的原文范围。

Android 的 `mobile/platform.mjs` 复用引擎并通过 `mobile_storage` 传入作品 UUID 与逻辑源路径；Rust 核对 SHA-256 修订号、目录边界和共享锁，执行原子替换。创建文档另有持久化创建意图；恢复不覆盖已有的不同内容。媒体访问、World 命令与 Godot 构建没有因此自动获得移动端实现。

桌面关闭会检查未保存草稿，返回作品库可保留编辑窗口；Android 则按作品在 WebView 本机存储维护恢复草稿，两种保证不同。完整平台限制见 [桌面宿主](../desktop/README.md) 和 [Android 宿主](../mobile/README.md)。

## World 查询、语义命令与事务

`scripts/adapters/node-world-projection.mjs` 读取正文和登记，交给 `engine/world-projection.mjs` 生成 World／Object／Resource 观察快照。GUI、`GET /api/world` 和 `scripts/world.mjs` 共用查询实现。投影保留原文修订号与属性范围，只存在于内存；资源的 `present-unverified` 状态表示发现文件，不表示字节已验证。

```text
GUI / HTTP / CLI 语义请求
  → 可移植命令校验和原文变更规划
  → 预览提案，或 Node 执行器在共享锁内重新校验
  → 原子单文件写入，或持久意图 / 数据发布 / 提交决定
  → 回执与新投影
```

| 已实现动作 | 持久化范围 |
| --- | --- |
| `property.set` | 一个现有文档中的一个字段，保真写回原文 |
| `changeset.apply` | 多个现有对象的属性批量修改；当前每个对象一个字段，使用可恢复事务 |
| `object.create` | 一个新正文与其登记共同发布／恢复 |
| `projection.update` | 原位修改投影标题／配置、追加新图片绑定；version 7 意图守护正文与登记两个既有文件，保留来源／模板和额外元数据 |
| `projection.create` | 新建 OC 投影配置与来源／图片登记；子模板快照完整嵌入正文，version 6 意图仍限两个新文件 |
| `scene.update` | 原位修改场景、保留继承／覆盖语义，追加必要依赖；version 8 意图守护正文与登记两个既有文件 |
| `scene.create` | 复用已有工程类型，新建 Scene2D 正文及派生角色／图片依赖；version 5 意图仍限两个新文件 |
| `relation.add` | 保真追加一个引用或共享归属关系，重新校验端点和关系图 |
| `resource.bind` | 向既有登记追加素材用途绑定；允许保留离线资源身份，实际构建另验资源字节 |
| `world.recover` | 按已持久化的提交决定完成恢复，外部内容冲突时保留现场 |

Node 语义命令与旧文档保存共享登记锁。多记录发布先保存意图和前后镜像，以提交标记决定恢复到完整旧版或新版；读者在活动事务期间拒绝取得混合状态。World、旧编辑、资源包及 Node／Rust 完整导出遵守相应屏障。语义批次还不是任意混合命令事务，资源文件内容和 Build 不属于这些作者事务。

请求中的 `actorRef` 只是操作标签；HTTP 鉴权仍由宿主负责。语义命令描述不等于已接入远程 AI、Lese 或协作权限系统。使用、协议及恢复边界见 [World 投影](WORLD_PROJECTION.md)、[批量事务](WORLD_TRANSACTIONS.md)、[对象创建](WORLD_OBJECT_CREATE.md)、[关系](WORLD_RELATIONS.md) 与 [资源绑定](WORLD_RESOURCES.md)。

## 构建与运行

现有 2D 构建工作台是一条明确的 Scene2D 链路：场景 JSON 引用已登记角色 UUID 和图片，支持方向键输入与 `idle`／`moving` 状态。它不会从故事正文推断程序。明确关联行为清单的 v2／v3 场景可通过 Godot GDScript 或工作树 Bevy Rust 通道执行受限参数／信号绑定；Nuis 与其他执行语言尚未接入。

```text
已保存的场景、对象和登记
  → node-build-snapshot：读取屏障、修订复查、图片字节与摘要
  → engine/json-source：严格 JSON 值与原文范围
  → engine/scene-model：场景语义、投影继承、依赖与来源
  → engine/build-plan：按来源发射 v1／v2 几何计划；明确行为场景组合为 v3
  → engine/backend-capabilities：分别核对执行操作、平台、计划与功能需求
  → 可信宿主注册表／通用执行器：固定实现与输出验证
  → 所选适配器：Godot 生成／导入／脚本检查、Bevy 数据检查，或 Bevy Rust Cargo 源工程／离线编译检查
  → build.json + snapshot.json + source-map.json + 生成项目
  → 校验冻结产物并创建独立运行副本
  → 所选引擎的独立进程 → 状态事件、诊断、session.json
```

0.0.8 的[执行后端中间层](BACKEND_MIDDLEWARE.md)分开纯数据能力、可信宿主编排和具体引擎实现。描述符精确声明七种操作；Godot 4 支持构建、无头逻辑、独立窗口及窗口截图，Bevy 只支持构建和无头逻辑；两者离屏、内嵌视口和 GPU 均为 `false`。`node-execution-backends.mjs` 固定宿主注入的实现和阶段，`node-project-build.mjs` 不包含具体引擎参数、环境或生成文件名；资源映射采用中立 `resourceFiles`。输出相对路径、碰撞、入口和预算在发布前核对。HTTP 仅接收已有任务语义，不能传入后端代码或路径；CLI 和本机宿主选择已登记的后端，网页没有选择下拉框。

新构建／会话记录另有 `executionAdapter` 指纹，和旧生成器 `backend.sha256` 分别检查；已知 Godot 明确允许无新字段的旧记录，其余冻结检查不变。Bevy 不接受缺少适配器指纹的历史记录。原 Godot v1／v2 生成器和运行脚本字节、作者格式及无行为 plan／runtime 协议均保持。Godot 显式行为另用 plan／runtime 3，不复用旧协议承载新事件。服务返回平台、完整描述符及任务／产物后端身份，UI 按操作分别判断并在描述符变化时撤销旧批准。Bevy 以独立工具链验证第二实现，旧替代测试夹具仍只证明宿主接口可注入。

Bevy 适配器生成 `scene-data.json`，由单独预编译的可信 Rust 程序检查和运行。`engine/scene-runtime-events.mjs` 只处理与渲染无关的 plan 1／2 事件准入：实例／定义配对、有限坐标、运动状态及 ready／finished 生命周期；源码导航来自冻结计划，不能来自进程输出任意路径。Godot 保留自己的历史协议读取实现。这条数据链路不增加动态 Cargo 编译、BRP、反射或作者 Rust 行为。独立 `bevy-rust-adapter.mjs` 则只接无图行为 plan 3，`bevy-rust-project.mjs` 原字节复制 TXT 并生成 UUID 分派，`bevy-rust/` 模板提供类型化上下文、ECS 就绪与固定步回调：每个绑定只操作自身实例，单次成功才提交候选位置与事件，累计预算覆盖完整运行。固定步回调的调度和错误处理留在运行实现，通用宿主继续只处理冻结计划、工具、进程与既有事件协议。编译／运行阶段由适配器在作者目录外维护临时 Cargo home 与 target，复用预缓存 registry 并使用 `--locked --offline`；源码工程清单只记录可迁移源码。两条通道分别核对工具和适配器身份，具体边界见 [Bevy 后端](BEVY_BACKEND.md)。

场景预览从相同冻结快照读取可移植计划，`scene-preview-service.mjs` 提供有限期的图片字节，`app-scene-preview.js` 和 Canvas 视图消费有效字段。预览与构建任务使用独立生命周期，读取和查看无需启动引擎或写入作者数据。捕获结果在冻结 `snapshot` 外另外携带 `sceneEditing`、`sourceLocations` 和 v3 的 `sceneStructure`：前者提供场景原文及 World／对象／正文修订，后者为场景、对象定义、场景声明与有效字段提供来源。`sceneStructure` 只携带组织分组与实例归属，`scene-structure.mjs` 严格验证后供视图使用，不进入计划或快照容器。预览服务复制这些编辑信息，本身不承担保存。

原文草稿预览使用独立入口 `captureSceneDraftPreview`。`engine/scene-draft-preview.mjs` 限定 128 KiB UTF-8、注册场景路径和原始正文基线，在克隆的只读观察中替换单份原文并重新派生 World 投影；登记记录、关系和资源绑定不变。Node 冻结层核对同一读取屏障、图片摘要和前后修订，草稿成功／失败均复查基线。返回独立域的预览摘要及 `draft` 来源信息，不产生可执行构建快照或 `sceneEditing`；`captureBuildSnapshot` 始终读取磁盘保存版本。

界面从主编辑器的原文保真序列化器取得草稿及基线。候选模型与图片完成后才替换上一有效结果，解析失败保留旧画面并标明来源；同场景返回编辑器再打开可继续草稿模式，切场景／切保存模式／销毁清理缓存。请求和精确来源定位核对场景、编辑会话、草稿令牌和内容摘要，异步旧响应不能覆盖新编辑。草稿定位只选择当前编辑器的原文本，不重读文件；保存来源继续使用原读取流程。预览服务本身保持只读；当前文本草稿的布局回写通过另一个本地接口接入，不提升预览结果的 World 保存权限。

```text
当前单场景源码草稿 + 有效草稿预览
  → Rust sceneSource.inspect：严格 JSON、稳定身份／坐标／分组检查
  → scene-source-layout：核验路径／基线／原文 SHA-256、模型与分组侧带
  → scene-layout 的共用几何会话 → Rust LayoutDraft：位置、100 批次历史
  → Rust sceneSource.patch → propose：仅变化坐标的精确数值 token 补丁
  → 主编辑器：复核 sceneId／会话／源码模式／完整原文，再应用到内存
  → 普通文档保存：沿用原版本与冲突检查
```

`engine/scene-source-layout.mjs` 不接收或制造 `sceneEditing`、World 修订或事务命令。源码的严格 JSON 检查与坐标数值补丁已迁入 Rust 的无状态 `sceneSource.inspect`／`sceneSource.patch`；JS 负责解码、预览元数据匹配、摘要和编辑会话归属。`createSceneSourceLayoutDraft` 在注入的摘要函数返回后绑定已分离的输入；`patchSceneSourcePositions` 调用 Rust，仅替换变化的数值 token，不从有效角色重建作者声明。Rust 内部按 UTF-8 字节范围修改原文，范围不持久化，也不取代导航使用的 UTF-16 来源映射。原文前后均限 128 KiB UTF-8，JSON 预算沿用 64 层和 100000 个值节点；检查 v1／v2／v3 的 1–128 个角色身份与位置、v3 的 0–128 个组和 16 层组织关系。字面孤立代理字符、解码重复键、身份歧义和不一致的分组侧带被拒绝，合法未改 token 的原写法保留。`prepareSceneSourceLayoutApply` 重新计算补丁并核对完整候选正文与来源摘要；宿主在异步返回后再次复核当前编辑会话、路径、场景身份、原文及编辑会话持有的保存基线，才替换内存中的源码。应用过程不读磁盘；外部文件变化不阻止本地补丁，之后的预览基线校验及普通保存的原版本条件分别拒绝过期预览和覆盖写入。

本地布局和保存版布局共用 `createSceneGeometryDraft` 及既有 Rust 协议；本地会话不暴露 `command`、`beginSave` 或保存阶段接口。UI 的本地操作归属独立于 World 写入忙碌状态，取消不碰主编辑器草稿。成功应用保留主编辑器的旧保存版本并重新比较 dirty；未保存修改重新预览草稿，恰好回到原基线则显示保存态，不触发 `scene.update`、索引重建或构建。它限定当前已登记场景的源码模式，没有跨文本／表单／布局的统一撤销栈或多文件提交。

共用 `engine/json-source.mjs` 以 `JSON.parse` 决定语法和值，再用无第三方依赖的词元扫描取得范围、预算和解码重复键信息；扫描不重新解释 JSON 值。此前源码布局已把严格检查与数值补丁迁入 Rust，并撤去专门的 YAML 包目录静态入口；当前行为编辑可直接复用轻量 JS 索引，无需为浏览器开放 `node_modules`。通用 YAML 文档解析与移动端既有 `/vendor/yaml/` 支持保持，JSON 索引的实现替换不删除 YAML 格式支持。范围为原文含 BOM 的 UTF-16 半开区间，附 JSON Pointer、是否精确以及正文 SHA-256 修订。索引限制为 8 Mi UTF-16 单元、64 层和 100000 个值节点，Node 读取另有字节限制；索引只保留在私有 WeakMap。解码后重复键在运行规划中拒绝，避免构建与保真保存解释不同；仅 v1 旧事务登记恢复保留 JSON 最后键语义，不提供歧义范围。v1 新索引预算或范围构建失败仍可使用旧 JSON 语法门槛恢复，宿主既有大小屏障继续生效；v2／v3 从首次接入即严格拒绝重复键和超预算索引，包括恢复。两种恢复模式均不解析当前投影正文。

`engine/scene-model.mjs` 解析场景字段、投影有效值和资源依赖，输出与声明对应的 `viento-scene-model` v1／v2／v3。`scene2DModelToPlan` 只发射 v1／v2 几何计划，作者 v3 也发射 plan v2 并剔除组织分组字段；显式行为由上层 `createScene2DPlan` 另行组合为 plan 3；已有 v1／v2 DTO 保持原样；来源范围独立于冻结计划，因此既有有效 v1 快照和生成文件保持一致。声明位置属于场景修订，继承字段属于投影修订；宽高分别映射配置项，合成尺寸只有近似容器位置。缺失字段也只返回最近容器提示。

场景预览的字段按钮将完整位置传给主编辑器。编辑器先读取当前正文并核对摘要，再把原文 UTF-16 偏移转换为 textarea 的 LF 偏移并选中精确值；正文变化、近似范围或无法定位时显示说明。已有未保存草稿及光标保留，过期异步读取不能改动后来打开的文档。普通文档链接继续可用，这条链路不写作者文件。

保存版 `createSceneLayoutDraft` 核对原声明与解析角色的身份、顺序和中心位置，再通过 `engine/scene-layout.mjs` 的共用几何会话创建 Rust 位置草稿。v2／v3 使用 `instanceId` 选择实例，保留作者 `objectId` 作为定义引用；适配器将实例 UUID 传入 Rust 协议名为 `objectId` 的不透明几何键。这组几何／历史操作仍只解释不透明键；另设的 `sceneSource.*` 才检查受限的 Scene2D 源码结构，不读取登记关系或修改旧操作的协议。`setPositions` 在 Rust 内完成整个批次的校验、原子更新及最多 100 批次的撤销／重做；JS 接收当前位置和状态快照。拖动、方向键微调和对齐各形成一个可整体撤销的批次。候选声明仍从原文解析结果复制，只替换已有角色的 `position`，保留继承、局部覆盖、明确去图和可选字段省略。

`engine/scene-layout.mjs` 的几何入口通过 `studio-core.mjs` 调用 Rust/WASM 核心，原有 JS 几何算法已移除。Rust 为所选对象计算共同位移；吸附以实际抓取对象的中心为锚点，坐标上限限制整组位移，保持相对间距。`alignSceneSelection` 使用已解析的有效尺寸形成选择集整体外接矩形，按其侧边或中心计算六向对齐，非法结果整批拒绝。`app-scene-preview-canvas.js` 复用这些几何规则，拖动中的位置只用于临时绘制，结束时提交一次位置批次；Esc、捕获丢失或模型／选择变化取消临时移动。视图平移与缩放独立于作者坐标。

多选仅在布局编辑器启用，已保存场景的预览保持原有单对象检查。布局的选择集与主选对象保留在页面内存，支持组合键、列表复选框以及全选／清除，不进入作者声明、归档或构建输入。X／Y 输入只在单选时显示，多选通过整体移动与对齐修改位置。批次草稿保留输入的 Scene2D v1／v2／v3 声明版本；保存版使用同一 `scene.update`，原文草稿版只提出坐标补丁；v2 选择与撤销分别作用于独立实例。v3 的组织分组保留在声明中；分组选择先展开为后代实例 UUID，Rust 仍只接收实例几何键。workspace 格式不变。

保存版 `web/modules/app-scene-layout.js` 流程管理拖拽、坐标输入、历史操作入口和明确的检查／保存步骤，撤销与保存阶段由 Rust 草稿提供，界面保留审阅正文和异步请求归属。检查调用 `scene.update` 的预览模式并展示实际候选原文，保存沿用同一修订基线与第 8 版事务；有效位置修改或开始输入都使前次检查失效。冲突保留输入，结果未知时暂停重试写入，通过只读 World 与原文核对场景身份、路径、修订和完整声明后确认结果。保存成功使旧构建计划失效，刷新失败单独报告。布局草稿及忙碌状态加入页面离开和桌面关闭检查，草稿仍只存在于当前会话内存。预览和布局草稿都是静态设计状态，运行语义仍由后端执行。

后续场景创作以结构化、类似剧本的文本为主要入口，实施顺序见 [文本驱动场景路线](ROADMAP.md#文本驱动场景的实施顺序)。当前已接入“OC 定义 → 用途投影 → 多个独立场景实例”的平面关系；实例身份与原对象身份分离。可嵌套的组织分组已接入，预览和布局大纲复用纯引擎的树与搜索结果，组来源可定位原文。文件内复用片段另有独立组合实验；配方已复用普通文档保存与依赖迁移，并支持已保存／未保存原文的只读预览和贡献来源定位；当前源码配方可通过单实例覆盖对话框生成精确原文草稿补丁，再由普通编辑器保存；0.0.10 源码另接单实例恢复继承与独立位置画布；共享演员六字段 SET-only 已另行接入；共享演员增删、整份放置管理和组织组创作已通过各自独立能力接入；空间变换层次、嵌套／跨文件复用和事件流程仍需另定语义。文本原文仍是持久权威，解析／展开结果和引擎工程都是派生数据。

Scene2D v2 在扁平 `actors` 中要求唯一小写 UUID `instanceId`，同一 `objectId` 可以出现多次；实例数量仍为 1–128。保真编辑匹配、布局选择与历史、来源映射、构建节点及运行事件均区分实例与定义。定义参与诊断和资源包依赖时按 `objectId` 去重，实例不另建 World 对象。新建表单默认 v2，旧场景只在显式启用并保存后升级：已有实例以旧对象 UUID 初始化，新复制的实例分配新 UUID；不以数组下标或显示名称决定身份，当前拒绝 v2→v1 降级。

`godot4-dispatch.mjs` 按计划版本选择原 v1 生成器或 `godot4-instances.mjs`／`runtime-v2.gd`。v2 来源映射与运行协议同时携带 `instanceId`、定义 `objectId`，接收端核对配对关系；重复定义不能折叠为一个运行节点或状态。原 v1 生成文件与生成器摘要保持兼容。预览版本随计划，冻结快照容器及构建／会话记录仍用现有版本。兼容保证是新代码能读取旧数据和产物；旧客户端的普通原文编辑仍可能接触新格式，并不保证所有旧入口都只读。

作者 v3 的持久组织层次由 `scene-groups.mjs` 验证：最多 128 组、16 层，身份、父组和实例归属严格核对。`buildSceneOutline` 提供确定顺序、保留祖先的搜索结果及后代实例列表，`app-scene-outline.js` 只负责 DOM、焦点、折叠和选择。组织层次不改变绝对坐标与 `actors` 绘制顺序。单场景源码与布局的坐标回写已接入；文件内片段已有下述独立实验 CLI、配方预览和单实例覆盖草稿编辑；共享演员增删、整份放置和组织组创作已有独立原文编辑接口；空间变换、剧本事件、多文件草稿及跨视图统一撤销仍未实现。源码布局所需的严格结构、身份／位置／分组检查与坐标补丁已迁入 Rust；完整模型、投影继承、依赖、来源导航和 World 规划仍在 JS。后续片段或共享草稿必须保持明确写回目标，避免单实例覆盖反向改动全部共用定义。

0.0.8 的[行为绑定](SCENE_BEHAVIORS.md)在场景几何与执行后端之间增加独立的作者清单。`scene-behaviors.mjs` 严格校验 `viento-scene-behaviors` v1、注册关系、稳定实例、源码和标量声明；`build-plan.mjs` 只为明确关联清单的场景组合 plan 3。源码和清单进入保存态快照，重放时从冻结原文重建同一计划。World v1 的 `behaviorBindings` 仍为 `[]`，不新增 World 对象类型或 workspace 格式。

Godot 适配器把 TXT 源码复制为按 UUID 命名的 `.gd` 文件，逐份编译，再为每个绑定创建独立 Node。导出参数和映射信号由真实反射检查；protocol 3 事件只能带已批准绑定的实例／定义身份及至多四个类型化标量。编译错误映射回 TXT，参数错误映射回清单 JSON Pointer，精确范围由冻结原文补充；界面只显示 DTO 与日志。选择式资源包重新派生并验证清单的场景／源码闭包，完整备份保留未完成正文。静态预览仍只生成几何计划，不校验或执行行为绑定。

当前每个绑定独立实例化，不反复替换场景演员脚本；参数注入和信号连接先于激活，运行事件核对 ready／finished 生命周期。脚本在 Godot 进程以用户权限运行，这不是沙箱；源码不进入 GUI 执行。当前通用参数与信号表单只编辑已有行为声明；尚无任意方法 RPC、热重载、状态机、运行值回写或脚本导出属性自动发现。C# 暂缓；Bevy 数据通道只消费无行为计划，新增 Rust 通道以独立身份接入就绪及固定步自身位置回调，不获得旧有限输入回放能力。Nuislang／ns-nova／yalivia 继续单独实现与验收，共享身份契约不承诺源码互译。选型与旧隔离探针仍保留于[构建文档](PROJECT_BUILD.md#行为绑定选型历史预研)。

`web/modules/app-scene-create.js` 共用创建／编辑场景表单，按字段维护投影继承与显式覆盖，提供实例复制、重排、分组管理和旧场景显式升级。`engine/world-scene-create.mjs` 和 `world-scene-update.mjs` 复用 Scene2D 规划器；宿主分别执行第 5 版创建和第 8 版更新事务，既有原文／字段编辑器继续可用。

`object-projection-template.mjs` 提供无解析器依赖的 OC 子模板继承、快照锁与配置规则，供浏览器直接导入；`object-projection.mjs` 负责正文识别及依赖验证；`world-object-projection.mjs` 规划创建，`app-object-projection.js` 提供表单。World 汇总同一 OC 的不同投影；场景可按投影运行映射继承配置，Build 保留投影 UUID 和原 OC 的来源身份。引擎适配器消费已解析值，不读取内置模板目录。见 [投影契约](OBJECT_PROJECTIONS.md)。

`web/modules/app-project-build.js` 提供 Linux 本机编辑器面板；`scripts/lib/project-build-service.mjs` 管理跨 HTTP 请求的任务、进度、取消和本次服务登记的产物 ID；CLI 调用同一 Node 构建／运行适配器。面板关闭后任务继续，重新打开可以观察。计划检查返回快照身份，面板构建以该身份拒绝过期输入；未保存草稿不会被静默加入构建。

当前运行对象来自 `engine/scene-runtime-query.mjs` 的分离观察 DTO，通用执行器在冻结构建全部验证后才建立它，任务视图独立于原始事件环。服务的 inspect 仅查询当前 owned run，UUID 过滤不变为引擎反射请求；`app-project-build.js` 检查任务／构建／快照归属，再本地检索和返回冻结声明。采样、取消与来源边界见[运行对象](RUNTIME_OBJECTS.md)。

宿主通过 `VIENTO_EXECUTION_BACKEND` 固定已登记的后端，再使用对应的 `VIENTO_GODOT_BIN`、`VIENTO_BEVY_BIN` 或 `VIENTO_BEVY_RUST_CARGO` 配置工具；未设置时默认 Godot。`/api/project-build` 限制回环连接与本机 Host／Origin，POST 沿用写鉴权；浏览器不能指定任意二进制、环境或磁盘输出目录。远程绑定的编辑服务、只读浏览服务与 Android 不提供执行能力。

构建记录固定输入、适配器与真实工具的版本／摘要，运行前重验生成文件，并从冻结产物创建隔离副本。运行节点与作者 UUID 的映射只保存在生成记录中，运行值不会自动改写原文。进程输出有界，取消、超时、SIGINT／SIGTERM 和桌面 owner 关闭会回收引擎；运行工作副本与引擎缓存随后清理。强制杀死宿主或断电后的会话恢复仍未实现。

产物仍需要对应本机工具：Godot 生成工程需要 Godot，Bevy 数据工程需要固定运行程序，Bevy Rust Cargo 源工程需要匹配工具链和锁定依赖；均非独立发行程序。无头测试只验逻辑，Godot 正常窗口预览验图形路径；Bevy 图片／窗口、内嵌运行视口、原生 GPU 计算、Live Build 与 Nuis／yalivia 仍是后续工作。参数、使用和验证入口见 [构建与运行](PROJECT_BUILD.md)。

## 共享 Rust 核心的运行边界

当前 `viento-studio-core` 只依赖序列化库，协议第 1 版保留 `move`、`align`、`validateBatch`，并增加 `layoutDraft.create/setPositions/undo/redo/reset/read/close`。Rust 的独立 `LayoutDraft` 持有初始位置、当前位置及最多 100 个批次的撤销／重做历史，判断 dirty；错误批次和无变化操作保留原状态与 redo。这些布局操作只接收身份、坐标、尺寸及操作参数。新增的无状态 `sceneSource.inspect`／`sceneSource.patch` 接收有界场景正文和位置修改，执行严格 JSON 扫描、源码几何结构检查与精确数值补丁；不创建草稿、不访问文件或 World，也不接收素材字节、路径或凭据。原生 CLI 用于复现和跨目标对比；编辑器实际执行的是同一 crate 的 WASM，尚未新增 Tauri 原生命令。它与独立 `viento-bevy-runtime` 是两个 crate，编辑核心不加载 Bevy 或渲染器。

`engine/studio-core.mjs` 只处理协议与内存边界，宿主通过 `initializeStudioCore(loadBytes)` 注入加载函数；浏览器适配器 `app-studio-core.js` 负责受限 HTTP 加载，Node 适配器 `node-studio-core.mjs` 负责文件读取。核心桥接不导入宿主模块。WASM 由适配器初始化一次，后续同步调用，拖拽无逐帧 IPC。缓冲由 Rust 持有，单条请求上限 1 MiB；桥接校验协议、缓冲范围及返回结构，各操作域独立校验。原协议版本及布局／保存操作保持兼容；可选 `viento_core_scene_source_version() === 1` 导出声明源码检查／补丁的支持，缺少该能力的旧核心仍可使用旧几何和历史，源码布局明确拒绝执行，不回退 JS 补丁。加载失败保留阅读和静态预览，布局编辑显示错误，无第二份 JS 算法回退。HTTP 只增加固定核心文件的静态入口，CSP 使用 `wasm-unsafe-eval`，不开放普通 JavaScript `unsafe-eval`。移动资源包含同一核心，但这不会自动启用 Android 场景工作台；设备支持仍需实测。

`npm run core:build` 在开发／打包时生成 `engine/studio-core.wasm` 与摘要记录，`check`、`start`、桌面和移动资源准备均接入此步骤。生成物不进入 Git；缓存按源代码及 WASM 摘要复核，安装包直接携带产物，运行时无需 Cargo。核心 crate 编译目录与生成文件纳入既有清理命令。WASM 目标及 CSP 的依据见 [Rust 编译目标](https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html) 与 [WebAssembly CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src#unsafe_webassembly_execution)。

原生 JSON-lines 适配器与每个 WASM 实例通过受限草稿表使用同一实现：每个线程／实例最多 32 份草稿，每份沿现有 Scene2D 上限接收 1–128 个对象。句柄是单调递增、不会重用的十进制字符串，不充当授权或持久身份。每次只返回当前位置和状态快照，历史不经 JS 往返；关闭、取消、重新读取以及打开失败会释放草稿。WASM 输入只消费一次，重复执行旧缓冲不会重复创建或撤销。

`engine/scene-layout.mjs` 的保存版适配保留作者原文、继承字段和修订前置条件；原文草稿适配由 `scene-source-layout.mjs` 负责。两者共用 Rust 几何会话，只缓存返回的视图快照，不独立维护位置历史或 dirty 比较。草稿仍仅驻留内存，关闭或重启不恢复。保存阶段、错误分类和重复请求门禁由独立 Rust `LayoutSaveWorkflow` 管理，见下方流程。源码布局的严格结构检查与数值补丁已由 Rust 执行；完整作者语义解析、回执内容与摘要校验、只读核对的 World／正文读取、实际保存事务及构建规划仍由 JS 及宿主适配承担。后续迁移顺序见 [Rust 核心路线](ROADMAP.md#studio-核心与界面解耦)，每次迁移都保持现有文件格式和事务兼容。

### 源码检查与坐标补丁

`sceneSource.inspect` 和 `sceneSource.patch` 每次重新扫描输入，保持 stateless，不占用布局的 32 个会话槽位。扫描器按解码后的 UTF-16 键检查整份 JSON 的重复字段，但只解释此操作需要的版本、身份、位置与组关系；未涉及的数值和字符串 token 不经全文反序列化／重排后写回。未变的指数、负零、超出浮点范围的其他字段、转义字符串、BOM 和 CRLF 保留原字节；变化坐标使用与既有 JavaScript 补丁一致的数值表达。组名长度继续按 UTF-16 单元计数。inspect 仅返回来源版本与角色数；patch 返回候选正文和 JSON Pointer 列表，不返回可复用的作者存储句柄。

该检查不替代完整 `Scene2DModel`：标题、视口、投影继承、资源和关系仍由原 JS 模型验证，保存态事务及 v1 历史恢复继续走原路径。兼容对照和执行范围见 [Rust 源码补丁验证](test-results/rust-scene-source/results.json)。

### 配方创作区与宿主接口

九个配方编辑区通过 `app-scene-authoring.js` 独立连接来源、目录、HTTP 预览和导航接口。`scene-authoring-workflow.mjs` 只消费注入的状态与操作，不读取构建目录、运行任务或页面；每入口保持独立回执，并只向自己的控制器暴露六个来源字段及一个能力标志。`scene-authoring-candidate.mjs` 负责固定操作语义的候选信封／目标来源检查，没有宿主 I/O。构建父窗口仅提供当前归属和处理成功导航，主编辑器保留最后来源复核、内存应用、保存基线与普通保存。详情见[场景创作工作流](SCENE_AUTHORING.md)。

这次拆分未统合各视图的选择、局部历史、审批状态或撤销，也未改变 Rust／WASM、配方格式、执行后端和 World 事务。后续面板与工作流交互可逐区调整；纯流程的成功通知与界面焦点行为分开验证。

### 文件内片段组合实验

0.0.8 的 `sceneComposition.expand` 接受单份配方原文，由 `scene_composition.rs` 执行严格 JSON、片段／放置／身份／覆盖与展开预算校验，返回普通 Scene2D v3 及独立来源映射。原生与 WASM 共用实现，可选 `viento_core_scene_composition_version() === 1` 能力导出使旧协议 1 核心继续支持原操作。组合无状态、无宿主依赖，不创建布局会话，不读写工程或分配随机身份。

`engine/scene-composition.mjs` 是可移植同步入口，`studio-core.mjs` 守护操作与响应，并检查每个贡献指针的模板／演员覆盖／放置／组引用归属。Node 的 `scripts/scene-compose.mjs` 提供至多 128 KiB 的普通文件读取，或通过 `readWorldSnapshot` 按 UUID 读取已登记配方；处理原始字节 SHA-256、可选修订守护和 stdout 输出。配方内每次放置明确保存局部键到演员／组 UUID 的映射，顺序变化不重建身份；覆盖先合并，位置再加偏移，输出仍受 128 实例、128 组及 16 层限制。来源以 JSON Pointer 记录声明、身份映射及字段贡献，合成坐标可包含模板／覆盖与偏移两个来源，不伪造精确字符范围或反向写回权限。

纯组合只检查声明。`scene-composition-document.mjs` 按当前正文顶层格式识别普通已登记 JSON 文档，在 Rust 校验后收集全部模板和覆盖的定义／图片依赖，并只读检查 self、嵌套配方、缺失来源和图片类别。配方登记、原文保存及冲突沿用现有文档机制；未完成原文可保存与完整备份，派生边不写回元数据，删除顶层格式标记后退出配方处理。

资源包目录把派生边与手工关系／素材引用合并，并把当前原文指纹纳入 revision；包读取器和导入计划从实际字节重新派生引用，要求相应文档／素材在包内或按类别和指纹锁定为 requirement。目标恰有同 UUID 内容不能补足包内遗漏，现有依赖的源码在规划／提交期间仍受指纹和变化检查。没有新增 World／journal 命令、workspace 或资源包格式；完整备份仍保留原始作者文件。

定义的投影有效值及生成场景依赖登记继续由已有模型和 `scene.create` 核验。生成 v3 单独登记后走原计划及 Godot 构建，编辑它不会回写配方。已登记 CLI bundle 的 `origin` 描述文档身份、相对源路径和 World 修订，仅是读取来源。当前源码配方的单实例覆盖、恢复继承、共享演员字段与结构、放置偏移、整份放置及组织分组管理走独立草稿补丁；嵌套／跨文件复用及多文件提交尚未接入；详细契约见[片段组合](SCENE_COMPOSITION.md)。

`scene-composition-preview.mjs` 为配方提供纯只读模型入口：对有效 workspace v2／v3 观察读取 recipe v1，检查全部声明依赖，在内部克隆中展开为 v3，将临时派生关系／绑定与作者原有登记合并，再复用 `resolveScene2DModel`。未保存原文先经既有 `overlaySceneDraftPreview` 核对同一保存基线；没有新 World 命令、journal 或核心语法。内部观察不返回宿主，输出只有模型、诊断与小型配方来源描述；World 修订和场景来源摘要恢复为有效的作者观察。

配方来源重映射覆盖场景标题／视口／背景、演员／组声明、字段和诊断。模板、覆盖、偏移和身份映射分别带真实 UTF-16 位置；多贡献字段的主位置为近似范围，独立贡献项才能精确选中。继承字段继续保留投影定义的来源与修订，生成 `/actors/N`、`/groups/N` 和生成摘要不会充当作者位置。位置只授权导航，不能转为 `sceneEditing` 或布局写入。

Node 的预览捕获对保存态和草稿配方都返回独立预览身份与冻结图片，不返回可执行 snapshot；源读取及资源摘要仍由既有前后快照／fence 核验。构建工作台区分可构建 Scene2D 与可预览文档，配方仅进入后者。前端复用画布、大纲和修订守护定位，展示贡献按钮；配方的普通 Scene2D 表单／布局保存和构建入口保持关闭，当前源码的单实例位置画布另走下述覆盖提案。失败草稿保留最后有效画面与其独立来源修订。

单实例覆盖另设 `sceneComposition.patchOverrides`，用独立可选能力导出，不改变展开和 recipe／World 协议。Rust 在完整校验前后原文及展开预算后，按稳定 `placementId` 与局部 `actorKey` 仅设置 position／size／color／speed／controls／imageResourceId；复用 scanner 的字节范围和数值序列化，保留未改原字节，必要时插入字段或覆盖容器。无状态操作不读取工程或创建历史会话。桥接验证回执目标、固定顺序真实路径与唯一语义变化，并经核心重新展开拒绝重复键等原文异常；坏回执禁用运行时，缺少新能力只关闭该入口。

恢复继承使用独立可选的 `viento_core_scene_composition_edit_version() === 1`，通过 `supportsStudioCoreCompositionEdit()` 门控新 `sceneComposition.editOverrides`；旧 set／expand 探针及请求保持。`resetFields` 与 set 的 `values` 使用同一六字段白名单，重复或交集拒绝；原生与 WASM 原子产生相同候选。位置和尺寸成对删除，偏移仍作用于恢复后的局部位置；图片字段删除与显式 `null` 分开。最后字段删除时移除目标演员覆盖条目，保留 `overrides` 数组，其他身份和顺序不变。桥接调度结束后严格重验原输入及输出，避免恶意回执通过删除非法条目来伪造合法原文；不会嵌套调用 WASM 缓冲接口。

`scene-composition-overrides.mjs` 绑定有效预览、作者原文和保存基线；异步摘要前分离输入，提案只写实际改动字段，并从 set 中排除选中的恢复字段，准备应用时重新检查来源和精确核心回执。Web 独立对话框编辑偏移前局部坐标与有效显示值；恢复时保留输入但禁用相应字段，取消恢复可继续编辑。检查阶段通过原预览服务重新解析继承、验证完整模型、依赖和真实图片，GUI 不推算继承值。恢复选择进入 dirty、表单签名和审阅批准守护；即使有效值相同，删除源码覆盖仍需检查。父控制器与主编辑器在内存应用前再次核对当前源码会话／修订，应用后由普通保存处理持久化和外部冲突。取消不动原草稿，迟到响应不能写入；来源导航、预览元数据或生成坐标都不能直接授予写权限。没有新 World 命令、元数据回写、共享模板修改或跨文件事务。

`scene-composition-layout.mjs` 复用上述原文／完整模型绑定，再通过 `createSceneGeometryDraft` 创建仅含一个固定实例 UUID 的 Rust 会话；渲染 DTO 仍返回其他演员的冻结副本。世界位置在纯适配器中减去作者放置偏移，`propose()` 只输出旧覆盖提案中的 `position`，`prepareSceneCompositionOverrideApply` 沿旧链重算精确候选。未动轴使用原局部值以避免浮点逆减漂移；局部与展开位置各限 ±100000，非法输入／其他 UUID 在修改几何、dirty 或历史前拒绝。移动、吸附、100 步历史继续由现有 Rust 实现，无新增 Rust／WASM 源码或协议；退出及失效打开释放同一有界会话。

`app-scene-composition-layout.js` 提供独立单实例对话框，显示完整场景作参照，固定可移动 UUID；`app-scene-preview-canvas.js` 的可移动实例门禁覆盖指针与方向键，默认仍兼容普通场景布局。位置输入使用展开后的中心坐标，局部位置和偏移只读显示，检查与应用期间锁定编辑，任何移动、数值输入或撤销使批准失效。`app-project-build.js` 复用配方候选预览／图片校验及主编辑器内存应用，保存仍走普通文档流程；不会把派生 `/actors/N` 交给普通 `sceneSource.patch` 或 `scene.update`。该单实例入口没有多选或对齐；独立批次入口另见下述边界。两者都不修改偏移、共享模板或跨视图统一历史；恢复位置继承继续使用独立覆盖表单。

批次位置另由 `scene_composition_patch.rs` 的无状态 `sceneComposition.patchPositions` 处理，独立可选 `viento_core_scene_composition_positions_version() === 1` 与 `supportsStudioCoreCompositionPositions()` 门控 `dispatchStudioCoreCompositionPositions`。请求只含协议、操作、原文和 1–128 个 `{ placementId, actorKey, position }`；严格拒绝重复／未知目标和其他字段。Rust 用同一次扫描定位全部字节范围，按作者放置及片段演员顺序组合替换和新增容器，再完整验证最终展开及 128 KiB 预算；不按多个单实例请求逐个改写，不留下部分成功正文。旧 set／edit／expand 域及探针保持，缺新能力只拒绝批次操作。桥接独立核对全部目标语义及规范路径，伪造非目标改动或恶意回执使运行时不可用。

`scene-composition-batch-layout.mjs` 从分离的当前原文和完整有效预览核对全部实例／放置／局部键及组织侧带，再创建一个已有 `createSceneGeometryDraft` 会话。移动／吸附和按有效尺寸六向对齐继续由 Rust 几何完成，每批在更改历史前分别检查各目标场景坐标和逆偏移局部坐标，任一越界时保留全部位置、dirty 与 redo。最多 100 步历史不分散到多个实例会话，释放仍幂等。未动轴保留基线局部值，`propose()` 只按作者顺序携带净变化目标和完整候选；`prepareSceneCompositionBatchLayoutApply` 重验来源、保存基线、全部身份、规范顺序和精确补丁。

`app-scene-composition-batch-layout.js` 是独立对话框，复用大纲的搜索／分组后代选择和画布多选；组织侧带通过 `sceneStructureActors` 合并给列表，不从平面运行 DTO 猜组。选择仅属于当前视图，可以在完整候选检查后换选而保留批准；原始字段签名仍阻止静默数值变动绕过检查。未完成数值输入锁定换选／移动／对齐，第一次撤销只回到显示的有效位置；检查和应用期间锁定所有作者操作。对话框持有独立图片副本，关闭、失效打开和销毁均释放副本及 Rust 会话。父预览归属不绑定批次内选择，宿主完整检查所有目标及真实素材后，仅在最后一次 live 来源守护成立时替换当前原文内存，普通保存继续处理写盘及外部冲突。无共享片段写回、偏移编辑、其他字段批次、跨文件提交或跨视图统一历史。

共享片段演员声明另设可选 `viento_core_scene_composition_fragment_version() === 1`／`supportsStudioCoreCompositionFragment()` 及独立 dispatcher。`sceneComposition.patchFragmentActor` 只接受现有 `fragmentId`／`actorKey` 和 position／size／color／speed／controls／imageResourceId 的非空设置子集，不接 reset、remove 或结构改变。Rust 复用严格 JSON 扫描及保真字节编辑，原子更新共享声明后完整展开所有放置，核对每个局部／偏移后坐标及最终 128 KiB 预算；未变字段、局部覆盖、UUID、组和继承开关不动。旧 expand／set／edit／positions 域拒绝新操作，缺 probe 只关闭共享字段入口；坏回执不能授权修改非目标语义。

`scene-composition-fragments.mjs` 在首次摘要 await 前分离模型及原文，绑定选中实例对应的共享声明与完整来源，返回 raw-only 已声明值及按作者顺序排列的全部 `{ instanceId, placementId, overrides }`。`propose(selectedValues)` 只携净源码变化，缺失声明明确添加相同有效值仍有效，全部引用被覆盖掩蔽时也允许声明变化；null 图片只在开启投影继承时有效。`prepareSceneCompositionFragmentApply` 重新核对来源摘要、保存基线、完整引用集合／顺序／覆盖列表和精确补丁，拒绝遗漏、伪造或异步变动的回执。纯模块不读素材，不写作品，也不持有几何会话。

独立 `app-scene-composition-fragments.js` 只用声明初始化表单，缺失值留空，每字段明确勾选才启用并发送；位置和尺寸各按一对处理。影响列表逐实例区分净字段变化与局部覆盖优先，全遮蔽明确提示只修改模板原文。图片清单由父预览沿现有只读 World 查询提供；表单不发送 World 请求，不复制画布图片。检查绑定 raw 表单签名与完整 canonical 提案，输入或静默变化使批准失效；pending 锁定操作，迟到打开／失败／检查／应用仍受父 owner 和源码 token 守护。父预览重新检查完整候选及真实图片，主编辑器仅更新原文内存，再普通保存；这里不编辑结构／偏移、引入多文件事务或统一历史。

共享声明恢复使用独立 `viento_core_scene_composition_fragment_edit_version() === 1`、`supportsStudioCoreCompositionFragmentEdit()` 与 `dispatchStudioCoreCompositionFragmentEdit`，操作为 `sceneComposition.editFragmentActor`。Rust 声明补丁实现独立置于 `scene_composition_fragment_patch.rs`，复用原严格扫描和保真编辑；`values` 与 `reset` 先检查原始意图不重叠，再原子设置／删除并完整展开所有放置。位置必需，禁止删除；尺寸、颜色、速度、控制仅 source `useProjectionDefaults: true` 可删，图片任一继承状态可删。开启继承时重新读取投影，关闭继承时删图片表示无图；局部覆盖、继承开关、身份、组、放置偏移和其他作者字节保持。

`draft.proposeEdit({ values, reset })` 返回净设置与实际存在的删除，始终包含规范顺序的 `reset`，原 `propose(values)` SET 形状不变。`prepareSceneCompositionFragmentApply` 根据提案形状选择独立能力，重算来源、全引用／覆盖掩蔽、候选和路径；旧调度域拒绝新操作，缺新能力只禁恢复。GUI 的五个恢复选择仅对允许删除的声明开放，与同字段设置互斥，不抹去原始输入；批准包含 reset/raw/canonical，全候选重新验证继承和实际图片。父／主宿主继续检查全部目标及 live source owner／token，只进行原文草稿内存应用，普通 Save 再处理持久化和外部冲突。

九个配方子对话框都会分离复制提案，各入口独立创作工作流的应用完成守护因此核对完整规范化提案快照、当前 owner 及同一结果回执身份，兼容合法复制而拒绝字段改变；单目标、位置批次、共享声明及放置偏移分别校验自己的提案目标形状；共享声明回执包括全部相关引用及覆盖掩蔽，放置回执包括全体演员和组映射。主编辑器写入仍在最后一次 live 来源检查后同步完成；父完成回调随后关闭原工作台并转交当前编辑器焦点，不把应用已确认误报为仍待处理。

### 布局保存工作流

`layoutSave.read/invalidate/begin/resolve/refreshed` 与位置草稿共用 `draftId` 和释放边界，没有第二份持久状态或额外会话表。每次检查、保存或核对取得草稿内单调递增的 `requestId`；完成事件必须同时匹配会话、当前阶段和请求。Rust 拒绝重复完成、过期令牌、未检查的保存，以及结果未确认时再次写入。保存阶段冻结后，原生位置修改和撤销接口同样拒绝变更。

```mermaid
stateDiagram-v2
    [*] --> editing
    editing --> checking: 检查脏草稿
    checking --> reviewed: 回执校验通过
    reviewed --> editing: 修改位置或开始输入
    reviewed --> applying: 保存已检查请求
    applying --> uncertain: 无法确认结果
    uncertain --> verifying: 只读核对
    applying --> refreshing: 确认已保存
    verifying --> refreshing: 登记与正文一致
    verifying --> conflict: 内容不同或版本冲突
    refreshing --> saved: 刷新完成或失败
    checking --> conflict: 版本冲突
    applying --> conflict: 版本冲突
```

图中省略可重试的错误返回：检查的一般失败回到可编辑状态；保存的明确声明／命令校验失败回到可编辑状态，其他失败进入待核对；核对的普通读取失败继续待核对。三个 World 冲突码统一进入冲突状态。核对仍执行“读取登记 → 读取正文并核对摘要 → 再读登记 → 比较完整声明”，不会再次提交保存。

确认写入后先进入 `refreshing`：已保存但仍忙，继续阻止页面离开；刷新失败只显示警告，最终保持 `saved`，不能使保存再次可用。前端在每次异步返回以及清理阶段核对操作归属，关闭再打开后的旧响应不能批准新草稿，也不能解除新请求的忙碌状态。草稿关闭会释放整套状态；这些内存令牌不是服务器事务 ID，不能提供跨重启恢复或网络幂等保证。

### 通用源码编辑工具

`engine/source-indentation.mjs` 只接收规范 LF 文本、UTF-16 选区、操作及缩进单位，返回一次整行替换与映射选区；输入及输出长度均有界。它不读取语言、工程类型、DOM、文件或后端。

`app-source-indentation.js` 负责工具条、IME、快捷键和浏览器原生编辑事务；正文宿主只提供编辑状态及来源标识。原生 input 沿既有脏状态和普通保存路径处理，程序载入正文另更新来源标识，语言刷新不会重置原文或撤销记录。此工具属于既有正文模块，不添加独立执行或持久化权限；Rust 原生文本命令和外部 LSP 后续可按相同职责分别接入。

`engine/source-position.mjs` 独立提供有界 LF／UTF-16 行索引和位置查询，不依赖 DOM、语言或文件。`app-source-position.js` 只接收正文元素、容器和共同的 `sourceEditorContext`，读取选区并移动光标；不调用缩进控制器、input、原文替换或保存接口。跳转窗口绑定来源标识及完整原文，关闭和焦点恢复后重新核对归属；可丢弃的排版镜像测量软换行后的滚动位置。正文模块数量及宿主权限不变。

`engine/source-diagnostic.mjs` 约束独立、不可变且有界的诊断展示快照，不接收构建任务或执行器对象。构建视图只提供代码、说明与详情；正文宿主负责读源、版本核对和位置转换，再将定位结果交给 `app-source-diagnostic.js`。面板只能展示／清理，正文输入令旧结果保持待复验，不能触发检查或保存。

`app-source-reveal.js` 是独立 DOM 适配器，供行号跳转和已核对来源导航共同使用；完整文本镜像避免在词中截断而改变折行。模态来源导航的激活路径延后焦点，窗口关闭后再次核对来源、忙碌状态、弹窗及新用户操作；同步 focus 回调不能把旧范围写入另一份源码。它们仍属于正文模块，不新增声明能力。

### 原文查找与替换

`engine/source-search.mjs` 提供有界字面匹配与单次替换规划，保留原始 UTF-16 范围；大小写选项不通过整篇转小写改变偏移。替换规划只返回最小包围区间和字面候选，不读取文件或控制编辑器。

`app-source-search.js` 消费既有 `sourceEditorContext`，负责非模态控件、输入法、快捷键、选区及原生撤销事务。跳转复用独立的 `revealSourceOffset`；替换通过一次原生 `insertText` 沿普通 input 更新草稿、诊断和保存状态，不直接覆写 `.value` 或绕开正文宿主保存。操作前后均核对来源令牌、确切原文及查找条件，重入或文档切换不能把旧选区或输入事件交给新来源。正文模块仍为既有模块，不增加执行器、构建或持久化权限。

媒体粘贴／拖放沿既有编辑适配器核对目标输入框：只有 `getContext(input).input === input` 的正文输入可以成为素材插入目标。搜索等辅助输入不会更新正文的最后目标，也不会因宿主的默认回退而上传素材或修改正文。该判断由通用媒体组件负责，不依赖搜索组件的 ID 或类名。

### 当前任务问题视图

`engine/project-problems.mjs` 严格捕获可序列化的单任务标量、诊断与来源信息，返回不可变快照；独立字面筛选接受严重度、查询和可选的本地化消息，不依赖 DOM、构建任务对象或文件访问。无效来源元数据整份拒绝，不静默遗漏诊断或修正来源。

`app-project-problems.js` 保持搜索控件与等价结果的行节点，消费快照、可用状态及来源令牌；只把所选条目和归属检查函数交给导航接口。`app-project-build.js` 负责从当前任务映射友好消息与数据，绑定后端、任务及窗口会话，保留现有构建／运行控制。主编辑宿主在原文读取与摘要计算后复核归属，再接已有版本检查、精确范围和延迟焦点交接。完成导航后的焦点交接由正文令牌守护，不要求已关闭的问题窗口继续可见。


## 配方与运行场景的显式衔接

`scene-composition-materialize.mjs` 消费保存态预览、已登记来源原文和读取前后的同一 World 修订，复用 Rust 展开，生成独立 Scene2D 及已有 `scene.create` 请求。它不从预览渲染模型反推作者声明，也不读取文件、执行后端或取得保存权限。`app-scene-materialize.js` 独立负责来源读取、目的地审阅、保存结果核对与会话守护；构建父窗口仅提供可用性、选中身份和保存后的目录交接。

配方依赖先经原有只读预览校验，目的场景再经原有创建事务校验。原配方不修改，新场景保留展开后的稳定实例身份与投影继承；行为关联、构建快照、后端输出及交付沿现有接口进行。不新增系统模块、Rust 协议或作品格式。

## 场景声音的独立边界

声音作者文档使用 `viento-scene-audio` schema 1，含稳定场景、轨道、资源与提示 UUID。共享 Rust 的 `sceneAudio.inspect`／`sceneAudio.sample` 严格校验 1–16 条轨道、0–64 个提示、0–60 秒及 0–1 音量；同刻提示保留作者顺序，采样只返回命令和声明状态，不推断素材自然结束。可选 WASM 能力缺失时明确失败，没有 JavaScript 规则替代。旧 `createSceneAudioProposal` 保持严格的定长、固定身份叶编辑契约。原 `createSceneAudioCueProposal` 继续接受完整提示行，按 UUID 核对保留项的固定轨道绑定与原相对顺序，只允许移除并在末尾追加新提示；旧契约保持。原 `createSceneAudioTimelineProposal` 继续独立接受完整编排，可将既有提示换到当前声明轨道，并按作者指定顺序保留、新增或移除提示。完整候选仍由同一 Rust 核心校验，不使用排序后的运行数组重写文档。运行时间优先，同刻才沿新的作者顺序。

新编排提案在只换轨而未增删／重排时修改 `/cues/<index>/trackId` 叶 token；结构变化时只替换 `/cues` 数组，按 UUID 复用保留提示原片段，并对明确修改的 trackId／时间／动作做叶补丁。空数组与删至空分别处理，源映射随保存后的新索引重新解析。轨道 role／volume／loop 可在同一候选中按既有叶路径修改。场景、轨道／资源身份、资源绑定和数组外原字节保持；这三种旧提案继续固定轨道数量、身份与资源；各自编辑模式由私有品牌记住，应用时按同一模式重算。新轨道提案单独扩展下述范围，沿用来源宿主复核，未增加 World 写命令、保存端口或 Rust ABI。

原 `createSceneAudioTrackProposal` 的 tracks 行完整包含 id／resourceId／role／volume／loop；保留项按原轨道身份复用，resourceId 和相对顺序固定，新轨道只在末尾追加且资源必须来自原文轨道所用集合。最终维持 1–16 轨，cue 可沿既有编排语义修改，但不能指向被移除轨道；完整候选仍由 Rust 检查。结构补丁分别复用 `/tracks` 与 `/cues` 原片段，按各自净变化替换数组或叶值；新增 ID 与当前提案内的其他身份保持隔离。

复制 UI 复制当前表单设置但不复制 cue；删除依据当前草稿提示引用禁用，并明确行为脚本／参数里的动态轨道 ID 须由作者检查。行为标量参数没有轨道静态语义，不能从没有 cue 引用推导安全删除；项目实际调用未知轨道时现有 `runtime_behavior_audio_track` 错误仍负责拒绝。

资源登记不进入写集。`resolveSceneAudio` 只要求每份使用资源存在于 assetBindings，因此保留多余绑定合法；它只将最终轨道使用的资源去重放入计划，冻结宿主只读取这些计划资源。`validateSceneAudioPlan` 禁止计划中的未使用音频资源，不禁止登记的绑定超集；现有声音目录同样接受合法超集。移除轨道不删除文件或登记绑定，复制不授予访问新素材的权限。

本轮 `scene-audio-resources.mjs` 以 `captureSceneAudioResources` 单独捕获已绑定素材目录；`createSceneAudioResourceProposal(source, edit, catalog)` 允许资源引用修改及同批轨道／提示结构编辑，旧四种声音提案不放宽。宿主复用现有声音创建目录的只读 inspect，核对原文／已保存基线与 World、场景、声音文档和候选目录修订；目录读取、审阅与应用之间的变化拒绝旧提案。应用重新读取并捕获新的品牌化目录实例，比较完整 DTO（含未绑定候选与 metadata 附注），并分别核对草稿及保存正文摘要。原文补丁只修改显式选择的 resourceId，仍由 Rust 检查完整声音候选；来源宿主在最后一次复核后同步写普通草稿。

素材绑定继续使用现有 World 的 `resource.bind`，只在独立 metadata 事务中追加绑定。声音表单不调用这一写命令；作者先保存绑定再选择素材，普通 Save 最终只写声音正文。两次保存不具有跨文件原子性，取消正文不会撤销绑定，旧绑定与资产不清理。目录候选仍为 unverified，不读取实际 PCM／哈希；构建使用的音频字节校验与冻结继续属于 build，独立试听只验证自己的本次读取副本。

`org.viento.scene-audio` 仅依赖文档模块，独立提供 `scene.authoring.audio@1`。视图通过来源读取、已绑定素材目录和草稿应用端口负责三语言表单、完整原文审阅和取消；来源宿主在每个异步边界检查 owner／token／修订，最终同步更新普通草稿。独立试听端口另负责一份所选素材的验证副本与浏览器播放生命周期，界面不取得行为控制器、后端运行或保存权限，编辑操作不会自动播放。

可移植计划解析器沿 Scene2D 的唯一 `audio` 登记关系取得声音文档，并核对声音到场景的依赖引用及资源绑定。来源映射按稳定身份回到作者原始 JSON Pointer；无声音关系时旧计划保持原样。新增 `audio.nonspatial`／`audio.timeline` 执行能力必须显式准入，Bevy 数据与 Rust 行为适配器均拒绝。构建的冻结宿主独立校验实际哈希和 WAV 容器：PCM16、8–96 kHz、单／双声道、每份不超过 32 MiB，不转码或改写作者素材。

Godot 生成器负责资源路径、播放器和时间驱动；每条轨道独立设置流实例、音量和循环。中立事件读取器独立核对声音就绪、提示顺序、终止与冻结来源，不把声音事件当演员状态。真实 Godot 混音缓冲测试区分零增益、停止和循环，其结果不代表物理扬声器验收；详情见[场景声音](SCENE_AUDIO.md)。声音首轮未包含行为触发和创建向导；后续已分别接入[项目行为声音控制](PROJECT_AUDIO_CONTROLS.md)与[首次添加声音](SCENE_AUDIO.md#从场景首次添加声音)。空间音频、混音总线以及声音与有限控制回放的组合仍未接入。

## 行为参数与音轨目录

`scene-audio-directory.mjs` 只捕获已保存声音声明的音轨身份，复用既有 Rust 声音规则；为行为来源建立深冻结、带私有品牌的目录，并仅允许从目录显式取出普通 UUID 字符串。它不依赖 DOM、文件系统、播放器或执行引擎，不生成行为提案，也不扩大普通行为参数的语义。

独立只读 `POST /api/scene-audio-directory` 沿用现有鉴权与请求来源检查。Node 服务检查已登记 Scene2D v2／v3、唯一 `audio` 关联、声音反向引用及声明；没有关联时返回空目录，歧义或无效声明拒绝读取。此接口不读取 WAV、不验证资源可用性，也不运行完整构建规划。API 布尔能力 `sceneAudioDirectory` 只控制宿主是否提供读取端口，不增加 Studio 模块或声明能力。

行为来源宿主先复核既有行为依赖，再读取音轨目录；两个结果的场景身份、路径和修订必须一致，每个异步步骤都检查原文、保存基线、会话和能力。表单通过可选 `getAudioTracks` 获取目录，选择后显式填入文本参数，继续使用原有检查／提案／草稿／普通保存。音频目录不加入行为依赖修订或普通应用路径，故不承诺持续引用保护。可选能力变化使用独立目录世代撤销迟到结果，不改变普通行为来源令牌或已审阅提案的应用权限；旧宿主缺少端口时仍可编辑普通参数。

本次保持 Rust ABI、作者格式、后端版本和运行协议；不增加安装或设备验收。操作与证据见[音轨选入](SCENE_BEHAVIORS.md#将音轨编号填入行为参数)和[专题记录](test-results/scene-behavior-audio-picker/README.md)。

## 素材试听的独立边界

`engine/scene-audio-audition.mjs` 的 `prepareSceneAudioAudition(source, catalog, resourceId, ports)` 在首次 await 前捕获来源五字段，要求已品牌化且精确匹配的绑定目录；通过 `getResources` 取得不同实例的 fresh catalog，比较完整创建 DTO（包括未绑定候选及登记附注）。`readBytes` 只读取选中的注册资源；独立 `digestBytes` 核对本次 Uint8Array 副本的大小和 SHA-256，再执行共享 PCM 校验。每个异步返回后检查来源及取消，私有品牌和 WeakMap 保存验证字节；公开描述只有资源身份、名称、声道、采样率、帧数与时长，`sceneAudioAuditionBytes` 每次返回新的 ArrayBuffer。这里没有播放、正文或 metadata 写入权。

`engine/audio-wav.mjs` 原样承接既有 PCM16 容器校验，`scripts/lib/audio-wav.mjs` 只重导出，Node 构建和浏览器准备层使用同一规则。Godot 适配器的完整来源指纹同时纳入新的 engine 路径，已有构建缓存因此需重建；适配器版本与协议保持，真实 Godot 回归和浏览器试听分别记录。`web/modules/app-scene-audio-media.js` 通过既有 `/asset-files/<UUID>` 只读地址受限读取，限制超时、取消、完整响应及登记大小，不接受任意 URL／路径；无需新增服务路由。目录仍是 unverified，读取成功和试听验证都不把目录提升为长期可信文件状态。

`web/modules/scene-audio-audition.js` 单独管理 WebAudio：显式点击时发起 AudioContext resume，验证字节后 decodeAudioData，经 GainNode 使用 0–1 音量，以 AudioBufferSourceNode 实现整份素材循环。解码前按帧数、输入／输出采样率与 float32 声道数估算内存，限制 128 MiB；文件上限仍为 32 MiB。一次只持有一份试听，停止撤销旧 generation，释放节点；迟到的 resume／读取／解码不能重新开始。无需 Blob URL，现有 CSP 保持。

播放器的 `pause()`、`resume()`、`seek(seconds)` 与 `snapshot()` 属于同一临时 owner；公开快照增加当前位置和时长，时钟取自 AudioContext，循环位置按素材时长取模。暂停停止并断开当前 source，保留缓冲、增益和 context；继续／播放中定位创建新的单次 source，旧 `onended` 与迟到继续结果需按 owner 和操作序号丢弃。停止释放整个 owner 与缓冲。非循环定位末尾统一暂停、继续从头；循环末尾归零。继续处理中只接受停止，不堆积暂停或定位命令。进度只触发轻量视图更新，不能重建表单或修改审阅。

来源宿主和表单复用现有实现，试听与草稿应用各走独立端口。编辑、重新读取目录、检查、应用、关闭及 hidden 都停止，包括暂停中的快照，语言切换保留表单与试听。这个端口不执行场景 cues 或行为，也不控制执行后端；21 模块／40 项声明能力、Rust ABI、Godot 0.11.0 与项目协议 4 不变。暂停／继续和定位只消费当前验证快照，不重读素材，也不升级目录 unverified 状态。本轮证据另列[试听控制专题](test-results/scene-audio-audition-transport/README.md)，此前基础播放与 PCM 指纹回归仍见[原专题](test-results/scene-audio-audition/README.md)；不把浏览器缓冲输出外推物理设备、Godot／Bevy或安装支持。

## 项目目标与运行入口的区分

`build-target.mjs` 分派单场景和项目计划，分别提供构建目标来源与入口场景访问。纯 `project-assembly` 声明和计划只消费作者 World；Node 在同一快照中冻结去重资源，Godot 才负责成员路径。运行会话以项目身份归档，只把入口子计划交给现有场景事件读取器。后端清单 v2 与目录 v2 显式保存组装信息，旧清单／目录仍可读取。作者服务使用普通登记和原子原文保存，独立窗口仅通过目录、保存与刷新端口工作。详细契约见[项目组装](PROJECT_ASSEMBLY.md)。

## 项目行为声音控制

`project.audio-control` 是执行后端能力，不增加 Studio 模块或作者格式。共享 Rust 仍拥有音轨和时间提示语义，本轮把 schema 1 的提示下限扩展为零，WASM 桥同步核对空数组；原非空声明及 ABI 保持。作者可用 `cues: []` 声明纯行为触发；首次创建表单默认定时播放，也可逐轨选择由行为触发。该选项只决定是否生成初始提示，不进入持久声音格式，不自动创建脚本或绑定。

`engine/project-audio-commands.mjs` 独立维护实际命令账本，项目协议 4 读取器从冻结行为绑定与音轨声明解析双来源，查询只返回已准入 DTO。命令序号、访问身份、局部时间、到期提示前缀与结束计数都受校验。最大观察数据包含声音、事件、状态与当前场景；仅协议 4 使用相应复制上限，旧协议预算不变。核心和界面不持有播放器、Godot 对象或任意资源路径。

Godot 的 `project-audio.gd` 维护访问内请求队列，桥接原场景播放器；场景初始化、声音就绪及零时刻提示完成后，先排空事件，再执行声音请求，最后切换或正常关闭。`audio-command` 只在实际调用播放器后发出，取消或失败不补造回执。只读 `app-project-audio-observation.js` 显示已执行命令并分别导航行为与音轨来源，不推断当前播放状态。旧单场景生成字节和声音子协议 1 保持，当前生成 `assembly.json` 为 5，作者组装与计划仍为 1。操作、预算与验证边界见[行为驱动场景声音](PROJECT_AUDIO_CONTROLS.md)。

## 项目动画控制的独立边界

0.1.6 后工作树以 `sceneAnimation.transport` 将播放头规则放入共享 Rust：输入完整动画声明、上一状态、显式场景时间与可选命令，输出 `sceneObjectId/phase/positionSeconds/timeSeconds`。主 ABI 与动画 schema 1／2 保持，增加可选 `viento_core_scene_animation_transport_version`；旧核心不会以 JS 回退模拟控制。相同时间命令按顺序处理，非循环末端包含浮点舍入边界，循环支持长场景时钟而不丢掉既有小播放头。

`project-animation-commands.mjs` 保存有界回执和双来源。protocol 5 reader 从冻结成员动画与行为绑定解析身份，调用 Rust 核对实际转移，逐访问隔离状态并核对结束时间与命令总数。来源路径不由后端线帧提供。查询只返回已准入的状态快照，40 MiB 观察复制上限容纳动画、声音、事件与共享状态，旧协议预算保留。

Godot 新 `project-control-runtime.gd` 继承既有项目协调器；`project-animation.gd` 排队，`project-animation-scene.gd` 桥接既有视觉运行。渲染从最后一次命令锚点和场景绝对时间计算，不逐帧累计播放头，避免后端与 Rust 在循环／结束边界漂移。队列使用当前访问与绑定，事件或声音失败、退出、过期端口都不能产生新的成功回执。新场景重建 transport；视觉停止不会冻结逻辑或声音。

`app-project-animation-observation.js` 只有只读快照与受守护的来源导航端口，不取得 Godot 对象或命令执行权。脚本起始内容仍是通用目录中的普通文本，创建与保存、行为绑定分别使用既有流程。含动画项目声明 `project.animation-control` 并生成 protocol 5／清单 6；无动画项目允许精确回退到 protocol 4／清单 5，其他协议不放宽。单场景四属性／序列帧生成文件不改；新增后端代码纳入构建指纹。

操作与实际验证范围见[项目动画控制](SCENE_ANIMATION.md#行为控制项目动画)及[本轮记录](test-results/project-animation-controls/README.md)。22 个 Studio 模块／43 项声明能力保持；该后端能力不等于 Bevy、Android 或当前安装支持。


## 命名片段的独立边界

`scene_animation.rs` 为作者 schema 3 增加有界 `clips`，独立可选 `viento_core_scene_animation_clips_version` 门控 `sceneAnimation.sampleClip` 与 `sceneAnimation.clipTransport`。原采样、原四字段 transport 和 ABI 保留。新 transport 状态增加 `clipId`，播放头始终为所选范围的本地秒数；`select` 归零并暂停，旧控制动作作用当前选择。采样只在局部范围循环一次，再用原曲线的绝对时刻插值，非循环片段终点不受整份动画 loop 干扰。

原文编辑仍由 `scene-animation-edit.mjs` 产生私有品牌提案；三字段旧请求保留已有片段，显式 clips 请求升级 schema 3。新增根属性与同 ID 叶补丁保留 BOM／换行和无关原文；增删只替换 clips 数组。`app-scene-animation-clips.js` 只负责片段表单，父编辑器继续拥有来源检查、完整审阅和普通草稿应用。共享 player 仅持有时钟与选择，编辑示意及保存态场景控制器分别消费 Rust 样本，不修改曲线或渲染器以模拟片段。

schema 3 使用 animation-plan 2 和 `locations.clips`，旧作者保持 plan 1。`project-animation-transport.mjs` 独立连接协议与 Rust：protocol 5 保留原 transport，protocol 6 调用 clipTransport；混合项目的旧动画只允许 null 选择。命令线帧不携带名称或来源，reader 从冻结计划派生片段声明和 `/clips/N`。中立账本显式按协议检查局部范围、选择连续性、稳定声明身份和预算；protocol 6 的快照／整观察累计字符串复制预算分别为 12／48 × 1024² 个 UTF-16 码元，另有节点与深度限制；这是复制检查预算，不是整个对象的内存字节上限，旧预算不扩大。只读观察组件额外提供片段来源，不获得执行权限。

Godot 新片段生成包装器保留旧视觉采样脚本及素材布局；仅 protocol 6 项目接新协调器、队列和场景 transport 模板。请求先检查类型和全动画上界，排空时按前一命令已选中的范围检查定位；仍从最后命令锚点计算，事件→声音→动画→离场顺序和 256／64 命令预算不变。schema 3 项目使用 assembly 7；旧 protocol 4／5 文件与来源映射保留，宿主按构建冻结协议选择观察，不能根据后端输出猜版本。

内置片段脚本起始内容继续普通 TXT 草稿、审阅、保存及行为绑定。旧控制 starter 同时补充 `has_method` 检查，避免没有动画控制端口的项目调用不存在的方法。22 个 Studio 模块／43 项声明能力保持；后端 `animation.clips2d` 与 Studio 模块能力分别计数。验收和限制见[本轮记录](test-results/scene-animation-clips/README.md)。


## 行为参数的动画片段目录

`scene-animation-directory.mjs` 复用 Rust 动画检查，独立约束保存态目录和行为来源品牌：动画正文限 128 KiB，行为来源限 32 KiB；原文五字段和场景三字段必须相符。catalog 只暴露名称、范围、循环与稳定 UUID；显式取值只返回普通字符串，不创建引用、提案或保存权限。旧 schema 1／2 与空 clips 保持原声明，不自动升级。

## 动画片段使用位置与只读来源

动画来源宿主在每次异步边界核对 source5、保存字节摘要及独立 usage generation；usage 与实例目标选择分别撤销，不改变普通提案应用权限。片段字段只发出显式查看请求，独立使用位置组件持有查询、暂存快照和只读定位，父编辑器继续持有审阅、普通草稿和播放器。UI 以来源会话、能力和当前片段归属废弃迟到结果，语言切换更新现有节点。沿用现有模块与动画作者能力，不增加 Rust ABI、作者格式或后端协议。


## 事件与动画的脚本组合

`script-authoring.mjs` 新增 `godot-project-animation-event` 起始内容，复用既有 `subscribe_event`／`unsubscribe_event` 和 `select_animation_clip`／`play_animation` 端口。模板仍沿普通 TXT 草稿、保存、行为绑定和文本参数流程；`event_name` 默认 `checkpoint`，空值不订阅，空 `clip_id` 选择完整动画。片段名称选择只填入 UUID，不增加作者格式、Studio 模块能力或后端协议。

就绪阶段只验证有效对象和所需方法并订阅，保留默认自动播放；同步回调依次提交选择和播放，重复触发从范围起点重播。事件 handled 仅确认回调已提交两条命令，执行事实仍由独立动画回执验证。缺少片段选择端口的旧项目安全返回，退出主动取消有效订阅并清空本地身份；旧访问继续由既有生命周期隔离。该组合不将事件系统变成动画状态机。作者用法见[事件动画片段](SCENE_ANIMATION.md#用项目事件触发动画片段)。

## 动画整段时长变换的作者边界

`sceneAnimation.retime` 是共享 Rust 的纯作者变换，接收已验证的完整动画 `document` 和 `durationSeconds`，返回 `{ document }`。独立可选导出 `viento_core_scene_animation_retime_version() = 1` 经 `supportsStudioCoreSceneAnimationRetime()` 门控；主协议、原检查／采样／transport 接口和作者 schema 1／2／3 保持。缺少能力时不在 JavaScript 中回退计算，普通动画编辑不受此可选区域影响。

变换只替换总时长、全部关键帧时间和片段起止，保留值、稳定身份、列表顺序、格式版本、插值、循环和图集网格。0 与旧终点精确映射，目标相同直接保留原数据；正常比例使用乘法，极端比例以归一化计算避免中间溢出或下溢。独立校验集合核对所有不同时间（含跨轨道、片段边界与总时长）仍严格有序，精度塌缩或结果不合法整次拒绝，随后重验原动画预算；该集合不重排作者列表。

`retimeSceneAnimationDraft(content, edit, durationSeconds)` 在异步边界前严格复制当前表单，与普通提案共用候选文档及 schema 升级规则，再调用 Rust，返回冻结文档供本地表单回填。返回值没有提案品牌或保存权限；原文仍经 `createSceneAnimationProposal` 的保真叶补丁、来源复核、普通草稿应用与 Save。独立 `app-scene-animation-retime.js` 维护目标输入，父编辑器维护当前表单与审阅；目标输入不使普通草稿变脏，失败／无变化保留审阅和预览，成功且有变化后重新检查。运行时钟、后端协议、资源读取及播放速率不参与变换。操作见[整段按比例调整时长](SCENE_ANIMATION.md#整段按比例调整时长)。

## 动画轨道复制与实例目录边界

`sceneAnimation.copyTrack` 接受精确信封 `{ protocolVersion, operation, document, sourceTrackId, targetInstanceId, newTrackId }`，通过独立可选 `viento_core_scene_animation_track_copy_version() = 1` 与 `supportsStudioCoreSceneAnimationTrackCopy()` 准入。Rust 校验完整动画，按稳定编号找到源轨道，复制后仅替换新 `id`／`instanceId` 并追加到末尾；新轨道编号按原 tracks 命名空间查重，同目标／属性拒绝，随后重验轨道、关键帧和正文预算。它不生成 UUID、读取 World 或推断目标图片；既有 schema、采样／transport 和后端协议保持。

`copySceneAnimationTrackDraft(content, edit, sourceTrackId, targetInstanceId, newTrackId)` 先捕获当前完整表单，复用候选格式规则并调用纯核心，返回冻结文档供本地回填。父编辑器从现有且来源匹配的目标目录确认新实例并分配新身份；不要求复制准备阶段通过其他轨道的目标完整性检查。普通检查与应用仍核对全部轨道目标。目录刷新、来源、选择和表单变化均废弃在途结果；来源宿主和 HTTP 服务没有新增能力。

独立 `app-scene-animation-track-copy.js` 负责源／目标暂选及准备状态，父编辑器持有表单、审阅和普通草稿应用；成功后才撤销旧预览／审阅。返回文档不是保存授权，结构提案沿原 `tracks` 数组替换规则保留外部未改原文、BOM 和换行，不能承诺旧轨道内部原字节保持。复制序列帧仍使用目标实例图片，逻辑坐标、资源绑定和命名片段均不复制。见[轨道复制操作](SCENE_ANIMATION.md#复制轨道到其他实例)。

## 动画自然完成的独立边界

`project-animation-completions.mjs` 管理有界完成与投递快照；`project-runtime-events.mjs` 将 protocol 7 的自然完成送入既有 Rust transport（`command:null`）核对。自动播放没有合法的行为发布者，因此完成不伪装成通用事件总线的 `event-publish`，而是从冻结动画／片段声明取得来源；只有订阅接收者使用行为来源。

新完成帧包含完成序号、当时已执行命令序号、访问和五字段播放状态，另有独立投递帧。reader 检查自然结束、去重、连续顺序、来源与预算后才提交；查询 DTO 再检查跨访问、命令快照和投递一致性。旧 protocol 1–6 的精确形状保持，旧 Rust/WASM ABI 与作者 schema 不变。

Godot 的完成管理器、项目包装器和场景完成桥分别负责订阅队列、安全点调度和自然结束锁存。播放推进只捕捉完成，不在采样过程中运行作者回调。排空顺序是事件、声音、动画命令、完成投递，再处理离场；回调提出的新命令仍经原队列执行。捕捉之后的动画命令或待离场／结束使旧投递跳过。场景重入使用新访问和订阅，清理不持有旧行为节点。

`app-project-animation-completion-observation.js` 只接受已验证 DTO 和来源导航端口；不持有播放器、保存或进程权限。内置衔接内容是普通 GDScript，经普通脚本创建和行为字段保存进入冻结工程。三语标签、来源会话与旧观察组件各自维护；完成记录不扩大为实时画面观察。

新含动画项目库存明确列出完成运行脚本及来源指纹，分发仍通过既有工程 ZIP；旧库存可读取，无动画生成分支不引入新脚本。实际验证范围见[本轮专题](test-results/project-animation-completion/README.md)。


## 动画状态表与源码生成边界

`animation_state_table.rs` 只接收初始状态、状态键和事件／完成边，拒绝歧义、缺失引用和超预算数据，输出稳定索引及事件目录。可选核心 marker 与 `animationStateTable.inspect` 保持旧 ABI 可用；`animation-state-table-core.mjs` 只做受限请求、回包核对和冻结。它不读取片段、保存文件、执行图或依赖 Godot。

`godot-animation-state-script.mjs` 将已验证索引发射为普通 GDScript，导出 `clip_<key>` 参数，通过现有项目事件、自然完成和动画命令端口执行。参数捕获、退出撤销和失败停止属于生成代码；新的运行协议、状态回执或播放头仲裁都不在该生成器中隐式加入。

`app-animation-state-script.js` 拥有独立表格和局部行身份；父脚本创建窗口把表格签名纳入审阅和异步草稿交接，只有当前精确生成源码能获得既有草稿品牌。三语切换不重置作者输入。生成后的保存态 TXT 属于作者，界面不反向解析任意改写源码。操作和限制见[动画指南](SCENE_ANIMATION.md#从状态表生成动画脚本)。

## 脚本参数接口与绑定修复边界

## 保存态脚本使用位置与来源导航

`engine/script-usage.mjs` 严格捕获有界目录，按保存的行为正文枚举脚本 UUID 匹配，保留参数类型和精确 JSON 来源范围。目录、只读原文与导航请求各有私有品牌；文档引用状态与行为绑定分开表达，不把无效正文静默计为零使用。该模块不解释脚本语言、不写文件、不依赖动画状态表或运行核心。

`script-usage-service.mjs` 通过同一次 World 快照观察当前工程的已登记非归属引用，明确返回缺失正文。独立 `/api/script-usage` 只读 POST 沿编辑会话鉴权并禁止缓存；`scriptUsage` 是可选服务标记。没有这项接口时，原有脚本创建和参数编辑继续可用。来源限额与整个响应预算都在完整交付前核对，不部分截断。

`app-script-usage-source.js` 将读取结果绑定当前 TXT 的五字段来源、保存基线和可选能力代数，只注入读取与导航端口。导航前重读目录，复核 World／脚本身份、目标保存版本和内容摘要；交接后由原导航流程维护目标文档加载和精确定位，窗口只守自己的选择与生命周期，避免正常切文档导致自取消。主编辑器仍负责未保存草稿确认，没有新保存入口。

`app-script-usage.js` 独立维护目录、当次只读原文和三语展示；它从品牌快照请求导航，不接收任意文件路径权限。既有 scripts 模块组合创建、状态表编辑和使用位置三个控制器并分开注入端口，仍为 22 模块／43 项声明能力。作者格式、Rust ABI、后端协议与生成代码保持。见[操作指南](SCENE_BEHAVIORS.md#从脚本查看使用位置)。


## 状态表静态图与字段定位

`engine/animation-state-graph.mjs` 从当前原始表格调用统一准入 facade（含组合优先使用 Rust `animationStateTable.inspectCombined`，其次共享来源使用 `inspectSelected`，其余依次按显式 `eventSelection`、标量条件、无条件分流到 `inspectBranches`、`inspectConditional`、`inspect`），将稳定状态与转换索引投影为只读图。图的节点、边及有限布局深冻结；同向同端点连线保留全部转换下标，自环与反向边分开布线。它不修改语义规则、发射脚本或读取文件，布局不进入作者声明。

`app-animation-state-graph.js` 只管理展开、图选择、SVG 与可键盘操作的文字列表。共享 `app-animation-state-script.js` 提供当前表格与字段定位闭包，因此创建与重编辑使用同一子组件。图形操作不调用表格 `onChange`，不会撤销已经生成的源码审阅；实际字段编辑仍通过原有路径使审阅失效。

`animation_state_conditions.rs` 扩展独立的标量条件域：`animationStateCondition.inspect/evaluate` 与 `animationStateTable.inspectConditional`。旧状态表操作及可选marker语义保持；新能力由 `viento_core_animation_state_conditions_version` 单独探测。`animation-state-conditions-core.mjs` 通过自身属性描述符选择新旧Rust准入，不执行作者getter。JS桥验证请求及回执对应关系，不另写比较求值回退。

## 动画状态快照与冻结来源

`project-animation-states.mjs` 从冻结项目计划构造只读控制器目录：完整源码 codec 识别固定 v1/v2/v3/v4/v5 生成器，绑定顺序、状态标识、片段参数和两类来源均由计划提供。普通或修改过的脚本排除；可选核心能力缺失和已识别脚本的非法参数显式报错。目录检查与运行执行分离，不读取作者目录中的最新脚本替代冻结内容。

Godot 的 `project-animation-state-runtime.gd` 继承完成通知调度，发放原端口时仅登记 WeakRef；显式离场或报错中止在实例清理前读取 `_active`、`_state`、`_selected_clip`。每访问最多一批，只发送绑定身份、状态索引和片段编号；进程无法提供任意来源路径或状态文字。正常窗口关闭沿已有 finish 请求处理；强制终止不尝试在树已清理后补采样。字段损坏产生诊断，不降格成“不可用”或伪造成功终帧。

protocol 8 的 reader 核对冻结目录、完整控制器顺序、状态/片段对应、访问、采样原因、场景时间和命令截止序号，并将索引转换为冻结状态标识与来源。正常场景退出必须有匹配快照，快照之后拒绝新的控制事件，仅允许清理音频结束及退出；报错记录允许保留未完成访问。ready/finished 含独立 `animationStateSequence`。DTO 为 `project.animationStates`，独立限制64批、每批32绑定、合计2048控制器，不放大旧协议预算。

退出快照引入时，Godot描述符升级0.17.0；该阶段严格识别到控制器的新项目选择protocol8／清单9，普通动画仍protocol7、无动画仍protocol4。新库存包括固定采样脚本与冻结目录，源码指纹覆盖识别依赖；旧库存字段与预算继续校验，交付ZIP能脱离作者工作区执行。旧作者生成器与Rust/WASM字节不需改变。

`app-project-animation-state-observation.js` 只渲染已验证DTO，独立拥有筛选、语言和导航票据；构建宿主提供来源打开端口，与命令、完成、事件和共享状态观察器并列。它没有创作、保存或执行权限。脚本接受状态与实际播放回执分别呈现，不能由快照推导实时状态图或混合能力。操作见[动画状态快照](SCENE_ANIMATION.md#查看运行后的动画状态快照)。


## 动画状态进入记录的独立边界

`project-animation-state-entries.mjs` 复用冻结控制器目录，为每次成功进入建立有界账本。wire `animation-state-entered` 只携带访问、绑定身份、索引、片段、场景时间和当时已执行的命令序号；reader 将状态名与两类来源从计划重建。相同状态重启仍有独立连续序号，不从命令反推状态，也不猜测触发原因。

## 动画条件来源与后端读取

共享状态条件在既有 `condition:{type,operator,value}` 上增加可选 `selector:{kind:"projectState",key}`。未声明selector时，条件继续使用事件载荷。独立Rust模块 `animation_state_selectors` 和可选marker验证完整声明，复用既有类型、表结构、分支顺序及预算；桥接回执同时验真selector所在的表行和索引IR，禁止丢失或错配来源。

旧 `inspectAnimationStateDeclaration` 继续限定v1–v3，避免原直接发射器忽略新字段。来源入口 `inspectAnimationStateDeclarationWithSelectors` 在任何selector属性出现时进入来源能力；其余声明沿用旧路径。v4发射器继续使用此入口；当前静态图、重新编辑和源码codec使用下节的 `inspectAnimationStateDeclarationWithCombinations`，无组合时再委托来源入口。旧生成器文件和正常输出字节保持，新封套只在确实使用新来源时成立，完整源码再生一致后才能重新编辑或登记为严格控制器。

来源描述保持引擎中立。Godot v4发射器单独解析它，在事件回调中调用已有 `read_state`，再使用既有严格标量比较；没有扩展运行协议或共享状态存储。缺失值和类型不符不匹配。表单只编辑描述，静态图只显示已准入声明，运行观察仍来自既有p9包装层；三者不互相推断条件结果。

该切片保持protocol9／Godot0.18.0／库存10及22模块／43项声明能力。新增可选Rust/WASM能力和作者生成器版本不迁移作品或改变已安装程序；未来新增数据来源、求值追踪、每实例播放头需要各自的明确契约。

## 逐实例正式动画运行边界

作者选择由 `scene_animation.rs` 的动画schema4负责：在版本3字段上增加必需的 `playbackScope: scene|instance`，片段及轨道预算保持。可选 `viento_core_scene_animation_instances_version() === 1` 与JS回执门禁只限制新格式，旧marker和旧文档继续可用。`scene-animation-edit.mjs` 只在显式选择instance时升级旧文档；版本4切回scene不降级。表单、完整提案审阅、原文草稿和普通Save分别负责，读取不迁移作者数据。同步源码必须重建WASM，不能仅放宽JS校验。

## 动画目标回看的独立边界

`engine/project-animation-target-review.mjs`先经完整`queryProjectRuntimeObservation`准入，再以`visitIndex / sceneId / explicit target`建立不可变品牌模型。`createProjectAnimationTargetReview`只列已观察分组；`queryProjectAnimationTargetReview`按组返回命令和完成；`findProjectAnimationTargetReview`由独立种类与序号定位分组。分组不使用来源绑定或定义身份，避免同实例多绑定被拆开、同定义实例被合并或重入访问互串。

完成项的`anchorCommand`来自已经严格验证的`targetCommandSequence`；0仅保留为空，不捏造自动播放命令。全局`commandSequence`仍是截点，两个记录序号域不合并。返回值深冻结、来源脱离调用方，非法品牌、访问器和伪造锚点拒绝。

`app-project-animation-target-review.js`独立维护组选择、记录高亮及来源票据，没有执行、存储、播放或网络权限。命令与完成观察通过`onReviewTarget`交给宿主，回看通过`onClose`归还最初入口焦点；各组件不读取兄弟DOM。宿主以同一完整观察调用`setObservation`，统一提供来源读取与编辑会话保护。命令来源、完成主体和订阅来源分别持有身份，追加记录或无关订阅状态变化不撤销有效读取；改组、改来源、换运行或失去继续权限立即撤销。独立CSS和中英日字典只负责呈现。

本轮不改Rust/WASM、作者格式、运行协议、后端版本与生成清单；不承担实时播放状态、未进入分支追踪或运行断言。实际验证范围见[专题](test-results/project-animation-target-review/README.md)，发布与安装单独验收。

## 场景到组装的作者边界

`setupProjectAssembly.openForScene(sceneId)` 与已有 `open(documentId)` 分开。宿主提供当前场景、作者会话与来源令牌；组装编辑器重新读取 `assembly-list`，确认身份后预填成员与入口。原 `review`／`assembly-save` 负责完整 JSON 审阅和修订保护，保存确认才调用 `applied` 让构建宿主选择新项目并清除旧计划。
