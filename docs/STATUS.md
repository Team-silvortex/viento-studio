Scene2D 来源模型已在 JS 层与构建计划分离，预览字段可定位到当前原文；旧 v1 计划、快照和生成文件保持兼容。来源范围随正文修订校验，过期或近似位置不误选，未保存草稿保留。Scene2D v2 已区分实例 `instanceId` 与定义 `objectId`，同一 OC／投影可在场景中重复使用；选择、位置历史、来源和 Godot 运行事件均按实例区分。新场景默认 v2，旧 v1 保留原规则，点击“启用场景实例”后经预览保存才升级。实例仍限 1–128 个，新增 v3 支持 0–128 个组织分组、最多 16 层；大纲可折叠、检索、整组选择及定位组名原文。分组不改变绝对坐标或叠放顺序，运行仍使用 plan/runtime v2。单场景未保存原文已可显式预览，支持返回编辑器修改后重开；错误保留最近有效画面，来源定位核对当前草稿摘要。预览不改登记或构建输入，草稿限 128 KiB UTF-8。当前源码模式可显式“调整草稿布局”，经完整正文审阅后仅把坐标补丁应用回文本草稿，再由主编辑器普通保存；取消保留原草稿，过期画面不能回写。保存态表单／事务布局保存仍要求先结束文本草稿。空间变换、片段、多文件提交、跨视图统一撤销、剧本事件和规模扩展待实现。

Studio 规则继续向 Rust 核心迁移，位置历史、dirty 判断、保存阶段与请求归属已迁移；源码布局的严格 JSON、v1／v2／v3 身份／坐标／分组检查和仅数值 token 补丁也已下沉，原文前后仍限 128 KiB。源码回写不再依赖浏览器 YAML 模块，相关 HTTP 包目录入口已撤除。后端 JSON/CST、完整场景语义、投影继承、资源与关系、回执正文／摘要校验、HTTP 访问与实际事务、大部分 World／构建规划仍在 JS；可选核心能力声明保持旧布局操作兼容，不增加场景格式或自动迁移工程。近期行为后端优先 GDScript 和 Rust，C# 暂缓；当前产品尚未提供任意用户脚本挂载。

这些能力的范围各自受契约约束：批量属性提交只接受现有对象的属性修改，不能混合创建、关系和资源动作；Scene2D 当前只有角色引用、图片、方向键移动及 `idle` / `moving` 状态。游戏起始模板本身用于设计文档，可执行内容还需显式场景声明。
