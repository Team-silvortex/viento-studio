## 验证与交付

固定 v1 / v2 / v3 合成样例已分别通过前身和新版本解析，新增回归核对索引不改写原文，以及 Node → Rust → Rust 的归档往返。CI 增加真实 Rust 工具参与的兼容任务，基础检查仍可独立运行。具体命令见 [验证指南](TESTING.md)。

本轮通过 **657 项应用测试（0 失败、0 跳过）**、**42 项 Rust 测试**（另 1 项默认忽略的大作品测试由本次真实实例验收补足），并通过 Linux 原生通用工程 / 字段 / 三语 / 媒体工作流和作品库 / 原生选择器 / 导出 / 恢复工作流。实际 0.0.1 AppImage 也完成旧格式编辑、媒体、保存及关闭验收。计数、安装包摘要及实际平台验收范围统一记录在 [结果文件](test-results/handoff-0.0.1/results.json)，原始日志与截图保存在本机 `dist/handoff-0.0.1/`。

本机桌面入口已更新为通过上述验收的同一份 AppImage；旧程序、启动器、桌面入口与安装记录保存在私有备份的 `application-before/`，可回退。作品路径及启动器的媒体插件配置沿用原值。

Android 在本轮新建的 API 35 模拟器中，实际从旧 ARM64 0.4.6 APK 用 `adb install -r` 覆盖为 0.0.1，没有卸载或使用降级标记。作品与文档身份、原文字节及版本、模板 / 上下文和已落盘 WebView 存储保持一致。先重启旧应用确认测试存储持久化，再执行升级，避免把立即强杀导致的未落盘误判为迁移丢失。本项通过真实 APK 的原生桥验证，不声称重新验收了系统选择器或实体手机。

`dist/current/` 集中保留本次程序交付物、源码归档和摘要清单，均不携带官方作品。Android 包使用调试签名；Windows / macOS 仍需对应系统验收，不能把配置核对当作已经完成设备升级。

过程中曾发生主机 OOM：已完成的备份和原件不受影响，第二次导入的临时副本被完整性检查识别为未完成，随后在新目录重新导入并逐文件核验通过。没有把可见的临时目录当作成功恢复。应用测试并发固定为 2，本轮 Rust 构建降为单任务；关闭本轮留下的 Gradle / Kotlin 守护进程后完成后续验收。

## 接续开发与回退

1. 在新仓库执行 `npm ci`，使用 `npm run desktop:dev` 或 `npm start -- --no-open`。已有作品选择与数据路径直接延续；新机器通过完整包恢复。
2. 原作品及前身检出保留；需要恢复时导入备份到新目录，核对后再选择，不覆盖已有新写入。
3. 继续推进 V-M1 / V-M2 时先建立语义 Schema、权威来源 ADR 和只读投影；本次版本重启未授权自动启用 v4 或迁移所有未来模型。
4. 本地交付与 GitHub 发布分别记录。本记录不代表已创建 Release、更新商店签名或完成远程 CI 运行。
