# 2D 关键帧动画

0.1.6 源码支持独立视觉关键帧动画：内置字段编辑、Rust 采样示意、已保存场景画面预览、Godot 场景与多场景工程执行。当前安装版尚未更新；发布范围见[版本记录](RELEASE_0.1.6.md)，开发验证保留于[验收记录](test-results/scene-animation/README.md)。

## 先试用示例

复制完整 [examples/scene-animation](../examples/scene-animation/README.md) 到新的临时作品，再用当前源码编辑服务打开。它包含两份场景实例、四条动画轨道、类型模板和双向登记，不需要外部素材。

1. 打开 `documents/animations/demo.json`，进入原文编辑，再点 **编辑场景动画**。
2. 调整时长、循环、轨道属性与关键帧时间／数值。目标可从 **按场景实例名称选择** 按名称选取，同一角色的多个实例以完整编号区分；也保留手动填写稳定 `instanceId`。
3. 使用 **检查并预览动画** 检查当前表单。初次打开有效原文也能直接播放；修改表单后需重新检查。可以播放、暂停、停止或拖动动画时间。
4. 审阅修改前后的完整原文，点击 **应用到原文草稿**，然后使用编辑器的普通保存。取消表单保留原文草稿。
5. 打开示例场景 `documents/scenes/demo.json`，选择 Godot 4 构建并运行。第一个实例在动画期间仍可用方向键移动。

**动画采样示意** 使用基本形状和实际 Rust 采样值；偏移按 12% 显示，下方保留原数值。它不加载真实场景、图片或物理。保存后的坐标、颜色和图片可在下述场景预览中查看；行为、物理和声音仍需通过后端运行。检查动画表单验证格式和曲线；实例目录就绪时还核对目标是否属于读取的已保存场景。应用前重读目录，目录变化时须刷新后重新检查。持久化保存之后的场景构建仍核对完整登记与实例归属。

## 按名称选择场景实例

打开动画表单后会读取所属场景的已保存实例目录。每条轨道的 **按场景实例名称选择** 显示角色名称和完整实例编号；选择只填入当前表单，仍需检查、审阅、应用草稿和普通保存。角色名称来自登记定义，同一个角色放置两次会有两个选项，不能用角色定义编号代替实例编号。

已删除的目标保留原编号并显示缺失提示，不会自动替换成第一项；选一个有效实例即可修复。**刷新场景实例** 重新读取目录，保留未完成的字段输入及焦点。目录更新会撤销依赖旧目录的检查结果，需重新检查后再应用。应用前也重读目录；若场景、登记或世界版本已变化，草稿不会被写入。

目录不可用、动画尚未登记或宿主未提供该能力时，手动编号和原动画字段编辑仍可使用；这时检查只验证动画本身，不确认目标存在。目录不监控磁盘，也不读取其他未保存的场景草稿。它独立读取声明身份，不要求音频、行为或执行后端可用；缺失素材不会使实例选择依赖构建成功。

目录、来源会话、三语表单与真实浏览器验收见[实例选择记录](test-results/scene-animation-targets/README.md)。首次创建与已保存场景画面预览已接入下述独立入口。

## 通道与时间

| 属性 | 意义 | 数值 |
| --- | --- | --- |
| 二维偏移 `offset2d` | 相对于演员逻辑位置的视觉偏移 | `[x, y]`，各 −10000 至 10000 |
| 二维旋转 `rotation2d` | 视觉旋转角度，允许连续多圈 | 度，−36000 至 36000 |
| 二维缩放 `scale2d` | 在场景尺寸基础上的视觉缩放 | `[x, y]`，各 0.01 至 100 |
| 不透明度 `opacity` | 乘在原演员视觉上的不透明度 | 0 至 1；0 为完全透明，1 保持原视觉不透明度 |

线性插值在相邻关键帧之间连续变化；逐帧保持保留前一帧值，到下一关键帧时切换。旋转按填写角度直接插值，例如 0→360 表示完整一圈，不自动改走最短角度。

每条轨道的首关键帧必须在 0 秒，时间严格递增且不超过动画时长。最后关键帧可早于时长，此后保持最后值。添加关键帧会优先使用末尾空余时间；末帧已到时长时使用最大间隙的中点，不自动延长整个动画。无法生成有效默认时间时，需手动调整新增关键帧时间；检查会拒绝无效时间，原有输入保留。

动画时长大于 0、至多 60 秒，包含 1–32 条轨道，每条 1–64 个关键帧，总计至多 512 个。轨道编号唯一；同一实例的同一属性只能有一条轨道，其他属性可独立变化。

循环动画在整周期边界回到 0 秒；非循环动画到末尾后保持最后状态。预览关闭、来源变化或应用草稿会结束当前播放，切到后台会暂停；切换界面语言保留输入、审阅和播放状态。

## 从场景首次创建动画

打开已保存的 Scene2D 场景，在 **构建与运行** 中选择该场景，点击 **场景动画**。这一步不需要安装或运行 Godot；场景应使用有稳定实例编号的第 2 或 3 版，并已登记实例对应的角色定义。先保存场景草稿，创建目录读取的是磁盘上的场景。

1. 选择工程已有的文档类型与 JSON 保存路径。默认优先使用 `animation`，其次是 `document`，没有这两种时使用工程的首个类型；不会替工程增添类型或改模板。
2. 按名称和完整实例编号选择目标，设置属性、时长、是否循环及末帧数值。新文档包含一条线性轨道和起止两帧：0 秒的偏移／旋转为 0，缩放为 `[1, 1]`，不透明度为 1；末帧使用填写的数值。
3. 点 **审阅新动画**，检查完整原文和双向关系，再点 **保存动画与关系**。预览不写入文件；保存一次提交新动画正文、新文档登记、场景登记三份文件。原场景正文和素材不变。
4. 点 **打开动画原文**，使用 **编辑场景动画** 继续增加轨道和关键帧。后续仍走普通草稿、审阅应用和编辑器保存。

**返回构建**、**取消创建** 和 Escape 都可以离开；改过设置后先确认丢弃。切换中英日保留输入和审阅。已有动画时入口显示原文导航，不重复创建；旧轨道目标失效时仍可打开动画修复。保存回复中断时，使用 **重新读取工程** 核对已保存文档和关系，确认前不再发送创建。

场景或登记在审阅后发生变化会拒绝旧请求，重新读取后再审阅。创建使用独立可恢复事务：中断后恢复完整旧状态或已提交状态；遇到外部修改保留冲突，不能覆盖作者的新内容。登记读取兼容单个前导 UTF-8 BOM，动画事务保留原场景登记的 BOM、换行和未改字段字节。验收范围见[首次创建记录](test-results/scene-animation-creation/README.md)。

## 在场景画面中播放已保存动画

保存动画后，在 **构建与运行 → 场景预览** 中选择所属场景。画面起初保持静态；点击 **播放动画**，或拖动 **动画时间**，即可把四种视觉变化叠加到实际坐标、颜色和图片上。**暂停动画** 保留当前画面，**停止并恢复静态场景** 恢复保存位置，平移和缩放视图不被重置。

标签、对象列表和属性继续显示已保存的逻辑位置。播放或定位动画时暂不能调整布局；停止后恢复布局编辑。未关联动画的场景保持静态；损坏的动画单独提示错误，不妨碍查看普通场景。修正并保存原文后，点击刷新重新载入。

场景、动画与图片取自同一次保存快照。此入口不读取未保存的动画表单，不运行物理、行为或声音，也不要求安装 Godot。旧宿主未声明动画预览能力时仍使用原静态预览。当前原文草稿及场景配方仍沿各自的静态预览通路。

切换场景、离开预览选项卡、关闭或刷新会清除当前播放；页面进入后台会暂停。切换中英日保留播放状态。此次源码浏览器验收见[场景动画预览记录](test-results/scene-animation-scene-preview/README.md)，不代表已更新安装版或验证游戏运行窗口。

## 动画文档与登记

动画使用独立的 `viento-scene-animation` 第 1 版 JSON，完整例子见[示例原文](../examples/scene-animation/documents/animations/demo.json)。可在 **项目类型与模板** 中按需增加动画类型；首次创建入口也支持工程现有类型。动画使用场景实例编号，不使用角色定义编号或数组行号。

登记保存在工程的 `metadata/documents` 中，新入口自动建立：

- 场景通过唯一的 `animation` 关系指向新动画文档。
- 动画文档通过 `references` 关系指回所属场景，资源绑定为空。旧的合法非归属回链仍可读取。

未建立 `animation` 关系的动画文档只作为普通数据存在；同一场景目前只选择一份动画清单。缺失目标、重复通道、损坏关系或超出预算都会阻止构建，不会静默跳过轨道。首次创建只核验保存身份和动画要求，不因无关音频、行为或渲染配置阻断；实际构建仍完整检查场景。

作者 JSON 至多 128 KiB；核心接收的紧凑 JSON 另限 64 KiB。编辑器保留 BOM、换行与未修改字段的原文；结构增删会重建对应轨道／关键帧数组。首次创建保存三份文件，已有文档的字段编辑仍只应用普通草稿，再单独保存。

## 运行与工程交付

Godot 适配器 0.12.0 为动画创建独立视觉容器。动画可以与输入移动、GDScript 行为和声音共同运行；逻辑坐标、行为节点及运行观察仍沿原通路。每次进入场景从时间 0 开始，离开时停止，重入重新计时。多个场景可以各自选择动画文档；导出工程 ZIP 包含其清单和运行脚本。

无动画的旧场景继续使用原生成器和运行脚本。Bevy 两条现有无头通路暂不支持视觉动画，会明确报告缺少能力；不能靠移除能力标记来丢弃动画。动画场景暂不接入控制重放／用例运行，普通运行和工程交付独立可用。

这是第一版视觉关键帧能力。序列帧、图集切片、骨骼、混合状态机、缓动曲线、关键帧事件和行为主动播放接口留待后续；它也不改变碰撞体或 3D 对象。
