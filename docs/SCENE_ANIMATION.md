## 先试用示例

复制完整 [examples/scene-animation](../examples/scene-animation/README.md) 到新的临时作品，再用当前源码编辑服务打开。它包含两份场景实例、四条动画轨道、类型模板和双向登记，不需要外部素材。

1. 打开 `documents/animations/demo.json`，进入原文编辑，再点 **编辑场景动画**。
2. 调整时长、循环、轨道属性与关键帧时间／数值。目标可从 **按场景实例名称选择** 按名称选取，同一角色的多个实例以完整编号区分；也保留手动填写稳定 `instanceId`。
3. 使用 **检查并预览动画** 检查当前表单。初次打开有效原文也能直接播放；修改表单后需重新检查。可以播放、暂停、停止或拖动动画时间。
4. 审阅修改前后的完整原文，点击 **应用到原文草稿**，然后使用编辑器的普通保存。取消表单保留原文草稿。
5. 打开示例场景 `documents/scenes/demo.json`，选择 Godot 4 构建并运行。第一个实例在动画期间仍可用方向键移动。

**动画采样示意** 使用基本形状和实际 Rust 采样值；偏移按 12% 显示，下方保留原数值。它不加载真实场景、图片或物理。保存后的坐标、颜色和图片可在下述场景预览中查看；行为、物理和声音仍需通过后端运行。检查动画表单验证格式和曲线；实例目录就绪时还核对目标是否属于读取的已保存场景。应用前重读目录，目录变化时须刷新后重新检查。持久化保存之后的场景构建仍核对完整登记与实例归属。

## 按名称选择场景实例

打开动画表单后会读取所属场景的已保存实例目录。每条轨道的 **按场景实例名称选择** 显示角色名称和完整实例编号；选择只填入当前表单，仍需检查、审阅、应用草稿和普通保存。角色名称来自登记定义，同一个角色放置两次会有两个选项，不能用角色定义编号代替实例编号。

已删除的目标保留原编号并显示缺失提示，不会自动替换成第一项；选一个有效实例即可修复。**刷新场景实例** 重新读取目录，保留未完成的字段输入及焦点。目录更新会撤销依赖旧目录的检查结果，需重新检查后再应用。应用前也重读目录；若场景、登记或世界版本已变化，草稿不会被写入。

目录不可用、动画尚未登记或宿主未提供该能力时，手动编号和原动画字段编辑仍可使用；这时检查只验证动画本身，不确认目标存在。目录不监控磁盘，也不读取其他未保存的场景草稿。它独立读取声明身份，不要求音频、行为或执行后端可用；缺失素材不会使实例选择依赖构建成功。

目录、来源会话、三语表单与真实浏览器验收见[实例选择记录](test-results/scene-animation-targets/README.md)。首次创建与已保存场景画面预览已接入下述独立入口。

## 通道与时间

| 属性 | 意义 | 数值 |
| --- | --- | --- |
| 二维偏移 `offset2d` | 相对于演员逻辑位置的视觉偏移 | `[x, y]`，各 −10000 至 10000 |
| 二维旋转 `rotation2d` | 视觉旋转角度，允许连续多圈 | 度，−36000 至 36000 |
| 二维缩放 `scale2d` | 在场景尺寸基础上的视觉缩放 | `[x, y]`，各 0.01 至 100 |
| 不透明度 `opacity` | 乘在原演员视觉上的不透明度 | 0 至 1；0 为完全透明，1 保持原视觉不透明度 |

线性插值在相邻关键帧之间连续变化；逐帧保持保留前一帧值，到下一关键帧时切换。旋转按填写角度直接插值，例如 0→360 表示完整一圈，不自动改走最短角度。

每条轨道的首关键帧必须在 0 秒，时间严格递增且不超过动画时长。最后关键帧可早于时长，此后保持最后值。添加关键帧会优先使用末尾空余时间；末帧已到时长时使用最大间隙的中点，不自动延长整个动画。无法生成有效默认时间时，需手动调整新增关键帧时间；检查会拒绝无效时间，原有输入保留。

动画时长大于 0、至多 60 秒，包含 1–32 条轨道，每条 1–64 个关键帧，总计至多 512 个。轨道编号唯一；同一实例的同一属性只能有一条轨道，其他属性可独立变化。

循环动画在整周期边界回到 0 秒；非循环动画到末尾后保持最后状态。预览关闭、来源变化或应用草稿会结束当前播放，切到后台会暂停；切换界面语言保留输入、审阅和播放状态。

## 整段按比例调整时长

0.1.6 后工作树可在 **编辑场景动画** 中填写独立的 **目标时长（秒）**，再点击 **按比例调整时长**。目标必须是大于 0、至多 60 秒的有限数值。操作以当前有效表单为起点，将全部关键帧时间和命名片段起止按同一比例调整；未保存的轨道数值、片段名称和其他字段编辑也会保留。

例如当前总时长 2 秒、关键帧位于 0／0.5／2 秒，片段为 0.5–2 秒，目标设为 4 秒后，关键帧变为 0／1／4 秒，片段变为 1–4 秒。数值、稳定编号、轨道／关键帧／片段顺序、插值、循环设置和图集网格不变，素材仍沿原实例引用。

1. 保持当前动画表单合法，在 **目标时长（秒）** 填入需要的时长。仅修改目标输入不会改变动画字段或已有审阅。
2. 点击 **按比例调整时长**，成功后核对回填的总时长、关键帧和片段范围。它只更新本地表单；有实际变化时须重新 **检查并预览动画**。
3. 审阅完整原文，点击 **应用到原文草稿**，再普通保存。取消表单不写盘；后续构建和工程交付读取保存后的动画。

原有时长字段仍只改变总时间边界，不会移动或裁掉关键帧／片段。若先手动缩短它，导致现有帧或片段越界，应先恢复合法时长再执行比例调整。其他无效或未填完的字段也会使整次操作拒绝，输入保留。

所有时间统一按双精度数值计算：0 秒和旧总时长精确映射到 0 秒和新总时长，相同目标时长不重新计算。不同轨道、片段边界和总时长之间的原有先后关系也必须保留；若缩放后的浮点精度使两个不同时间重合或越界，则整次拒绝，不合并、删帧或微调时间。失败或相同时长保留已有审阅和预览，作者可换一个目标时长再试。

调整本身保留动画 schema 1／2／3；当前表单另有新增序列帧或片段时，沿用普通编辑的格式升级规则。之后的原文提案按叶位置修改时间，保留 BOM、换行和无关原文。旧核心缺少此可选能力时，只禁用比例调整区域，普通字段编辑仍可使用；它不增加运行时播放速率、声音同步或后端能力。

## 复制轨道到其他实例

0.1.6 后工作树可将当前动画中的一条轨道复制给**同一场景的另一个实例**。在 **编辑场景动画 → 复制动画轨道** 中显式选择 **源动画轨道** 和 **目标场景实例**，再点击 **复制动画轨道**。目标来自已读取的有效场景实例目录，没有默认目标；目录未就绪时先用 **刷新场景实例** 读取保存态场景。

1. 保持当前完整表单合法，选择要复制的源轨道。操作使用当前未保存的关键帧、数值和网格设置，也可以选择本次表单新加的有效轨道。
2. 选择目标实例并执行复制。成功后在轨道列表末尾新增一条轨道，分配新的轨道 UUID；源轨道保留。原关键帧时间、数值、插值和网格完整复制，整份动画的时长、循环与命名片段保持。
3. 使用 **检查并预览动画** 核对结果，审阅完整原文，应用到普通草稿并保存。新轨道和源轨道之后可以分别编辑；取消表单不写盘。

同一实例的同一属性只能有一条轨道。目标已有相同属性（包括选择源实例自身）时整次拒绝，不覆盖或合并；目标已有其他属性仍可复制。复制后须继续满足最多 32 条轨道、每轨 64 帧、总计 512 帧和原文预算。无效字段、身份冲突或超限保留原表单、审阅和预览；仅改变源／目标暂选也不会使动画字段变脏。

复制只改新轨道的编号和目标实例，不复制对象、素材或绑定。偏移和缩放仍以目标自身逻辑位置／尺寸为基准；序列帧只带网格与帧号，使用目标实例自己的图片。命名片段仍是整份动画共享的时间窗口，新轨道按同一窗口采样，不生成新的片段。目标目录只证明本次保存态实例选择，图片、登记及完整场景能否构建仍由后续检查负责。

目录刷新、来源或表单变化使在途复制失效，不把迟到结果写入新会话。复制前只要求新目标属于当前目录；其他旧轨道丢失目标时仍可继续修复表单，最终检查／应用沿既有全目标复核。目录缺失或旧核心没有复制能力时，仅禁用复制区域，普通手动字段编辑保持。

复制本身保留动画 schema 1／2／3；当前表单中的其他修改仍沿普通格式升级规则。新增轨道属于结构变化，普通原文提案会重写 `tracks` 数组，数组内的空白、转义或数字拼写可能规范化；BOM、换行风格及数组外未修改字节保持。它不建立跨场景引用、持续同步或运行时克隆。实际验证范围见[轨道复制专题](test-results/scene-animation-track-copy/README.md)。

## 从场景首次创建动画

打开已保存的 Scene2D 场景，在 **构建与运行** 中选择该场景，点击 **场景动画**。这一步不需要安装或运行 Godot；场景应使用有稳定实例编号的第 2 或 3 版，并已登记实例对应的角色定义。先保存场景草稿，创建目录读取的是磁盘上的场景。

1. 选择工程已有的文档类型与 JSON 保存路径。默认优先使用 `animation`，其次是 `document`，没有这两种时使用工程的首个类型；不会替工程增添类型或改模板。
2. 按名称和完整实例编号选择目标，设置属性、时长、是否循环及末帧数值。新文档包含一条线性轨道和起止两帧：0 秒的偏移／旋转为 0，缩放为 `[1, 1]`，不透明度为 1；末帧使用填写的数值。
3. 点 **审阅新动画**，检查完整原文和双向关系，再点 **保存动画与关系**。预览不写入文件；保存一次提交新动画正文、新文档登记、场景登记三份文件。原场景正文和素材不变。
4. 点 **打开动画原文**，使用 **编辑场景动画** 继续增加轨道和关键帧。后续仍走普通草稿、审阅应用和编辑器保存。

**返回构建**、**取消创建** 和 Escape 都可以离开；改过设置后先确认丢弃。切换中英日保留输入和审阅。已有动画时入口显示原文导航，不重复创建；旧轨道目标失效时仍可打开动画修复。保存回复中断时，使用 **重新读取工程** 核对已保存文档和关系，确认前不再发送创建。

场景或登记在审阅后发生变化会拒绝旧请求，重新读取后再审阅。创建使用独立可恢复事务：中断后恢复完整旧状态或已提交状态；遇到外部修改保留冲突，不能覆盖作者的新内容。登记读取兼容单个前导 UTF-8 BOM，动画事务保留原场景登记的 BOM、换行和未改字段字节。验收范围见[首次创建记录](test-results/scene-animation-creation/README.md)。

## 在场景画面中播放已保存动画

保存动画后，在 **构建与运行 → 场景预览** 中选择所属场景。画面起初保持静态；点击 **播放动画**，或拖动 **动画时间**，即可把视觉变化叠加到实际坐标、颜色和图片上；当前工作树也支持等分图集的帧切换。**暂停动画** 保留当前画面，**停止并恢复静态场景** 恢复保存位置，平移和缩放视图不被重置。

标签、对象列表和属性继续显示已保存的逻辑位置。播放或定位动画时暂不能调整布局；停止后恢复布局编辑。未关联动画的场景保持静态；损坏的动画单独提示错误，不妨碍查看普通场景。修正并保存原文后，点击刷新重新载入。

场景、动画与图片取自同一次保存快照。此入口不读取未保存的动画表单，不运行物理、行为或声音，也不要求安装 Godot。旧宿主未声明动画预览能力时仍使用原静态预览。当前原文草稿及场景配方仍沿各自的静态预览通路。

切换场景、离开预览选项卡、关闭或刷新会清除当前播放；页面进入后台会暂停。切换中英日保留播放状态。此次源码浏览器验收见[场景动画预览记录](test-results/scene-animation-scene-preview/README.md)，不代表已更新安装版或验证游戏运行窗口。

## 动画文档与登记

动画使用独立的 `viento-scene-animation` JSON；原四属性使用第 1 版，新增序列帧使用第 2 版，命名片段使用第 3 版。原四属性的完整例子见[示例原文](../examples/scene-animation/documents/animations/demo.json)。可在 **项目类型与模板** 中按需增加动画类型；首次创建入口也支持工程现有类型。动画使用场景实例编号，不使用角色定义编号或数组行号。

登记保存在工程的 `metadata/documents` 中，新入口自动建立：

- 场景通过唯一的 `animation` 关系指向新动画文档。
- 动画文档通过 `references` 关系指回所属场景，资源绑定为空。旧的合法非归属回链仍可读取。

未建立 `animation` 关系的动画文档只作为普通数据存在；同一场景目前只选择一份动画清单。缺失目标、重复通道、损坏关系或超出预算都会阻止构建，不会静默跳过轨道。首次创建只核验保存身份和动画要求，不因无关音频、行为或渲染配置阻断；实际构建仍完整检查场景。

作者 JSON 至多 128 KiB；核心接收的紧凑 JSON 另限 64 KiB。编辑器保留 BOM、换行与未修改字段的原文；结构增删会重建对应轨道／关键帧数组。首次创建保存三份文件，已有文档的字段编辑仍只应用普通草稿，再单独保存。

## 运行与工程交付

Godot 适配器 0.12.0 为动画创建独立视觉容器。动画可以与输入移动、GDScript 行为和声音共同运行；逻辑坐标、行为节点及运行观察仍沿原通路。每次进入场景从时间 0 开始，离开时停止，重入重新计时。多个场景可以各自选择动画文档；导出工程 ZIP 包含其清单和运行脚本。

无动画的旧场景继续使用原生成器和运行脚本。Bevy 两条现有无头通路暂不支持视觉动画，会明确报告缺少能力；不能靠移除能力标记来丢弃动画。动画场景暂不接入控制重放／用例运行，普通运行和工程交付独立可用。

等分网格序列帧已在下述工作树接入。任意矩形／裁边／旋转打包图集、换图轨道、骨骼、混合状态机、缓动曲线和关键帧事件留待后续；行为主动播放接口已在下述工作树接入；动画也不改变碰撞体或 3D 对象。


## 等分网格序列帧

0.1.6 之后工作树可把目标实例现有的图片作为图集。图片从左到右、从上到下等分，帧索引从 0 开始。图片选择仍由场景／投影负责，动画文档不另存一份资源路径或图片身份；修改实例图片后，现有网格规则作用于新图片。

1. 通过既有素材导入与绑定，在场景或投影的图片字段选择图集，并保存。若尚无动画，先使用 **场景动画** 创建起始文档。
2. 打开动画原文，选择 **编辑场景动画**；新增轨道或把已有轨道的 **动画属性** 改为 **序列帧（等分网格）**。
3. 填写 **图集列数**、**图集行数** 和各关键帧的 **帧索引（从 0 开始）**。插值固定为 **逐帧保持**；到达关键帧时立刻切换，没有帧号之间的线性插值。
4. 点 **检查并预览动画**，审阅完整原文。首次使用序列帧会在提案中将动画 `schemaVersion` 从 1 升为 2；取消保留原文。点击 **应用到原文草稿** 后仍需普通保存。
5. 在 **构建与运行 → 场景预览** 播放或定位，查看实际图片帧。表单中的示意只显示基本形状和帧索引。选择 Godot 构建运行或交付生成工程，复用同一份图片资源。

网格每轴为 1–64 的整数，至多 4096 格；帧索引为 `0` 到 `columns × rows - 1` 的整数。例如 2 列、2 行的轨道：

```json
{
  "id": "12121212-1212-4212-8212-121212121212",
  "instanceId": "bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbb1",
  "property": "spriteFrame2d",
  "interpolation": "step",
  "grid": { "columns": 2, "rows": 2 },
  "keyframes": [
    { "atSeconds": 0, "value": 0 },
    { "atSeconds": 0.5, "value": 1 },
    { "atSeconds": 1, "value": 3 }
  ]
}
```

此轨道放在第 2 版动画的 `tracks` 中，时长须覆盖全部关键帧。原有时长、轨道数、关键帧数及正文大小限制继续适用；同一实例只能有一条序列帧轨道，可与偏移、旋转、缩放和不透明度组合。删除序列帧后文档保留第 2 版；旧文档不会被批量迁移。旧内核没有序列帧能力时，界面保留原有四属性。

帧切换保持实例逻辑尺寸。共享同一图片的不同实例有各自的帧状态；标签、行为和碰撞不随裁切改变。停止场景动画遵循既有静态恢复约定，显示原先的整张图片；默认静态帧属于后续独立视觉配置。

预览从同一冻结快照读取图片。整图解码尺寸按角色尺寸乘以网格行列计算，并合并共享资源需求；总解码预算仍为 16M 像素、单轴至多 16384。超过预算显示已有缺图提示，不阻断其他图片；解码失败会释放预留预算。着色缓存只处理当前格子并复用结果，总计至多 32 MiB，单项至多 16 MiB，较大的整图静态着色会降采样。等分裁切使用归一化位置，不要求作者填写原图像素坐标。

序列帧首次接入时 Godot 适配器为 0.13.0，含序列帧的计划额外要求 `animation.sprite2d`；只含原四属性的生成工程继续使用原 0.12.0 动画生成器与运行脚本。Bevy 未声明序列帧能力，准入时明确拒绝。首轮创建仍生成第 1 版四属性起始文档，随后由字段编辑添加序列帧。

## 行为控制项目动画

先给成员场景创建并保存动画，再将场景放入项目组装。在 **新建脚本 → Godot / 项目动画控制** 中选择工程自己的脚本文档类型和路径，审阅起始内容、应用普通草稿并保存。随后通过 **场景行为** 将脚本绑定到场景实例，设置 `command`（`play`、`pause`、`stop` 或 `seek`）与 `time_seconds`。最后选择**项目组装**目标构建并运行。模板的 `_ready()` 请求会等场景初始化完成后执行。

脚本通过现有 `viento_project` 行为端口控制当前场景的整份动画；同场景多实例、各视觉属性和序列帧共用一个播放头，无需再次填写动画编号。可在已有的同步项目事件回调中调用同样接口：

```gdscript
func _ready() -> void:
    if not has_meta("viento_project"):
        return
    var project = get_meta("viento_project")
    project.seek_animation(0.5)
    project.play_animation()
```

| 接口 | 执行效果 |
| --- | --- |
| `play_animation()` | 从当前播放头继续；非循环末尾从 0 秒重播 |
| `pause_animation()` | 保持当前画面和播放头 |
| `stop_animation()` | 回到动画 0 秒并停止；仍显示动画首帧 |
| `seek_animation(seconds)` | 定位并暂停；接受 0 到动画时长，循环末尾归 0 |

控制仅改变视觉动画，演员逻辑位置、行为、声音和场景时钟继续运行。后端的停止显示动画首帧；场景预览的 **停止并恢复静态场景** 则恢复保存态整图和逻辑布局，两者是各自入口的明确操作。

接口返回 `true` 表示请求已进入有界队列。初始化完成后，安全点依次处理事件、声音、动画，然后切换或关闭场景；只有实际执行的命令才写入记录。每次运行最多受理 256 条动画命令，最多 64 条待执行。场景切换撤销旧访问端口，新场景及再次进入的场景从自动播放 0 秒开始；旧端口返回 `false`。缺少动画、越界时间或超出预算会产生可定位的行为诊断，失败后不继续执行队列。

运行后的 **动画控制记录** 显示命令、执行后的播放头、当时场景时间、访问次数和状态，可按场景或动画编号筛选。**打开控制来源** 与 **打开动画声明** 分别导航本次构建冻结的行为绑定与动画文档；记录不是持续更新的当前画面。切换场景保留历史，重新运行从序号 0 开始。面板与脚本起始内容支持中、英、日。

持久动画 schema 1／2 和自动播放默认值保持。Godot 适配器 0.14.0 对含动画的项目生成 protocol 5／assembly 清单 6；无动画项目仍为 protocol 4／清单 5。旧单场景生成器继续保持原自动播放，项目脚本模板在单场景中不会获得项目端口。命名片段由下面独立增量扩展；逐轨控制、混合、骨骼、3D 与 Bevy 动画运行继续独立推进。

## 命名动画片段

行为参数现可通过 **读取动画片段 → 填入动画片段编号** 按名称选入已保存的片段，再审阅并普通保存。详见[片段编号选入](SCENE_BEHAVIORS.md#将动画片段编号填入行为参数)。

当前工作树可以在同一份动画里划分“待机”“移动”“攻击”等片段。片段共享原轨道和实例素材，只定义原时间轴上的区间，不复制关键帧或图片。名称供作者阅读，脚本通过稳定 UUID 选择；重命名不会改变编号。

1. 在 **编辑场景动画 → 命名动画片段** 添加片段，填写名称、开始、结束及独立循环设置，保留自动生成的完整编号。
2. 点击 **检查并预览动画**，在播放选择中切换 **完整动画** 或某个片段。切换会暂停到所选范围起点；滑条显示片段本地时间，旁边保留原时间轴范围。非关键帧起止点仍按原曲线插值。
3. 审阅完整原文、应用到普通草稿，再普通保存。取消不写盘。首次加入片段才升级动画 schema 3；删除最后片段仍保留 schema 3 和空列表。修改轨道不会降级或丢掉片段。
4. 已保存场景画面预览提供相同选择，使用同一 Rust 采样规则。选择和播放不改变保存数据；行为、碰撞及声音继续由运行后端处理。
5. 在 **新建脚本** 选择项目动画片段起始内容，保存后通过既有场景行为绑定，填入片段 UUID，再构建项目组装。单场景运行默认仍播放完整动画。

schema 3 在原根字段之外增加 `clips`，最多 32 项，可重叠、可为空：

```json
"clips": [
  {
    "id": "41414141-4141-4141-8141-414141414141",
    "name": "待机",
    "startSeconds": 0.25,
    "endSeconds": 0.75,
    "loop": true
  }
]
```

名称必须已去除首尾空白，长度为 1–128 个 Unicode 码点，不含换行、制表符等 ASCII 控制字符；必须满足 `0 ≤ startSeconds < endSeconds ≤ durationSeconds`。缩短总时长造成片段越界时会拒绝检查，不能静默裁剪；既有轨道、关键帧和正文预算仍适用。旧核心缺少片段能力时不能忽略片段后保存。

```gdscript
func _ready() -> void:
    if not has_meta("viento_project"):
        return
    var project = get_meta("viento_project")
    if not project.has_method("select_animation_clip"):
        return
    project.select_animation_clip("41414141-4141-4141-8141-414141414141")
    project.play_animation()
```

`select_animation_clip(id)` 选择后回到片段本地 0 秒并暂停；`select_animation_clip()` 恢复完整动画，也暂停到 0 秒。原 `play_animation/pause_animation/stop_animation/seek_animation` 操作当前选择，定位秒数相对片段起点；停止保留选择并显示该片段首帧。每次场景访问默认选择完整动画并自动播放，重入不继承之前的片段。

同帧“选择→定位→播放”按队列顺序执行，定位范围在执行时按已选择的片段校验。非法或已删除 UUID、其他场景的片段和越界定位产生行为诊断，不按名称猜替代。片段 UUID 在行为参数里仍是普通字符串，目前没有静态引用保护或自动删除迁移。返回 `true` 仅表示排队受理。

**动画控制记录** 显示所选片段、原时间轴范围及本地播放头，可按片段名称／编号筛选；**打开动画片段声明** 导航本次冻结计划中的 `/clips/N`，行为、整份动画和片段保留各自来源。记录是命令执行时的快照，不持续追踪实时画面。

**0.1.7 发布基线**：schema 3 要求 `animation.clips2d`，动画计划为第 2 版；Godot 适配器 0.15.0 对含 schema 3 的项目生成 protocol 6／清单 7。只含 schema 1／2 动画的项目继续生成 protocol 5／清单 6，无动画项目仍为 protocol 4／清单 5。Bevy 未声明动画片段支持。片段混合、状态机、关键帧事件、播放速率、骨骼与 3D 动画不在本轮范围。实际源码、Chrome、Godot 与工程交付验证见[命名片段验收](test-results/scene-animation-clips/README.md)，尚未更新安装包。


## 用项目事件触发动画片段

**新建脚本 → Godot / 事件动画片段**（`godot-project-animation-event`）组合已有项目事件与动画选择端口。它是可编辑的普通 TXT 起始内容，不增加动画格式、行为参数语义或运行协议。

1. 保存场景动画及所需命名片段，创建上述脚本草稿并普通保存。
2. 通过首次行为创建或已有行为管理，将脚本绑定到同场景实例；在行为编辑器中按需添加文本参数 `event_name` 和 `clip_id`。`event_name` 默认 `checkpoint`，留空则禁用订阅；`clip_id` 留空选择完整动画，或通过 **读取动画片段 → 填入动画片段编号** 按名称填入已保存片段的 UUID。
3. 审阅行为修改、应用普通草稿并保存，再构建项目组装。另一个作者行为负责在订阅建立后发布同名事件；此模板只订阅，不自行发布。载荷仍须满足项目事件的标量规则，模板回调不使用其值。
4. 收到事件后，回调先选择片段（空编号传 `null`），选择请求受理后再请求播放；每次事件都从所选范围本地 0 秒重播。查看 **项目事件记录** 与 **动画控制记录**，分别核对事件投递和实际动画命令。

`_ready()` 不选择、暂停或播放动画，场景原有默认自动播放保持，直到事件实际触发控制。同步回调返回 `true` 只表示选择和播放请求均已入队；事件“已处理”不证明动画已执行，更不代表片段播放完成。实际结果与问题沿用既有命令回执及行为诊断，失败时不自动改选其他片段。

脚本只在项目端口是有效对象、且具有订阅、取消订阅、选择片段与播放四个方法时订阅。普通单场景及缺少 `select_animation_clip` 的旧项目端口安全返回，即使 `clip_id` 为空也不绕过检查。退出时清空本地订阅身份并主动取消有效端口上的订阅，过期访问的 `false` 返回可忽略；场景生命周期仍会撤销旧访问订阅。该模板不提供动画状态机、混合或播放完成事件。

每次触发占两条动画请求，仍共用最多 64 条待处理、256 条累计请求的预算；没有其他动画请求时，同一批最多接受 32 次触发。所有绑定控制同一场景播放头，多个监听者按队列顺序执行，最后的选择决定后续播放范围；模板不增加去抖或缓冲。启动时需要等其他行为完成订阅后再发布，例如使用 `call_deferred`。

本轮作者界面、保存到构建和实际 Godot 的分段验证见[事件动画验收](test-results/project-event-animation/README.md)。

## 查看动画片段使用位置

0.1.6 后工作树可在 **编辑场景动画 → 命名动画片段** 的片段行点击 **查看使用位置**。面板按当前片段编号列出所属场景已关联行为文档中，值完全等于该编号的文本参数，并显示绑定、实例和参数名称。

点 **查看参数原文** 可在当前面板打开只读的已保存行为快照，选中对应参数值；多个参数写入同一编号时，各自定位到自己的位置。**重新定位参数** 只调整这份快照的选区，**刷新已保存行为** 才重新读取磁盘。原文保留 BOM、换行和转义，界面按文本控件的换行规则定位。

查询不改变动画字段、已有审阅、普通草稿或播放器；读取失败后可以重试。切换片段、移除当前片段、关闭窗口或失去读取能力时，旧回复和旧来源按钮不能作用到新的编辑会话。三语切换保留输入和原文选区。未提供此接口的旧服务仍可使用普通动画编辑。

这是**当前场景已保存行为的完整编号文字匹配**，不是全工程静态引用分析。脚本正文、其他场景、未保存行为草稿和动态拼接不在查询范围；未找到匹配不证明没有使用。当前表单新加的片段也可查看线索，查询不会替它保存。重命名保留片段编号；移除仍由普通审阅与保存完成，不自动修改参数，也不保护或迁移未来引用。

读取只核对动画和行为的声明、登记与保存修订，不读取图片、执行脚本或要求场景能完整构建。实际执行依然使用现有构建与后端校验。源码 HTTP、两种正文目录的普通保存和真实浏览器的验收见[本轮记录](test-results/scene-animation-usage/README.md)。

## 动画自然完成与片段衔接

在 **新建脚本** 选择 **Godot / 动画完成后衔接片段**，审阅后创建普通 TXT 草稿并保存，再通过已有场景行为入口关联该脚本。在行为字段表中添加两个字符串参数：

| 参数 | 用途 |
| --- | --- |
| `finished_clip_id` | 要等待自然结束的片段编号；留空表示完整动画 |
| `next_clip_id` | 完成后选择并从头播放的片段编号；留空表示完整动画 |

两项都可以用已有 **读取动画片段** 辅助按名称选择并明确填入 UUID。完整审阅、应用原文草稿和普通保存保持独立；这些参数仍是普通字符串，不会随片段删除自动修复。

例如保留“事件动画片段”行为，让 `checkpoint` 启动非循环的攻击片段；再添加一个“动画完成后衔接片段”行为，等待攻击编号，下一片段填写循环待机编号。两个脚本就绪时只订阅通知，衔接脚本不会自行启动攻击；未匹配的完成通知不产生播放命令。多个行为仍共用当前场景的一个播放头。

自然完成只在**正在播放的非循环范围到达末尾**时产生，一轮只记录一次，重播后可以再次完成。暂停／恢复保留播放进度；选择、停止、手动定位到末尾都不等于自然完成。循环片段不会发完成通知。时刻记录实际观察到完成的场景时间，不承诺恰好在理论截止时刻回调。

Godot 行为端口提供 `subscribe_animation_completed(callback)` 和 `unsubscribe_animation_completed(token)`。回调接收片段 UUID，完整动画接收 `null`，同步返回 `true` 表示处理完通知；订阅令牌只属于当前场景访问和行为。内置脚本检查端口可用性并在离开时取消订阅。单场景直接运行、旧生成工程或没有项目端口时不订阅，需重新构建带动画的项目组装来使用此能力。

自然完成与回调分两步：先留下完成记录，再在运行安全点投递。如果中间已有新的动画命令、离场或结束请求，旧通知标为跳过，避免旧攻击的结束覆盖作者的新操作。取消订阅或接收行为释放也会跳过，跳过本次不表示仍有效的订阅被永久取消。命令执行前若时钟已到末尾，会先记录自然完成，再执行命令；这类已经被新命令替代的通知仍可看到完成，但不会再驱动衔接。回调失败会留下诊断，未完成投递不能写成成功。

在 **构建与运行** 的项目运行结果中，**动画自然完成记录**独立显示自然完成、场景访问、时间、动画／片段声明与接收行为的处理或跳过情况，可筛选并回到冻结来源。它不是实时播放头；已有动画命令记录继续只表示命令执行时的状态。重新运行使用新的记录，旧来源不会误指向新任务。

每次运行最多 320 次自然完成、64 个待投递完成、1024 次接收投递；至多 64 个活动订阅，令牌累计至多 1024 个。衔接仍占原有两条选择／播放命令，沿用总计 256、同时待处理 64 条命令预算，不提供无限自动连播。

作者动画 schema 1／2／3、Rust 采样与文档持久化规则保持。新构建的含动画项目使用 Godot 适配器 0.16.0、项目 protocol 7 和生成清单 8；旧 schema 动画以完整范围参与，`clipId` 为 `null`。无动画项目继续 protocol 4，历史 protocol 1–6 观察及清单仍可验证。单独 Scene2D 的动画生成分支保持既有范围。这一步接通顺序衔接，不包含状态机图、混合、骨骼、逐实例独立播放头、Bevy 或 3D 动画。


## 从状态表生成动画脚本

在 **新建脚本 → Godot / 动画状态表** 配置状态、初始状态和转换规则。先检查完整生成源码，再点击 **创建脚本草稿**，最后使用编辑器的普通保存。取消不会创建文件。新生成的 TXT 包含版本化状态表注释，可按下节重新编辑；也可以继续手写普通源码，但手改后不再通过表格覆盖。

1. 添加 1–16 个状态。状态标识以小写字母开头，后续可用小写字母、数字和下划线，最多 32 个字符。每个状态生成一个普通文本参数 `clip_<状态标识>`：例如 `idle` 对应 `clip_idle`。改名会保留本次表格内的转换目标；删除被引用状态会留下缺失引用，必须显式修正后才能生成。
2. 明确选择初始状态，添加 0–64 条转换。每条包含起点、终点，以及 **项目事件** 或 **动画自然完成**。同一状态不能有两条相同事件规则，也不能有两条完成规则；不同状态可以响应同名事件。没有匹配规则时保持当前状态，显式指向自己的规则会从头重播。
3. 事件名沿用项目事件规则：ASCII 字母开头，后续字母、数字、`.`、`_` 或 `-`，1–64 字符，排除保留名称 `constructor`、`prototype`、`__proto__`。一张表最多使用 32 个不同事件。事件转换可选用下节的[载荷条件](#按事件载荷选择转换)；未设置条件时忽略合法标量载荷。
4. 保存生成脚本，通过现有行为入口绑定到当前场景实例；在 **编辑场景行为** 添加对应 `clip_...` 文本参数，并通过 **读取动画片段 → 填入动画片段编号** 选择片段。空参数表示完整动画；待机通常选循环片段，带完成转换的状态应选择非循环片段。新建脚本窗口没有场景归属信息，实际进入状态时由项目端口检查片段归属；构建不将这些普通文本参数视为静态片段引用。
5. 构建项目组装并运行。脚本会先完成事件和完成通知订阅，再选择并播放初始状态；事件到来或当前片段自然结束时沿匹配规则转换。使用既有 **项目事件记录**、**动画控制记录**、**动画自然完成记录**核对结果与来源。

例如建立 `idle`、`walk`、`attack` 三个状态；`idle + move → walk`，`walk + stop → idle`，`idle／walk + attack → attack`，`attack + 自然完成 → idle`。在行为中填入 `clip_idle`、`clip_walk`、`clip_attack`，事件发布由其他普通行为负责。表格不隐式增加输入绑定、攻击锁、返回上一状态或条件表达式。

状态指脚本已受理的转换目标，选择和播放仍是两条排队命令；同步返回成功不是引擎执行回执。第二条请求失败时控制器停止处理并清理订阅，已受理的第一条请求不会回滚。事件与完成同一安全点到达时，沿既有 protocol 7 顺序先执行事件及动画命令，过期完成通知会跳过。

当前播放头属于整个场景；同一场景应只绑定一份状态控制脚本，并避免另一行为同时控制动画。此表可查看当前声明的[静态状态图](#查看状态转换图)，尚无多角色独立播放、所有权仲裁、层级状态或混合。完成匹配使用进入状态时捕获的片段；参数在就绪时读取，运行中改变导出字段不会自动重配表。

Rust 纯核心负责有界表格校验和索引化结果，独立 Godot 发射器生成普通源码，界面只负责表单及审阅；旧核心缺少可选支持时仍可创建其他脚本。既有动画／行为作者格式、protocol 7、Godot 适配器 0.16.0 及工程交付方式保持。本轮验证见[状态表专题](test-results/animation-state-table/README.md)。


## 重新编辑已保存的状态表

打开含状态表声明的 TXT，在原文编辑模式点击 **编辑动画状态表**。这个入口读取当前原文草稿，包括尚未保存的合法状态表修改；它不会从磁盘重新载入并盖掉草稿。新建脚本尚未第一次保存时，先完成普通保存再使用这个入口。

1. 修改初始状态、状态或事件／自然完成转换，点击 **检查并生成脚本**。窗口展示修改前后完整原文，任何继续改表都会撤销上次审阅。没有变化时不产生新草稿。
2. 检查新增和移除的 `clip_...` 参数。状态改名或删除会改变导出参数集合；已保存的行为绑定不会自动迁移；保存脚本后，先[查看脚本使用位置](SCENE_BEHAVIORS.md#从脚本查看使用位置)定位已登记绑定，再在行为编辑器[按接口补齐或显式更名参数](SCENE_BEHAVIORS.md#根据脚本接口修复参数)。这里只审阅和修改脚本，不保证所有引用该脚本的行为仍可构建。
3. 点击 **应用到原文草稿**，回到编辑器检查内容，再普通保存。文件路径、文档身份、登记和行为关系保持；取消或返回不会写正文。重新打开表格可继续编辑尚未保存的生成源码。

第一行是简短的脚本标题；第二行 `#@viento-animation-state-script ` 后的单行 JSON 保存 `format`、声明 `schemaVersion: 1`、独立生成器标识 `godot-gdscript-v1` 与中立状态表。该注释和生成的 GDScript 一起存于同一 TXT，无旁置文件。生成器标识与产品、运行协议版本分别维护；运行时仍使用既有项目接口，不读取表格注释来执行行为。

打开时，Rust 检查表格，固定版本发射器重建完整源码；只有逐字匹配才允许表格修改。可选 BOM 与统一 LF／CRLF 会保留，混合换行不自动整理。即使声明看起来合法，手改函数、默认参数、注释、增加代码或未知生成版本都会阻止表格覆盖，并保留原文供普通源码编辑。旧无声明脚本继续按普通 TXT 使用，不猜测转换，也不自动迁移。

这项能力是声明式源码的再次编辑，不是任意 GDScript 的逆向解析。场景播放头、状态键对应参数和既有运行预算沿用上一节；每实例播放、混合和运行中的状态观察继续独立推进；当前表格可查看下节的静态转换图。实际范围见[重编辑验证](test-results/animation-state-reedit/README.md)。


## 查看状态转换图

在 **新建脚本** 的动画状态表，或 **编辑动画状态表** 中，展开 **查看状态图**。图读取当前表格，包括尚未保存的修改。初始状态单独标记；箭头表示事件或自然完成的声明方向。没有转换的状态也会显示，自循环和双向转换保留；同一对状态间的多条转换可以共用图中连线，详细触发条件分别列出。

选择状态或转换后，可点击 **定位状态字段** 或 **定位转换字段** 回到表格修改。图的选择、展开、收起和字段定位只改变视图，不修改表格，也不使已完成的源码审阅失效。实际修改字段后，图和审阅仍按原有编辑流程更新。窄屏可在图区域内滚动，状态和转换的文字列表提供同等选择与定位入口；中英日切换保留作者输入。

图只在当前完整表格通过 Rust 检查后显示。状态标识未填写、引用缺失、同一状态重复触发等情况会清除旧图并提示修正；恢复合法字段后可继续查看。旧核心不支持状态表时显示能力不可用，不用前端猜测生成图。删除状态再新增同名状态，仍须明确修复原有缺失引用。

这是一份静态声明视图，无法说明运行时正处于哪个状态、事件是否发生或片段是否存在。图中不编辑连线、不保存额外布局；完整源码审阅、应用普通草稿和保存仍由现有编辑器完成。手改或未知版本脚本的表格准入规则保持。真实浏览器、来源保存和边界验证见[状态图验收](test-results/animation-state-graph/README.md)。


## 按事件载荷选择转换

在新建或重编辑动画状态表的事件转换中，将 **事件载荷条件** 从 **无条件** 切换为 **比较事件载荷**，选择类型、比较方式和值。例如 `idle + move → walk` 设置 **数字 / 大于 / 0**，只有 `move` 携带正数时才切换。条件不满足会忽略这次事件，不改变状态或中断其他事件接收者。

| 类型 | 比较方式 | 值范围 |
| --- | --- | --- |
| 布尔值 | 等于、不等于 | `true` 或 `false` |
| 数字 | 等于、不等于、小于、小于或等于、大于、大于或等于 | 有限数，绝对值不超过 1,000,000,000 |
| 字符串 | 等于、不等于 | 有效 Unicode，UTF-8 最多 4096 字节；允许空字符串 |

条件保留明确类型。布尔值 `false`、数字 `0` 和字符串 `"0"` 不相等；类型不同时，即使选 **不等于** 也不触发。Godot 整数和浮点数共用数字类型，按精确双精度值比较，不使用近似容差；负零与零相等。数字输入空白或尚未填写完成时不能生成脚本，也不会被解释成零。

只有事件转换可设置条件。临时切换为自然完成会隐藏条件并保留当前窗口的输入，切回事件可继续编辑；生成的自然完成声明没有条件。同一状态对同一事件仍只允许一条转换，不支持按行优先级设置多个条件分支、共享状态查询、复合表达式或任意代码条件。静态图文字显示条件类型、运算符和值，但不模拟实际载荷。

无条件脚本继续使用 `godot-gdscript-v1`，源码生成结果保持。至少一条事件带条件时使用 `godot-gdscript-v2`；移除最后一个条件后，可以通过完整源码审阅、应用草稿和普通保存明确恢复 v1。两个版本都只允许精确重建的固定源码再次编辑，手改正文或未知版本仍由普通源码编辑器处理。BOM与一致的CRLF保留。有条件声明最多32 KiB，数值比较值按每项32字节保守计入预算，避免不同JSON序列化造成边界差异。v2 完整源码包含声明、BOM及换行，最多64 KiB；超出时应缩短条件文本或减少转换。条件不会增加行为绑定参数，原有 `clip_<状态键>` 接口保持。

条件检查与比较由独立 Rust 核心能力负责；旧核心可继续处理无条件表，无法生成或重新审阅带条件表，不会静默移除已有条件。比较值经固定Godot生成器编码，运行端口、协议7和适配器0.16.0保持。Godot对内嵌NUL的字符串表示有限制：核心和声明可保留该字符，运行比较避免误命中截断前缀，但不保证这类载荷能完整往返。实际Rust/WASM、Godot、工程ZIP与Chrome范围见[条件验收](test-results/animation-state-conditions/README.md)。
