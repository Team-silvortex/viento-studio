## 先试用示例

复制完整 [examples/scene-animation](../examples/scene-animation/README.md) 到新的临时作品，再用当前源码编辑服务打开。它包含两份场景实例、四条动画轨道、类型模板和双向登记，不需要外部素材。

1. 打开 `documents/animations/demo.json`，进入原文编辑，再点 **编辑场景动画**。
2. 调整时长、循环、轨道属性与关键帧时间／数值。目标可从 **按场景实例名称选择** 按名称选取，同一角色的多个实例以完整编号区分；也保留手动填写稳定 `instanceId`。
3. 使用 **检查并预览动画** 检查当前表单。初次打开有效原文也能直接播放；修改表单后需重新检查。可以播放、暂停、停止或拖动动画时间。
4. 审阅修改前后的完整原文，点击 **应用到原文草稿**，然后使用编辑器的普通保存。取消表单保留原文草稿。
5. 打开示例场景 `documents/scenes/demo.json`，选择 Godot 4 构建并运行。第一个实例在动画期间仍可用方向键移动。

**动画采样示意** 使用基本形状和实际 Rust 采样值；偏移按 12% 显示，下方保留原数值。它不加载真实场景、图片或物理。保存后的坐标、颜色和图片可在下述场景预览中查看；行为、物理和声音仍需通过后端运行。检查动画表单验证格式和曲线；实例目录就绪时还核对目标是否属于读取的已保存场景。应用前重读目录，目录变化时须刷新后重新检查。持久化保存之后的场景构建仍核对完整登记与实例归属。

## 按名称选择场景实例

打开动画表单后会读取所属场景的已保存实例目录。每条轨道的 **按场景实例名称选择** 显示角色名称和完整实例编号；选择只填入当前表单，仍需检查、审阅、应用草稿和普通保存。角色名称来自登记定义，同一个角色放置两次会有两个选项，不能用角色定义编号代替实例编号。

已删除的目标保留原编号并显示缺失提示，不会自动替换成第一项；选一个有效实例即可修复。**刷新场景实例** 重新读取目录，保留未完成的字段输入及焦点。目录更新会撤销依赖旧目录的检查结果，需重新检查后再应用。应用前也重读目录；若场景、登记或世界版本已变化，草稿不会被写入。

目录不可用、动画尚未登记或宿主未提供该能力时，手动编号和原动画字段编辑仍可使用；这时检查只验证动画本身，不确认目标存在。目录不监控磁盘，也不读取其他未保存的场景草稿。它独立读取声明身份，不要求音频、行为或执行后端可用；缺失素材不会使实例选择依赖构建成功。

目录、来源会话、三语表单与真实浏览器验收见[实例选择记录](test-results/scene-animation-targets/README.md)。首次创建与已保存场景画面预览已接入下述独立入口。

## 通道与时间

| 属性 | 意义 | 数值 |
| --- | --- | --- |
| 二维偏移 `offset2d` | 相对于演员逻辑位置的视觉偏移 | `[x, y]`，各 −10000 至 10000 |
| 二维旋转 `rotation2d` | 视觉旋转角度，允许连续多圈 | 度，−36000 至 36000 |
| 二维缩放 `scale2d` | 在场景尺寸基础上的视觉缩放 | `[x, y]`，各 0.01 至 100 |
| 不透明度 `opacity` | 乘在原演员视觉上的不透明度 | 0 至 1；0 为完全透明，1 保持原视觉不透明度 |

线性插值在相邻关键帧之间连续变化；逐帧保持保留前一帧值，到下一关键帧时切换。旋转按填写角度直接插值，例如 0→360 表示完整一圈，不自动改走最短角度。

每条轨道的首关键帧必须在 0 秒，时间严格递增且不超过动画时长。最后关键帧可早于时长，此后保持最后值。添加关键帧会优先使用末尾空余时间；末帧已到时长时使用最大间隙的中点，不自动延长整个动画。无法生成有效默认时间时，需手动调整新增关键帧时间；检查会拒绝无效时间，原有输入保留。

动画时长大于 0、至多 60 秒，包含 1–32 条轨道，每条 1–64 个关键帧，总计至多 512 个。轨道编号唯一；同一实例的同一属性只能有一条轨道，其他属性可独立变化。

循环动画在整周期边界回到 0 秒；非循环动画到末尾后保持最后状态。预览关闭、来源变化或应用草稿会结束当前播放，切到后台会暂停；切换界面语言保留输入、审阅和播放状态。

## 整段按比例调整时长

可在 **编辑场景动画** 中填写独立的 **目标时长（秒）**，再点击 **按比例调整时长**。目标必须是大于 0、至多 60 秒的有限数值。操作以当前有效表单为起点，将全部关键帧时间和命名片段起止按同一比例调整；未保存的轨道数值、片段名称和其他字段编辑也会保留。

例如当前总时长 2 秒、关键帧位于 0／0.5／2 秒，片段为 0.5–2 秒，目标设为 4 秒后，关键帧变为 0／1／4 秒，片段变为 1–4 秒。数值、稳定编号、轨道／关键帧／片段顺序、插值、循环设置和图集网格不变，素材仍沿原实例引用。

1. 保持当前动画表单合法，在 **目标时长（秒）** 填入需要的时长。仅修改目标输入不会改变动画字段或已有审阅。
2. 点击 **按比例调整时长**，成功后核对回填的总时长、关键帧和片段范围。它只更新本地表单；有实际变化时须重新 **检查并预览动画**。
3. 审阅完整原文，点击 **应用到原文草稿**，再普通保存。取消表单不写盘；后续构建和工程交付读取保存后的动画。

原有时长字段仍只改变总时间边界，不会移动或裁掉关键帧／片段。若先手动缩短它，导致现有帧或片段越界，应先恢复合法时长再执行比例调整。其他无效或未填完的字段也会使整次操作拒绝，输入保留。

所有时间统一按双精度数值计算：0 秒和旧总时长精确映射到 0 秒和新总时长，相同目标时长不重新计算。不同轨道、片段边界和总时长之间的原有先后关系也必须保留；若缩放后的浮点精度使两个不同时间重合或越界，则整次拒绝，不合并、删帧或微调时间。失败或相同时长保留已有审阅和预览，作者可换一个目标时长再试。

调整本身保留动画 schema 1／2／3／4 及已有运行范围；当前表单另有新增序列帧或片段时，沿用普通编辑的格式升级规则。之后的原文提案按叶位置修改时间，保留 BOM、换行和无关原文。旧核心缺少此可选能力时，只禁用比例调整区域，普通字段编辑仍可使用；它不增加运行时播放速率、声音同步或后端能力。

## 复制轨道到其他实例

可将当前动画中的一条轨道复制给**同一场景的另一个实例**。在 **编辑场景动画 → 复制动画轨道** 中显式选择 **源动画轨道** 和 **目标场景实例**，再点击 **复制动画轨道**。目标来自已读取的有效场景实例目录，没有默认目标；目录未就绪时先用 **刷新场景实例** 读取保存态场景。

1. 保持当前完整表单合法，选择要复制的源轨道。操作使用当前未保存的关键帧、数值和网格设置，也可以选择本次表单新加的有效轨道。
2. 选择目标实例并执行复制。成功后在轨道列表末尾新增一条轨道，分配新的轨道 UUID；源轨道保留。原关键帧时间、数值、插值和网格完整复制，整份动画的时长、循环与命名片段保持。
3. 使用 **检查并预览动画** 核对结果，审阅完整原文，应用到普通草稿并保存。新轨道和源轨道之后可以分别编辑；取消表单不写盘。

同一实例的同一属性只能有一条轨道。目标已有相同属性（包括选择源实例自身）时整次拒绝，不覆盖或合并；目标已有其他属性仍可复制。复制后须继续满足最多 32 条轨道、每轨 64 帧、总计 512 帧和原文预算。无效字段、身份冲突或超限保留原表单、审阅和预览；仅改变源／目标暂选也不会使动画字段变脏。

复制只改新轨道的编号和目标实例，不复制对象、素材或绑定。偏移和缩放仍以目标自身逻辑位置／尺寸为基准；序列帧只带网格与帧号，使用目标实例自己的图片。命名片段仍是整份动画共享的时间窗口，新轨道按同一窗口采样，不生成新的片段。目标目录只证明本次保存态实例选择，图片、登记及完整场景能否构建仍由后续检查负责。

目录刷新、来源或表单变化使在途复制失效，不把迟到结果写入新会话。复制前只要求新目标属于当前目录；其他旧轨道丢失目标时仍可继续修复表单，最终检查／应用沿既有全目标复核。目录缺失或旧核心没有复制能力时，仅禁用复制区域，普通手动字段编辑保持。

复制本身保留动画 schema 1／2／3／4 及已有运行范围；当前表单中的其他修改仍沿普通格式升级规则。新增轨道属于结构变化，普通原文提案会重写 `tracks` 数组，数组内的空白、转义或数字拼写可能规范化；BOM、换行风格及数组外未修改字节保持。它不建立跨场景引用、持续同步或运行时克隆。实际验证范围见[轨道复制专题](test-results/scene-animation-track-copy/README.md)。

## 按实例预览已保存动画

在 **构建与运行 → 场景预览 → 已保存场景动画** 增加 **动画预览范围**。选择 **按实例预览** 后，按名称与实例编号选择角色，再选择完整动画或命名片段。列表仅包含当前保存态动画有轨道的实例；同一角色定义的两份实例各自保留选择和进度。

- **播放／暂停选中实例** 和时间条只控制当前实例。切换实例选择时，其他实例继续播放；各实例的状态与进度可在下方列表对照。
- **停止选中实例** 恢复该实例的静态图形，保留它选择的片段；其他播放、暂停或末帧画面保持。**全部恢复静态** 停止所有实例，随后可重新编辑场景布局。
- 非循环片段停在自己的末帧，循环片段独立循环。片段时间从 0 开始，仍复用原时间轴和关键帧。动画 schema 1／2 可独立预览完整动画，命名片段要求 schema 3／4。
- 切换中英日保留输入节点、焦点和播放进度。进入后台会暂停所有实例并保留最后绘制画面；离开预览、刷新场景或切换预览范围会恢复静态并清理当前会话。

这项选择只用于当前保存态画面预览，不写入动画或场景，也不执行行为、状态脚本、声音和物理。标签、对象列表及属性继续表示逻辑位置；存在任何预览画面时暂停布局编辑，平移和缩放仍可用。预览数量沿现有最多 32 条轨道约束，不扩大作者预算。

独立会话按稳定实例身份分组，播放与采样规则仍由 Rust 负责；每份样本保留自己的时间，Canvas 在整层校验通过后一次替换画面。源码或快照失效、采样失败会撤销旧回调并恢复静态。

这里的逐实例预览不会改变作者保存的运行范围、状态脚本或生成工程。正式运行需独立选择下节的范围并保存；旧项目仍按整场景运行。预览的既有验证见[本轮验收](test-results/scene-animation-instance-preview/README.md)。

## 为正式运行选择播放范围

已有场景尚无组装时，可在 **构建与运行 → 用当前场景创建组装** 预填单成员项目，经审阅和保存后继续构建；见[从当前场景开始](PROJECT_ASSEMBLY.md#从当前场景开始)。

1. 打开动画原文，进入 **编辑场景动画 → 运行播放范围**。选择 **整场景共用播放** 或 **每个实例独立播放**。
2. 点击 **检查并预览动画**，核对完整原文及变化路径。首次从旧文档选择逐实例范围时，候选升级到动画 `schemaVersion: 4`，明确写入 `playbackScope: "instance"`；既有轨道与片段保留。
3. 点击 **应用到原文草稿**，再使用编辑器的普通保存。检查和预览不写文件，取消不会升级；单纯打开旧格式也不补写范围。版本4切回 `scene` 时仍保留版本4，不自动降级。
4. 选择 **项目组装** 目标重新检查、构建并运行。单独场景构建不支持 `instance` 范围，会明确报告 `build_animation_instances_require_project`；保存态场景预览仍可单独使用。

`scene` 保留一个场景播放头，进入场景后按原规则自动播放完整动画。`instance` 只为动画有轨道的实例建立独立播放状态，初始停止；行为可先选择片段，调用现有播放接口才开始推进，状态表控制器会在就绪时主动选择并播放初始状态。相同角色定义的两份实例按实例UUID区分；一个实例的多个行为仍共用该实例的播放状态，没有自动所有权仲裁或混合。

目标由已保存范围和行为所属实例决定，不能通过片段参数名或显示名推断。选择、暂停、停止、定位及自然完成只作用对应目标；轨道和命名片段仍保存在同一份动画声明中，不复制资源或改写状态表脚本。动画没有该绑定实例的轨道时，逐实例端口不会控制另一个角色。改变范围不要求迁移已有 v1–v5 状态表作者源码，参数配置仍使用[按状态配置动画片段](#按状态配置动画片段)。

**正式 `stop_animation()`** 把所选范围的本地播放头设为0并显示该处采样；选择具名片段时是片段起点，保留片段选择。**预览停止** 则撤销临时视觉覆盖、恢复作者静态画面。预览的“动画预览范围”与本字段相互独立，临时切换不产生保存修改。

文档4包含必需的 `playbackScope` 和沿用版本3规则的 `clips`（可为空），对应动画子计划3；场景及组装父计划格式保持。只有项目包含 `instance` 范围时要求 `animation.instances2d` 并生成 **项目协议11／清单12**。当前 Godot 执行适配器为 0.22.0；整场景、逐实例与物理组合使用的生成器及协议分别见[当前项目协议选择](PROJECT_BUILD.md#当前项目协议选择)。旧格式读取不迁移作品；生成缓存需按适配器指纹重新构建。Bevy 尚未接入逐实例正式动画。

协议11的 **动画控制记录** 和 **动画自然完成记录** 显示明确的整场景／实例目标，可按实例筛选。完成记录分别显示“目标最后命令序号”和“全部命令截止”：前者核对同目标的最后命令，后者保留全项目顺序。其他实例的新命令不会使当前目标的完成通知失效；同目标被后续命令替代、访问结束或订阅撤销时，旧通知仍按规则跳过。全局请求、完成和投递预算不按实例翻倍。

运行端校验原端口对象、场景访问、登记绑定和实际行为身份，拒绝修改兼容字段或替换绑定记录后借此重定向动画。这是公开端口的来源身份约束，不是GDScript代码沙箱；作者脚本仍在本机引擎进程中运行。中间层边界见[架构](ARCHITECTURE.md#逐实例正式动画运行边界)，准确验收范围见[本轮记录](test-results/animation-instance-runtime/README.md)。

## 从场景首次创建动画

打开已保存的 Scene2D 场景，在 **构建与运行** 中选择该场景，点击 **场景动画**。这一步不需要安装或运行 Godot；场景应使用有稳定实例编号的第 2 或 3 版，并已登记实例对应的角色定义。先保存场景草稿，创建目录读取的是磁盘上的场景。

1. 选择工程已有的文档类型与 JSON 保存路径。默认优先使用 `animation`，其次是 `document`，没有这两种时使用工程的首个类型；不会替工程增添类型或改模板。
2. 按名称和完整实例编号选择目标，设置属性、时长、是否循环及末帧数值。新文档包含一条线性轨道和起止两帧：0 秒的偏移／旋转为 0，缩放为 `[1, 1]`，不透明度为 1；末帧使用填写的数值。
3. 点 **审阅新动画**，检查完整原文和双向关系，再点 **保存动画与关系**。预览不写入文件；保存一次提交新动画正文、新文档登记、场景登记三份文件。原场景正文和素材不变。
4. 点 **打开动画原文**，使用 **编辑场景动画** 继续增加轨道和关键帧。后续仍走普通草稿、审阅应用和编辑器保存。

**返回构建**、**取消创建** 和 Escape 都可以离开；改过设置后先确认丢弃。切换中英日保留输入和审阅。已有动画时入口显示原文导航，不重复创建；旧轨道目标失效时仍可打开动画修复。保存回复中断时，使用 **重新读取工程** 核对已保存文档和关系，确认前不再发送创建。

场景或登记在审阅后发生变化会拒绝旧请求，重新读取后再审阅。创建使用独立可恢复事务：中断后恢复完整旧状态或已提交状态；遇到外部修改保留冲突，不能覆盖作者的新内容。登记读取兼容单个前导 UTF-8 BOM，动画事务保留原场景登记的 BOM、换行和未改字段字节。验收范围见[首次创建记录](test-results/scene-animation-creation/README.md)。

## 在场景画面中播放已保存动画

保存动画后，在 **构建与运行 → 场景预览** 中选择所属场景。画面起初保持静态；点击 **播放动画**，或拖动 **动画时间**，即可把视觉变化叠加到实际坐标、颜色和图片上；等分图集轨道同时支持帧切换。**暂停动画** 保留当前画面，**停止并恢复静态场景** 恢复保存位置，平移和缩放视图不被重置。

标签、对象列表和属性继续显示已保存的逻辑位置。播放或定位动画时暂不能调整布局；停止后恢复布局编辑。未关联动画的场景保持静态；损坏的动画单独提示错误，不妨碍查看普通场景。修正并保存原文后，点击刷新重新载入。

场景、动画与图片取自同一次保存快照。此入口不读取未保存的动画表单，不运行物理、行为或声音，也不要求安装 Godot。旧宿主未声明动画预览能力时仍使用原静态预览。当前原文草稿及场景配方仍沿各自的静态预览通路。

切换场景、离开预览选项卡、关闭或刷新会清除当前播放；页面进入后台会暂停。切换中英日保留播放状态。此次源码浏览器验收见[场景动画预览记录](test-results/scene-animation-scene-preview/README.md)，不代表已更新安装版或验证游戏运行窗口。

## 动画文档与登记

动画使用独立的 `viento-scene-animation` JSON；原四属性使用第 1 版，新增序列帧使用第 2 版，命名片段使用第 3 版，显式运行范围使用第 4 版。第4版的 `playbackScope` 必须为 `scene` 或 `instance`，其 `clips` 沿用第3版规则。原四属性的完整例子见[示例原文](../examples/scene-animation/documents/animations/demo.json)。可在 **项目类型与模板** 中按需增加动画类型；首次创建入口也支持工程现有类型。动画使用场景实例编号，不使用角色定义编号或数组行号。

登记保存在工程的 `metadata/documents` 中，新入口自动建立：

- 场景通过唯一的 `animation` 关系指向新动画文档。
- 动画文档通过 `references` 关系指回所属场景，资源绑定为空。旧的合法非归属回链仍可读取。

未建立 `animation` 关系的动画文档只作为普通数据存在；同一场景目前只选择一份动画清单。缺失目标、重复通道、损坏关系或超出预算都会阻止构建，不会静默跳过轨道。首次创建只核验保存身份和动画要求，不因无关音频、行为或渲染配置阻断；实际构建仍完整检查场景。

作者 JSON 至多 128 KiB；核心接收的紧凑 JSON 另限 64 KiB。编辑器保留 BOM、换行与未修改字段的原文；结构增删会重建对应轨道／关键帧数组。首次创建保存三份文件，已有文档的字段编辑仍只应用普通草稿，再单独保存。

## 运行与工程交付

动画首次接入时，Godot 适配器 0.12.0 为动画创建独立视觉容器。动画可以与输入移动、GDScript 行为和声音共同运行；逻辑坐标、行为节点及运行观察仍沿原通路。每次进入场景从时间 0 开始，离开时停止，重入重新计时；整场景范围自动播放，显式逐实例范围初始停止并等待行为控制。多个场景可以各自选择动画文档；导出工程 ZIP 包含其清单和运行脚本。

无动画的旧场景继续使用原生成器和运行脚本。Bevy 两条现有无头通路暂不支持视觉动画，会明确报告缺少能力；不能靠移除能力标记来丢弃动画。动画场景暂不接入控制重放／用例运行，普通运行和工程交付独立可用。

等分网格序列帧见下一节。任意矩形／裁边／旋转打包图集、换图轨道、骨骼、混合状态机、缓动曲线和关键帧事件留待后续；行为主动播放见[项目动画控制](#行为控制项目动画)；动画也不改变碰撞体或 3D 对象。


## 等分网格序列帧

可把目标实例现有的图片作为图集。图片从左到右、从上到下等分，帧索引从 0 开始。图片选择仍由场景／投影负责，动画文档不另存一份资源路径或图片身份；修改实例图片后，现有网格规则作用于新图片。

1. 通过既有素材导入与绑定，在场景或投影的图片字段选择图集，并保存。若尚无动画，先使用 **场景动画** 创建起始文档。
2. 打开动画原文，选择 **编辑场景动画**；新增轨道或把已有轨道的 **动画属性** 改为 **序列帧（等分网格）**。
3. 填写 **图集列数**、**图集行数** 和各关键帧的 **帧索引（从 0 开始）**。插值固定为 **逐帧保持**；到达关键帧时立刻切换，没有帧号之间的线性插值。
4. 点 **检查并预览动画**，审阅完整原文。首次使用序列帧会在提案中将动画 `schemaVersion` 从 1 升为 2；取消保留原文。点击 **应用到原文草稿** 后仍需普通保存。
5. 在 **构建与运行 → 场景预览** 播放或定位，查看实际图片帧。表单中的示意只显示基本形状和帧索引。选择 Godot 构建运行或交付生成工程，复用同一份图片资源。

网格每轴为 1–64 的整数，至多 4096 格；帧索引为 `0` 到 `columns × rows - 1` 的整数。例如 2 列、2 行的轨道：

```json
{
  "id": "12121212-1212-4212-8212-121212121212",
  "instanceId": "bbbbbbbb-bbbb-4bbb-8bbb-bbbbbbbbbbb1",
  "property": "spriteFrame2d",
  "interpolation": "step",
  "grid": { "columns": 2, "rows": 2 },
  "keyframes": [
    { "atSeconds": 0, "value": 0 },
    { "atSeconds": 0.5, "value": 1 },
    { "atSeconds": 1, "value": 3 }
  ]
}
```

此轨道放在第 2 版动画的 `tracks` 中，时长须覆盖全部关键帧。原有时长、轨道数、关键帧数及正文大小限制继续适用；同一实例只能有一条序列帧轨道，可与偏移、旋转、缩放和不透明度组合。删除序列帧后文档保留第 2 版；旧文档不会被批量迁移。旧内核没有序列帧能力时，界面保留原有四属性。

帧切换保持实例逻辑尺寸。共享同一图片的不同实例有各自的帧状态；标签、行为和碰撞不随裁切改变。停止场景动画遵循既有静态恢复约定，显示原先的整张图片；默认静态帧属于后续独立视觉配置。

预览从同一冻结快照读取图片。整图解码尺寸按角色尺寸乘以网格行列计算，并合并共享资源需求；总解码预算仍为 16M 像素、单轴至多 16384。超过预算显示已有缺图提示，不阻断其他图片；解码失败会释放预留预算。着色缓存只处理当前格子并复用结果，总计至多 32 MiB，单项至多 16 MiB，较大的整图静态着色会降采样。等分裁切使用归一化位置，不要求作者填写原图像素坐标。

序列帧首次接入时 Godot 适配器为 0.13.0，含序列帧的计划额外要求 `animation.sprite2d`；只含原四属性的生成工程继续使用原 0.12.0 动画生成器与运行脚本。Bevy 未声明序列帧能力，准入时明确拒绝。首轮创建仍生成第 1 版四属性起始文档，随后由字段编辑添加序列帧。

## 行为控制项目动画

先给成员场景创建并保存动画，再将场景放入项目组装。在 **新建脚本 → Godot / 项目动画控制** 中选择工程自己的脚本文档类型和路径，审阅起始内容、应用普通草稿并保存。随后通过 **场景行为** 将脚本绑定到场景实例，设置 `command`（`play`、`pause`、`stop` 或 `seek`）与 `time_seconds`。最后选择**项目组装**目标构建并运行。模板的 `_ready()` 请求会等场景初始化完成后执行。

脚本通过现有 `viento_project` 行为端口控制动画，无需再次填写动画编号。整场景范围下所有实例共用一个播放头；[逐实例范围](#为正式运行选择播放范围)下，端口只控制该绑定所属实例的轨道，各实例独立选择片段和推进。可在已有的同步项目事件回调中调用同样接口：

```gdscript
func _ready() -> void:
    if not has_meta("viento_project"):
        return
    var project = get_meta("viento_project")
    project.seek_animation(0.5)
    project.play_animation()
```

| 接口 | 执行效果 |
| --- | --- |
| `play_animation()` | 从当前播放头继续；非循环末尾从 0 秒重播 |
| `pause_animation()` | 保持当前画面和播放头 |
| `stop_animation()` | 回到所选范围本地 0 秒并停止，保留片段选择并显示起点采样 |
| `seek_animation(seconds)` | 定位并暂停；接受 0 到动画时长，循环末尾归 0 |

控制仅改变视觉动画，演员逻辑位置、行为、声音和场景时钟继续运行。后端的停止显示所选范围的起点采样；场景预览的 **停止并恢复静态场景** 则恢复保存态整图和逻辑布局，两者是各自入口的明确操作。

接口返回 `true` 表示请求已进入有界队列。初始化完成后，安全点依次处理事件、声音、动画，然后切换或关闭场景；只有实际执行的命令才写入记录。每次运行最多受理 256 条动画命令，最多 64 条待执行。场景切换撤销旧访问端口，新场景及再次进入的场景从 0 秒开始：整场景自动播放，逐实例初始停止；旧端口返回 `false`。缺少动画、越界时间或超出预算会产生可定位的行为诊断，失败后不继续执行队列。

运行后的 **动画控制记录** 显示命令、执行后的播放头、当时场景时间、访问次数和状态，可按场景或动画编号筛选。**打开控制来源** 与 **打开动画声明** 分别导航本次构建冻结的行为绑定与动画文档；记录不是持续更新的当前画面。切换场景保留历史，重新运行从序号 0 开始。面板与脚本起始内容支持中、英、日。

项目动画控制首次接入时，持久动画 schema 1／2 和自动播放默认值保持。Godot 适配器 0.14.0 对含动画的项目生成 protocol 5／assembly 清单 6；无动画项目仍为 protocol 4／清单 5。旧单场景生成器继续保持原自动播放，项目脚本模板在单场景中不会获得项目端口。命名片段由下面独立增量扩展；逐轨控制、混合、骨骼、3D 与 Bevy 动画运行继续独立推进。

## 命名动画片段

行为参数现可通过 **读取动画片段 → 填入动画片段编号** 按名称选入已保存的片段，再审阅并普通保存。详见[片段编号选入](SCENE_BEHAVIORS.md#将动画片段编号填入行为参数)。

可以在同一份动画里划分“待机”“移动”“攻击”等片段。片段共享原轨道和实例素材，只定义原时间轴上的区间，不复制关键帧或图片。名称供作者阅读，脚本通过稳定 UUID 选择；重命名不会改变编号。

1. 在 **编辑场景动画 → 命名动画片段** 添加片段，填写名称、开始、结束及独立循环设置，保留自动生成的完整编号。
2. 点击 **检查并预览动画**，在播放选择中切换 **完整动画** 或某个片段。切换会暂停到所选范围起点；滑条显示片段本地时间，旁边保留原时间轴范围。非关键帧起止点仍按原曲线插值。
3. 审阅完整原文、应用到普通草稿，再普通保存。取消不写盘。旧文档首次加入片段才升级动画 schema 3；已有版本4保留其格式与运行范围，删除最后片段仍保留当前版本和空列表。修改轨道不会降级或丢掉片段。
4. 已保存场景画面预览提供相同选择，使用同一 Rust 采样规则。选择和播放不改变保存数据；行为、碰撞及声音继续由运行后端处理。
5. 在 **新建脚本** 选择项目动画片段起始内容，保存后通过既有场景行为绑定，填入片段 UUID，再构建项目组装。单场景运行默认仍播放完整动画。

schema 3 在原根字段之外增加 `clips`，最多 32 项，可重叠、可为空：

```json
"clips": [
  {
    "id": "41414141-4141-4141-8141-414141414141",
    "name": "待机",
    "startSeconds": 0.25,
    "endSeconds": 0.75,
    "loop": true
  }
]
```

名称必须已去除首尾空白，长度为 1–128 个 Unicode 码点，不含换行、制表符等 ASCII 控制字符；必须满足 `0 ≤ startSeconds < endSeconds ≤ durationSeconds`。缩短总时长造成片段越界时会拒绝检查，不能静默裁剪；既有轨道、关键帧和正文预算仍适用。旧核心缺少片段能力时不能忽略片段后保存。

```gdscript
func _ready() -> void:
    if not has_meta("viento_project"):
        return
    var project = get_meta("viento_project")
    if not project.has_method("select_animation_clip"):
        return
    project.select_animation_clip("41414141-4141-4141-8141-414141414141")
    project.play_animation()
```

`select_animation_clip(id)` 选择后回到片段本地 0 秒并暂停；`select_animation_clip()` 恢复完整动画，也暂停到 0 秒。原 `play_animation/pause_animation/stop_animation/seek_animation` 操作当前选择，定位秒数相对片段起点；停止保留选择并显示该片段首帧。每次场景访问默认选择完整动画，重入不继承之前的片段；整场景范围自动播放，逐实例范围初始停止，直到行为选择或播放。

同帧“选择→定位→播放”按队列顺序执行，定位范围在执行时按已选择的片段校验。非法或已删除 UUID、其他场景的片段和越界定位产生行为诊断，不按名称猜替代。片段 UUID 在行为参数里仍是普通字符串，目前没有静态引用保护或自动删除迁移。返回 `true` 仅表示排队受理。

**动画控制记录** 显示所选片段、原时间轴范围及本地播放头，可按片段名称／编号筛选；**打开动画片段声明** 导航本次冻结计划中的 `/clips/N`，行为、整份动画和片段保留各自来源。记录是命令执行时的快照，不持续追踪实时画面。

命名片段要求 `animation.clips2d`；动画文档 schema 3 对应动画子计划 2，显式运行范围的 schema 4 对应子计划 3。Godot 项目协议按[当前内容选择](PROJECT_BUILD.md#当前项目协议选择)，Bevy 尚未声明动画支持。片段可由[状态表](#从状态表生成动画脚本)控制；混合、关键帧事件、播放速率、骨骼与 3D 动画仍未接入。首次源码、Chrome、Godot 与工程交付证据见[命名片段验收](test-results/scene-animation-clips/README.md)，发布时点另见[历史归档](history/scene-animation-2026-10-25.md#命名片段首次发布基线)。


## 用项目事件触发动画片段

**新建脚本 → Godot / 事件动画片段**（`godot-project-animation-event`）组合已有项目事件与动画选择端口。它是可编辑的普通 TXT 起始内容，不增加动画格式、行为参数语义或运行协议。

1. 保存场景动画及所需命名片段，创建上述脚本草稿并普通保存。
2. 通过首次行为创建或已有行为管理，将脚本绑定到同场景实例；在行为编辑器中按需添加文本参数 `event_name` 和 `clip_id`。`event_name` 默认 `checkpoint`，留空则禁用订阅；`clip_id` 留空选择完整动画，或通过 **读取动画片段 → 填入动画片段编号** 按名称填入已保存片段的 UUID。
3. 审阅行为修改、应用普通草稿并保存，再构建项目组装。另一个作者行为负责在订阅建立后发布同名事件；此模板只订阅，不自行发布。载荷仍须满足项目事件的标量规则，模板回调不使用其值。
4. 收到事件后，回调先选择片段（空编号传 `null`），选择请求受理后再请求播放；每次事件都从所选范围本地 0 秒重播。查看 **项目事件记录** 与 **动画控制记录**，分别核对事件投递和实际动画命令。

`_ready()` 不选择、暂停或播放动画，整场景原有默认自动播放保持；逐实例范围则保持初始停止，直到事件或其他行为实际触发控制。同步回调返回 `true` 只表示选择和播放请求均已入队；事件“已处理”不证明动画已执行，更不代表片段播放完成。实际结果与问题沿用既有命令回执及行为诊断，失败时不自动改选其他片段。

脚本只在项目端口是有效对象、且具有订阅、取消订阅、选择片段与播放四个方法时订阅。普通单场景及缺少 `select_animation_clip` 的旧项目端口安全返回，即使 `clip_id` 为空也不绕过检查。退出时清空本地订阅身份并主动取消有效端口上的订阅，过期访问的 `false` 返回可忽略；场景生命周期仍会撤销旧访问订阅。该模板不提供动画状态机、混合或播放完成事件。

每次触发占两条动画请求，仍共用最多 64 条待处理、256 条累计请求的预算；没有其他动画请求时，同一批最多接受 32 次触发。整场景范围的所有绑定控制同一播放头；逐实例范围按绑定所属实例分开。同一目标的多个监听者仍按队列顺序执行，最后的选择决定该目标后续播放范围；模板不增加去抖或缓冲。启动时需要等其他行为完成订阅后再发布，例如使用 `call_deferred`。

本轮作者界面、保存到构建和实际 Godot 的分段验证见[事件动画验收](test-results/project-event-animation/README.md)。

## 查看动画片段使用位置

可在 **编辑场景动画 → 命名动画片段** 的片段行点击 **查看使用位置**。面板按当前片段编号列出所属场景已关联行为文档中，值完全等于该编号的文本参数，并显示绑定、实例和参数名称。

点 **查看参数原文** 可在当前面板打开只读的已保存行为快照，选中对应参数值；多个参数写入同一编号时，各自定位到自己的位置。**重新定位参数** 只调整这份快照的选区，**刷新已保存行为** 才重新读取磁盘。原文保留 BOM、换行和转义，界面按文本控件的换行规则定位。

查询不改变动画字段、已有审阅、普通草稿或播放器；读取失败后可以重试。切换片段、移除当前片段、关闭窗口或失去读取能力时，旧回复和旧来源按钮不能作用到新的编辑会话。三语切换保留输入和原文选区。未提供此接口的旧服务仍可使用普通动画编辑。

这是**当前场景已保存行为的完整编号文字匹配**，不是全工程静态引用分析。脚本正文、其他场景、未保存行为草稿和动态拼接不在查询范围；未找到匹配不证明没有使用。当前表单新加的片段也可查看线索，查询不会替它保存。重命名保留片段编号；移除仍由普通审阅与保存完成，不自动修改参数，也不保护或迁移未来引用。

读取只核对动画和行为的声明、登记与保存修订，不读取图片、执行脚本或要求场景能完整构建。实际执行依然使用现有构建与后端校验。源码 HTTP、两种正文目录的普通保存和真实浏览器的验收见[本轮记录](test-results/scene-animation-usage/README.md)。

## 动画自然完成与片段衔接

在 **新建脚本** 选择 **Godot / 动画完成后衔接片段**，审阅后创建普通 TXT 草稿并保存，再通过已有场景行为入口关联该脚本。在行为字段表中添加两个字符串参数：

| 参数 | 用途 |
| --- | --- |
| `finished_clip_id` | 要等待自然结束的片段编号；留空表示完整动画 |
| `next_clip_id` | 完成后选择并从头播放的片段编号；留空表示完整动画 |

两项都可以用已有 **读取动画片段** 辅助按名称选择并明确填入 UUID。完整审阅、应用原文草稿和普通保存保持独立；这些参数仍是普通字符串，不会随片段删除自动修复。

例如保留“事件动画片段”行为，让 `checkpoint` 启动非循环的攻击片段；再添加一个“动画完成后衔接片段”行为，等待攻击编号，下一片段填写循环待机编号。两个脚本就绪时只订阅通知，衔接脚本不会自行启动攻击；未匹配的完成通知不产生播放命令。整场景范围的多个行为共用一个播放头；逐实例范围中，启动与衔接行为须绑定同一个目标实例，其他实例的完成不触发它。

自然完成只在**正在播放的非循环范围到达末尾**时产生，一轮只记录一次，重播后可以再次完成。暂停／恢复保留播放进度；选择、停止、手动定位到末尾都不等于自然完成。循环片段不会发完成通知。时刻记录实际观察到完成的场景时间，不承诺恰好在理论截止时刻回调。

Godot 行为端口提供 `subscribe_animation_completed(callback)` 和 `unsubscribe_animation_completed(token)`。回调接收片段 UUID，完整动画接收 `null`，同步返回 `true` 表示处理完通知；订阅令牌只属于当前场景访问和行为。内置脚本检查端口可用性并在离开时取消订阅。单场景直接运行、旧生成工程或没有项目端口时不订阅，需重新构建带动画的项目组装来使用此能力。

自然完成与回调分两步：先留下完成记录，再在运行安全点投递。如果中间已有替代该目标的新动画命令、离场或结束请求，旧通知标为跳过，避免旧攻击的结束覆盖作者的新操作。取消订阅或接收行为释放也会跳过，跳过本次不表示仍有效的订阅被永久取消。命令执行前若时钟已到末尾，会先记录自然完成，再执行命令；这类已经被新命令替代的通知仍可看到完成，但不会再驱动衔接。协议11按完成记录的 `targetCommandSequence` 核对同目标命令锚点，其他实例的命令不会取消它；`commandSequence` 仍是完成时的全局截止序号。回调失败会留下诊断，未完成投递不能写成成功。

在 **构建与运行** 的项目运行结果中，**动画自然完成记录**独立显示自然完成、场景访问、时间、动画／片段声明与接收行为的处理或跳过情况，可筛选并回到冻结来源。它不是实时播放头；已有动画命令记录继续只表示命令执行时的状态。重新运行使用新的记录，旧来源不会误指向新任务。

每次运行最多 320 次自然完成、64 个待投递完成、1024 次接收投递；至多 64 个活动订阅，令牌累计至多 1024 个。衔接仍占原有两条选择／播放命令，沿用总计 256、同时待处理 64 条命令预算，不提供无限自动连播。

自然完成首次接入时，作者动画 schema 1／2／3、Rust 采样与文档持久化规则保持。当时新构建的含动画项目使用 Godot 适配器 0.16.0、项目 protocol 7 和生成清单 8；旧 schema 动画以完整范围参与，`clipId` 为 `null`。无动画项目继续 protocol 4，历史 protocol 1–6 观察及清单仍可验证。单独 Scene2D 的动画生成分支保持既有范围。该阶段接通顺序衔接，后续状态表及[逐实例运行](#为正式运行选择播放范围)分别接入；混合、骨骼、Bevy 和 3D 动画仍未接入。


## 从状态表生成动画脚本

在 **新建脚本 → Godot / 动画状态表** 配置状态、初始状态和转换规则。先检查完整生成源码，再点击 **创建脚本草稿**，最后使用编辑器的普通保存。取消不会创建文件。新生成的 TXT 包含版本化状态表注释，可按下节重新编辑；也可以继续手写普通源码，但手改后不再通过表格覆盖。

1. 添加 1–16 个状态。状态标识以小写字母开头，后续可用小写字母、数字和下划线，最多 32 个字符。每个状态生成一个普通文本参数 `clip_<状态标识>`：例如 `idle` 对应 `clip_idle`。改名会保留本次表格内的转换目标；删除被引用状态会留下缺失引用，必须显式修正后才能生成。
2. 明确选择初始状态，添加 0–64 条转换。每条包含起点、终点，以及 **项目事件** 或 **动画自然完成**。默认单一转换模式下，同一状态不能有两条相同事件规则；需要分支时显式开启下节的[有序事件分支](#按顺序匹配事件分支)。同一状态始终最多一条完成规则；不同状态可以响应同名事件。没有匹配规则时保持当前状态，显式指向自己的规则会从头重播。
3. 事件名沿用项目事件规则：ASCII 字母开头，后续字母、数字、`.`、`_` 或 `-`，1–64 字符，排除保留名称 `constructor`、`prototype`、`__proto__`。一张表最多使用 32 个不同事件。事件转换可选用下节的[载荷条件](#按事件载荷选择转换)；未设置条件时忽略合法标量载荷。
4. 保存生成脚本，通过现有行为入口绑定到当前场景实例；在 **编辑场景行为** 添加对应 `clip_...` 文本参数，并通过 **读取动画片段 → 填入动画片段编号** 选择片段。空参数表示完整动画；待机通常选循环片段，带完成转换的状态应选择非循环片段。新建脚本窗口没有场景归属信息，实际进入状态时由项目端口检查片段归属；构建不将这些普通文本参数视为静态片段引用。
5. 构建项目组装并运行。脚本会先完成事件和完成通知订阅，再选择并播放初始状态；事件到来或当前片段自然结束时沿匹配规则转换。使用既有 **项目事件记录**、**动画控制记录**、**动画自然完成记录**核对结果与来源。

例如建立 `idle`、`walk`、`attack` 三个状态；`idle + move → walk`，`walk + stop → idle`，`idle／walk + attack → attack`，`attack + 自然完成 → idle`。在行为中填入 `clip_idle`、`clip_walk`、`clip_attack`，事件发布由其他普通行为负责。表格不隐式增加输入绑定、攻击锁、返回上一状态或条件表达式。

状态指脚本已受理的转换目标，选择和播放仍是两条排队命令；同步返回成功不是引擎执行回执。第二条请求失败时控制器停止处理并清理订阅，已受理的第一条请求不会回滚。事件与完成同一安全点到达时，沿既有 protocol 7 顺序先执行事件及动画命令，过期完成通知会跳过。

整场景范围共用一个播放头，建议只让一份控制器管理它；显式逐实例范围可让不同实例各绑定控制器并独立播放。同一实例的多个控制器仍会竞争该实例播放头，尚无所有权仲裁。此表可查看当前声明的[静态状态图](#查看状态转换图)，层级状态和混合未接入。完成匹配使用进入状态时捕获的片段；参数在就绪时读取，运行中改变导出字段不会自动重配表。

Rust 纯核心负责有界表格校验和索引化结果，独立 Godot 发射器生成普通源码，界面只负责表单及审阅；旧核心缺少可选支持时仍可创建其他脚本。状态表首次接入时，动画／行为作者格式、protocol 7、Godot 适配器 0.16.0 及工程交付方式保持。当时验证见[状态表专题](test-results/animation-state-table/README.md)。


## 重新编辑已保存的状态表

打开含状态表声明的 TXT，在原文编辑模式点击 **编辑动画状态表**。这个入口读取当前原文草稿，包括尚未保存的合法状态表修改；它不会从磁盘重新载入并盖掉草稿。新建脚本尚未第一次保存时，先完成普通保存再使用这个入口。

1. 修改初始状态、状态或事件／自然完成转换，点击 **检查并生成脚本**。窗口展示修改前后完整原文，任何继续改表都会撤销上次审阅。没有变化时不产生新草稿。
2. 检查新增和移除的 `clip_...` 参数。状态改名或删除会改变导出参数集合；已保存的行为绑定不会自动迁移；保存脚本后，先[查看脚本使用位置](SCENE_BEHAVIORS.md#从脚本查看使用位置)定位已登记绑定，再在行为编辑器[按接口补齐或显式更名参数](SCENE_BEHAVIORS.md#根据脚本接口修复参数)。这里只审阅和修改脚本，不保证所有引用该脚本的行为仍可构建。
3. 点击 **应用到原文草稿**，回到编辑器检查内容，再普通保存。文件路径、文档身份、登记和行为关系保持；取消或返回不会写正文。重新打开表格可继续编辑尚未保存的生成源码。

第一行是简短的脚本标题；第二行 `#@viento-animation-state-script ` 后的单行 JSON 保存 `format`、声明 `schemaVersion: 1`、独立生成器标识（无条件 v1、载荷条件 v2、有序分支 v3、共享状态条件 v4、组合条件 v5）与中立状态表。该注释和生成的 GDScript 一起存于同一 TXT，无旁置文件。生成器标识与产品、运行协议版本分别维护；运行时仍使用既有项目接口，不读取表格注释来执行行为。

打开时，Rust 检查表格，固定版本发射器重建完整源码；只有逐字匹配才允许表格修改。可选 BOM 与统一 LF／CRLF 会保留，混合换行不自动整理。即使声明看起来合法，手改函数、默认参数、注释、增加代码或未知生成版本都会阻止表格覆盖，并保留原文供普通源码编辑。旧无声明脚本继续按普通 TXT 使用，不猜测转换，也不自动迁移。

这项能力是声明式源码的再次编辑，不是任意 GDScript 的逆向解析。场景播放头、状态键对应参数和既有运行预算沿用上一节；当前逐实例播放由[显式范围](#为正式运行选择播放范围)决定，运行观察由下述独立面板提供，混合尚未接入；当前表格可查看下节的静态转换图。实际范围见[重编辑验证](test-results/animation-state-reedit/README.md)。


## 按状态配置动画片段

在场景的行为文档中打开 **编辑场景行为**，选择绑定到已保存状态表脚本的那一项，再点击 **读取状态片段配置**。**状态与动画片段** 按状态列出 `clip_<状态键>`，可直接按片段名称、时间范围、循环设置及完整编号选择。也可以明确选择 **完整动画（空值）**；其循环设置请在动画文档中核对。

1. 为各状态选择片段。例如 `idle` 选择循环待机片段，`attack` 选择非循环攻击片段。下拉选择只留在配置面板中；**重置片段选择** 恢复当前参数表中的值。
2. 点击 **应用状态片段到参数表**。系统重新读取已保存动画，确认目录未变后，只更新当前绑定的状态片段参数，缺项追加到末尾。其他参数、信号、绑定和脚本保持原样。
3. 使用原有 **检查行为修改 → 审阅完整原文 → 应用到原文草稿 → 保存**。应用到参数表后仍可取消整次行为修改；关闭未应用的片段选择不会修改原文。
4. 在项目构建中重新规划、构建并运行。实际进入及自然完成可在各自观察面板中核对。该轮实测覆盖事件驱动 `idle → attack`，攻击片段自然结束后回到 `idle`。

当前片段不存在于本场景、参数类型错误、目标参数重名或补齐后超过 32 项，会阻止此配置应用；无效值保留显示，直到作者明确修复。完成转换对应循环片段会提示“不会自然完成”，但允许作者保留该选择。切换绑定、实例或脚本，或实际修改参数表，需重新读取配置；切换界面语言保留选择和焦点。

面板只识别完整匹配已支持 v1–v5 生成源码的状态表。普通或手改脚本继续使用通用参数表；模型、目录服务、界面与普通保存各自独立。检查只反映读取时的已保存动画，不提供持续引用保护、删除迁移或跨绑定批量修改。此助手不选择运行范围；整场景仍共用播放头，逐实例控制须另外[修改动画范围](#为正式运行选择播放范围)并保存，混合尚未接入。见[本轮验收](test-results/animation-state-bindings/README.md)。

## 构建前检查状态片段绑定

保存场景、动画和行为修改后，选择项目组装并执行 **检查计划**。支持的完整生成状态脚本（v1–v5）会检查所有绑定与状态：片段参数须为空字符串或小写 UUID，非空编号须属于该绑定所在场景；场景须声明动画，逐实例范围还须有绑定实例自己的轨道。尚未进入的状态也会检查。空值仍表示完整动画，循环片段合法。

发现问题后，点击诊断中的 **打开原文**，定位到行为 JSON 的参数值、实例编号或绑定。修正后普通 **保存**，重新 **检查计划 → 构建项目 → 无头测试／窗口预览**。中英日提示会说明需要修复的字段；诊断引用检查时的原文修订，BOM、CRLF 和非 BMP 字符不会偏移选区。一次最多显示 256 条诊断，超出时明确提示先修正已列出的问题。

这一检查只面向新建构建快照中的已保存组装，在读取资源、选择后端、识别工具和创建输出之前拒绝确定的错误。普通、手改或未知版本脚本仍使用原有运行时检查；它不分析任意脚本、不自动改正文，也不阻止旧冻结工程的恢复和回看。运行中的动态无效请求继续由引擎拒绝。没有新增作者格式或运行协议，验收见[动画绑定预检](test-results/project-animation-preflight/README.md)。

## 查看状态转换图

在 **新建脚本** 的动画状态表，或 **编辑动画状态表** 中，展开 **查看状态图**。图读取当前表格，包括尚未保存的修改。初始状态单独标记；箭头表示事件或自然完成的声明方向。没有转换的状态也会显示，自循环和双向转换保留；同一对状态间的多条转换可以共用图中连线，详细触发条件分别列出。

选择状态或转换后，可点击 **定位状态字段** 或 **定位转换字段** 回到表格修改。图的选择、展开、收起和字段定位只改变视图，不修改表格，也不使已完成的源码审阅失效。实际修改字段后，图和审阅仍按原有编辑流程更新。窄屏可在图区域内滚动，状态和转换的文字列表提供同等选择与定位入口；中英日切换保留作者输入。

图只在当前完整表格通过 Rust 检查后显示。状态标识未填写、引用缺失、单一转换模式下重复事件或有序模式中兜底分支位置错误等情况会清除旧图并提示修正；恢复合法字段后可继续查看。旧核心不支持状态表时显示能力不可用，不用前端猜测生成图。删除状态再新增同名状态，仍须明确修复原有缺失引用。

这是一份静态声明视图，无法说明运行时正处于哪个状态、事件是否发生或片段是否存在。图中不编辑连线、不保存额外布局；完整源码审阅、应用普通草稿和保存仍由现有编辑器完成。手改或未知版本脚本的表格准入规则保持。真实浏览器、来源保存和边界验证见[状态图验收](test-results/animation-state-graph/README.md)。


## 按事件载荷选择转换

在新建或重编辑动画状态表的事件转换中，将 **条件组合方式** 设为 **单条件**，再将 **条件来源** 从 **无条件** 切换为 **事件载荷**，选择类型、比较方式和值。例如 `idle + move → walk` 设置 **数字 / 大于 / 0**，只有 `move` 携带正数时才切换。单一转换模式中，条件不满足会忽略这次事件，不改变状态或中断其他事件接收者；有序分支模式会继续检查后续分支。

| 类型 | 比较方式 | 值范围 |
| --- | --- | --- |
| 布尔值 | 等于、不等于 | `true` 或 `false` |
| 数字 | 等于、不等于、小于、小于或等于、大于、大于或等于 | 有限数，绝对值不超过 1,000,000,000 |
| 字符串 | 等于、不等于 | 有效 Unicode，UTF-8 最多 4096 字节；允许空字符串 |

条件保留明确类型。布尔值 `false`、数字 `0` 和字符串 `"0"` 不相等；类型不同时，即使选 **不等于** 也不触发。Godot 整数和浮点数共用数字类型，按精确双精度值比较，不使用近似容差；负零与零相等。数字输入空白或尚未填写完成时不能生成脚本，也不会被解释成零。

只有事件转换可设置条件。临时切换为自然完成会隐藏条件并保留当前窗口的输入，切回事件可继续编辑；生成的自然完成声明没有条件。默认单一转换模式下，同一状态对同一事件只允许一条转换；多个条件分支使用下节的显式有序模式。共享状态查询见[项目共享状态条件](#按项目共享状态选择转换)；多个标量可以使用[组合条件](#组合多个转换条件)，嵌套表达式和任意代码条件仍未接入。静态图文字显示条件类型、运算符和值，但不模拟实际载荷。

单一转换模式下，无条件脚本继续使用 `godot-gdscript-v1`，源码生成结果保持。未设置共享状态来源或组合条件、且至少一条事件带条件时使用 `godot-gdscript-v2`；移除最后一个条件后，可以通过完整源码审阅、应用草稿和普通保存明确恢复 v1。两个版本都只允许精确重建的固定源码再次编辑，手改正文或未知版本仍由普通源码编辑器处理。BOM与一致的CRLF保留。有条件声明最多32 KiB，数值比较值按每项32字节保守计入预算，避免不同JSON序列化造成边界差异。v2 完整源码包含声明、BOM及换行，最多64 KiB；超出时应缩短条件文本或减少转换。条件不会增加行为绑定参数，原有 `clip_<状态键>` 接口保持。

条件检查与比较由独立 Rust 核心能力负责；旧核心可继续处理无条件表，无法生成或重新审阅带条件表，不会静默移除已有条件。比较值经固定Godot生成器编码，条件首次接入时复用协议7和适配器0.16.0；当前协议按[项目内容选择](PROJECT_BUILD.md#当前项目协议选择)。Godot对内嵌NUL的字符串表示有限制：核心和声明可保留该字符，运行比较避免误命中截断前缀，但不保证这类载荷能完整往返。实际Rust/WASM、Godot、工程ZIP与Chrome范围见[条件验收](test-results/animation-state-conditions/README.md)。


## 按顺序匹配事件分支

使用 **事件转换选择 → 按顺序匹配事件分支**。默认仍是 **每个事件单一转换**；开启后，同一状态可以对同名事件声明多条转换，按表格顺序检查，执行第一条匹配的转换。例如当前状态为 `idle`，事件名为 `attack`：

| 顺序 | 条件 | 目标状态 |
| --- | --- | --- |
| 1 | 数字 / 大于或等于 / 10 | `heavy` |
| 2 | 数字 / 大于 / 0 | `light` |
| 3 | 无条件 | `idle` |

载荷为 `12` 时只执行第一条；为 `3` 时执行第二条；为 `0` 时执行兜底。每组可以不设兜底，全部条件不匹配时保持状态。类型不匹配继续检查下一条，即使比较方式是“不等于”；无条件兜底接收任何合法标量载荷。不同起点或不同事件互不影响，也可以在列表中交错排列。

使用 **上移转换／下移转换** 调整优先级。序号表示当前列表顺序；移动保留状态引用、条件输入和行身份，并撤销已有源码审阅。完成转换每个起点仍只能有一条。一个同起点／同事件组最多有一条无条件兜底，必须位于该组最后；放错位置时不能生成源码，静态图也会提示修正。

重编辑时先 **检查并生成脚本**，审阅整份源码，再 **应用到原文草稿** 和普通保存。切回单一转换模式会保留全部输入；需要手动处理重复事件后才能继续生成，程序不会自动删分支。分支模式本身不改变 `clip_<状态标识>` 参数，状态增删／改名仍按已有绑定修复流程处理。

有序模式在中立表顶层显式记录 `eventSelection: "firstMatch"`；未设置共享状态来源或组合条件时使用 `godot-gdscript-v3`。即使当前没有重复事件、没有条件或没有转换，也保留 v3，避免静默切换语义。旧 v1/v2 声明与生成器保持原规则；只有明确关闭模式、修正重复项并审阅保存，才重新生成适用的旧版本。v3 采用与 v2 相同的32 KiB声明预算与64 KiB完整源码预算，保留BOM及统一换行，仍拒绝覆盖手改源码。

准入由独立可选 Rust 能力负责，Godot 发射器负责顺序执行，表单与普通保存分别维护。缺少分支能力时保留输入并禁用生成；旧模式继续按原能力使用。有序分支开发时沿用项目 protocol 7 和 Godot 0.16.0；当前还支持下节的退出状态快照。该分支切片不改变播放范围；当前范围见[逐实例运行](#为正式运行选择播放范围)。共享状态条件已由[独立切片](#按项目共享状态选择转换)接入；混合及其他后端动画仍未接入。验证见[有序分支专题](test-results/animation-state-branches/README.md)。


## 查看运行后的动画状态快照

在 **项目构建与运行** 增加独立的 **动画状态快照**。已保存的场景绑定版本化状态表脚本后，重新生成并运行项目；切换场景、正常结束或脚本错误中止时，系统在清理实例前读取控制器实际字段。只有经过完整源码验证的 v1/v2/v3/v4/v5 生成脚本才参与，手写或手改脚本不从同名变量猜测状态。

每次场景访问单独记录采样原因、场景时间与已执行动画命令截止序号。同一脚本绑定多个实例时分别显示完整绑定和实例编号；可按场景、行为绑定、脚本路径或状态标识筛选。**打开行为绑定** 定位参数声明，**打开状态脚本** 返回生成脚本原文；导航沿用现有来源版本和未保存草稿保护。

**脚本已接受状态** 表示该生成脚本已接受选片段、播放请求并更新了自己的状态，不能等同于播放执行成功。实际执行结果仍查看独立的动画命令和完成通知。例如 `idle` 和 `alert` 使用同一片段时，快照仍可区分二者；多个绑定共享一个场景播放头时，各自脚本状态也可能与最后执行的片段不同。

控制器停用显示当前没有已接受状态；实例尚未创建或已释放显示未读取到脚本状态。取消、超时或强制终止可能来不及采样，此时显示尚未采集，不根据最后一条动画命令补造结果。快照本身只记录访问退出边界；逐次进入由下节单独记录，播放头由作者范围决定，实时高亮和断点未接入。

退出快照引入时，新生成且包含可识别绑定的动画项目使用运行协议 8、Godot 适配器 0.17.0、工程清单 9；当前同时支持下节的状态进入记录。普通动画项目继续生成协议 7，无动画项目继续协议 4。当时既有的旧协议 1–7 读取与作者 v1/v2/v3 源码保持。缺失片段参数沿源码默认值选择完整动画；提供值必须是空文本或小写 UUID，格式错误会定位到绑定参数。该历史版本中，格式合法但不属于当前动画的编号在运行时报告错误；当前新项目构建包含[状态片段绑定预检](#构建前检查状态片段绑定)，旧冻结工程和动态运行请求保留原检查。重建只更新构建产物，不迁移作者正文或已安装程序。

实际浏览器、Godot、独立 ZIP 交付和兼容性范围见[状态快照验收](test-results/project-animation-state-snapshot/README.md)。


## 查看每次成功进入状态的记录

在 **项目构建与运行** 增加独立的 **动画状态进入记录**。保存状态表脚本、重新生成项目并运行后，每次 `_enter_state` 成功都会留下记录，包括初始进入、同一帧连续进入不同状态、以及同状态重启。例如 `idle → action → idle → idle` 会保留四次进入，最后一次不会因为名字相同而合并。

记录显示状态标识、片段、场景访问、场景时间、完整绑定身份和**进入时已执行动画命令序号**。选择同一片段的两个状态也能分别显示；同一脚本的多个绑定分别记录。可以按场景、行为绑定、脚本或状态筛选，使用 **打开行为绑定** 和 **打开状态脚本** 返回冻结来源；这些操作不修改作品。

**脚本接受进入状态** 表示该次选片段和播放请求都已被接受，实际命令可能仍在队列中。因此进入记录可以先于对应的播放回执，多次进入也可以具有相同的已执行命令序号。后续执行失败时，已接受的进入仍保留，错误与执行结果查看原有诊断和命令面板。选片段或播放请求未被接受时，不产生成功进入记录；条件不满足、未知事件等没有进入的情况也不补造记录。

离场时的**动画状态快照**继续单独显示最后采样结果。历史中的最后一次进入不证明控制器此刻仍已激活：它可能随后停用、释放或遇到取消。强制结束保留已采集的进入记录，可能没有离场快照。旧协议9不记录触发来源；协议10新增的来源查看见下节。条件结果、失败转换原因、断点与实时状态图仍未接入。

采集由构建产物中的独立包装脚本完成，继承完整验证的 v1/v2/v3/v4/v5 作者脚本，在原进入方法成功返回后读取实际字段；作者文件、导出参数和普通保存流程保持。手写或手改脚本不自动包装。0.1.9发布时的可识别控制器项目使用协议9／Godot0.18.0／清单10；当前整场景控制器项目重新生成时使用下述协议10来源采集；显式逐实例项目使用协议11并复用来源采集。普通整场景动画项目仍协议7，无动画项目仍协议4；旧格式继续读取。

每个项目会话最多128条成功进入记录，与现有256个动画请求预算对应；超限显式报错，不截断或覆盖旧记录。生成的包装文件列入工程库存和来源映射，交付ZIP包含原作者脚本与包装层，可脱离作者目录执行。详见[状态进入记录验收](test-results/project-animation-state-entries/README.md)。


## 按控制器回看运行记录

在 **动画状态进入记录** 中，点击一条记录的 **回看此控制器**。回看固定到该绑定的本次场景访问，显示完整进入顺序；同一脚本的其他绑定、以及离场后再次进入的访问分别查看。使用记录选择框或上一条／下一条逐步检查，重复状态、同帧进入与同状态重启都各占一条。

回看展示选中记录的状态、片段、时间及进入时已经执行的命令截止序号。下方的后续命令只包含同绑定、本次访问中序号大于该截止值的实际执行回执。**它们不与某次进入一一配对**：多条进入可能都发生在命令队列执行前，具有同一截止序号，因此可看到相同的后续回执。不能据此推断该次状态已经播放成功，未出现命令也不等于请求被拒绝。

离场快照单独显示实际采样结果，包括已接受状态、停用或未读取到实例。它属于该绑定本次访问的最后采样，并非所选历史时刻的即时状态；取消或超时可能没有采样。协议10／11可显示实际触发入口及关联通知，见下节；条件求值、失败分支和具体命中转换仍不作推测。

平铺列表的搜索与回看分开：修改搜索不会裁剪当前控制器的完整顺序。新记录追加、命令到达和语言切换保留选中项；切换运行、所选记录被替换或删除会撤销旧选择。关闭回看仅关闭视图，不取消运行或改变作品。来源按钮沿用原版本检查与未保存草稿保护。

回看最初作为协议9记录的只读投影接入；当前同时支持协议10／11的来源证据，不改变作者格式或增加回看执行操作。实际中英日、来源、Godot与浏览器范围见[控制器回看验收](test-results/project-animation-state-review/README.md)。


## 按项目共享状态选择转换

新建动画状态表或重新编辑已保存的状态表时，在事件转换的条件来源中选择 **项目共享状态**，填写例如 `combat.enabled` 的键，再选择布尔、数字或字符串及比较值。静态图显示相同的键和比较条件。修改后仍须检查并审阅完整源码，应用到草稿，再用编辑器的普通保存；来源、键或比较条件变化会撤销旧审阅。界面切换来源和语言时保留输入。

共享状态由行为通过现有 `write_state`／`erase_state` 接口维护，作用域和限制见[项目共享状态](PROJECT_SHARED_STATE.md)。键区分大小写，以ASCII字母开头，后续允许字母、数字、下划线、点和连字符，最多64字符；`constructor`、`prototype`、`__proto__` 禁用。编辑器不会自动去掉键首尾空格，也不把未完成的数字输入转成零。

例如，事件名为 `attack`，条件为共享状态 `combat.enabled` 的布尔值等于 `true`：收到该事件时才读取并比较这个键，此条件不使用事件载荷。省略共享状态来源的旧条件继续比较事件载荷；同一状态／事件的有序分支可以混用两种来源，首个匹配项生效，无条件兜底必须排在该组最后。已经匹配的转换若请求失败，不再尝试后续分支。

**读取发生在事件回调执行时**。发布事件会冻结载荷；共享状态写入立即生效，所以发布后、队列投递前修改的值会被条件读取。键变化本身不触发转换。键不存在或值的类型与条件不同，一律不匹配，包括“不等于”；`false`、`0` 和空字符串都是合法值，不视为缺失。数字为绝对值不超过10亿的有限数，字符串为最多4096个UTF-8字节的有效Unicode；比较保持既有严格类型和字符串字节语义。

包含共享状态条件且没有组合条件的声明使用同文件 `godot-gdscript-v4` 源码封套，独立Rust能力检查声明，新版发射器生成读取端口的代码。旧v1／v2／v3源码仍按原规则完整再生验真，手写修改不会被自动覆盖；显式移除最后一项共享状态条件后可生成符合剩余特征的旧版源码。旧核心缺少该能力时明确拒绝，不会剥掉条件后继续生成。

单条件支持事件转换上的标量比较；多个比较可使用下节的平面组合。完成转换不接受条件，没有任意表达式、状态监听或自动转换。该条件切片验收时使用protocol9／Godot0.18.0／库存10，当前整场景控制器工程按下述协议10采集来源，显式逐实例项目使用协议11；状态进入记录和离场快照可照常查看，但当前观察没有记录每次条件求值或失败分支，不能由快照反推原因。逐实例播放已由[独立运行范围](#为正式运行选择播放范围)接入；Bevy动画与安装版验收仍各自推进。实际验证见[共享状态条件验收](test-results/animation-shared-state-conditions/README.md)。


## 组合多个转换条件

在新建或重新编辑动画状态表时，将事件转换的 **条件组合方式** 设为 **全部满足** 或 **任一满足**，再添加条件。每项仍选择事件载荷或项目共享状态，填写类型、运算符和值。一个组合允许1–8项，可以上移、下移、删除；空组合暂存输入但不能生成源码。完成转换仍不接受条件，不支持组合嵌套。

例如 `attack` 事件的“全部满足”包含 `combat.enabled == true` 和事件载荷 `>= 3`：只有允许战斗且载荷达到3才转换。改为“任一满足”后，其中一项匹配就转换。缺少共享键或类型不一致的项视为不匹配，包括“不等于”。运行时按作者顺序短路：全部满足遇到第一项不匹配便停止；任一满足遇到第一项匹配便停止。只在实际执行到某项时读取其共享键，读取时机是事件交付时；写状态本身不会触发转换，也不把整个组合解释为发布时的快照。

单条件与组合分别保留输入，全部满足与任一满足共享同一列表。首次从单条件进入组合时，已有条件复制为第1项，界面会提示；此后两套输入独立。重新打开一个原本就是组合的表时，首次切回单条件从无条件开始，界面明确提示，原组合仍保留。添加、删除、排序、修改组合方式或比较值都会撤销旧源码审阅；三语切换不重建输入节点。静态图显示组合结构和顺序，不模拟求值。

组合仍可作为 `firstMatch` 有序分支的一条条件，与单条件和末尾无条件兜底混用。只有完全省略 `condition` 才是无条件；单项组合也保持组合身份。第一个匹配的转换请求若失败，会停用控制器，不会继续尝试其他分支或兜底。

包含组合的声明使用独立 `godot-gdscript-v5` 源码封套，即使同时包含共享状态或有序分支。须通过完整源码审阅、应用草稿、普通保存才写回TXT。显式删除最后一个组合后，生成器根据剩余特征选择v1–v4；旧四个生成器不变。缺少组合能力的核心明确阻止生成，可以保留输入并明确切回单条件。声明总预算32 KiB，每个数字叶子保守计32字节；含声明、BOM和换行的完整源码仍限64 KiB。

该组合切片验收时沿用protocol9／Godot0.18.0／库存10；当前整场景控制器工程按下述协议10采集来源，显式逐实例项目使用协议11，既有进入记录、完成通知、离场快照保持独立；纯载荷组合不要求共享状态读取端口。当前没有记录逐项条件结果，不能把未进入目标状态当作某一项失败的证据。参见[组合条件验收](test-results/animation-condition-groups/README.md)。


## 查看状态进入的触发来源

保存动画状态表脚本后，重新生成工程并运行，在 **动画状态进入记录** 中查看每条记录的进入来源。新工程会区分四种入口：

- **初始化回调**：包装脚本首次进入初始化入口时接受的状态。
- **事件回调**：实际投递给该控制器的项目事件，显示消息序号及订阅编号；回看区显示事件名和原始标量值。
- **动画完成回调**：实际自然完成通知，显示完成序号及订阅编号；回看区显示对应片段和完成时刻。
- **直接进入**：没有可核验的初始化或派发作用域，例如其他脚本直接请求进入状态。不会用最近事件代替实际来源。

点击 **回看此控制器**，可以把进入状态与关联事件值或完成片段对照。比如一个事件被条件拒绝后，下一个事件才进入目标，记录会关联真正触发的第二条事件；同名事件、同帧多个事件、同脚本多绑定也按序号和订阅分别保存。`false`、`0`、空字符串正常显示，不表示没有载荷。旧协议9记录显示 **来源未记录**，不会补猜历史。

**回调待确认**表示进入已被脚本接受，但同步回调的投递回执尚未到达；运行中止时也可能保留这种状态。**回调已处理**说明该通知已被处理，仍不代表排队的动画命令都已执行。进入、命令、自然完成及离场快照继续分别显示。

本轮只记录入口来源，没有记录命中哪条转换边、每项条件的结果或未进入分支。两个分支进入同一个状态时，不从目标状态反推分支。没有自动生成新的播放头、混合或Bevy动画能力。

新生成且完整识别v1–v5作者脚本的整场景工程使用 **运行协议10／清单11**；显式逐实例项目使用协议11／清单12并复用此来源证据。当前适配器与生成器版本见[协议选择表](PROJECT_BUILD.md#当前项目协议选择)。不改作者TXT，旧工程和旧记录保持原格式。普通整场景动画项目仍协议7，无动画项目仍协议4。运行资源一并进入交付ZIP，可离开作者目录执行。Studio旧构建缓存仍按适配器版本／指纹要求重新生成，不自动迁移。每会话128条成功进入的限制保持。实际验证与保留范围见[动画进入来源验收](test-results/animation-entry-triggers/README.md)。

从事件出发调试时，使用[按事件回看投递与动画进入](PROJECT_EVENTS.md#按事件回看投递与动画进入)，逐个对照订阅状态并直接打开对应控制器历史。此视图复用上述协议10／11来源；旧协议3–9只展示事件，不反推进入原因。


## 手动试算事件分支

在 **新建脚本 → Godot / 动画状态表** 或 **编辑动画状态表** 中展开 **状态试算**。选择 **样本当前状态**，填写 **样本事件名称** 和载荷类型／值；需要的共享键列在 **手动共享状态样本** 中，默认 **缺失（不提供此键）**。点击 **试算此事件** 查看当前表的候选转换、逐项比较与最终选择。

例如规则为 `idle + action → attack`，要求共享键 `combat.enabled == true` 且载荷 `>= 3`：样本载荷为数字 `3`、共享键为布尔 `true` 时选择该分支；共享键缺失时第一项不匹配，后续条件标为未求值。字符串 `"3"` 与数字 `3` 类型不同；缺键和类型不匹配对“不等于”也返回不匹配。

有序分支按表中顺序检查，选中后不再计算后续分支；全部满足遇到首个不匹配、任一满足遇到首个匹配都会短路。**未求值**不会显示成条件失败或伪造实际值。合法但未配置的事件名称也可试算，结果为没有候选转换。点击 **定位转换字段** 返回相应表格行。

样本仅属于当前编辑会话，不参与源码审阅、作者表或普通保存。修改样本／真实条件、重排转换或撤销核心能力会使旧结果失效；切换语言保留输入和焦点。关闭后重新打开表单会清空样本。无效表格不能试算，应先修正字段；暂时无效期间保留已填写样本。

试算假定控制器处于所选状态，并对同一共享键使用固定值。实际回调可能逐次读到不同值，状态进入或播放也可能失败；试算选中不证明运行成功。它不执行脚本、不发布事件、不读取实时共享状态，也不是[运行事件回看](PROJECT_EVENTS.md#按事件回看投递与动画进入)。自然完成的手动假设见下节；未激活控制器和脚本副作用仍不在试算范围。

条件使用既有 Rust 严格比较，数字没有误差容限。Godot 对内嵌 NUL 字符的表示限制仍存在：手动语义可以保留该字符，但原生构造／解码可能替换或截断；应以实际收到的值复核，不能把原字符串的试算当作引擎完整往返保证。完整应用、实际浏览器和原始 v1–v5 Godot 脚本对照见[本轮验收](test-results/animation-state-event-preview/README.md)。


## 连续试算事件与完成转换

在状态表的 **状态试算** 中先选择触发方式，填写样本并点击试算。查看结果后，点击 **记录并继续**，将这一步的输入和结果加入历史，并把预测目标设为下一步的样本当前状态；未命中转换时记录一步并保持状态，同状态转换也保留独立步骤。单次试算本身不会推进，记录后也不会自动触发下一事件。

例如先在 `idle` 输入攻击事件并试算，记录后当前样本状态变成 `attack`。切换到完成触发再试算，可以检查表中 `attack → idle` 的完成转换，记录后继续从 `idle` 输入下一事件。完成模式假定控制器有效，且当前选中片段的自然完成通知已经送达；作者表不包含实际片段绑定、循环状态或播放进度，因此它不能判断播放器何时结束，也不能模拟不匹配片段通知。

步骤历史保留每一步的状态、触发样本和选择结果，可展开查看当时的逐项比较与短路。历史只读；修改下一样本不会改写已经记录的步骤。**撤回最后一步** 恢复该步之前的样本状态和输入，清除当前待采用结果，可以重新试算另一条路径。**清空步骤** 从当前样本状态重新开始；手动切换当前状态也会开始新序列，避免把跳转伪装成连续转换。

切换事件／完成模式保留各自输入；完成模式不读取隐藏的事件数字或共享样本。修改真实状态表、重排转换、重置表单或换文档会清除旧路径，关闭后重新打开表单也会清空。折叠试算区保留本地步骤，展开时重新核验表格。语言切换保留当前输入和可用的历史详情。

每条序列最多32步，规范化样本合计最多64KiB；到达上限仍可做单次试算，可撤回或清空后继续记录。用于撤回的原始输入缓冲另有256KiB累计限制，包含隐藏的未完成输入；超限时缩短输入、撤回或清空步骤，旧输入不会被截断。每个事件样本继续受原有类型、64共享键和16KiB共享值预算约束。每一步使用自己的固定共享值快照，不模拟脚本写回、自动级联或状态进入失败；“记录并继续”是作者显式接受预测目标的手动假设，不证明真实执行。源码草稿、审阅资格和普通保存保持独立。实际范围见[连续试算验收](test-results/animation-state-trial-sequence/README.md)。


## 保存与重跑手动试算用例

在状态试算里记录至少一步后，点击 **导出当前路径 JSON**。下载的 `animation-state-trial-case.json` 将起始状态、每步规范化输入及当时预测的目标状态／是否发生转换保存为手动预期。未采用的试算结果和隐藏输入缓冲不导出；该文件可自己命名、保存和迁移，当前不自动登记到工程或作者源码。

点击 **导入用例 JSON** 选择此前保存的文件。导入只载入用例，不运行、不替换当前手动路径，也不改样本或源码审阅。再点击 **在当前表上重跑**，从用例起始状态逐步求值；每一步沿当前表预测的状态继续。第一处不符会显示预期和当前试算结果，后续步骤标为未运行。展开步骤详情可查看共享样本及逐项比较。修改状态表会清除旧回放结果，但保留载入用例供再次重跑。

预期只对照目标状态与是否选中转换。例如 `idle → idle` 的自循环与没有匹配转换会得到不同结果；两条通往同一目标的分支不会据此区分，条件短路详情可另行查看。导出的预期源于手动采纳的预测路径，可以通过下节内置编辑器或文件明确修改；“符合手动预期”不证明实际事件投递、片段绑定、播放或脚本进入成功。完成步骤继续假设所选片段通知已到达，共享状态不会自动跨步骤继承。

用例采用 `format: "viento.animation-state-trial-case"`、`version: 1`、`initialStateKey` 和 `steps`。每步包含 `input` 与 `expected: {"stateKey":"目标状态", "transition":true}`；未发生转换用 `false`，且期望状态须保持前一步的期望状态。以下是未知事件保持待机的一步用例：

```json
{
  "format": "viento.animation-state-trial-case",
  "version": 1,
  "initialStateKey": "idle",
  "steps": [{
    "input": {"kind": "event", "event": {"name": "unconfigured", "value": false}, "projectState": []},
    "expected": {"stateKey": "idle", "transition": false}
  }]
}
```

完整文件先检查再载入：1–32步、规范化输入合计64KiB、文件最多128KiB；原有标量及共享样本限制继续生效。未知版本、多余或重复字段、不完整输入及矛盾的无转换预期都会被拒绝。当前表缺少用例起始状态时明确报错，不自动换状态；已删除的预期目标可以保留，用于报告规则变化造成的不符。

取消选择、读取失败或无效文件会保留此前载入的用例和结果。**清除载入用例** 只清此区域，手动路径保持。折叠使未完成的文件读取失效；关闭、重置或换文档清空本次载入，已下载文件保留。中英日切换保持可用结果与展开详情。验证与平台范围见[本轮验收](test-results/animation-state-trial-case/README.md)。


## 在 Studio 内编辑试算用例

在 **试算用例** 区域，可以点击 **从当前路径建立用例**，将已记录的手动步骤带入编辑草稿；也可以导入已有文件后点击 **编辑用例 JSON**。编辑的是用例的 JSON 表示，初始显示会整理缩进；若整理后超过文件预算则保留紧凑表示。原文件不会被覆盖。

修改初始状态、步骤输入或预期后，先点击 **检查 JSON**。检查通过显示用例摘要，再点击 **应用用例**，才替换本次载入的用例并清除旧回放结果。检查通过后继续输入会撤销应用资格，需再检查。非法 JSON、额外字段、超限样本或矛盾预期会保留输入，并保持原用例。**取消编辑** 丢弃这次编辑，原用例和仍有效的旧结果保留。

应用不会自动重跑；继续点击 **在当前表上重跑** 对照手动预期。修改样本后，原预期保持原值，首次差异仍会报告；如确实需要调整预期，应在 JSON 中明确修改并重新检查、应用，不会自动把结果写成新预期。

点击 **导出载入用例 JSON**，下载当前已应用版本。它与 **导出当前路径 JSON** 各有来源：前者导出载入／编辑后的用例，后者从当前手动记录捕获。应用只更新本次载入对象，需导出才能把修改保存为文件；关闭表单会清除本次编辑和载入状态。

编辑器打开时，导入、创建、清除、重跑和导出入口暂停，避免覆盖未完成输入；可随时应用或取消。先前未完成的文件读取会失效。折叠试算区保留 JSON 缓冲，但撤销已检查结果，展开后需重新检查；切换中英日保留输入节点、焦点和选区。修改作者状态表不会丢弃独立用例草稿；关闭、重置表单或切换文档才清空会话。编辑区内按 Escape 先取消用例编辑并返回入口，输入法组合期间不拦截 Escape。

文本原样保留，UTF-8 字节计数与128KiB文件预算单独显示，不使用字符截断代替校验。32步／64KiB规范化输入限制仍来自原用例契约。预期的含义、完成通知假设与同目标分支限制仍按上一节执行。实际验证见[本轮验收](test-results/animation-state-trial-case-editor/README.md)。

## 按动画目标回看运行记录

在已产生协议11记录的项目运行中，命令和自然完成条目增加 **回看动画目标**：

1. 点击一条命令或完成记录的入口，打开它所属目标的本次场景访问记录。当前记录高亮，顶部可切换其他已记录目标。
2. **此目标的已执行命令**汇集同一播放目标的所有行为来源。同一个实例上的多个绑定会一起显示；共享定义的不同实例、同场景再次进入分别显示。
3. **此目标的自然完成记录**分别显示目标最后命令序号和全部命令截止。点 **查看目标锚点命令**，定位到该目标最后执行的命令。例如A的最后命令为4、B随后执行到6，A的完成仍关联4，全局截止可以为6。
4. 使用命令、动画、片段或订阅来源入口返回原文。关闭回看回到最初的入口；若该条目已被原列表筛选隐藏，则回到相应搜索框。

两份列表各自使用原始全局序号，不合并成推测的执行顺序。回看仅展示采集时的状态与播放位置，不是实时播放头，也不会倒放或重演。完成通知被处理只证明同步回调成功，不保证后续命令已执行。整场景自动播放可以在没有命令的情况下完成，此时目标锚点为0并明确显示无命令。

这里只列有命令或完成证据的目标，不推断未产生记录的实例。只有协议11有明确目标，旧协议继续使用原观察列表；在协议11的混合项目内，整场景目标也可回看。主列表筛选与回看选择互不裁剪。重新运行、无效记录及来源替换会清理失效选择；异步原文读取在换目标、离开场景、出现草稿或关闭界面后撤销。验收见[独立专题](test-results/project-animation-target-review/README.md)。
