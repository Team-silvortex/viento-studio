# 项目工作流

本页按创建、编辑、整理、保存和交付一份作品的顺序介绍日常操作，适用于桌面版与本地浏览器编辑服务。首次启动见 [开始使用](GETTING_STARTED.md)；开发源码、已发布版本及各平台的能力差异见 [当前状态](STATUS.md)。Android 当前支持新建、编辑保存和完整项目迁移，素材访问、项目类型配置及下述 World / 构建面板尚未接入，见 [移动端说明](../mobile/README.md)。

游戏工程的主路径是 **设定 → 投影 → 场景实现 → 组装打包 → 工程交付**。基本创作优先在 Studio 内完成：源码、字段表、投影和场景表单各自修改作者数据，保存后再交给后端构建。当前执行闭环以已登记的 Scene2D 为范围；已保存片段配方可在界面中生成独立 Scene2D，接入同一行为、构建和交付流程。Scene3D 仍走独立创作与导出入口。

本页先介绍所有工程共用的文档与资源操作，再说明 [二维游戏交付](#8-从设定到场景再交付生成工程)。文学、戏剧、影视策划和资料工程可在分享／迁移步骤结束；不要求每份工程都进入游戏构建。

## 日常工作流

### 1. 创建或打开工程

在作品库创建工程，或导入完整的 `.viento.zip` 项目包。0.3.0 源码可选择空白、游戏、文学、戏剧、影视和软件设计模板，默认空白工程。模板提供文档类型与起始正文，新工程的正文目录为空，不预置具体作品或素材。

选择最接近内容用途的模板即可；之后可以在本工程内调整类型、字段和模板。工程数据保存在独立作品文件夹，应用升级不会覆盖它们。使用本地浏览器编辑服务时，先按 [开始使用](GETTING_STARTED.md) 指定要编辑的工程。

### 2. 新建并编辑文档

切换到 **编辑** 模式，新建文档时选择类型和保存位置。类型决定新建模板与解析规则；把文档存入其他正文子目录不会改变它已经选定的类型。

| 编辑方式 | 适合的操作 |
| --- | --- |
| 源码 | 写正文、增加或删除字段、调整 JSON / YAML 层级 |
| 字段编辑 | 逐项调整已有文字、数值和布尔属性，搜索字段、折叠分组 |
| 分段编辑 | 按解析后的内容块修改已保存文档 |

三种方式共用当前草稿，切换界面语言也保留编辑内容。新文档首次保存前可使用源码或字段表，保存后可进入分段编辑。字段表的格式与限制见 [字段编辑](FIELD_EDITING.md)。

新建支持 `.md`、`.txt`、`.json`、`.yaml`、`.yml`。省略扩展名时，编辑器按当前模板格式补全。隐藏路径、`node_modules`、保留文件名、过长名称及不支持的后缀会在写入前拒绝。遇到重名、大小写或 Unicode 等价名称冲突时，为新文档换一个位置；不要覆盖原登记来获得新身份。已登记但原文缺失的文档，应恢复原始源文件以保留其 UUID、归属和素材绑定。

模板读取失败时会明确提示使用空模板。先检查模板问题再继续输入；已写好的草稿不会被另一套内置模板补写。

### 3. 按需调整类型和模板

先保存或结束正文草稿，再打开顶部的 **项目类型与模板**，也可从 **设置** 进入。

1. 选择已有类型，或点击 **新增类型**。名称用于展示；类型标识创建后固定，默认子目录只是新建建议位置。
2. 编辑 Markdown、文本、JSON 或 YAML 起始正文。需要时展开字段解析与展示规则，按精确字段名设置标题、长字段或分组。
3. 点击 **预览解析结果**，确认字段与正文的划分，然后 **保存并应用**。

修改模板影响之后新建的文档，不覆盖已经写好的正文。修改解析规则或分组会更新同类型文档的展示。预览本身不写入工程；只读浏览模式不提供项目配置写入。

新增类型时，**取消新增** 返回之前选中的类型；编辑已有类型时，**放弃修改** 恢复最后保存的配置。**返回编辑器** 关闭窗口。上述操作或切换类型遇到未保存修改时会先提示；Esc 在新增时取消新增，其他时候返回编辑器。已经保存并应用的内容会保留。

### 4. 用“世界与对象”整理属性、归属和资源

**世界与对象** 读取已保存内容。先保存或结束文档草稿，再打开该面板进行写入。对象通过稳定 ID 对应源文档，属性编辑仍然写回原文。

| 操作 | 使用路径 |
| --- | --- |
| 查看对象 | 搜索名称、身份或原文路径，选择对象查看属性与来源 |
| 创建对象 | **创建对象 → 选择类型、填写原文与路径 → 预览新对象 → 保存新对象** |
| 修改属性 | 选择属性的修改操作，输入新值，预览后保存；支持将多个对象的属性修改加入待提交批次，再整批预览和保存 |
| 添加关系 | **添加关系 → 选择引用或归属、目标对象及可选标签 → 预览关系 → 保存关系** |
| 绑定资源 | **绑定资源 → 选择已登记素材、填写用途 → 预览绑定 → 保存绑定** |

角色的简短背景可以直接写进角色文档。若背景篇幅较长，先保存为独立故事文档，再在 **世界与对象** 中选择这份故事，添加 **归属** 关系，目标选择角色，标签可填“背景故事”。这会把故事放入目标角色的附属内容；共享故事可分别归属多个角色，正文仍只保存一份。循环归属和重复关系会被拒绝。**引用** 仅建立关联，不把当前对象放入目标对象的附属目录。

这些操作已提供界面入口，日常新增归属无需手工改元数据。旧作品批量整理与持久格式见 [文档模型](OC_DOCUMENT_MODEL.md)。当前面板提供关系和资源绑定的添加，不提供它们的删除或修改界面。

资源绑定适合封面、立绘等正文之外的附件；正文内的图片、视频、音频使用下一步的插入素材。面板显示“文件存在，内容尚未校验”时，只说明找到了文件，不能代替完整内容核验。出现 **恢复未完成的提交** 时，按提示恢复后核对保存结果，不要反复提交同一批修改。

### 5. 插入图片、视频和音频

在编辑草稿中定位插入位置，使用 **插入素材** 导入文件或选择已登记素材，也可粘贴或拖入受支持文件。正文保存稳定的 `asset:<UUID>` 引用；JSON / YAML 使用结构化媒体内容。媒体文件保存在作品的素材存储中，不放进应用安装目录。

文字字段也可插入素材标记；已有结构化媒体对象的 `src` 字段可以更换同类型素材。导入格式、正文引用、预览与附件绑定的区别见 [图片、视频与音频资源](MEDIA_RESOURCES.md)；音频专项说明见 [音频资源](AUDIO_RESOURCES.md)。

仅需取出一个原始文件时，在素材清单或插入素材窗口使用 **导出原文件**，保留原格式，不转码；要连同身份和依赖搬到另一工程，请使用资源包。

### 6. 保存并检查结果

点击 **保存修改**，或使用 `Ctrl/Cmd+S`。字段编辑内还可使用 `Ctrl/Cmd+Enter`。保存冲突会保留草稿，按提示核对最新版本后再处理。

正文写入与索引、预览刷新是两个步骤。如果提示“已保存，但刷新失败”，先重试刷新，不要把它当成正文未保存而重复覆盖。之前可用的目录和已保存正文会保留。模板设置保存后也会等待索引更新再结束。

导出与构建读取已保存内容。桌面返回作品库会保留当前窗口草稿，关闭应用前仍应保存；Android 的中断恢复副本也不能代替完整备份。

### 7. 分享、跨工程复用或迁移

| 目的 | 入口与结果 |
| --- | --- |
| 给他人阅读当前文档或内容 | 编辑器 **导出** 中选择 HTML / Markdown ZIP；解压后阅读 |
| 将选定对象和素材用于另一工程 | **导出 → 资源包**，选择内容及依赖；在目标工程预览并导入 `.viento-package.zip` |
| 取出单张图片、一段音视频等原文件 | 素材清单或插入素材窗口的 **导出原文件** |
| 备份、换电脑、继续编辑整个工程 | 完整 `.viento.zip` 项目包，携带定义、模板、正文、元数据和素材，导入后重建缓存 |
| 交给另一台机器或协作者使用已生成的后端工程 | **构建与运行 → 后端工程 → 工程详情 → 交付工程**，生成 `.viento-build.zip`；接收方仍需相应工具 |

导出只包含已保存内容，不携带编辑草稿。完整项目包会收集外置素材，排除缓存、本机绝对路径绑定和锁；离线或缺失素材需先修复再导出。包导入会校验内容，不覆盖同名已有作品。

具体操作见 [导出](EXPORT.md)、[资源包](RESOURCE_PACKAGES.md)；磁盘上的保存与迁移规则见 [作品库布局](WORKSPACE_LAYOUT.md)。

### 8. 从设定到场景，再交付生成工程

当前执行链路以 **Linux 本机编辑服务** 的已保存 Scene2D 为范围。普通故事和游戏设计文档需显式创建场景声明，才能进入构建。

| 环节 | 在 Studio 中完成什么 | 下一步读取什么 |
| --- | --- | --- |
| 设定 | 用文档、字段表和世界与对象编写角色、物品、背景与关系 | 已保存对象及稳定身份 |
| 投影 | 为同一 OC 创建独立 [RPG 等用途配置](OBJECT_PROJECTIONS.md) | 已保存投影及继承字段 |
| 场景 | [创建或编辑 Scene2D](PROJECT_BUILD.md)，选择对象／投影、图片、实例与分组，在世界工作平面调整布局 | 已登记场景及依赖 |
| 取景与屏幕显示 | 分别设置[运行主相机与世界边界](SCENE_CAMERA2D.md)、只读[文本／数值条 HUD](SCENE_HUD2D.md)；编辑取景不代替运行镜头 | 独立保存的相机／HUD 声明与场景引用 |
| 运行内容 | 分别创建／编辑[行为](SCENE_BEHAVIORS.md)、[声音](SCENE_AUDIO.md)、[动画](SCENE_ANIMATION.md)和[物理](SCENE_PHYSICS2D.md) | 普通保存后的声明、脚本与资源 |
| 组装 | 在 **构建与运行 → 项目组装** 中选择场景与启动入口，按需加入共享状态、事件和键盘映射 | 已保存的[项目组装](PROJECT_ASSEMBLY.md)；单场景可直接构建 |
| 场景流程 | 通过普通行为正文配置[动作／事件导航](SCENE_NAVIGATION.md)、[不同成员重试](SCENE_RETRY.md)或本版提供的[原地重启](SCENE_RESTART.md)，保存后检查组装及参数 | 已保存的行为绑定、脚本及组装；[可选暂停／恢复](PROJECT_PAUSE.md)和[键鼠菜单](PROJECT_MENU.md)沿各自普通TXT启用，暂停中重开与新会话仍独立推进 |
| 检查与运行 | 选择目标，检查计划、构建，再执行无头测试或窗口预览，查看诊断和运行记录 | 本次成功构建的冻结快照 |
| 交付 | **后端工程 → 工程详情 → 交付工程**，审阅库存和工具依赖，再准备并保存包 | `.viento-build.zip` 及校验清单 |

各编辑器保留自己的未保存输入。已有声明的表单修改通常经过 **检查 → 审阅完整原文 → 应用到原文草稿 → 普通保存**；首次创建则按对应窗口审阅并保存正文、登记与关联。预览、试算和读取目录不会自动保存。构建消费已保存数据，内容修改后要重新构建才能交付新结果。

重复实例需要相同行为配置时，0.3.0 可在 **编辑场景行为** 选择来源绑定，再明确选择 **复制到场景实例 → 复制当前绑定**。复制当前参数与信号并分配新绑定身份，参数内的 UUID 保留；按需核对目标后，仍走 **检查 → 完整审阅 → 应用草稿 → 普通保存**。仅选择目标或取消不写作品数据，脚本与引用关系单独管理。详见[实例配置复制](SCENE_BEHAVIORS.md#复制当前绑定到场景实例)。

需要复用布局时，从[新建场景配方](SCENE_COMPOSITION.md#新建场景配方)选择对象／投影，建立演员和起始排布。保存后在 **场景预览 → 从配方创建场景** 审阅并生成独立 Scene2D，保留实例身份及投影继承；后续两份正文各自编辑。配方和 Scene3D 不直接进入 Scene2D 构建目录。

| 后端通道 | 当前交付内容与接收方条件 |
| --- | --- |
| Godot 4 | 生成工程、脚本与所需素材；接收方需兼容 Godot，可按范围无头测试或窗口预览 |
| Bevy 数据通道 | 无图场景数据工程；接收方需匹配的可信无头运行程序 |
| Bevy Rust 作者行为通道 | 无图 Cargo 源工程和作者 Rust 行为；接收方需固定工具链及预缓存依赖，临时编译后运行 |

两条 Bevy 通道的选择与限制见 [Bevy 后端](BEVY_BACKEND.md)。交付包不携带工具、缓存、二进制或原始作者快照；要继续编辑整份作者工程，另行导出 `.viento.zip`。这些工程包尚不是独立游戏安装程序。0.3.0 的[暂停核心和作者操作](PROJECT_PAUSE.md)已接通Godot组装，原生／离线与完整应用回归已通过；本轮[运行菜单](PROJECT_MENU.md)已补原窗口／离线组合；从空白完整作者任务、跨启动存档、持续运行和独立发行仍属[开发路线](ROADMAP.md)，不能按现有工程交付按钮推导这些结果。

准备交付包占用服务任务位置，直到 ZIP 写入和复核结束。取消准备或关闭尚未下载的窗口会清理临时包；桌面保存对话框需先完成或取消。构建面板的 **返回编辑器** 不会取消正在执行的任务。文件库存、工具检查与迁移范围见 [后端工程管理](BACKEND_PROJECTS.md#交付生成工程)。

Scene3D 使用[独立创作与导出](SCENE3D.md)；Nuis / ns-nova / yalivia 执行、嵌入运行视口和独立游戏发行见 [开发路线](ROADMAP.md)。

### 场景声音与时间提示

先导入 PCM16 WAV，在已保存场景的 **构建与运行 → 场景声音设置** 中创建音轨；每轨选择定时播放或行为触发，审阅后保存正文与关联。已有文档通过 **编辑场景声音** 调整轨道、时间提示、素材与音量，再检查、审阅、应用草稿并普通保存。

[场景声音指南](SCENE_AUDIO.md)集中说明提示排序、轨道复制／移除、已绑定素材选择及就地试听。试听、暂停和定位使用本次已校验的音频副本，不执行场景时间提示；Godot 构建与实际播放另行验证。行为播放／停止和回执见 [声音控制](PROJECT_AUDIO_CONTROLS.md)。

### 9. 行为编辑与外部工具方向

先在主编辑器操作栏点击 **新建脚本**，从空 Node 或参数／信号示例开始，选择工程已有类型与正文目录内的 `.txt` 路径，审阅完整内容后 **创建脚本草稿**。继续编辑并普通保存后，TXT 才成为已登记脚本；不要求工程存在 `script` 类型，不改变文档类型模板，也不自动关联场景或执行源码。取消不写文件，有其他未保存草稿时先完成当前编辑。详见[内置脚本创建](SCENE_BEHAVIORS.md#内置脚本创建)。

脚本与场景保存后，在 **构建与运行** 选择已保存的 Scene2D v2／v3，再首次添加行为：选择稳定场景实例和已登记 TXT，按需增删绑定，预览新声明与登记变更，确认后一次保存新正文、新登记和场景关联。当前界面可选择 Godot／GDScript 或 Bevy／Rust，创建 1–32 条绑定并使用最多 8 份已登记 TXT；初始参数与信号映射为空。后端选项只写作者声明，宿主工具仍需另行配置；本面板不执行源代码。缺少脚本时可点击 **新建 TXT 脚本并返回**，暂存当前配置，经普通脚本选择器创建并保存 TXT，或取消创建，再点击 **返回场景行为设置**。返回会重新核对来源和目录，保留原配置；仍需明确选择脚本并重新审阅，不自动绑定。具体边界见[创建脚本后返回场景](SCENE_BEHAVIORS.md#创建脚本后返回场景)。场景已有行为关联时转到现有绑定文档；保存完成后可打开新原文继续编辑。详见[首次添加行为](SCENE_BEHAVIORS.md#从场景首次添加行为)。

已有绑定使用独立的 **编辑场景行为** 面板。打开已有的已登记绑定 JSON，在源码编辑模式下选择绑定和场景实例、选择已关联的 TXT 脚本，并编辑带明确类型的参数与信号映射。新增绑定使用稳定 UUID，同一实例可挂多份行为；至少保留一条绑定。点击 **检查行为修改** 审阅完整原文和依赖，再 **应用到原文草稿**，最后普通保存。脚本正文仍在内置 TXT 源码编辑器修改。

已有声音声明保存后，行为面板还可 **读取场景音轨**，在任意文本参数旁选择并明确 **填入音轨编号**。读取或切换选项保留参数与现有审阅；填入后走同一检查、草稿与普通保存流程，不按参数名推断用途，也不自动修改声音或关系。操作见[音轨选入](SCENE_BEHAVIORS.md#将音轨编号填入行为参数)。

首次创建使用可恢复的多文件保存；已有绑定的表单编辑仅应用当前文档草稿，不修改所属场景／后端／语言，也不自动增加元数据关联。原文、文档会话、保存基线或依赖改变后，需要重新打开并检查；构建仍消费已保存内容，真实脚本类型和信号由后端验证。操作与限制见 [内置行为编辑](SCENE_BEHAVIORS.md#内置行为编辑010-之后的工作树)。

外部 IDE 和语言服务是独立接入方向，LSP 目前尚未实现。后续接口将围绕文档 URI、语言、版本、来源范围、诊断和受版本守护的草稿修改设计；内置编辑器与外部工具应共享作者来源规则，生成工程的外部修改不会自动回导。

## 俯视收集参考游戏初稿

[晶石庭院](../examples/topdown-collect/README.md)是一份可复制打开的普通作者工程，串起角色原设定、玩家用途投影、四个 Scene2D、真实碰撞拾取、受伤、开门、通关／失败和不同成员重试，包含镜头、HUD、动画与声音。工程内的操作指南随作者包和组装资源闭包携带；现有 UI 仍需显式选择脚本和填写参数。

[本轮实测](test-results/topdown-collect/README.md)分别覆盖已存在样例的编辑保存／取消／重开、三语预览与构建、Godot 原窗口方向键玩法，以及作者包／资源包／生成工程迁移。不表示已完成从空白工程的逐步界面复建、暂停、同场景即时重启、存档、长期运行或独立游戏发行；这些继续按[路线图](ROADMAP.md)推进。

已有行为的参数需要引用其他成员、当前场景实例或键盘动作时，可在 **编辑场景行为 → 按名称连接行为参数** 读取保存态目录。显式选择组装、参考项和目标文本参数，再 **填入参数值**；原有检查、完整原文审阅和普通保存继续生效。细节与失效处理见[行为指南](SCENE_BEHAVIORS.md#按名称填写成员实例与输入动作)，从空白复建仍按[路线图](ROADMAP.md)继续。

首次绑定当前官方重试脚本后，**脚本参数接口 → 补齐缺失参数** 可以明确加入三项原始默认值；再用名称选择器填写动作／成员，手动设置初始状态并沿原有审阅保存。现有值和其他绑定保持，手改脚本不推断接口。[操作及边界](SCENE_BEHAVIORS.md#官方重试脚本的参数起始项)和[空白结构后的试点](test-results/scene-retry-parameters/README.md)分别记录作者辅助与实际运行。

0.3.0 提供的[原地重启](SCENE_RESTART.md)沿相同普通脚本和行为保存链：显式补齐动作／初始值两参数，不填写目标场景；重建当前成员，保留未列共享键和累计预算。状态范围由作者明确选择，不能靠重启绕过有限运行上限。
