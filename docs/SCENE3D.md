## 可组合的距离雾（0.1.0 之后的工作树）

场景可以直接增加可选的 `fog` 组件，不需要切换或细分游戏模板。在原文模式打开 **编辑3D环境**，勾选 **距离雾**，填写雾颜色和密度，检查完整候选后应用草稿，再普通保存。取消保留原文；下次打开读取已保存参数。中、英、日界面使用同一份场景数据。

```json
"fog": { "color": "#aabbcc", "density": 0.05 }
```

颜色为六位十六进制值；密度是每场景单位的衰减系数，范围 `0..1`，数值越大，远处物体越难辨认。缺少组件或密度为 `0` 表示无雾，旧场景不会自动增加组件。关闭时可将密度改为 `0`；也可在原文中移除整个可选组件。雾量按相机到表面点的距离 `d` 计算为 `1 - exp(-density * d)`。它只改变物体着色，背景颜色独立，编辑器的选中边缘仍作为可读提示覆盖画面。

这是 schema 1 的可选扩展，旧的无雾声明和计划保持兼容；含雾文件需要支持 `viento_core_scene3d_fog_version() === 1` 的新核心。旧核心只禁用雾表单，其他环境字段仍可编辑；不能解析雾的旧版本会拒绝该声明，不会静默丢弃字段。

Rust 负责完整语义、数值范围及保真原文修改。共享提案负责来源绑定与审阅；表单只通过原有环境草稿接口应用。WebGL2 消费冻结模型，用当前临时镜头和相对坐标计算雾；Godot 适配器消费同一计划，映射到 `WorldEnvironment` 的指数雾，并检查运行中实际 Environment 属性。Godot 配置参考[官方环境接口](https://docs.godotengine.org/en/4.6/classes/class_environment.html)与[Compatibility 着色器公式](https://github.com/godotengine/godot/blob/4.5-stable/drivers/gles3/shaders/scene.glsl)。两端的材质和色彩管线仍不同，不保证像素完全相同；极小密度在 GPU／Godot float32 中可下溢为零，作者声明保留原值。

这一步不引入天气预设目录、自动时间推进或玩法规则。雨雪粒子、空间天气区域、变化曲线及玩法订阅以后分别接入；Bevy 当前仍是独立 2D 无头执行能力，尚无 3D 雾。实测范围与保存记录见[距离雾专题](test-results/scene3d-fog/results.json)。

## 在编辑器中预览

使用现有 JSON 文档类型创建并保存正文。可复制[三个方块样例](../examples/scene3d/scene.json)，在原文编辑模式点击 **3D 预览**。预览读取当前编辑会话，已保存内容和未保存草稿都可查看；**刷新当前草稿**读取最新原文。选择对象可查看身份、位置、旋转、尺寸和原文路径。视角操作只改变观看方式，**重置视角**回到作者相机。

预览不授予保存或引擎执行权限。原文无效时保留最近有效画面并显示诊断；切换文档或离开原文会话后，旧响应不能更新新窗口。关闭时释放渲染资源。旧核心缺少 3D 能力或宿主不支持 WebGL2 时，界面明确说明当前不可预览；普通编辑与 2D 入口继续可用。

## 双指导航（0.1.0 之后的工作树）

在有效 3D 画布上放下两根手指，可同时**平移和捏合缩放**，无需切换拖动方式。双指中心处、观察目标所在深度的世界位置会跟随双指中心移动；张开手指放大，合拢缩小。透视与正交共用这一锚点规则；透视中其他深度的物体仍会有视差。

| 操作 | 行为 |
| --- | --- |
| 单指操作后加入第二根手指 | 升级为双指导航，停止原来的单指点击或拖动候选 |
| 两指保持间距一起移动 | 平移临时镜头与观察目标 |
| 两指张开／合拢，同时移动中心 | 在中心锚点处缩放并平移；保留观看方向、临时上方向和投影模式 |
| 抬起任一手指，或系统取消触摸 | 结束整次双指手势；剩下的手指不会继续拖动、点选或聚焦 |
| 全部抬起后重新触摸 | 按原单指规则开始新一轮操作 |

两指间距至少为 **4 CSS 像素**，任一手指从双指开始位置累计移动超过 **4 CSS 像素**后才启动导航。开始后，同一浏览器动画帧内的移动先合并为两指最新位置，再一次绘制并更新两指和镜头基准，避免两指事件先后在缩放边界引起轻微缩放；达到缩放上下限后反向捏合会立即响应，中心平移仍遵守实际有效缩放。聚焦后的取景距离边界继续有效，不突然切回普通缩放范围。超出默认缩放区间的作者视角在本段双指手势中使用相对距离范围，避免开始操作时镜头突然跳动；该范围在本段内固定，已有聚焦范围仍沿用。

第三根手指、混入鼠标或其他指针、捕获丢失、滚动、画布尺寸变化，以及模型刷新、重置、投影切换、聚焦或滚轮操作都会结束当前双指手势。正常抬指会先提交最后一批待处理的有效位移，再结束；取消、滚动或其他视图变更则丢弃待处理位移并取消排帧，旧回调不能更新已结束的手势。之后的旧触点不能继续操作或误选对象，需重新开始主触点。两个触点的转动不会旋转镜头；当前没有双指旋转、惯性或作者对象变换。

缩放和平移作为一次候选检查、一次最终绘制提交；非法输入或矩阵预检失败保留原相机。实际绘图失败还会撤销不完整画面的命中和方向提示回执，避免继续对失败画面点选。双指导航仅改变当前观看方式，所选身份、搜索、作者相机、对象坐标、原文和普通保存保持。

支持此操作的渲染器会显示中英日触控说明。旧渲染器未声明支持时不显示这条提示，其已有单指和鼠标操作继续可用；没有新增按钮、系统模块、声明能力、Rust 操作、作者格式或后端接口。

专题证据分别见[汇总](test-results/scene3d-touch/report.json)、[相关回归](test-results/scene3d-touch/targeted-tests.tap)、[浏览器记录](test-results/scene3d-touch/browser/browser.json)、[预检](test-results/scene3d-touch/preflight.json)与[准备副本](test-results/scene3d-touch/prepared.json)。记录按自身实际环境说明范围，不代表 Android 实机、硬件 GPU 或新安装产物验收。

## 坐标方向提示（0.1.0 之后的工作树）

3D 画面右上角增加约 **96 × 96 px** 的方向提示，显示世界坐标的 **+X、+Y、+Z** 正方向在当前画面中的朝向。旋转镜头、切换标准方向或恢复作者相机时，三轴会跟随实际画面变化；平移、缩放或透视／正交切换本身不改变朝向。

| 提示 | 含义 |
| --- | --- |
| `+X`、`+Y`、`+Z` 与三种轴颜色 | 表示固定的世界正方向，文字与颜色同时标识，不依赖颜色单独识别 |
| 空心端点 | 该正方向背向观察者 |
| 实心端点 | 该正方向朝向观察者，或处于画面平面内 |
| 投影到中心的端点 | 该轴朝向或背向当前镜头；仍保留可读的 `+` 轴标签 |

端点按远近顺序绘制；两个轴投影重合时，标签会分开排列。说明文字另提供每个轴朝向、背向或位于画面平面的三语无障碍名称。它没有持续播报区域，不会在每次拖动时触发实时朗读。

方向提示只在当前渲染器提供有效绘图回执后显示。它跟随成功画面更新，不用定时轮询、重新解析原文或保存；无 WebGL2、没有有效帧、实际绘图失败、收到失效回执或关闭预览时隐藏。新草稿无效但最近有效画面仍保留时，提示继续对应那一幅有效画面。旧渲染器没有回执接口时不显示提示，原有声明与可用预览继续工作。

角落提示不拦截指针，经过该区域的拖动仍交给画布；它不能点击切换观察方向，也不是对象变换手柄、测量尺或坐标网格。需要切换视角时继续使用 **观察方向** 控件。提示不读取作者名称、文本、元数据或引擎工程，不新增作者 schema、Rust 操作、Studio 模块、声明能力或保存权限。

## 正交观察（0.1.0 之后的工作树）

在 **3D 预览 → 视图投影** 中选择 **正交**，可比较不同深度对象的布局和大小；选择 **透视**恢复近大远小的显示方式。两种投影共用当前临时镜头、六个观察方向、点选与边缘提示、旋转／平移手势，以及单对象和整景聚焦。

切换投影时，相机位置、观察目标、方向、距离、裁剪范围、所选对象、搜索条件、拖动方式和已有聚焦距离边界保持。正交显示范围根据当前相机距离和视场角换算，使**观察目标所在深度的画面中心与尺度保持一致**。其他深度处的显示大小会变化：相对透视，目标前方的对象可能变小，目标后方的对象可能变大。这是投影差异，切换本身不会重新移动镜头或保证全部对象都在画面内；需要完整取景时使用 **聚焦全部对象**。

| 操作 | 正交模式下的行为 |
| --- | --- |
| **按方向查看**、**聚焦所选对象**、**聚焦全部对象** | 使用当前投影计算取景距离与临时裁剪，保留方向和上方向并包住对应的旋转角点 |
| **平移视角**、Shift 左拖、中键拖动 | 所有深度的几何按相同屏幕位移跟随拖动，不发出对象点选 |
| **旋转视角** | 围绕当前目标旋转；同尺寸对象不会仅因深度改变显示尺度 |
| 滚轮 | 通过当前镜头距离改变正交显示范围；保留观看方向与临时上方向 |
| **重置视角**、成功的 **刷新当前草稿** | 恢复作者相机，保留当前投影和拖动方式 |
| 关闭后重新打开预览 | 重新读取草稿，恢复默认透视投影与旋转模式 |

切换会停止正在进行的手势，旧点击与移动不能在新投影下继续；选择和对象声明仍保留。正交继续遵守当前近／远裁剪及实体遮挡，不能透过前方物体选中后方对象。无效新草稿保留最近有效模型和诊断；原文定位仍须匹配当前完整来源。数值或 Float32 上传预检失败时保留原投影，实际绘制失败恢复原模式并使不完整命中帧失效。

投影模式只属于当前预览，没有写入作者 `camera`、正文、元数据、普通保存或导出计划。Godot 工程仍按作者声明导出，不因预览选择正交而改变；没有新增 Rust 操作、场景 schema、Studio 模块、声明能力或执行后端权限。缺少可选投影接口的旧渲染器只禁用该控件；WebGL2 不可用时继续显示声明。

本轮证据分别见[专题汇总](test-results/scene3d-orthographic/report.json)、[相关回归](test-results/scene3d-orthographic/targeted-tests.tap)、[浏览器记录](test-results/scene3d-orthographic/browser/browser.json)、[预检](test-results/scene3d-orthographic/preflight.json)与[准备副本](test-results/scene3d-orthographic/prepared.json)。报告各自说明实际执行范围和环境，旧平移与标准方向证据保留原时点，不据此宣称全量应用、Rust、安装包、Android 设备或硬件 GPU 已重新验收。

## 临时镜头平移（0.1.0 之后的工作树）

在 **3D 预览 → 拖动方式** 中选择 **平移视角**，然后在画布中拖动。相机与观察目标一起沿画面横纵方向移动，目标深度附近的物体跟随指针；视线方向、相机到目标的距离、视场角和裁剪范围保持。物体处于不同深度时，透视投影下的屏幕位移会不同；[正交观察](#正交观察010-之后的工作树)下所有深度采用相同屏幕位移。它不会修改对象坐标、作者相机或原文，也不产生作者移动提案。

| 操作 | 行为 |
| --- | --- |
| **旋转视角**模式中左键拖动 | 沿原有轨道旋转；没有拖动的单击选择对象，双击聚焦 |
| **平移视角**模式中左键或单指拖动 | 仅平移临时镜头；单击或双击不触发对象选择、聚焦 |
| 按住 **Shift** 再左键拖动，或使用鼠标中键拖动 | 本次手势临时平移，不改变选择框中的模式 |
| 滚轮 | 沿当前方向缩放，保留精确俯视／仰视的临时上方向 |
| **重置视角**、成功的 **刷新当前草稿** | 恢复作者相机，保留当前拖动模式；无效草稿仍保留最近有效预览 |
| 关闭后重新打开预览 | 重新读取草稿，恢复默认旋转模式 |

手势在按下时确定模式，中途改变 Shift 状态不会切换同一次拖动。切换模式、观察方向、聚焦、重置、刷新、画布尺寸变化、滚动、第三个触点、混合指针或额外鼠标按钮、捕获丢失或绘图上下文丢失会停止旧手势；后续移动不能继续操作旧画面。平移不产生画布点选或双击聚焦事件，列表仍可用于选择对象。搜索、所选身份和对象声明保留；无效新草稿可以继续浏览最近有效模型，精确原文定位仍要求当前来源一致。

移动尺度由当前相机距离、视场角、CSS 画布尺寸和实际绘图缓冲比例计算；后两者分别处理，适应窄屏及受限绘图缓冲。数学层支持标准方向与自由视角，包括精确俯视、仰视和聚焦后的远距离或毫米级场景。非有限数值、溢出、无法分辨的位移或明显姿态精度损失会整次拒绝。GPU 上传另检查实际 Float32 数值；绘制失败保留上次相机并使不完整命中帧失效，沿原错误接口显示诊断。

平移专题最初只覆盖单指拖动；当前另接[双指导航](#双指导航010-之后的工作树)，第二根触控手指可升级为同时平移和捏合，鼠标与单指原有模式继续保留。

平移专题最初只覆盖透视预览；当前投影选择另见[正交观察](#正交观察010-之后的工作树)。镜头平移仍不属于对象平移、作者相机编辑、空间层级、动画或统一撤销。缺少可选拖动模式接口的旧渲染器只禁用该控件；WebGL2 不可用时继续显示对象声明。中英日界面共用同一只读接口，没有新增模块、声明能力、Rust ABI、保存或后端权限。

本轮证据分别见[专题汇总](test-results/scene3d-pan/report.json)、[相关回归](test-results/scene3d-pan/targeted-tests.tap)、[浏览器记录](test-results/scene3d-pan/browser/browser.json)、[预检](test-results/scene3d-pan/preflight.json)与[准备副本](test-results/scene3d-pan/prepared.json)。这些记录各自说明实际运行范围和环境；不将旧证据计作本轮全量应用、Rust、安装包、Android 设备或硬件 GPU 验收。

## 标准观察方向（0.1.0 之后的工作树）

在 **3D 预览** 的 **观察方向** 中选择前、后、左、右、俯视或仰视，再点击 **按方向查看**。选择框只选择下一次操作，选择本身不移动相机；操作会包住当前有效预览的全部对象，搜索和所选对象不限制取景。标准方向最初沿用透视投影；当前按所选[视图投影](#正交观察010-之后的工作树)取景，保留视场角参数，方向选择本身不会切换投影模式。

| 方向 | 从场景中心的哪一侧观看 | 画面上方 |
| --- | --- | --- |
| 前／后 | +Z／−Z | +Y |
| 左／右 | −X／+X | +Y |
| 俯视 | +Y | −Z |
| 仰视 | −Y | +Z |

俯视和仰视精确对齐 Y 轴，使用独立临时上方向，不通过小倾角避开极点。进入标准方向后，**旋转视角**模式沿画面局部横纵轴旋转，可以越过极点；**平移视角**沿当前画面平面移动相机和目标，滚轮只改变距离。**聚焦所选对象**与**聚焦全部对象**保留当前方向和上方向；**重置视角**或成功刷新恢复原作者相机及原世界 Y 轴轨道方式。选择框保留的是待执行的方向，不作为拖动后的实时姿态指示。

该入口只改变临时视图，不改作者相机、元数据、正文、选择、筛选或保存基线。无效草稿仍可从各方向查看最后有效模型，诊断保留；原文定位继续要求来源一致。缺少可选渲染方法、WebGL2 不可用、加载中或会话已关闭时禁用；失败不假报切换成功。窄屏控件换行、画布和对象声明可纵向滚动。

验证见[标准方向记录](test-results/scene3d-standard-views/results.json)：254项相关回归、真实 Chrome 的七类流程、中英日390px显示及520个截图／GPU像素比较通过，桌面和移动资源的16项内容与12次方向计算另行核对。采用显式 ANGLE／SwiftShader 软件路径，未重新执行完整应用、Rust、安装包、Android设备或硬件GPU验收；旧默认无头合成限制仍按原记录保留。

在 **3D 预览** 中单击可见方块，右侧选择和对象声明同步到该实例；单击空白保持已有选择。双击对象复用 **聚焦所选对象**，只改变临时观看方式。列表选择与画布选择消费同一份有效模型中的稳定 UUID；已有名称／UUID 筛选保持，点击筛选结果之外的对象时使用原有“所选对象不在当前结果中”说明，不清空查询，也不跳转或修改原文。

## 只读浏览导航（0.1.0）

在 **3D 预览** 的对象列表中，使用 **按名称或UUID查找对象** 做文字筛选；名称和 UUID 按忽略大小写的字面子串匹配，输入前后空白只从查询中去除。原名称、对象顺序和身份保持。**清空搜索**恢复完整列表；当前选中对象被筛选隐藏时仍保留选择和声明，界面明确提示。

选择对象后点击 **聚焦所选对象**，临时镜头指向该方块中心并保持当前观看方向。旋转和非均匀尺寸以包含八个角的包围球计算；透视模式按实际画布宽高比和较小视场角留出 1.2 倍空间，正交模式则按对应的平行投影范围取景，详见[正交观察](#正交观察010-之后的工作树)。聚焦使用自己的临时近／远裁剪面，作者裁剪范围很短时也能完整看到对象；特别远或近的聚焦距离不会在第一次滚轮操作时突然套用普通轨道的默认距离边界。GPU 使用以当前观看目标为中心的临时浮动原点，改善远坐标微小几何的绘图精度；显示的镜头坐标仍属于作者坐标系。

聚焦、拖动和滚轮均只改变当前观看方式，不写入作者相机、对象、原文或保存基线。**重置视角**或成功 **刷新当前草稿**重新使用作者相机；刷新、重置和关闭清理旧拖动与聚焦状态。对象无效、画面尚未加载、GPU 上下文丢失或视图已关闭时，聚焦不修改当前视角。此能力不要求任何作者编辑补丁探针。

点击 **定位对象原文**时，宿主按稳定 UUID 重新解析当前完整原文，取得本次源快照的精确 UTF-16 声明范围，再返回编辑器选择整份对象声明。原文含 BOM、非 BMP 字符或 CRLF 时保留原字节；浏览器文本框的 CRLF／CR 显示换行为 LF，只有完整显示文本与源规范化结果一致时才转换选择偏移。定位不编辑或保存文字。

定位只对同一文档、原文会话、路径、token 和完整内容生效；异步等待后还须核对当前选择、查询和会话审批。草稿已改变时，旧有效画面仍可查看，但旧范围不用于新原文，需先 **刷新当前草稿**。宿主未提供定位接口时，搜索和可用的 GPU 聚焦继续独立使用；无法绘图时仍可搜索和查看声明。接口见[只读导航契约](../engine/README.md#3d-只读浏览导航未发布增量)。

## 编辑单个对象的变换（0.1.0）

只有勾选的字段进入提案。尺寸直接修改作者的 `size`，单位和 XYZ 欧拉约定沿用下文；同值坐标不会重新编码。没有净变化时显示未改变，不形成可应用提案。取消或返回编辑器只丢弃本次表单修改。切换对象、修改表单或来源变化后须重新检查；文档切换、会话变化与取消也会使等待中的应用失效。

Rust 先验证完整原文，按稳定实例身份定位所选对象，再只替换净变化的数字 token，并验证完整结果。BOM、CRLF、键的转义拼写、未变数字的指数或负零写法，以及其他对象、相机、灯光和其余原文均保留。前后原文分别限 128 KiB UTF-8；原文无效、未知字段、越界或最终增长超限时整次拒绝。变更路径按 `position`、`rotationDegrees`、`size`，各字段按 XYZ 排序，形如 `/objects/1/position/0`。

变换使用新的可选核心能力；旧核心缺少它时只禁用这份表单，已支持的 3D 只读预览和原文编辑仍可使用。原生能力和可移植接口见[引擎说明](../engine/README.md#3d-单对象变换未发布增量)。

## 等距分布多个对象的位置（0.1.0）

在 JSON 原文会话点击 **等距分布3D位置**，勾选 3–128 个对象，再选择作者 X、Y 或 Z 轴。点击 **检查等距分布**后，Rust 按各对象该轴的原坐标从小到大排列，同坐标按原声明顺序排列；点击顺序不会改变结果。审阅中的分布顺序来自同份原文，与原文顺序的全部所选前后声明分别展示。筛选隐藏的已选对象仍参与，默认不选择对象。

原排序两端的坐标与数字拼写保持。中间坐标按 `start + (end - start) * (i / (n - 1))` 的二进制64位浮点运算顺序计算，只修改所选轴；未选对象、其他轴、旋转、尺寸、名称颜色、相机与光照保持。分布对象的作者位置，与屏幕视角和外形边缘无关。原坐标全同或没有净变化时没有可应用审批；非零跨度的计算结果若因精度不足不能严格递增，整次拒绝并保留原文，不自动挤压或合并对象。

检查后审阅分布顺序、完整前后对象、净变化路径及完整候选，再 **应用到原文草稿**，最后使用普通保存。对象、轴、查询、原文、文档或会话变化都会撤销审批；关闭、取消和旧列表事件不能影响重新打开的操作。已有未保存草稿也可作为来源。查看结果时刷新独立预览。

Rust 校验原文、所有目标和完整最终模型，只拼接净变化数字词元；BOM、CRLF、转义键及其他原字节保持。最终 UTF-8 预算为128KiB，在合并所有修改后一次判断；无效输入、精度不足或超限均不会产生部分结果。独立可选核心能力、第十五模块及第七私有作者提案只取得自己的五字段来源和草稿接口。缺新能力只关闭此入口；对象格式、只读渲染器、旧六作者域与执行后端分别保持。接口见[核心契约](../engine/README.md#3d-单轴等距分布未发布增量)。

## 批量移除对象（0.1.0）

在已登记 JSON 场景的原文编辑会话中点击 **批量移除3D对象**，勾选待移除对象，再点击 **检查3D移除**。默认不选择任何对象；名称／UUID搜索只过滤列表，隐藏的已选对象仍参与操作。列表和计数明确显示完整选择，不根据只读预览的选中状态猜测输入。

审阅待移除和保留对象的完整声明、原文变更路径和全部候选，再点击 **应用到原文草稿**。路径使用删除前的数组索引，目标按原声明顺序列出，与勾选顺序无关。场景至少保留一个对象；一轮最多移除当前对象数减一，128个对象可以移除127个。全选会明确阻止检查，不会自动保留某个对象或截断选择。取消与返回不修改原文。

Rust基于同一份有效原文一次删除选中声明及必要逗号／邻近布局，并完整检查最终场景。全部幸存对象的顺序、UUID、属性和声明文本原样保留，删除区间之外的原字节也保留；被删项之间的空白不属于保留承诺。无效原文不能靠删除修复，整个操作一起成功或拒绝。移除场景对象不删除素材。

应用只更新草稿，仍需编辑器普通保存，保存继续检测外部文件冲突。随后可刷新独立预览；预览选择只按自己的现有刷新规则回退，不参与作者审批。此入口有自己的第九私有提案和来源端口，仅依赖文档模块；缺新核心能力只禁用批量移除，其他作者能力保持。具体契约见[核心接口](../engine/README.md#3d-批量移除未发布增量)。

## 批量复制对象（0.1.0）

在 JSON 原文会话点击 **批量复制3D对象**，勾选要复制的原对象，填写 XYZ 共同位置偏移，再点击 **检查3D复制**。默认不选择对象，偏移为零；零偏移会生成独立身份的副本，可以审阅与应用，画面可能与原对象重叠。这里的偏移作用于作者世界位置，旋转和尺寸不会改变偏移方向。

每个来源在本次表单会话中只分配一次新的 UUID。重新检查、更改偏移、查询或取消后重新勾选会复用该身份；关闭并重新打开会创建新的一组身份。审阅明确列出来源 UUID→副本 UUID、完整原对象与副本声明、新对象路径及完整候选。副本名称直接继承，不自动加后缀；之后可使用独立属性入口修改名称。

搜索只筛选列表，隐藏的已选对象仍参与。本次最多复制 `min(当前原对象数, 128 - 当前原对象数)` 个对象；每个来源最多复制一次，所以64原件＋64副本是单次最大成功批次。界面分别显示剩余对象名额及本次容量；超出容量不会静默截断选择。已经128个对象时不能追加。

共同偏移各轴为有限数，范围±200000米；每个副本最终位置各轴仍须在±100000米内。任一来源缺失、身份重复或新UUID冲突、目标越界、原文无效、最终对象数或128KiB UTF-8预算超限，都整批拒绝。浮点舍入没有改变位置时仍会复制，原数值拼写保持。Rust 不循环调用单对象复制，不验证或提交中间文档；所有副本在一处插入，最终完整候选一次校验。

原对象、身份、顺序及其所有字节保持。每个副本从来源完整 CST 声明复制，只替换新UUID值及净变化位置数字词元；名称、颜色、尺寸、旋转、键转义、其他数值写法、内部空白与字符串转义保持。副本按原来源的声明顺序追加，点击顺序不影响追加顺序，也不会重配来源与新UUID。

完整审阅后 **应用到原文草稿**，再普通保存。选择、偏移、查询、身份映射、原文或会话变化会撤销旧审批；取消、关闭和旧列表事件不能改变新的表单操作。查看结果时刷新独立预览；预览选择不会自动跳到副本，原来的遮挡与声明顺序规则继续有效。

第十六模块与第八私有作者提案只取得自己的五字段来源与草稿接口，缺新可选核心能力只关闭批量复制。旧七作者域、原格式、渲染、2D、执行后端与磁盘保存分别保持。接口见[核心契约](../engine/README.md#3d-批量复制未发布增量)。

## 管理方块对象（0.1.0）

在 JSON 文档的原文编辑会话中点击 **管理3D对象**，选择 **新增方块**、**复制方块**或 **移除方块**。点击 **检查3D对象**后，审阅数量变化、修改前后声明、原文变更路径和完整候选，再点击 **应用到原文草稿**。应用后仍需编辑器普通保存；已有未保存草稿也可作为来源。

| 操作 | 当前行为 |
| --- | --- |
| 新增方块 | 填写名称和颜色，表单为本次操作分配并显示新的 UUID；位置和旋转为 `[0,0,0]`，尺寸为 `[1,1,1]`，追加到声明末尾 |
| 复制方块 | 选择原对象并明确填写名称，使用本次操作的新 UUID；原位置、旋转、尺寸和颜色保持，复制对象追加到末尾 |
| 移除方块 | 按稳定 UUID 移除所选声明；场景必须保留至少一个对象 |

新增或复制的 UUID 在本次表单操作中保持，反复检查不会重新分配。复制不会自动偏移，重叠是可能的；应用后可使用独立变换表单调整。取消或返回只丢弃本次表单，源草稿不变。切换操作或对象、修改输入、来源变化后须重新检查；切换文档或编辑会话也会使旧审批和等待中的应用失效。

Rust 验证完整原文和最终结果，只追加新项、复制原对象的 CST 字节范围，或删除所选项及必需的分隔符。复制只替换新身份和语义改变的名称值；同名时保留原名称的转义写法，数值指数、负零、键拼写和声明顺序保持。其他对象、相机、灯光、BOM、CRLF 和其余原字节不变。新增／复制身份必须全新且不能冲突，未知对象拒绝；前后各限 1–128 个对象和 128 KiB UTF-8，并沿用所有 3D 作者约束，失败不产生部分原文修改。

独立提案层绑定来源路径、token、原文、保存基线及当前摘要；应用前重新生成完整补丁，宿主在异步完成后复查当前会话和审批。该入口只取得原文草稿应用接口，不取得变换控制器、渲染器、World 命令、文件写入或引擎执行接口。对象管理使用自己的可选核心探针；缺少它时只关闭这个入口，已有只读预览、变换和普通编辑能力各自保持。接口见[对象结构管理](../engine/README.md#3d-对象结构管理未发布增量)。

## 编辑对象名称和颜色（0.1.0）

在 JSON 文档的原文编辑会话中点击 **编辑3D属性**，按稳定 UUID 选择对象，勾选要修改的 **名称**或 **颜色**。填写后点击 **检查3D属性**，审阅修改前后对象、实际变更路径和完整候选原文，再 **应用到原文草稿**，最后普通保存。已保存内容和已有未保存草稿均可作为来源。

只设置勾选的属性，不提供属性删除或恢复。名称沿用 1–256 个 Unicode 码点的作者规则，不新增去空白规则；颜色使用六位十六进制值。未修改的名称和颜色保持原声明，同值解码字符串保留原转义写法。没有净变化时不形成可应用提案。选择对象、修改输入或来源变化后须重新检查，文档／会话切换与取消会使旧审批失效；取消不改变原文草稿。

Rust 先校验完整原文，按稳定实例定位，只替换净变化的 `name`／`color` 字符串值 token，再校验完整结果。UUID、几何、其他对象、相机、灯光、场景名称、视口、键拼写、数值词法、BOM、CRLF 和其余原字节保持。路径按名称、颜色排序，形如 `/objects/1/name`、`/objects/1/color`；两份原文各限 128 KiB UTF-8，名称增长也计入预算。未知实例、无效属性或最终超限均整次拒绝。

此表单只取得当前来源读取和自己的草稿应用接口；它不取得对象增删、变换、环境、预览渲染器、World 或后端接口。应用准备重查来源路径、token、原文、保存基线及当前摘要，并重算精确补丁；宿主在异步等待后核对当前会话和审批，只更新内存，普通保存处理磁盘写入和外部冲突。缺少独立属性核心能力时仅关闭这个入口，旧能力各自保持。接口见[属性编辑契约](../engine/README.md#3d-对象属性原文编辑未发布增量)。

## 编辑作者环境（0.1.0）

在 JSON 文档的原文编辑会话中点击 **编辑3D环境**。逐项勾选要修改的 **背景颜色**、**作者相机位置 XYZ**、**作者相机目标 XYZ**、**垂直视野（度）**、**相机裁剪范围**、**光照方向 XYZ**、**光照颜色**或 **光照强度**。裁剪范围同时提交近、远裁剪面，向量提交 XYZ 三个分量；未勾选项保持原声明。

点击 **检查3D环境**，审阅修改前后环境、实际变更路径和完整候选原文，然后 **应用到原文草稿**，再普通保存。没有净变化时不形成可应用提案。已保存内容和当前未保存草稿均可作为来源；修改表单、切换文档、来源或会话变化都会使旧审批失效。取消只丢弃这份环境表单。

此处读取并修改作者相机声明；预览中的临时旋转、缩放与观看位置不会写入表单或作者原文。需要查看新环境时重新打开 **3D 预览**或 **刷新当前草稿**。环境编辑不取得预览渲染器、对象或变换表单、后端执行或普通保存权限。

背景、相机和灯光的所选字段在一个原子补丁中更新，再校验完整最终场景。例如近裁剪面单独增长可能超过旧远裁剪面，二者一起修改时按最终值检查；相机位置与目标也可一起调整，不要求中间状态有效。方向和裁剪规则沿用下文作者表示，整次失败不会部分修改原文。

Rust 只替换净变化的数字或颜色字符串值 token。同值数值保留指数、负零写法，同值解码颜色保留原字符串转义。所有对象、场景名称、视口、键拼写、顺序、BOM、CRLF 与未修改原文保持；前后各限 128 KiB UTF-8，完整原文无效时拒绝。路径按背景、相机位置／目标 XYZ、视野、近平面／远平面、灯光方向 XYZ、颜色、强度排序，与原键顺序无关。

应用前绑定并重查来源路径、token、完整原文、保存基线及当前摘要，重新生成补丁；异步完成后宿主还须核对编辑会话和当前审批。只更新源草稿，磁盘持久化与外部冲突继续由普通保存处理。环境使用独立可选核心能力；缺少它仅关闭这个表单，已支持的只读预览、对象和变换入口各自保持。接口见[环境编辑契约](../engine/README.md#3d-环境原文编辑未发布增量)。

## 通用粒子场

0.1.0 之后的工作树支持可选 `particleField`。在 **编辑3D环境** 中勾选 **粒子场**，填写范围、速度、尺寸、颜色、数量与种子，经完整原文审阅后应用到草稿，再普通保存。旧场景不会自动加入此字段。数量为 0 时关闭；雨和雪由这些参数组合，不要求不同工程模板。

```json
"particleField": {
  "center": [0, 3, 0],
  "extent": [12, 8, 12],
  "velocity": [0, -8, 0],
  "size": [0.03, 0.45, 0.03],
  "color": "#c5ddff",
  "count": 512,
  "seed": 1
}
```

以上是细长、快速下落的雨粒参数。雪可使用 `velocity: [0.25, -0.7, 0]`、`size: [0.11, 0.11, 0.11]` 和白色。当前粒子为轴对齐方块，在盒状范围内循环移动，没有纹理、透明度、碰撞、积雪或天气玩法事件。

| 字段 | 约束与含义 |
| --- | --- |
| `center` | 三轴中心，各分量 −100000–100000 |
| `extent` | 三轴范围全长，各分量 0.01–10000 |
| `velocity` | 每秒场景单位，三轴各分量 −1000–1000 |
| `size` | 粒子三轴尺寸，0.001–1000，且不能超过对应轴范围 |
| `color` | 六位十六进制颜色 |
| `count` | 0–4096 整数，0 表示关闭 |
| `seed` | 0–4294967295 整数，同一值给出可重复的起始分布 |

打开 **3D预览** 后，粒子从 0 秒开始静止显示。**播放粒子／暂停粒子** 控制临时预览；输入 **预览时刻（秒）** 后点击 **查看时刻**，或 **回到起点**。范围为 0–3600 秒，到达上限自动停止。离开页面、关闭预览、来源变化或渲染中断都会停止；不会自动恢复播放，也不会修改原文或触发保存。粒子不成为独立作者对象，不影响检索、点选及“聚焦全部对象”的范围。

Rust 负责声明验证、确定性起始分布和显式时刻采样；预览时钟、控件和 GPU 绘制分别独立。粒子沿用当前镜头、深度遮挡与雾。Godot 导出保留同一声明及起始分布，生成可检查的 MultiMesh／shader 和有界时钟。Godot 默认无头 dummy 渲染器不能回读非空 MultiMesh 实例：`--check` 可检查工程，`--run` 对此明确报告验证不可用；真实图形渲染验证单独记录，不将参数回执当作像素证明。

本轮源码、Rust／WASM、浏览器和 Godot 的具体范围见[粒子专题](test-results/scene3d-particles/results.json)。尚不代表已安装桌面、Android 实机或物理 GPU 验收。

## 作者表示

场景具有 `format: "viento-scene3d"`、`schemaVersion: 1`，以及 `name`、`viewport`、`background`、`camera`、`light`、`objects`；当前工作树另允许可选 `fog` 与 `particleField`。各级声明严格校验，规则见[JSON Schema](../schemas/scene3d-v1.schema.json)；跨字段约束和完整数值预算由 Rust 额外执行。

| 字段 | 当前语义 |
| --- | --- |
| `viewport` | 两个 1–8192 的整数，表示作者视口宽高，预览保持该比例随窗口缩放 |
| `background` | 六位十六进制颜色 |
| `camera` | `position`、`target`、透视 `fovDegrees`、`near`、`far` |
| `light` | 方向向量 `direction`、六位颜色 `color` 与 0–16 的 `energy` |
| `objects` | 1–128 个显式稳定 `instanceId`、名称、`primitive: "box"`、位置、旋转、尺寸与颜色 |

使用右手坐标系，Y 向上，镜头沿本地 −Z 观看；位置与尺寸以米解释。`rotationDegrees` 采用 XYZ 欧拉顺序，渲染矩阵为 `T · Rx · Ry · Rz · S`，Godot 适配显式指定同一顺序。绘图和 Godot 向量使用浮点表示；极远位置和很小尺寸的组合仍可能受绘图精度影响，作者声明保持原值。尺寸为 0.001–1000，位置各分量为 −100000–100000，旋转各分量为 −36000–36000；名称长度为 1–256 个 Unicode 码点。预览绘制缓冲按设备像素比例缩放，每边最多 2048 像素。

相机视点与目标至少相距 0.01，视向水平分量与总长度之比至少为 0.0001；方向光也须非零并满足同一水平比例，避免与 Y 向上约定平行。`near` 为 0.001–10000，`far` 不超过 100000，二者至少相差 0.001，且 `far` 至少为 `near` 的 1.01 倍。视角为 1–179 度。原文限制 128 KiB UTF-8；BOM、CRLF、数值拼写和稳定身份在读取与导出中保持。

派生模型和计划保持声明顺序、稳定身份和作者数值。对象来源包含 JSON Pointer 与精确 UTF-16 范围；范围只对应生成它的原文。当前几何对象不要求 OC 定义或投影依赖；后续模型素材、投影、层级和行为分别定义自己的版本与引用规则。

## 导出和实际引擎检查

npm run --silent scene:3d -- --input examples/scene3d/scene.json --emit model

明确提供本机 Godot 可执行文件，可在同一次导出中增加 `--check --godot-bin /absolute/path/to/godot`，或 `--run --godot-bin /absolute/path/to/godot`。运行只接受当次导出所持有的来源与文件凭据，先检查生成工程，再执行有限 3D 探针；不会扫描认领或运行已有外部工程。

引擎产生的缓存仍属于这份派生工程。现有 2D 后端工程目录、运行控制、用例和事件协议保持原有契约；3D 实测记录自己的静态树、相机、灯光、几何与变换结果。此阶段不包含物理、材质贴图、模型文件、动画、行为绑定或独立 3D 保存／执行事务。

`org.viento.scene3d-translation`、`org.viento.scene3d-alignment` 与 `org.viento.scene3d-distribution` 分别取得独立的五字段来源和自己的草稿应用接口，只依赖文档模块，分别声明 `scene.authoring.translation3d`、`scene.authoring.alignment3d` 与 `scene.authoring.distribution3d`；共享宿主末端守护不共享审批。

`org.viento.scene3d` 只依赖文档模块，提供 `scene.representation.scene3d` 与 `scene.preview.scene3d`。工程需求是声明数据，实际核心、WebGL2 和工具可用性各自检测；预览取得当前来源读取和可选的受守护光标定位接口，没有原文修改或保存权限。画布选择只属于视图，不新增模块或能力声明。模板类型名和戏剧场次不会隐式变为 3D 数据。

独立 `org.viento.scene3d-transforms` 同样依赖文档模块，声明 `scene.authoring.transforms3d`，由宿主另行注入当前来源读取及草稿应用接口。静态模块声明不授予写文件、World 命令或引擎执行权限，旧预览控制器不取得这份应用接口。

独立 `org.viento.scene3d-objects` 依赖文档模块，声明 `scene.authoring.objects3d`，只取得当前来源读取和自己的草稿应用接口。独立 `org.viento.scene3d-environment` 同样依赖文档模块，声明 `scene.authoring.environment3d`；独立 `org.viento.scene3d-properties` 声明 `scene.authoring.properties3d`。各自仅取得自己的来源读取与草稿应用接口。当前 0.1.0 共声明 17 个模块、33 项能力；声明、装配和实际宿主权限分开，不表示所有模块内部已经拆分完成，也不表示工具已安装。
