# 场景 HUD：屏幕文本与数值条

0.2.10 源码提供独立 HUD 作者文档。首轮支持固定文本、读取项目共享状态的文本和数值条，使用屏幕锚点布局；Godot 项目组装通过独立 CanvasLayer 显示。该切片服务于 [0.5.0 的完整 2D 游戏出口](MILESTONE_0.5.0.md)，当前没有菜单按钮、指针事件、图标／自定义字体、完整游戏暂停或跨启动存档。

## 从内置编辑到运行

1. 在“构建与运行”选择一个已登记的二维场景，打开 **场景 HUD**。该入口支持作者 Scene2D 1／2／3，不改场景格式。
2. 添加文本或状态条。列表顺序是叠放顺序，可上移、下移或删除。填写九点屏幕锚点、像素偏移及尺寸，再填写内容／状态键／颜色等字段。
3. 用预览示例检查缺失、0、false、空字符串和数值。示例只属于编辑器，不保存、不写状态、不读取正在运行的游戏。预览使用场景设计 viewport，字形与行距为示意，实际窗口字体由当前引擎决定。
4. **审阅 HUD 设置**，核对完整候选原文，再显式保存。首次保存审阅的是三文件创建：HUD 正文、HUD 登记、场景登记的引用追加；场景正文不改。已有 HUD 只版本保护更新其正文，保留元素数组之外的原文与 BOM／换行。
5. 将场景放入项目组装，检查计划、构建并运行。HUD 读取项目共享状态；单独场景构建会提示需要组装。修改后要重新构建，预览草稿不改变冻结运行工程。

离开有修改的表单会提示放弃；确定的冲突保留草稿并要求重新读取／审阅。不确定的保存响应只允许重新读取核对，不能立即自动重试创建。场景或 HUD 来源失效后，旧审阅不能继续提交。

## 独立作者文件

```json
{
  "format": "viento-scene-hud2d",
  "schemaVersion": 1,
  "sceneObjectId": "11111111-1111-4111-8111-111111111111",
  "elements": [
    {
      "id": "22222222-2222-4222-8222-222222222222",
      "kind": "label",
      "anchor": "top-left",
      "offset": [16, 16],
      "size": [240, 40],
      "fontSize": 24,
      "color": "#ffffff",
      "content": { "kind": "state", "key": "score", "prefix": "Score: ", "suffix": "", "missing": "—" }
    },
    {
      "id": "33333333-3333-4333-8333-333333333333",
      "kind": "bar",
      "anchor": "top-right",
      "offset": [-16, 16],
      "size": [200, 20],
      "key": "health",
      "min": 0,
      "max": 100,
      "fallback": 0,
      "fillColor": "#80d9b6",
      "backgroundColor": "#102030ff"
    }
  ]
}
```

文档至多 64 KiB UTF-8、0–32 个有唯一 UUID 的有序元素。未知字段、重复 JSON 键、访问器、稀疏数组、非法 Unicode 和超限数据拒绝，不静默补默认值。注册路径位于当前作品正文目录内的独立 `.json`，由作者创建时选择。

- 场景登记：`references → HUD UUID`，`slot: "hud2d"`，同一场景只选一个。
- HUD 登记：`references → sceneObjectId`，`slot: "scene"`，只绑定一个场景。
- 九点锚：`top-left/top-center/top-right/center-left/center/center-right/bottom-left/bottom-center/bottom-right`。
- 偏移为整数 ±8192，尺寸为整数 1–2048；文字字号 8–72，颜色为 `#RRGGBB` 或 `#RRGGBBAA`。
- 固定文本使用 `content: {kind:"literal",text:"..."}`，最多 256 个 Unicode 码点；状态文本前后缀各至多 64，缺失提示至多 256。
- 状态键沿用项目共享状态规则；数值条 `min/max/fallback` 均有限且在 ±1e9 内，`min < max`。

## 状态显示与布局

缺失键与 0、false、空串不同。文本可加前后缀；布尔值显示 `true/false`，数值以确定规则最多三位小数，消除负零；最终文本超过 256 码点后加省略号。共享状态中的不可显示 C0／DEL 只在显示时替换为 U+FFFD，TAB／LF／CR 保留，不修改状态，也不因此终止游戏。作者文本拒绝其他 C0／DEL。数值条遇到缺失或非数值使用 fallback，比例按 `[0,1]` 夹取，实际状态值不改。

设锚点比例为 `a=(0,0.5,1)`，左上角为 `a × viewport + offset − a × elementSize`。运行使用实际 viewport，窗口尺寸变化时重新布局；默认无自动折行，文本由元素矩形裁剪。世界相机的中心、缩放、跟随和世界边界不进入 HUD 坐标。控件忽略鼠标并不获取焦点，本轮只读显示不接管玩法输入。

## 合同、宿主与后端

`engine/scene-hud2d.mjs` 负责文档、依赖与冻结计划；`scene-hud2d-view.mjs` 只给出显示几何和文本／比例；`world-hud2d-create.mjs` 只规划数据。HUD 创建命令为 `hud2d.create`，宿主持有三文件事务日志 v14、提交与中断恢复。旧日志版本继续独立读取，只有显式创建 HUD 才写 v14。

成员计划含 `hud2d:{format:"viento-hud2d-plan",schemaVersion:1,manifest,document}`。能力 `scene.hud2d` 必须出现在成员、组装并集、注册执行适配器和实际生成回执中，不能删去 capability 来让不支持的后端忽略声明。HUD 来源修订冻结，作者／后端生成文件不混合。

Godot 执行描述符为 0.46.0；含 HUD 的组装在内部选择 0.45.0 显示层，新组装最终统一叠加[关卡重试层](SCENE_RETRY.md)。该层从既有项目宿主只读初始共享状态，并在状态修订／视口变化后刷新；每次场景访问独立建立、离场释放。HUD层不改内部协议、旧媒体／相机脚本或无 HUD 内容；最外重试层分别保留和验证原设置。HUD 外层与相机内层分别验证库存，外层设置不能掩盖内层漂移。Bevy 尚未提供此能力，明确拒绝。

资源包会从正文推导场景依赖，恢复后重新校验双向引用；排除依赖时只允许延后“场景不可用”诊断，选定目标时必须读取并核对实际场景来源及登记。作者包恢复与 `.viento-build.zip` 交付是不同出口，后者仍需兼容 Godot，尚不是独立游戏发行。

分层实测、失败修复及平台范围见 [HUD 验证记录](test-results/scene-hud2d/README.md)。当前 JS／Web 是实现承载，原生替代应复用文档、状态显示、能力准入与恢复样例，无需保留 DOM 或 Godot 节点组织。
