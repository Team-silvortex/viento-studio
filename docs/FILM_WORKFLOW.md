# 影视创作工作流

影视与游戏可以共用设定、对象、文档、资源和迁移基础。**0.3.0 源码**新增 **影视** 起始模板，包标识 `org.viento.oc-film`，模板包版本仍为1.0.0，与应用版本分别维护；本机安装仍为0.2.0。

当前支持影视策划、剧本、分镜和素材组织。镜头时间线、剪辑、自动摄影机调度、逐帧渲染和成片输出尚未接入；这里的“制作计划”和“交付目标”是作者文档，不会启动后期工具或生成影片。

## 创建影视工程

在作品库选择 **新建 → 影视**，输入工程名称并选择保存位置。创建后的正文和素材目录为空，8份模板与类型定义复制到工程内，以后可自行修改。默认仍是空白工程；新增选项不修改既有工程或旧模板。

| 类型 | 正文目录 | 解析 | 用途 |
| --- | --- | --- | --- |
| 影视说明 `document` | `documents/` | structured | 形式、题材、主题、风格、观众及制作目标 |
| 人物 `character` | `documents/characters/` | structured | 身份、动机、背景、人物关系与表演参考 |
| 故事大纲 `outline` | `documents/outlines/` | prose | 冲突、情节、场次安排、结局与伏笔 |
| 剧本场次 `scene` | `documents/scenes/` | prose | 时地、在场人物、动作、对白与衔接 |
| 分镜 `shot` | `documents/shots/` | structured | 镜头号、所属场次、景别、视角、运镜、预计时长、画面与声音 |
| 拍摄地点 `location` | `documents/locations/` | structured | 环境、拍摄条件、灯光、收音及参考 |
| 制作计划 `production-plan` | `documents/production-plans/` | structured | 分场安排、拍摄录音、剪辑后期、资源、进度与交付检查 |
| 道具 `prop` | `documents/props/` | structured | 使用人物、出现镜头、叙事作用、外观与连续性 |

这些是可调整的创作起点。短片、动画、剧集或游戏过场可以按实际需要使用其中的类型，不必为每一种制作形式另建固定模板包。

## 从人物与场次开始

1. 新建影视说明和故事大纲，确定主题、冲突和场次顺序。
2. 新建人物，直接在人物的“背景与经历”填写小传；同一人物的背景不拆成另一套独立档案。人物关系沿[对象关系操作](WORLD_RELATIONS.md)，已登记素材沿[资源绑定](WORLD_RESOURCES.md)显式关联。
3. 新建剧本场次，填写时间、地点、人物、动作与对白。场次和大纲使用 `prose`；重复的“人物甲：”或带冒号的时间提示会保留为正文，不作为同名元数据字段合并。
4. 将需要细化的场次拆为分镜，记录镜头号、景别、视角、运镜、画面、对白与声音。完整对白可保留在场次中，分镜记录对应段落和声音提示。模板中的“预计时长”是普通创作文字，例如“约5秒”；它不建立可执行的播放时钟或剪辑点。
5. 按需求补拍摄地点、道具与制作计划。沿普通检查、审阅、保存与重开流程维护文档。

影视的 `scene` 是工程自定义文档类型，正文为Markdown剧本。它不会因类型名与某个游戏概念相同，就被当作可运行的Scene2D或Scene3D。内置游戏场景编辑器及构建适配器继续依据明确的场景格式和能力运行。

## 图片、视频与音频

在桌面或本地编辑服务的文档编辑器使用[插入图片／视频／音频](MEDIA_RESOURCES.md)，选择已登记素材或导入新素材，再保存正文。可以在分镜中放参考图、动作视频和对白录音，也可以在人物、场次或地点文档中引用同一资源。

素材继续按稳定资源ID保存引用，文件与登记保留在工程的资源目录和元数据目录中。模板包不携带参考作品或素材，也不把文件复制进程序安装目录。资源格式、大小、播放及浏览器解码限制沿现有媒体能力；本轮不是视频转码或设备播放验收。移动端仍有独立的[素材功能限制](../mobile/README.md)。

“所属场次”“出现场次与镜头”等初始字段是作者文字，不会凭文本自动创建跨文档关系。需要机器可核对的关系时，使用现有显式对象关系操作，保留登记身份。

## 分享、迁移与交付

分享单篇剧本或分镜可以使用[文档导出](EXPORT.md)。整份影视工程使用 `.viento.zip`：保留工程清单、类型、模板、正文、元数据及素材，导入后仍独立于应用的模板目录。若只复用一部分对象和素材，使用[选择式资源包](RESOURCE_PACKAGES.md)；单个原始媒体可从资源入口导出。

当前影视交付物是作者工程、文档与资源；`.viento.zip` 不是视频文件。生成Godot或Bevy工程另走明确的游戏／场景构建，不由“影视”模板自动开启。

模板格式、来源摘要与兼容规则见[模板契约](PROJECT_TEMPLATES.md)。本轮真实创建、剧本／分镜保存、资源和迁移的结果以[验证记录](test-results/film-template/README.md)为准，不外推到已安装程序或Android设备。

## 后续镜头执行能力

后续可在共用对象和场景上逐步增加镜头序列、明确时间、摄影机调度、声音同步、预览与渲染交付。作者定义、中立时间与身份合同、后端执行和编辑器渲染分别接入；Godot、Bevy及未来ns-nova的支持各自声明和验证。影视分支不增加当前0.5.0两款2D参考游戏的出口要求，主线顺序仍见[路线图](ROADMAP.md)。
