暂停与恢复已收录于 **0.3.0** 源码，本机已安装版本仍为 **0.2.0**。当前接通 Godot 项目组装的同一访问暂停：角色、物理、普通行为、动画、声音和游戏时钟停止，恢复后继续原来的节点与进度。它沿普通 TXT／行为保存链启用，不修改已有作品或生成工程。

## 在 Studio 中启用

1. 在[项目输入映射](PROJECT_ASSEMBLY.md#项目键盘输入映射)保存动作 `pause`，例如选择 `KeyP`；组装明确引用该映射。可以使用其他合法已注册动作，模板不代建映射。`ui_cancel` 保留给 Escape 结束运行，不能选为暂停动作。
2. 在 **新建脚本 → Godot / 按动作暂停与恢复** 创建并普通保存 TXT。这只是普通作者脚本，不修改运行时或暂停节点。
3. 在当前场景明确关联该脚本并新增行为绑定。一个场景访问只配置一个官方暂停控制器；不要把暂停绑定复制到每个角色。不同成员可分别配置各自的一份。
4. 打开 **编辑场景行为 → 脚本参数接口 → 补齐缺失参数**，明确加入下表三个缺失的 String 参数。已有值不会被覆盖；缺失参数仍可使用脚本原有默认值。
5. **检查行为修改 → 审阅完整原文 → 应用到原文草稿 → 普通保存**。取消不写文件；应用只更新草稿。保存后检查、构建整个项目组装，再打开实际窗口。

| 参数 | 脚本默认值 | 含义 |
| --- | --- | --- |
| `action_name` | `pause` | 已注册的暂停／恢复动作；建议独立映射 P |
| `paused_text` | `Paused` | 暂停面板标题，作者可填写中英日文字 |
| `resume_text` | `Release controls to resume` | 恢复等待松键时的提示 |

动作名须为1–64个 ASCII 小写字母、数字或下划线，首字母为小写字母；不能是 `ui_cancel`。每条提示须为1–160个 Unicode 字符，不含控制字符或无效 Unicode；按字符而非 UTF-8 字节计数，原文不自动裁剪或翻译。

参数辅助只识别当前官方完整正文的四种表示：LF／统一 CRLF，各可有一个开头 BOM。额外注释或正文修改后，继续普通参数编辑，不猜测导出属性，也不执行源码。构建预检与能力推导仍只匹配原始官方完整字节；它们不会因参数辅助接受更多表示而放宽。未映射动作提供独立输入建议；实际运行配置必须确认动作已注册。重复官方绑定、无效参数与提示会定位到绑定或参数的原文范围，阻断构建。

## 暂停、恢复与输入

已配置的当前访问使用独立引擎控制器处理新按下：先观察输入边沿，再仅响应未被 GUI 消费的事件。进入场景时已按住、键盘重复与界面已处理的按下不触发；必须释放后重新按下。

| 状态 | 游戏行为 | 下一步 |
| --- | --- | --- |
| `running` | 正常推进当前访问 | 新按下暂停动作，或失焦时请求暂停 |
| `paused` | 玩法与游戏时钟停止，显示基础暂停面板 | 新按下暂停动作，请求恢复 |
| `waiting-for-release` | 仍暂停，显示作者的松键提示 | 窗口有焦点且所有已注册输入动作释放后，才实际恢复 |

恢复闸门检查全部已注册输入动作，包括默认 `ui_*` 动作和暂停动作本身。因此按住方向键或跳跃键请求恢复时，游戏不会立刻移动或产生新的跳跃边沿；先松开这些动作，再继续。没有清改全局输入状态，也没有给旧作者脚本补写新的输入逻辑。

失焦向当前控制器提交暂停；若正处理业务队列，等待安全点再暂停。重聚焦不会自动恢复，也不会重放先前按住的按键。等待松键时再次失焦，回到暂停状态。Escape 结束与窗口关闭继续保留；未配置[运行菜单](PROJECT_MENU.md)时，本页基础面板只提供按键控制与文字提示；菜单另行配置，完整可访问性交互仍待验收。

## 同一访问与安全边界

暂停沿用当前场景访问号、节点实例、共享状态与单调事件／媒体序号。它不重建角色、重入场景、复位分数，也不重新开始一段会话；要重建当前成员，使用[原地重启](SCENE_RESTART.md)。

只有当前访问登记的合法暂停端口可请求控制。进入暂停须处于非物理回调、非 flush 的安全点，事件、声音、动画及完成投递队列为空，没有待处理导航、重试／重启或结束。拒绝不改变阶段、树暂停状态、队列、预算或业务状态；不得靠“先清队列再暂停”丢失语义。

独立控制器使用 `ALWAYS` 处理输入、焦点、提示与关闭；协调器、当前场景及普通作者行为继续使用 `PAUSABLE`，没有把全部玩法代码提为暂停期间运行。延迟回调和信号本身可能在树暂停期间抵达，普通状态／事件／媒体／导航端口与已预约 flush 还会检查暂停门禁，不能因此推进业务。作者 GDScript 仍是实际引擎源码，这不是代码沙箱。

场景离开、结束或中止先撤销控制器和旧访问，再释放由本层持有的树暂停；不会为了关闭而先唤醒旧玩法。旧端口返回不可用，下一访问另行配置。重复请求已经处于的阶段为幂等操作，不制造额外暂停观察；同一端口重复配置相同参数允许幂等，其他控制器不能抢占当前配置。

暂停冻结游戏局部／总时钟与玩法推进，不冻结宿主墙钟超时、输出限制、调度观察或本次会话有限预算。恢复不补额度、不清累计账本；长时间停在暂停面板仍可因原有预览超时结束，不能据此推导持续运行或跨启动存档。

## 构建、后端与观察

Godot当前执行描述符为 **0.49.0**；本页暂停外层仍为0.48.0，可在其外按需叠加[运行菜单](PROJECT_MENU.md)。精确绑定官方暂停脚本时，成员和组装显式要求 `project.pause`；冻结计划与后端能力分别复查，删掉声明不能降级运行。单独 Scene2D 构建应改用包含该成员的项目组装。两个 Bevy 通道当前均不支持暂停，不从 Godot 的实现推断支持。

`project.pause` 是可选外层：实际要求暂停的生成工程使用 **0.48.0**，包含两份新 GD、暂停清单及保留的原入口／设置；没有暂停需求的生成工程继续原 **0.47.0** 重启层，旧生成内容保持。外层独立认证后再校验完整内层库存，工程 ZIP 仍可检查和迁移。应用版本、作者格式、事务日志与项目业务线协议4／7／10／11均不升级；执行描述符与生成器版本分别记录。

独立 `VIENTO_PROJECT_PAUSE` 协议1只传递暂停观察，不混入旧业务事件。纯读取器核对当前组装、成员、访问、连续序号、合法阶段转换和冻结的游戏时间，默认仅保留最近32条转换。宿主与构建面板只读展示暂停、等待松键或恢复状态；显示最后状态不提供执行权限，未完成观察另行标明，也不冒充实时玩法位置。

完整作者迁移使用 `.viento.zip`，已生成工程交付使用 `.viento-build.zip`；后者仍依赖 Godot 工具，不是独立游戏发行物。本轮实际 UI 作者现场含102文件、35登记文档、9项素材；[标准作者包](test-results/project-pause/browser/author-final.viento.zip)保存101份标准数据及清单，顶层 README 作为原字节旁附，真实 Rust 导入后快照和全部作者哈希一致。素材及素材登记的18份 Git 忽略文件完整进入 ZIP，不能靠原始证据目录自动提交保证迁移完整性。
