# 从失败页重试关卡

0.2.10 源码新增 **Godot / 按动作重试关卡** 普通脚本模板，用于“开始→关卡”和“失败页→关卡”。它重新建立目标场景，并在目标行为就绪前一次性应用显式初始值。未列出的会话状态保持，作者文件和素材不受影响。

这一步接通不同组装成员之间的关卡重试；本页保留0.2.10的运行语义。同场景重启由工作树新增的[独立重启接口](SCENE_RESTART.md)负责，全新会话、暂停和跨启动存档仍待推进，见[0.5.0 门槛](MILESTONE_0.5.0.md)。

## 在内置编辑器中配置

1. 将开始、游玩、失败三个已保存场景加入同一[项目组装](PROJECT_ASSEMBLY.md)，开始场景作为入口。三个场景均使用稳定实例承载行为；[HUD](SCENE_HUD2D.md)可以显示操作提示、`score` 和 `health`。
2. 创建并保存输入映射，例如 `menu_confirm → Enter`；再在组装中引用并保存。脚本模板不会创建输入动作。
3. **新建脚本 → Godot / 按动作重试关卡**，审阅源码，创建普通 TXT 草稿并保存。
4. 在开始场景中显式关联该脚本，用行为编辑器添加绑定。源码完整匹配当前官方模板时，可在 **脚本参数接口 → 补齐缺失参数** 明确添加下面三个 **String** 参数；已有值保持，手改脚本仍可手动添加。再从 **按名称连接行为参数** 明确选择组装、已保存动作与目标成员，修改初始化JSON，检查完整修改、应用到原文草稿并普通保存。
5. 在失败场景复用该脚本，使用相同目标和初始值。目标填游玩场景的完整小写 UUID，不能填失败场景自身。
6. 游玩场景使用[按事件切换场景](SCENE_NAVIGATION.md)，订阅 `game.failed` 并指向失败场景。伤害、生命耗尽或触发区等玩法行为负责发布事件；重试模板不会自行判定失败。
7. 保存全部来源，检查组装、重新构建并窗口运行。第一次进入与失败后重试都应看到初始位置、分数和生命值；按住确认键跨场景时需要释放后重新按下。

| 参数 | 示例 | 含义 |
| --- | --- | --- |
| `action_name` | `menu_confirm` | 默认 `ui_accept`；动作必须已注册 |
| `target_scene_id` | 游玩场景 UUID | 当前组装中的另一个成员 |
| `state_values_json` | `{"level":1,"score":0,"health":100,"key_found":false}` | 明确复位这些键，其余进度保留 |

JSON 直接输入参数的值栏。参数类型仍为 String，编辑器负责原文中的引号转义。省略该参数时默认 `{"score":0,"health":100}`；填写 `{}` 只重建目标场景，不改共享值。不存在的键会创建，未列出的键不会删除。重建后目标行为仍可按自身逻辑继续改变状态。

## 初始值的规则

`state_values_json` 必须是严格 JSON 对象，原文最多4096 UTF-8字节、0–16个键。键沿用[共享状态](PROJECT_SHARED_STATE.md)规则；值支持布尔、绝对值不超过10亿的有限数字和有效 Unicode 字符串。拒绝 null、数组、嵌套对象、重复解码键、BOM、尾逗号及无效转义／代理项。作者预检与实际 Godot 解析分别验证同一组样本。

只有与官方模板源码完全相同的脚本参与专用构建前检查。无效目标、动作或 JSON 定位到行为文档及具体参数；成员场景原本损坏时先报告原始场景错误。修改后的自定义脚本不推断语义，仍可自行使用下面的运行接口。动作映射提示继续复用既有非阻断建议。

## 重试何时生效

重试请求先检查当前访问、目标、待处理切换、初始值和剩余额度。拒绝返回 `false`，不改共享状态或预留额度；接受后复制初始值并占用同一个场景切换槽位。确认键的长按、重复键、界面已处理的输入和失焦候选沿用导航模板的保护。

旧访问的事件、声音与动画请求先按原规则处理。到实际切换边界时，将全部初始值一起覆盖到最新共享状态，再关闭旧场景并创建目标场景；目标行为和 HUD 看到完整覆盖后的值。期间未指定的键可继续由旧访问正常更新；后续写入也必须保证覆盖后仍满足状态容量。旧访问退出后，原状态／事件／媒体／重试接口均失效。

每个声明键在接受时预留一次状态变更额度，同值也预留；实际状态修订只记录发生变化的键。已接受请求在结束或中止时取消，不应用初始值，也不返还已预留额度。这是同一次有限运行会话：访问号、状态修订、事件序号和累计预算都继续，累计运行计时不重置，新访问的场景局部计时从0开始；不会绕过上限。

## 后端接口与交付

普通项目行为继续通过 `viento_project` 使用状态、事件和媒体。新增独立访问接口：

```gdscript
var retry = get_meta("viento_project_retry")
var accepted = retry.request_retry(target_scene_id, {"score": 0, "health": 100})
```

`request_retry` 接受0–16个标量键的 Dictionary，并复制传入的初始值，切换时合并到最新共享状态；自定义调用同样拒绝自身场景、组装外目标、过期接口、竞争切换和不足的额度。JSON 字节限制属于模板文本参数，Dictionary 还须符合共享状态总容量限制。已有项目和动画接口身份保持。

0.2.10发布时的Godot执行描述符及重试生成层为 **0.46.0**；当前工作树在其外增加[0.47.0独立重启层](SCENE_RESTART.md)，原重试内层仍声明 `project.scene-retry`。新层保留并校验原入口、设置、时钟设置和宿主，旧85份后端GD／文本保持原字节。作者格式、事务日志和业务运行协议不升级；应用为0.2.10，本机安装仍0.2.0。Bevy 尚未接入此运行能力。

作者资源包按原依赖闭包保留普通脚本、行为、HUD、输入映射和素材；生成工程 ZIP 保留重试层并可迁移检查运行。它仍需要 Godot 工具，不是独立游戏发行物。实际作者、原生窗口、离线工程与完整回归见[重试验证](test-results/scene-retry/README.md)。
