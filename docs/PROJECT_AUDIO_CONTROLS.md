# 行为驱动场景声音

本页能力已纳入源码交付；开发证据保留执行时的 0.1.3 工作树身份，安装及目标设备范围以[当前状态](STATUS.md)为准。

[0.1.4 源码](RELEASE_0.1.4.md)支持在 Godot 项目组装中请求播放／停止当前场景已声明的音轨。声音控制独立于[项目事件](PROJECT_EVENTS.md)：普通行为、事件回调都可以调用同一接口；事件系统不依赖声音播放器，界面只查看执行结果。

## 作者工作流

1. 通过素材库导入 PCM16 WAV，在已保存 Scene2D 的 **场景声音设置** 创建音轨。已有轨道也可通过 **编辑场景声音** 修改音量和循环，详见[场景声音](SCENE_AUDIO.md)。
2. 新建音轨时可将 **播放方式** 设为 **由行为触发**，该轨道不生成定时提示；全部选择时自动得到 `cues: []`。然后从声音原文复制目标音轨的 `id`。已有声明仍可通过普通原文调整提示；轨道与素材绑定保持，定时播放也可以与行为命令并存。
3. **新建脚本 → Godot / 事件声音**，审阅后普通保存。为成员场景绑定该脚本，在行为参数 `track_id` 填入当前场景的音轨 UUID。新建脚本本身不会自动创建绑定或运行。
4. 将场景放入[项目组装](PROJECT_ASSEMBLY.md)，检查、构建并运行组装。示例订阅 `sound`，延迟发布 `true`；`true` 请求从头播放，`false` 请求停止。也可以直接在行为逻辑中调用声音接口。
5. **构建与运行 → 声音控制记录** 查看实际执行的命令，按音轨或资源标识筛选。**打开控制来源** 返回行为绑定，**打开音轨声明** 返回声音文档；有真实文本范围时定位该范围。
6. 通过后端工程的 **交付工程** 导出 ZIP。交付物包含协调器、声音控制模块、成员工程、脚本和 WAV，在新目录中由 Godot 导入运行。

当前接口仅注入项目组装的行为。普通单场景运行没有 `viento_project`；起始脚本会安全返回。轨道 UUID 只在所在场景内查找，不加载路径、不自动寻找其他场景的同名音轨。中英日界面保留作者身份原文。

## 接口与执行顺序

```gdscript
@export var track_id: String = ""

func _on_sound(value) -> bool:
    if typeof(value) != TYPE_BOOL:
        return false
    var project = get_meta("viento_project")
    if value:
        return project.play_audio(track_id)
    return project.stop_audio(track_id)
```

`play_audio(track_id)` 和 `stop_audio(track_id)` 返回布尔值。`true` 表示请求已受理，不表示此时已经输出声音。播放从头重新开始；停止是幂等操作，但每次实际执行仍会形成独立命令回执。音量、循环和资源由冻结声音声明决定，本接口不编辑作者数据。

行为 `_ready()` 可能早于音轨初始化，因此请求进入独立有界队列。场景完整初始化、音轨就绪及零时刻提示执行完后，在安全执行点先排空项目事件，再按请求顺序执行声音命令。事件回调中新加入的声音请求同样进入队列。两类队列均清空后，才执行场景切换或正常窗口关闭。

后续场景时间推进时，已经到期的时间线提示先执行，再执行该安全点的行为声音请求。时间线可以在后续时刻再次覆盖先前播放／停止结果。这是离散控制命令，不是逐采样精度的音乐时间轴。

每次运行最多受理 **256** 条声音请求，同时待执行最多 **64** 条。超限或当前场景未声明的轨道会在调用行为处报告错误，使本次运行失败；拒绝不会消耗命令序号或请求预算。旧访问端口、已结束或失败的项目返回 `false`，不能控制后来进入的场景。退出会统一停止该场景声音；新运行从空控制记录开始。

失败和宿主取消可能留下未执行的已受理请求，不制造完成回执，也不撤销此前已执行的命令或作者副作用。界面只保留实际收到并校验通过的执行回执；具体失败原因见任务问题列表。

## 观察记录与中间层

每条记录显示会话内连续序号、动作、场景访问与局部时间、音轨和资源 UUID，以及两份各自冻结的来源。切场景保留历史与筛选，新任务清空；历史来源不会变成当前同对象或同音轨的新来源。回源受任务、访问及草稿状态保护。

“已执行播放命令”表示后端已调用播放器，不证明物理设备发出了声音，也不表示此刻仍在播放。自然结束、当前位置、设备状态和混音测量不在本观察契约内。普通定时提示仍属于原声音流，不伪装成行为控制记录。

可移植核心负责有界命令账本、冻结来源准入和只读查询；Godot 的请求队列与场景播放器桥接独立实现；界面不解析原始日志，也不取得播放控制端口。时间线声明与空提示校验继续由 Rust 负责，不新增 Rust ABI。

项目协议 **4** 增加 `audio-command` 与起止 `audioCommandSequence`。原项目协议 1／2／3、单场景协议及声音子协议 1 保持；作者项目组装和计划仍为 1。Godot 适配器为 **0.11.0**，生成 `assembly.json` 为 schema **5**；统一后端工程清单与交付包版本保持。适配器指纹变化后旧本机构建需重建，独立旧 ZIP 保留原生成代码。

声音声明 schema 1 的提示范围扩展为 **0–64**；原有非空声明含义不变。空提示需要本轮源码支持，旧安装校验仍可能要求至少一条。源码与安装验收分开，不因资源准备或浏览器通过而声称 Android、其他系统或新版 Tauri 已验收。

实际结果见[本轮验收](test-results/project-audio-controls/README.md)。后续能力包括 Bevy 声音、空间声源、总线混音、暂停／跳转、实时音量和自然结束观察。
