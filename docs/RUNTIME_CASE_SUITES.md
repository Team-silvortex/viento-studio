本页能力已纳入 [0.0.9 源码交付](RELEASE_0.0.9.md)。保留的“未发布增量”标题和阶段验证描述对应此前 0.0.8 工作树，旧报告版本与条件保持；已安装程序需另行更新。

## 已完成成员详情（未发布增量）

每份实际执行的成员现在保存独立报告，可从「查看用例详情」查看失败步骤、预期／实际值和容差，并显式下载 JSON；前面成员的详情不受最后一个运行会话覆盖。取消或执行失败保留采样前缀，未运行成员没有报告。文件保存失败停止余项，却不会改写已提交的通过／失败检查。当前任务归属、缓存与纯校验边界见[成员报告](RUNTIME_CASE_REPORTS.md)。

验收组把同一场景的已保存用例按顺序运行，用来重复检查一条完整工作流。每份用例仍由 Godot 或 Bevy 执行原控制程序，再由同一纯评判比较实际样本；验收组只保存成员身份与顺序。源码版本为 **0.0.9**，已有安装未更新。单份用例与保存方法见[运行验收](RUNTIME_CASES.md)。

## 工作台使用

1. 在构建工作台为无行为的 Scene2D v2／v3 场景生成第 2 版冻结构建，保存所需运行用例。
2. 打开“批量运行验收”，点击“刷新验收组与用例”，按希望运行的顺序勾选成员。已选成员显示在前面；取消选择再选入会移到末尾。
3. 选择普通 JSON 文档类型和工程正文目录内的新位置，明确保存验收组。此步骤不要求已配置引擎工具。
4. 点击“运行已保存验收组”。工作台显示成员进度和汇总；未保存的成员选择、跨场景绑定、源离线或不匹配的冻结构建不能启动新批次。

“载入验收组”明确替换当前选择，有修改时先确认；“作为新验收组”保留选择并解除旧保存身份。同场景另存创建新的普通文档 UUID。无修改保存和另存保留已载入原文字节，包括 BOM／CRLF；调整成员才重新生成正文。外部正文／场景冲突保留选择与原修订，不自动覆盖。未确认保存回执需要刷新并明确载入核对后才能再次写入，关闭面板或迟到响应不能据此重复创建。

## 作者格式与预算

```json
{
  "format": "viento-runtime-case-suite",
  "schemaVersion": 1,
  "sceneObjectId": "dddddddd-dddd-4ddd-8ddd-dddddddddddd",
  "documentIds": [
    "11111111-1111-4111-8111-111111111111",
    "22222222-2222-4222-8222-222222222222"
  ]
}
```

这里的 UUID 是示意；必须引用工程内实际登记的场景和 `viento-runtime-case-document` 文档。组本身复用普通文档登记，标题来自文件名，成员关系以正文为权威，不额外写入元数据镜像。严格只允许上面四个字段；成员有序且不重复，不能引用组自身、场景或另一组。一个组只有一个场景。

| 限制 | 准入规则 |
| --- | --- |
| 正文 | 最大 16 KiB UTF-8 JSON，拒绝重复键和非法结构 |
| 成员 | 1–16 份已登记 JSON 用例文档，全部绑定同一场景 |
| 合计实例步骤 | 冻结演员数 × 所有成员程序步数之和 ≤ 4096 |
| 合计检查 | 所有成员检查数之和 ≤ 1024 |
| 单份用例 | 沿用原来最多 64 步、8 秒模拟时间、128 条检查等预算 |
| 执行时间 | 宿主整批执行截止预算 120 秒；单份沿用各引擎阶段最多 30 秒，终止清理后释放槽；HTTP 不接收调整预算 |

全部成员、实例目标、来源依赖和联合预算在创建任务前核对。仅接受无行为冻结 plan 2；空组、缺失成员、跨场景、错误实例、配方／旧 plan／行为场景均拒绝。当前支持稳定 UUID 迁移；克隆并重写 UUID、嵌套组、自动更新预期、作者脚本断言和并行成员执行尚未实现。

## 执行与结果

宿主一次捕获验收组及所有成员正文，保留各自 SHA 修订。批次启动后的作者修改或源工程离线不改变这些输入；下一次启动重新读取当前作者文件。每成员重新核对冻结构建／快照身份、文件和工具，产物被替换时停止余项。等待准入期间已被清理的旧构建被拒绝，不分配任务。

| 情况 | 当前成员 | 余下成员 | 汇总 |
| --- | --- | --- | --- |
| 引擎执行完整且检查全部符合 | 通过 | 继续 | 全部通过后“通过” |
| 引擎执行完整但有预期不符 | 未通过 | 继续 | 全部完成后“未通过” |
| 进程／协议错误、缺样本或超时 | 未完成 | 未运行 | 未完成 |
| 取消 | 保留已收到样本，当前标未完成 | 未运行 | 未完成 |

任务执行成功与验收通过分别记录：检查失败不会伪装成引擎进程失败。取消等待当前进程退出后释放唯一执行槽；最终成员已提交的完整结果不被迟到取消改写。汇总“完成”只数通过、未通过和未完成，未运行另列；只有所有成员通过／未通过时 `complete` 才为真。

`viento-runtime-case-suite-run` 独立回执包含冻结构建／快照、后端、组与成员修订、顺序、各成员会话身份和计数，原子保存到构建缓存的 `suites/<UUID>/suite.json`。原单份运行记录分别保留，生成缓存不进入作者工程包。工作台对象观察显示当前／最后成员；单份用例结果与“从采样生成”仍只针对单份运行，避免误用组中最后一份的采样。

## CLI 与中间层

```sh
node scripts/project-build.mjs --command run \
  --root /path/to/workspace --build /path/to/frozen-build \
  --runtime-suite documents/runtime-suites/group.json
```

`--runtime-suite` 接受已登记组的 UUID 或工程相对正文路径，必须提供源工程与冻结构建；与 `--runtime-case`、`--control-program`、窗口、交互和截图模式互斥。不接受任意外部组文件、脚本或执行队列。全部完整但有断言失败时执行记录仍为 `succeeded`，CLI 按验收失败返回非零退出码。

轻量纯入口 [runtime-case-suite-contract.mjs](../engine/runtime-case-suite-contract.mjs)定义成员格式与汇总；[runtime-case-suite.mjs](../engine/runtime-case-suite.mjs)重导出同一规则并另接作者正文、依赖与联合预算。GUI 只载入轻量入口，避免把作者 CST／YAML 解析带进浏览器模块图。Node 作者服务复用[通用文档写入](../scripts/lib/runtime-author-documents.mjs)保护，捕获与调度分别位于 [runtime-case-suites.mjs](../scripts/lib/runtime-case-suites.mjs) 和 [node-runtime-case-suite.mjs](../scripts/adapters/node-runtime-case-suite.mjs)。GUI 的[独立控制器](../web/modules/app-runtime-case-suites.js)只编辑成员和呈现宿主进度，不调度引擎。Godot／Bevy 接口、原控制／trace 和原生核心无需认识验收组。

HTTP 的 `suite-list`、`suite-load`、`suite-save` 使用原作者鉴权与修订保护；`suite-run` 仅接收已归属构建 ID、已保存组 UUID 与预期组修订。后端、工具路径、输出路径和预算继续归可信宿主。新批次要求当前作者来源可读取；源离线的旧单份冻结回放保持原有行为。

## 资源包与完整迁移

选择式资源包从组正文派生必要成员和场景，再复用原用例的定义／素材闭包；可选场景子内容可加入同场景组，共享成员、场景、定义去重。完整归档保存标准工程数据根内所有作者原文，包括尚未修好的文档。

读包只允许明确声明为文档要求的缺失正文延期到目标工程；包内已有场景和成员结构立即检查，即使所有成员正文留到目标工程提供；全部成员正文到齐后检查联合预算。导入用目标实际正文、语义和摘要补齐并再核对，预览后变化不能发布。目录迁移保留 UUID、顺序和原字节。曾发现“成员全部延期时包内坏场景漏过读取检查”的缺陷，现将场景准入抽成与单份用例共享的校验，详见[本轮验收](test-results/runtime-case-suites/results.json)。
