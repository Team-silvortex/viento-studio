# 作品库布局与数据契约

本页是工程目录、权威数据、素材定位和完整迁移的格式参考。当前新建工程使用 v3；v1、v2 工程及迁移包继续按原目录读取，不因应用升级自动搬动数据。应用版本与作品格式独立，当前功能和平台边界见 [当前状态](STATUS.md)。

实际操作见 [项目工作流](PROJECT_WORKFLOW.md)，类型与模板定义见 [模板契约](PROJECT_TEMPLATES.md)，系统默认路径见 [本机数据目录](LOCAL_DATA_STORAGE.md)。

## 程序与作品

程序保留 `web/`、`engine/`、`scripts/`、`desktop/`、`mobile/`、`src-tauri/` 和 `schemas/`。作品独立保存在系统应用数据目录的 `io.viento.studio/workspaces/`，完整备份放在同级 `backups/`；开发时读取应用配置目录中的 `viento.config.json`，不在源码仓库保存本机选择。详见 [本机数据目录](LOCAL_DATA_STORAGE.md)。`VIENTO_WORKSPACE_ROOT` 可以指定其他作品，`VIENTO_APP_ROOT` 可以指定程序位置。

应用安装资源包含代码、内置起始模板目录、通用格式定义、界面资源和运行环境；日常作品的正文、修改后的模板、元数据和素材原文件独立保存。新建时把所选包的类型和模板复制进工程，之后不依赖安装目录中的包。已有资料通过打开作品文件夹或完整迁移包导入。

## 目录标准

```text
作品库/
├── workspace.json                 格式版本、作品身份、名称、目录及类型声明
├── documents/                     正文，按项目需要分子目录
├── templates/                     项目自己的可修改模板
├── metadata/
│   ├── assets/<UUID>.json         素材身份、名称、分类、定位与内容指纹
│   └── documents/<UUID>.json      文档身份、源文件位置与附件关联
├── assets/                        默认素材存储，可另行绑定外置目录
│   ├── images/
│   ├── videos/
│   ├── media/                    编辑器新导入的 images/、videos/ 和 audio/
│   └── …                         保留既有分类；按实际类型扩展
└── .viento/
    ├── workspace.json             旧版兼容标记，阻止旧程序漏备份元数据
    ├── local.json                 本机素材绑定，不随作品迁移
    ├── session.lock               桌面会话锁
    ├── registry.lock              登记期间的进程锁
    ├── migrations/                显式迁移的变更记录
    ├── legacy/                    升级保留的历史清单（如有）
    ├── world-transactions/        World 提交与恢复状态（如有）
    ├── package-import/            资源包导入与恢复状态（如有）
    └── cache/                     派生产物，可重建
        ├── docs-standard/
        └── indexes/
            ├── documents.json
            ├── assets.json
            └── references.json
```

以上为新建 v3 项目。旧 v1、v2 项目的正文、模板目录仍是 `design-data/`、`data-template/`，内部层级保留。当前开发源码提供空白、游戏、文学、戏剧和软件设计五种起始包，默认空白，各包类型不同；正文最初为空。包清单及旧六类型兼容规则见 [工程模板](PROJECT_TEMPLATES.md#内置工程模板包)。

旧作品整理的文件校验与缓存回收见 [历史迁移记录](STRUCTURE_MIGRATION.md)。新环境不需要重复执行旧作品的搬迁；按清单打开作品或导入完整包即可。

v1 清单位于 `.viento/workspace.json`；登记升级到 v2 后会写入根目录公共清单，将旧清单的原始字节保留到 `.viento/legacy/`，并在原位置写入旧版拒绝标记。当前程序以公共清单为准；公共清单丢失时不会把标记误当成作品身份。不理解公共清单的旧程序会由此拒绝打开，避免生成缺少元数据的旧式备份。

迁移时保留 `.viento/workspace.json` 标记，它也进入完整备份并保留在版本控制中。只把 `.viento/cache/` 视作可重建缓存；本机绑定、历史清单、提交恢复记录和兼容标记各有独立职责。

## 原始数据与派生产物

| 数据 | 权威来源 | 迁移方式 |
| --- | --- | --- |
| 作品身份与目录声明 | `workspace.json` | 完整备份包含 |
| 正文、标题、属性、规则、背景经历 | `documents/`，旧项目为 `design-data/` | 保留原文与字节格式 |
| 作品模板 | `templates/`，旧项目为 `data-template/` | 随作品迁移 |
| 素材身份、分类、来源与位置 | `metadata/assets/` | 即使原文件离线也保留 |
| 文档身份及正文外的附件关联 | `metadata/documents/` | 随文档迁移 |
| 素材原文件 | 默认或绑定的素材目录 | 完整备份携带，包括未登记文件 |
| 标准化结果、索引 | `.viento/cache/` | 不入备份，打开后重建 |
| 旧版拒绝标记 | `.viento/workspace.json`（v2、v3） | 随作品完整迁移 |
| 本机绝对路径、会话锁 | `.viento/` 对应状态文件 | 不入备份 |
| 未完成提交与导入的恢复状态 | `.viento/world-transactions/`、`.viento/package-import/` | 先恢复并核对结果；活动事务会阻止读取或归档 |
| 实验构建产物与运行副本 | 宿主构建缓存，位于作者工程之外 | 不进入作品包，可从已保存工程重建 |

已有源文件中的标题、数值、章节信息不复制成另一份需要人工同步的元数据。解析器生成的标准化 `meta` 属于派生产物。

标准化缓存位于 `docs-standard/.entries/<相对源路径的 SHA-256>.json`。原始相对路径完整参与计算，包含文件扩展名和 Unicode 字节，因此不同格式的同名文档、合法长文件名以及带 `.json` 后缀的正文目录可以共存。该值只用于派生缓存地址，文档身份仍由元数据 UUID 表示；源路径与原文保留在缓存内容中。索引与核验兼容旧的镜像目录缓存；重建按缓存记录的源路径迁移旧命名，局部重建只更新、清理选定范围。

v2、v3 标准化直接扫描各自的正文根；正文子目录可以叫 `assets`、`templates`、`metadata`、`tmp` 等，不会因此被当成程序目录跳过。隐藏目录及 `node_modules` 仍按新建路径规则排除。新建和保存使用独立短名称的临时文件，允许符合文件系统限制的长源文件名。

素材目录内的说明文本也可能是作者资料，不能仅凭文件名推断为缓存。旧作品整理时保留了这类文件，具体证据见 [历史迁移记录](STRUCTURE_MIGRATION.md)。

## 清单与身份

格式定义位于 [schemas/](../schemas/README.md)。v3 使用固定数据根 `documents`、`templates`、`metadata`，v2 保留 `design-data`、`data-template`、`metadata`；正文目录内可按项目需要分层。当前提供一个逻辑素材存储 `main`，默认相对位置为 `assets`。不支持的目录声明会被拒绝，不会悄悄忽略。

素材和文档分别使用 UUID，登记文件名与 ID 一致。素材记录包含 `name`、`kind`、`tags`、`location.store`、`location.path`、`content.size`、`content.sha256`、`legacyPaths`；可扩展来源等信息。

ID 表示素材身份，SHA-256 表示某份文件内容。改名、移动或替换素材时保留 ID；替换内容需要明确更新登记指纹。常规重建不会把变化后的文件自动认定为原版本。无法提供原文件时，`content` 可为 `null`，表示尚未核验。

文档登记项保存 `sourcePath`、`documentType`、`parserProfile`、`relations` 和 `assetBindings`。源文档不需要为此改写。编辑器新建时保存选定类型，随后改变保存目录也不会改变类型；外部新增文档在重建时按项目目录定义补充登记。删除或外部移动文件不会自动删除原登记。移动源文件后需要同步更新登记位置，避免把同一文档误认为新文档。首次登记会读取已有 v1 缓存中的附件关系，也可用 `--legacy-index` 指定旧索引。

编辑器现有路径标识仍保留兼容，索引另提供稳定 `id`。从旧索引继承的附件关系标记为 `origin: legacy-index`，表示保留当时的显示关联，不表示人工确认。登记后的索引不按相似名称自动扩大关联。

当前界面可在 **世界与对象** 中新增引用或归属关系、绑定已登记资源；这些操作更新相应元数据，属性修改则写回作者原文。操作顺序见 [日常工作流](PROJECT_WORKFLOW.md#日常工作流)。

保留旧路径的素材继续拥有该路径的引用。其他新素材不能占用它；登记前会检查整批路径，冲突时不写入新登记。需要复用旧路径时，应先更新原素材的引用和 `legacyPaths`。

## 引用与素材目录

正文可以使用 `asset:<UUID>` 声明素材引用；预览素材列表通过登记项解析。正文之外的立绘、封面等附件用文档登记中的 `assetBindings` 保存。普通旧路径引用继续可读，`legacyPaths` 用于兼容改名或移动前的素材位置。

```text
正文中的 asset:<UUID> 或附件中的 assetId
    → 素材登记：main + images/某英雄/技能.png
    → 素材存储：作品库/assets 或本机另外选择的目录
```

浏览服务提供 `/asset-files/<UUID>` 访问素材；既有 `/assets/...` 路径也可经登记解析。图片、视频、字体及其他原文件不进入程序安装资源。

编辑器的“插入素材”可以导入文件、复用已有素材，也可接收粘贴和拖入。新素材分别存入当前素材目录的 `media/images/`、`media/videos/` 或 `media/audio/`，正文插入稳定 ID 引用；JSON / YAML 使用媒体对象列表。操作见 [图片、视频与音频资源](MEDIA_RESOURCES.md)，音频语法与缓冲细节见 [音频资源引用](AUDIO_RESOURCES.md)。

素材可以使用 `assets/` 下的任意子目录。登记中保存原始相对文件名；正文 URL 中的空格、`#`、`%` 等按 URL 语法编码。图片地址转换会保留实际文件名，媒体文件支持按区间读取。

关闭使用该作品的编辑窗口后，可绑定外置素材目录：

```sh
npm run workspace -- bind-assets --root /完整路径/作品库 --directory /完整路径/素材目录
VIENTO_WORKSPACE_ROOT=/完整路径/作品库 npm run rebuild
npm run workspace -- verify --root /完整路径/作品库
```

绑定只更新 `.viento/local.json` 的主素材路径，保留其他本机字段，并与登记、素材入库共用登记锁；被占用时失败重试，原绑定保留。写入绑定时，配置文件及其 `.viento/` 父目录不能是符号链接；用户选择的素材目录别名会解析成实际目录。重新绑定默认目录时，填写该作品 `assets/` 的完整路径即可。绑定离线时保留其位置，不自动改回另一处同名目录。

绑定不会搬动文件、重分配 ID 或接受新内容指纹。换盘前应完整复制素材目录，绑定后按上面的步骤重建并核验；目录存在不等于素材齐全。上传途中若绑定改变，本次导入返回可重试错误并清理临时文件，避免文件写入旧目录却登记到新目录。

外部新增素材后执行 `npm run workspace -- register --root /完整路径/作品库`，或重新打开桌面作品库以补充登记。编辑器导入已包含登记步骤。登记是增量操作，重复执行不重复分配 ID，也不重写已有素材指纹。登记期间使用进程锁；进程已退出的完整锁可自动恢复，无法确认的锁会报错保留。

清单和素材定位中的路径使用 `/`，必须在相应数据根内。工具检查路径穿越、链接、保留文件名以及大小写冲突；发现歧义时报告，不静默改名覆盖。核验同时检查登记文件及父目录的链接和实际文件类型，不把目录或符号链接当成有效正文/素材；`..portrait.png` 等合法文件名仍可正常使用。

## 索引与验证

- `documents.json` 来自源文档与文档登记，可在素材离线时构建。
- `assets.json` 来自素材登记，附带本机可用状态与访问 URL；缺失文件不会消失于目录中。
- `references.json` 来自正文引用及附件关联，包含未知 ID 或未登记路径的未解析引用。

引用索引读取解析后的字段、列表和正文，统一处理图片、视频、音频的稳定 ID 与旧路径；代码围栏中的示例和 YAML 注释不作为素材引用。单独一行的 `asset:UUID` 声明仍然有效。旧路径经 `legacyPaths` 对应回原 UUID，改名不会产生第二份身份；`resolved` 表示已找到登记，实际文件的在线状态由 `assets.json` 给出。

旧图片相对路径以原始正文目录为基准，不包含预览地址的 `docs-standard/` 前缀。编辑器的 HTML/Markdown 分享采用相同引用提取规则，携带裸 ID 声明及旧路径图片，未嵌入正文的内容放在关联素材中；同一素材的多个附件角色只展示一次，登记中的角色保持原样。未知 ID 或缺失文件会使分享失败，修复后可重新导出；代码示例和注释继续排除。

三份索引带相同的 `generation`，逐文件原子写入，文档索引最后发布。联合读取的调用方应核对代号，不一致时重试。当前编辑器保留 `/web/data/index.json` 的访问地址，由服务映射到作品的 `indexes/documents.json`。

日常重建只读元数据和文件状态，不遍历并重新哈希整个素材存储。`available` 表示文件存在且大小未发现异常，不代表已经进行内容哈希核验。完整核验使用：

```sh
npm run workspace -- verify --root /完整路径/作品库
```

该命令核对素材 SHA-256、文档位置和登记的附件 ID；缺失、变更或尚未登记指纹都会报告，返回非零退出码。源文档内容允许正常编辑，迁移时的字节不变性另由迁移快照清单核对。

## 提交恢复与本机状态

`.viento/world-transactions/` 保存 World 命令的活动意图、提交所需数据及回执；`.viento/package-import/` 保存选择式资源包导入的活动状态。读取屏障会检查活动事务，防止编辑器、索引或导出把半次提交当成完整工程。完成记录与待恢复记录不同，不能手工删除活动目录来绕过提示。

发现未完成提交时，使用 **世界与对象 → 恢复未完成的提交**；未完成资源导入则在资源包界面恢复。恢复后核对原文、登记和预览。它们是持久提交的恢复机制，尚不是供用户任意撤销历史操作的通用日志。详细事务契约见 [World 事务 ADR](adr/0004-recoverable-source-changesets.md) 和 [资源包持久提交](RESOURCE_PACKAGES.md#持久提交和恢复)。

当前实验构建把工具、生成工程和运行副本放在宿主缓存中，避免混入作者正文与素材。位置、保留策略和异常退出限制见 [构建记录与清理](PROJECT_BUILD.md#记录与清理)。

## 完整迁移

桌面版“导出备份”生成 `.viento.zip`，包含公共清单、正文、模板、全部元数据和全部素材原文件。包内 `manifest.json` 保存作品信息及逐文件路径、大小和 SHA-256；v2、v3 公共清单与 `.viento/workspace.json` 兼容标记也作为受校验文件入包。v3 包保留项目类型配置，恢复后仍使用项目自己的目录和模板。

外置素材在包内归到 `assets/`，导入后可直接按相对位置使用。缓存、本机绑定、锁和系统旁车文件不入包。素材目录离线或已登记原文件缺失时，完整备份会失败，并保留已有备份文件。

导入先在新临时文件夹内校验所有内容，再交付新作品库；任何校验失败都会撤回本次导入，不覆盖已有作品。v1 包仍按原格式读取和恢复，可随后用登记命令升级；升级保留作品 ID。

选择一部分对象与素材跨工程复用，使用已实现的 `.viento-package.zip` [资源包](RESOURCE_PACKAGES.md)，它与整份工程备份的清单和导入规则不同。仅取出原始媒体文件，使用 [单素材导出](EXPORT.md#单个素材导出原文件)。完整的素材改名、删除管理和缩略图生成尚未提供。
