0.0.8 源码支持把场景配方作为工程中的普通已登记 JSON 文档：在一个配方中定义可复用片段，给每次放置分配稳定身份和局部覆盖，再由共享 Rust 核心展开为现有 **Scene2D v3**。正文编辑、保存、完整备份和选择式资源包复用已有流程；配方依赖从当前源码读取，不自动改写元数据。场景预览已能读取已保存配方和当前未保存原文，查看展开画面及每个字段的贡献来源。片段展开、预览和局部覆盖纳入 [0.0.8 源码交付](RELEASE_0.0.8.md)，没有新安装包或设备验收；当前源码编辑中的同一份配方可编辑单实例局部覆盖，经检查后应用到原文草稿，再普通保存。当前 0.0.10 源码另接共享片段演员的六字段设置、声明恢复、放置偏移，以及独立演员增删结构表单；整份放置、组织分组及片段定义另有独立管理入口；片段重命名也已接入定义管理，嵌套及跨文件写回仍分别开发。

**0.0.10 源码**新增六字段 **恢复继承**：删除所选实例的局部覆盖，让片段声明或投影值重新生效。恢复与其他字段修改共用一次原子 Rust 补丁、完整候选预览和普通保存；本轮[新增证据](test-results/scene-composition-inheritance/results.json)与此前版本记录分别保留。

同一版源码现可从独立画布调整 **一个实例的位置**：拖动、键盘或场景坐标输入产生局部位置覆盖，经完整检查后应用到配方原文草稿。它复用既有 Rust 几何历史和 set 补丁，范围与证据见[单实例画布记录](test-results/scene-composition-canvas/results.json)。

当前另有 **调整配方布局** 批次画布：多选实例后整体移动、吸附或六向对齐，在同一个 Rust 历史会话中撤销，再把净变化目标一次应用到当前原文草稿。新无状态位置补丁支持多放置目标的原子修改；旧单实例入口仍可用。本轮证据另存[批次画布记录](test-results/scene-composition-batch-canvas/results.json)，未提交或发布新版本。

配方是这条链路的作者输入，生成场景是一次展开的结果。编辑生成场景不会反向修改配方；重新展开也不会合并生成场景中后来发生的编辑。片段不嵌套、不跨文件，不引入 Scene2D v4、workspace 升级或多文件保存事务。

同一版源码现可 **编辑共享片段**：逐字段明确勾选后设置原文声明，检查全部引用实例及局部覆盖影响，再应用当前原文草稿并普通保存。本轮记录另存[共享片段字段专题](test-results/scene-composition-fragment-editor/results.json)，该专题验证在 0.0.9 工作树完成，能力纳入 0.0.10 源码。

当前另接 **共享声明恢复**：对允许移除的现有声明勾选恢复，重新使用投影继承；没有开启继承的片段可移除图片声明而变为无图。设置与恢复可放在一次检查和原子应用中，局部覆盖仍优先。[新增专题](test-results/scene-composition-fragment-inheritance/results.json)独立记录这一增量。

同一版源码现可 **调整整组偏移**：编辑选中实例所属 placement 的 `offset`，统一作用于该放置的全部演员。局部位置覆盖继续保留，组织组只负责分组；完整候选及所有身份检查后应用原文草稿，再普通保存。[放置偏移专题](test-results/scene-composition-placement-offset/results.json)单独记录，该专题验证保留 0.0.9 条件，当前源码版本为 0.0.10。

当前 0.0.10 源码把九个配方编辑入口的来源、审阅和应用连接抽成独立[创作工作流](SCENE_AUTHORING.md)。各表单／画布及局部历史继续独立；完整候选检查与主编辑器普通保存方式保持。

## 新建场景配方

0.1.1 之后的工作树增加独立 **新建场景配方** 入口。先在 **世界与对象** 中创建并保存普通对象，或为同一 OC 创建兼容二维场景的游戏投影；回到干净的编辑器，在编辑操作区打开助手。

1. 选择工程已有文档类型和未占用的 JSON 路径，填写配方名称。
2. 设置片段、画布与背景；在演员列表中选择已登记对象／二维投影，为每项设置独立演员标识、位置和 **继承投影默认值**。用 **添加演员／移除演员** 调整起始清单，首版支持 1–64 项；同一对象可以多次引用。普通对象使用基础外观和方向键控制，多个此类演员会同时响应输入，保存后可用共享片段编辑器调整控制。
3. 需要快速排开时，先用下面的 **起始排布** 预览并应用位置，再点击 **审阅场景配方**，统一核对完整 JSON。初次创建生成一个片段与一次放置，包含列表中的全部演员；任何一项无效都会阻止整份创建。放置与各实例各自分配稳定 UUID，切换演员、重新审阅和改语言不会重新分配，删除一项不改变其他身份。
4. 点击 **创建配方草稿**。此时仅进入普通 JSON 编辑器，尚未写文件；继续修改后点击普通 **保存** 才登记到工程。
5. 保存后进入 **构建与运行 → 场景预览**，使用既有片段／放置／布局工具继续丰富，或 **从配方创建场景** 接到构建运行。

演员切换仅改变当前编辑项，保留已填内容和未完成的坐标；它不会撤销已经通过的审阅。实际修改、添加或移除会要求重新审阅。添加只初始化新项，不自动重排现有演员；起始批量排列使用显式排布，保存后的精细调整沿用独立布局编辑器。

对象目录独立读取作者工程，不依赖 Godot 或 Bevy 是否可用。它排除不可读、有错误和不兼容的投影，以及其他配方，避免把嵌套配方误当演员。创建前重新读取目录；工程、来源或路径变化会要求重审，已有编辑草稿不会被覆盖。加载时可返回／取消，未保存设置参与退出保护。保存遇到占用路径时保留完整草稿，换路径后再保存。

继承只写 `useProjectionDefaults` 与位置，不将当前投影的展开值复制到配方。普通保存与后续依赖检查保持各自职责；保存草稿本身不承诺依赖以后不变。此助手不增加后端执行权限、文件格式版本或新的写入 API，版本仍为 0.1.1；助手首版见[创建验收](test-results/scene-composition-create/README.md)，多演员扩展见[本轮记录](test-results/scene-composition-multi-create/README.md)；此前已安装包不包含这次新增入口。

### 起始排布

在新配方助手内选择 **横排、竖排或网格**，填写起点、横纵间距及网格列数。排布按演员列表顺序计算全部位置；间距是中心之间的距离，不读取投影外观或物体尺寸，也不自动解决重叠。

1. 点击 **预览排布**，核对每个演员的原位置与新位置。此时表单坐标和正文都不改变；未完成的坐标或任何越界结果会拒绝整份排布。
2. 点击 **应用排布**，只更新创建表单的演员坐标，保留身份、顺序、对象与继承。旧完整 JSON 审阅失效，需要重新审阅后才能创建草稿。
3. **撤销本次排布** 恢复最近一次应用之前的坐标，包括原先输入的数字写法；它不是已有场景编辑器的撤销历史。后续手动修改或增删演员会使这个撤销入口失效，避免覆盖新的内容。

选择其他演员和切换语言只改变视图；修改排布设置会撤销排布预览，但不会移动任何演员。未应用的排布设置也参加退出确认。排布仅是起始表单工具，不写文件、不分配身份，也不把解析出的投影字段复制回配方。当前工作树的[验收记录](test-results/scene-composition-create-layout/README.md)独立保存，未重新安装。

## 从配方创建运行场景

0.1.1 之后的工作树增加 **从配方创建场景**，让已保存的配方接入既有二维构建流程：

1. 保存配方及其依赖，在 **构建与运行 → 场景预览** 选择该配方。
2. 点击 **从配方创建场景**。窗口重新读取配方，核对来源修订并检查完整配方依赖；未使用片段中的无效引用也会阻止创建。
3. 选择工程已有文档类型、新场景名称和新的 JSON 路径。检查来源、实例／分组数量及完整展开原文，再预览创建。
4. 明确保存后，正文与依赖登记一起创建；工作台自动选中新场景并切到构建页。
5. 按需通过 **新建脚本** 和 **添加场景行为** 完成 GDScript 行为，再检查计划、构建、无头运行及交付生成工程。

生成的是独立 Scene2D v3 文档，有自己的文档 UUID；实例、分组身份和投影继承声明沿用配方展开结果。原配方及其登记不改写；之后两份文档独立维护，再次创建必须使用新身份和路径，不覆盖或合并已有场景。片段与原配方的贡献定位仅属于配方预览，生成场景的诊断定位其自身原文。

来源读取前后会比较整个工程修订，保存仍经 `scene.create` 的事务与冲突检查。修改目的地会撤销旧审阅；存在未保存编辑草稿时不能创建。保存结果不确定时先只读核对，避免重复写入。这个入口不增加配方直接构建、跨文件同步或新的引擎权限。

真实浏览器与 Godot 的串联验证见[二维工作流记录](test-results/two-dimensional-workflow/README.md)。交付物仍为需要兼容引擎工具的工程 ZIP，不是独立游戏安装包。

## 查看样例

在仓库根目录使用 Node.js 24、Rust 稳定版和 `wasm32-unknown-unknown` 目标，先按[开发说明](../.github/CONTRIBUTING.md#开始开发)准备依赖。运行：

```sh
npm run scene:compose -- --input examples/scene-composition/recipe.json
npm run scene:compose -- --input examples/scene-composition/recipe.json --emit bundle
```

默认输出 Scene2D v3 JSON；`--emit bundle` 同时输出场景、来源映射和配方原始字节的 SHA-256 修订号。`--input` 模式只读取指定的普通文件，结果写到标准输出；不保存场景、不登记工程、不启动 Godot。脚本准备共享核心时可能重建程序侧 WASM 缓存。需要把 JSON 交给另一个程序时，使用 `npm run --silent scene:compose -- ...`，避免 npm 的任务标题混入输出。

样例引用[已有 Scene2D 合成工程](../examples/scene2d/README.md)中的定义和图片 UUID。单独展开不检查这些依赖是否在某份工程中存在，也不会自动把它们复制进工程。样例说明见 [examples/scene-composition](../examples/scene-composition/README.md)。

## 作为工程文档保存与迁移

使用工程已有的文档类型创建 `.json` 正文，并按普通文档登记。脚本化创建可使用既有 `object.create`；界面中仍通过原文编辑和普通保存修改它。配方自己的文档 UUID 表示作者文件，`placementId`、生成的 `instanceId` 和 `groupId` 继续由配方显式持有。工程没有新增配方专属类型、World 命令、journal 事件或 workspace 格式。

顶层 `format: "viento-scene-composition"` 选择配方处理；文件名、目录和文档类型不参与猜测。删除顶层 `format` 后，正文按普通 JSON 处理，原先手工登记的关系和素材绑定仍然保留。未写完的配方可以普通保存，冲突仍由既有正文修订检查处理；完整项目备份保留这些作者字节。无效配方、缺失依赖、错误素材类别或不合法 UTF-8 会阻止该配方的展开与选择式资源打包，修复正文后可重试。

选择式资源包读取当前配方中**全部片段的演员定义**及**全部模板和放置覆盖中的图片 UUID**，包括未使用片段和被覆盖的原图片；`null` 或省略不产生图片依赖。依赖按 UUID 去重，并与已有元数据关系、正文素材和资源绑定合并。引用的定义必须有已登记正文，不能是配方自己或另一份配方；图片必须登记为 `image`。投影引用继续由既有投影链路收集其来源定义和图片。派生边只服务于当前检查和依赖闭包，不写回 `metadata/`。

在编辑器 **导出 → 资源包** 中选择这份普通文档，即可沿当前依赖闭包迁移原文、身份和素材。关闭自动包含依赖后，未携带的依赖必须以正确类别列入 `requirements`，并锁定登记与源文件指纹。导入会重新检查包内原始配方，不能靠删掉清单依赖或目标恰好存在同 UUID 内容绕过。资源包往返保持配方正文原字节和文档 UUID，不把展开结果替换成作者文件。完整项目包继续备份工程的原始文档，语义错误不会触发自动展开或改写。详见[资源包规则](RESOURCE_PACKAGES.md#场景配方的派生依赖)。

## 读取工程内的已登记配方

已有配方登记后，可按文档 UUID 展开并检查依赖：

```sh
npm run --silent scene:compose -- --root /临时工程 --object <配方文档UUID>
npm run --silent scene:compose -- --root /临时工程 --object <配方文档UUID> --emit bundle
npm run --silent scene:compose -- --root /临时工程 --object <配方文档UUID> --revision sha256:<原文摘要> --emit bundle
```

`--root` 与 `--object` 必须同时提供，不能与 `--input` 混用；`--revision` 只用于已登记模式，须与当前原文摘要一致。该模式从工程快照读取已登记的 `.json` 正文，核对所有派生定义和图片依赖，然后向 stdout 输出。它不创建生成场景、不修改配方或登记，也不启动构建。独立 `--input` 模式保持只检查配方结构的行为，不能替代工程依赖检查。已登记模式核对声明的引用可用性和图片登记类别；实际图片字节、投影有效值和运行可行性仍交给原有场景模型与构建流程。

已登记模式的 bundle 在原有 `sourceRevision`、`scene`、`sourceMap` 外增加 `origin`：`kind: "registered-document"`、`objectId`、工程相对 `sourcePath`、`worldId` 与 `worldRevision`。来源信息用于核对本次读取的文档和快照，没有写入授权。普通 `--emit scene` 仍只输出既有 v3。

## 在编辑器中预览配方

工程中的配方保存为普通已登记 `.json` 后，在构建工作台的 **场景预览** 选项卡选择它。预览列表同时容纳 Scene2D 和配方；构建／运行列表继续只接受实际 Scene2D 文档。配方自身不作为可执行快照交给 Godot。

预览读取配方当前原文，在内存中展开并复用 Scene2D v3 模型，显示演员、组织分组、投影继承值与图片。对当前正在源码编辑的同一份配方，可显式查看未保存草稿；投影定义和素材仍读取保存版本。预览不会保存原文、创建生成场景、登记派生关系或改动元数据。坏草稿保留最近有效画面并单独显示诊断；旧画面只保留自己的来源修订，不能指向后来改过的正文。

演员检查器显示片段、放置及局部键。字段只有一个配方来源时可直接定位；位置由模板或覆盖与偏移共同得到时，界面分别提供 **片段字段／局部覆盖／放置偏移**，每个按钮指向相应原文数值。整体合成值的主位置不声明精确可选范围。组名和父组映射也可定位，继承的宽高、图片等继续指向原投影定义。标题、画布尺寸和背景颜色均可定位到配方的 `scene` 字段。

已保存来源会核对读盘后的正文修订；草稿来源会核对当前编辑会话和精确文本摘要。定位保留未保存内容，变化后的旧来源不能误选。预览本身不开放 Scene2D 表单或构建／运行。同一份配方处于当前源码编辑会话时，可进入独立覆盖对话框、单实例位置画布、配方批次画布或共享片段字段表单修改原文草稿；保存仍沿用主编辑器。生成 v3 若需要独立构建或编辑，按下文另行登记。

## 编辑单个实例的局部覆盖

先在原文编辑器打开一份已登记配方，并预览当前原文。在演员检查器中选择 **编辑此实例覆盖**；入口只针对当前源码会话、同一路径和同一修订的有效配方，旧画面或其他文档不能取得写入权限。

1. 调整局部位置、宽高、颜色、速度、控制方式或图片。位置是 **偏移前** 的片段内坐标，画布位置仍等于局部位置加放置偏移。图片从已登记图片中选择；只有启用投影继承的演员支持把图片明确设为 `null`。
2. 点击 **检查覆盖修改**，审阅完整修改后原文。Rust 先校验整份输入和展开，再生成精确补丁；预览服务继续检查完整模型、依赖及实际图片内容。无效修改不会启用应用按钮。
3. 点击 **应用到原文草稿**。编辑器重新核对源会话、原文摘要、保存基线和提案，将结果放入同一份原文草稿。随后在主编辑器 **保存**，才会写入工程文件；没有独立的覆盖保存事务。

未改动的字段保持原有继承或覆盖，不会把检查器显示的投影默认值全部写入配方。操作按稳定的 `placementId` 与局部 `actorKey` 定位，只修改该演员的六类覆盖字段；共用片段、其他放置、演员身份及分组保持原样。已有值只替换所需 token，新增字段或覆盖容器、删除覆盖字段均保留范围外的原始字节，包括 BOM、行尾、字段顺序、未改数字拼写和空白。

已有局部覆盖的字段可点击 **恢复继承**，位置的 X／Y 和尺寸的宽／高各作为一对处理。选中后输入框禁用，但保留恢复前的输入；点击 **取消恢复** 可继续编辑这些值。即使覆盖值与继承值相同，删除覆盖仍是需要检查的源码变化。表单显示的仍是恢复前的值，**检查覆盖修改** 会重新读取片段和投影，再验证完整候选；界面不自行推算新的继承值。

恢复图片会删除局部 `imageResourceId` 字段；明确选择 **不使用图片** 则写入 `null`，两者含义不同。恢复后是否存在图片，由片段声明及投影决定。可以同时恢复几个字段并修改其他字段，Rust 在同一请求中处理 set／reset，不能对同一字段同时设置和恢复。删除最后一个覆盖字段时，删除所选演员的覆盖条目，保留 `overrides` 数组；若它原来只有该条目，结果是 `overrides: []`。

**取消修改／返回预览** 保留原源码草稿。检查之后继续改表单或恢复选择，需要重新检查；源码、选择或预览基线变化会使旧提案失效，迟到响应不能应用。恢复后依赖或图片无效时保留表单及诊断，不能应用。外部文件变化仍由既有预览修订和普通保存冲突机制处理。此入口没有共享片段编辑、从画布拖动回写、跨文件事务或统一撤销；来源导航仍只负责选中原文。

## 从画布调整单个实例位置

在同一配方的源码编辑会话中预览当前原文，选择演员，然后点击 **调整此实例布局**。有未保存文字时先点击 **预览当前草稿**；旧保存画面、失效草稿、其他文档或未选演员不会开放位置写回。

1. 拖动高亮实例，或在画布聚焦时用方向键移动 1 像素、Shift 加方向键移动 10 像素。可选择 **吸附到 32 像素网格**；X／Y 输入的是展开后的 **场景中心坐标**。整个场景只用作参照，其他实例不能移动。
2. **撤销布局修改／重做布局修改** 使用独立 Rust 会话的最多 100 步历史。一次拖动结束形成一步；Esc、指针取消或捕获丢失会放弃临时拖动。空白区域、中键或按住空格拖动只平移视图，缩放不改变作者坐标。
3. 点击 **检查布局修改**，审阅完整候选原文。位置换算为局部位置覆盖，再经原预览服务校验完整模型、依赖和图片。继续移动或输入会撤销上次检查批准，需要重新检查。
4. 点击 **应用到原文草稿**，结果只进入当前原文编辑器。最后在主编辑器 **保存** 才写入工程；保存仍核对原基线和外部文件变化。

这一入口只设置所选 `instanceId` 对应的 `placementId`／`actorKey` 的 `position`，不改变模板、放置偏移、兄弟实例、分组、图片或其他属性。局部位置和展开后的场景位置各限 ±100000；若减去偏移后越界，修改在几何历史更新前拒绝。未移动的轴保留原局部数值，避免小数偏移逆减产生无关变化；返回原位置不生成提案。正文预算及范围外原字节保护仍沿用局部覆盖补丁。

**取消修改／返回预览** 不改变现有原文草稿。来源会话、文本摘要、保存基线或预览归属变化后，旧批准不能应用；检查及应用期间禁止位置修改，迟到响应不能改新会话。此处没有多选、对齐、共享片段编辑或跨视图统一撤销。需要删除位置覆盖时，使用 **编辑此实例覆盖 → 恢复继承**，位置画布与恢复表单分别维护自己的操作。

## 从画布批量调整配方实例

在同一配方的源码编辑会话中预览当前原文，点击 **调整配方布局**。入口位于配方预览的工具栏，不要求先选择演员；打开后默认选择当前演员，没有有效选择时使用第一个实例。旧的 **调整此实例布局** 继续固定一个实例，两种画布分别维护操作历史。

1. 按 Shift 或 Ctrl／⌘ 点击画布对象，或勾选右侧大纲中的实例。搜索可以按名称和稳定身份筛选，分组按钮选择该组及子组的全部实例；折叠和筛选只改变列表，不改变选择或绘制顺序。**全选对象／清除选择** 同样只改变当前视图。
2. 拖动已选对象可整体移动，吸附以拖动的对象为 32 像素网格锚点并保持间距。方向键移动全部所选实例 1 像素，Shift 加方向键移动 10 像素。选择一个实例时可输入展开后的场景 X／Y 中心坐标；多个实例时显示选择数量，并提供左、水平居中、右、顶部、垂直居中和底部对齐，按各实例的有效尺寸计算。
3. 每次完整拖动、方向键或对齐形成同一个 Rust 会话中的一步，可整批撤销和重做，最多保留 100 步。Esc 或指针取消放弃当前临时拖动；平移、网格显示、缩放、搜索和选择不写位置历史。某个数值尚未输入完成时，不允许移动、对齐或换选；此时第一次撤销仅恢复显示的有效坐标，随后撤销才处理已有位置历史。
4. 点击 **检查布局修改**。界面同时列出本轮净变化的实例、放置、局部键和局部位置，并展示完整候选原文。列表包含本会话已修改的全部实例，不受最后选择集影响；回到开场位置的实例自动退出候选。Rust 原子生成整批原文补丁，预览服务重新检查完整模型、依赖和实际图片。
5. 确认后点击 **整批应用到原文草稿**，只替换当前编辑器内存中的同一份原文。随后在主编辑器 **保存** 写入工程，保存基线、外部修改和冲突处理仍沿用普通文档流程。

每个目标按稳定 `instanceId` 对应到作者 `placementId`／`actorKey`，场景位置分别减去自己的放置偏移后写为局部 `position`。局部和展开位置各限 ±100000；任一目标越界，整批在更新位置、dirty、撤销或 redo 前拒绝。未移动的轴保留基线局部数值，避免小数逆减漂移；原位不生成空覆盖。补丁按作者放置及片段演员顺序规范化，在同一放置缺少覆盖容器时只插入一次，输入及完整最终候选各限 128 KiB。

检查后位置修改、输入或历史操作使批准失效。单纯通过按钮或大纲换选不改变已检查的候选；未经输入事件更改显示坐标仍会被原始字段签名拒绝，不能借换选、拖动或对齐绕过。检查和应用期间锁定选择及位置操作。源码会话、路径、摘要、保存基线或父预览失效后保留本地批次，但旧批准不能应用；迟到打开、检查及应用回执不能影响新的会话。**取消修改／返回预览** 保留原文草稿，退出会释放该 Rust 会话及画布持有的图片副本。

批次入口只设置净变化实例的位置覆盖。共享片段、放置偏移、身份映射、组织分组、图片与其他属性保持原样；恢复位置继承仍使用单实例覆盖表单。本段不新增作者格式、World 命令、跨文件提交或跨视图统一撤销，生成场景的直接编辑仍不反向更新配方。

## 编辑共享片段的演员声明

这是当前 **0.0.10 源码** 的独立入口。它编辑选中实例所引用的 `fragmentId`／`actorKey` 声明；同一演员在多个放置中的实例共用此声明，已有局部覆盖继续优先。

1. 在主编辑器打开已登记配方的源码并预览当前原文，选择一个实例，点击 **编辑共享片段**。
2. 表单显示片段原文已经声明的值；未声明字段留空。每个字段先勾选 **修改**，再填写新值。位置和尺寸各作为一对设置；不勾选的字段保持原有声明或继承。
3. 查看 **共享片段的引用实例**：所有相关实例按放置顺序列出身份，分别说明哪些净修改参与共享变化、哪些字段由局部覆盖优先。点击 **检查共享片段修改**，检查完整候选及实际图片并审阅完整原文。
4. 通过检查后，点击 **应用到原文草稿** 返回编辑器，再使用主编辑器 **保存**。应用前不写作品文件；取消修改或返回预览保留原草稿。

| 字段 | 本入口的设置语义 |
| --- | --- |
| 位置 | 设置片段局部中心坐标；每个放置再加自己的偏移，局部及展开位置都必须在每轴 ±100000 内 |
| 尺寸 | 明确设置宽度和高度，范围各为 1–2048 |
| 颜色 | 设置 `#RRGGBB` 或 `#RRGGBBAA` |
| 速度 | 设置 0–2000 的有限数值 |
| 控制 | 明确选择方向键或不接受输入 |
| 场景图片 | 选择已登记图片；只有片段开启投影继承时才可明确选择不使用图片，即 `imageResourceId: null` |

例如片段声明位置 `[120,180]`，第二次放置有 `[100,140]` 局部覆盖及 `[360,80]` 偏移，画布显示 `[460,220]`。共享表单仍显示 `[120,180]`，修改它会影响未覆盖的实例；第二次放置保留自己的位置覆盖。表单不会把选中实例的有效值或覆盖值批量写成模板默认值。

未声明字段明确设置为当前投影的同一有效值，仍会新增作者声明。已经声明的字段勾选后保持原值，则没有需要应用的变化；检查候选只携带净声明修改。所有实例均有局部覆盖时，会明确提示 **本次只更新片段声明**，仍可检查并保存这次源码变化。

设置路径编辑现有演员的六类值，允许的共享声明恢复另见下节；定义、身份映射、分组、继承开关、放置偏移或局部覆盖不变。恢复某个实例仍使用 **编辑此实例覆盖**。检查或应用期间锁定操作；原始输入或勾选变化、来源路径／token／摘要、保存基线或父预览失效后需要重新检查，迟到操作不能改新会话。普通保存继续处理外部文件冲突。没有跨文件提交、共享结构编辑、几何历史或跨视图统一撤销。

## 恢复共享片段的投影继承

在同一 **编辑共享片段** 表单中，已声明且允许移除的字段增加 **恢复继承** 选项。恢复会删除共享演员的原文声明，不会改写某个放置的覆盖，也不切换片段的继承开关。

| 字段 | 可移除条件与结果 |
| --- | --- |
| 位置 | 必需声明，不能恢复或删除 |
| 尺寸、颜色、速度、控制 | 仅当该片段演员已启用 `useProjectionDefaults: true` 时可恢复；删除后重新读取对应投影继承 |
| 场景图片 | 已启用继承时，删除后重新使用投影图片；未启用继承时，选项显示 **移除图片声明**，删除后无图 |

未声明字段的恢复选项禁用，表单不补猜测的默认值。每个字段的 **修改** 与 **恢复继承／移除图片声明** 互斥，选择另一项会取消前一项；恢复前输入保持可见，取消恢复后可继续选择修改并编辑。多个恢复及其他字段设置可一起 **检查共享片段修改**，得到一份原子候选。只包含实际删除和净设置，检查前不写入作者文件。

`imageResourceId: null` 是明确不使用图片；删除此声明则重新读取继承，两者不同。例如启用继承的片段把图片声明为 null，即使当前画面无图，恢复仍是需要检查和保存的源码变化。未启用继承时图片删除表示无图，不能删除尺寸、颜色、速度或控制等必需声明。

所有引用实例继续按作者放置顺序显示。列表分别说明哪些净字段重新继承投影、哪些共享图片声明移除后无图、哪些字段仍由局部覆盖优先；全部实例均被覆盖时，仍允许只改变共享声明。**完整候选** 会重新验证继承、所有放置偏移和真实图片，界面不会预先推算恢复后的值；缺依赖或无效继承保留选择和诊断，不开放应用。

批准绑定恢复选择、全部原始输入和完整候选，静默变化同样要求重新检查。检查／应用期间所有操作锁定，取消只丢弃本次提案；通过检查后应用当前原文草稿，再普通 **保存**。旧核心缺少新恢复能力时仅禁用这些恢复选项，原六字段设置仍可用。此增量没有模板结构创作、空间层次、跨文件写回或统一撤销；验证方法见[共享声明恢复验证](TESTING.md#共享声明恢复与原子设置删除)。

## 调整整组放置偏移

1. 在主编辑器打开配方源码并预览当前原文，选择任一实例，点击 **调整整组偏移**。
2. 表单显示该放置已经声明的 X／Y。若原文省略 `offset`，输入留空，并明确显示当前预览按 `[0,0]` 生效；不会自动新增零声明。
3. 填写两项偏移，或勾选 **移除偏移声明，恢复缺省零偏移**。恢复只删除该放置的可选 `offset`，保留恢复前输入；取消恢复后可继续编辑。未声明字段不能再次删除。
4. 确认 **此放置的全部实例** 与组织组列表，再 **检查放置偏移修改**。检查完整场景、所有目标身份及实际图片，审阅只读原文差异和完整候选后 **应用到原文草稿**，最后在主编辑器普通 **保存**。

场景位置按“局部位置（包含该演员的位置覆盖）＋放置偏移”计算。偏移作用于该 placement 的所有演员，包括从另一实例打开表单时列出的同放置成员；其他放置及共用片段保持。组织分组的身份和父子关系不变，组自身不提供空间变换。比如局部位置覆盖 `[100,140]` 加偏移 `[360,80]` 得到 `[460,220]`，把偏移改为 `[400,90]` 后得到 `[500,230]`，局部覆盖仍为原值。

偏移 X／Y 是一对有限数值，各限 ±100000；每个实例展开后的坐标也须在各轴 ±100000 内。任一成员越界会拒绝整个候选，输入保留，不产生部分修改。声明 `[0,0]` 与省略 `offset` 虽然画面相同，仍是不同作者原文：可以明确添加零声明，也可以删除已有零声明；保持原声明同值不产生提案。

完整批准绑定数值输入、恢复选择、全部演员／组目标及精确候选，静默变化也要求重新检查。检查和应用期间锁定操作，来源 owner／token／摘要／保存基线或父预览过期不能应用；取消或返回只丢弃本次提案，原文草稿保持。实际写盘与外部文件冲突继续由普通保存处理。此表单不创建画布或几何历史，不修改演员局部覆盖、共享声明、组结构、其他属性、跨文件内容或统一撤销。旧核心缺新 placement 能力时仅关闭此入口，其他配方工具仍可用。

## 编辑片段的演员结构

**0.0.10 源码**新增“编辑片段结构”。在源码模式打开已登记配方的场景预览，从工具栏进入；不用先选演员，也可选择尚未放置的片段。旧“编辑共享片段”继续处理字段设置和恢复继承。

1. 选择片段，然后选择“新增演员”或选中已有成员后“移除演员”。每次审阅只包含一个结构操作。
2. 新增时填写片段内唯一的局部键，选择已有定义、局部位置和可选现有组织组。普通定义使用显式尺寸、颜色、速度与控制；游戏投影可以选择继承默认值。可选择已登记图片，完整预览会再次检查定义与图片。
3. 查看全部相关放置。新增会为每个放置分配独立实例 UUID；身份在本次草稿及重检期间保持。移除会列出旧实例 UUID 和将被清理的局部覆盖字段。尚未放置的片段允许空影响列表；仍检查声明和已登记依赖，但没有有效实例可供渲染，也不会据此保证投影默认值在将来放置时一定可用。
4. 点击“检查片段结构修改”，核对完整候选原文和场景。检查通过后点击“应用到原文草稿”，返回主编辑器，最后使用普通“保存”。取消、来源过期或检查失败不会修改作者原文。

结构修改同时更新 `fragments[*].actors` 与全部相关 `placements[*].actorIds`。移除还删除该局部键的覆盖条目，保留空 `overrides` 数组、组织组、其他映射和覆盖；不会删除定义文档或素材。不能移除片段的最后一个演员。所有声明和展开后的演员仍各限 128，原文及候选仍限 128 KiB，所有放置的偏移后坐标都须有效。新增身份不得与已有实例、组、放置或当前配方身份碰撞。

Rust 独立可选结构能力负责精确字节补丁和完整展开，提案助手绑定当前原文、保存基线与影响身份。父控制器检查完整候选及实际依赖，主编辑器再核对当前草稿会话，只替换内存；普通保存继续检测磁盘冲突。保留原有 recipe v1 和生成 Scene2D v3，组仍只负责组织。此演员入口不执行放置增删；整份放置另由下文独立入口管理。片段定义和组织组使用下文独立入口；片段重命名见下节；跨文件引用、空间层次变换和跨视图统一撤销另行开发。

## 管理片段定义

当前 0.0.10 源码新增 **管理片段定义**。在源码模式打开已登记配方的场景预览，从工具栏进入；不需要选中演员。这个入口维护共享声明，生成实例由独立的“管理片段放置”完成。

- **新增片段定义**：填写配方内唯一的片段标识，选择一个已登记定义或游戏投影，填写初始演员的局部标识、位置和显式字段，或选择投影继承。界面创建含一个演员、空组织组的未放置片段；之后可通过演员和组织组入口完善内容。
- **复制片段定义**：选择已有片段并填写新片段标识。完整复制原演员与组织组声明，仅替换片段标识；字段省略、继承开关、图片 `null`、数值写法及声明顺序保持。新片段独立，复用对象和素材引用；原放置的偏移、局部覆盖与身份映射留在原放置中。
- **移除片段定义**：只能删除没有任何放置引用的片段。界面列出阻挡移除的放置身份；先通过放置管理处理引用，再移除定义。不会删除引用的对象文档、素材或其他片段，每个有效配方保留至少一份定义。

新建和复制只追加片段，不生成放置或实例／组 UUID；原场景的演员有效字段、顺序和组织关系保持。移除前面的未使用片段会改变后面声明的原文路径，检查会重新建立完整来源，保留精确定位。片段重命名见下节；此入口没有排序、级联删除、空间变换或跨文件事务。

一次审阅包含一个定义操作，显示原有与候选声明、引用范围及完整候选原文。实际预览检查全部片段的基础对象与显式图片登记依赖；未放置片段没有有效实例可供渲染，本次检查不保证它的投影默认值或图片内容已经可消费。首次放置时再次检查有效投影和实际图片。检查成功后只应用到当前原文草稿，再回主编辑器普通保存；取消、来源变化、迟到响应或外部保存冲突保留输入。

独立可选 Rust `definitions` 能力共用原生／WASM 的新增、CST 复制和未引用删除规则。纯提案的 `targets` 固定为空，表示没有生成实例目标；原文意图和补丁仍精确复算。原文及候选最多 128 KiB，每份配方最多 32 片段，全部声明演员与组织组各最多 128，未放置定义也计入声明预算；展开预算保持。验证范围见[片段定义记录](test-results/scene-composition-definition-authoring/results.json)。

来源的 JSON Pointer、UTF-16 范围和有序贡献项由 Rust CST 的只读定位接口重新核对；这条校验不修改源文，也不向浏览器开放服务端解析依赖。

## 重命名片段定义

在 **管理片段定义** 中选择片段，点击 **重命名片段定义**，填写新的配方内唯一标识，再 **检查片段定义修改 → 应用到原文草稿**，最后普通保存。已使用和未使用片段都可重命名；检查显示原、新标识、原文顺序中的全部相关放置，以及保留的演员和组身份。此操作仍属于原有定义编辑域，九个编辑入口保持。

Rust 在同一次原子补丁中修改所选 `fragments[*].fragmentId` 和全部匹配的 `placements[*].fragmentId` 值。演员、组及放置 UUID、局部键、声明与绘制顺序、偏移、覆盖和有效场景不变；原文 BOM、CRLF、转义键、未修改数值写法及其他字节保持。贡献来源中的片段标识和精确原文范围随候选重新校验，旧标识回执不能用于新原文。

标识区分大小写，沿用本地标识规则和 64 字符上限；不得与其他片段冲突。输入原标识不会产生可应用的修改；无效标识、过时来源或超过 128 KiB 的增长保留草稿并拒绝操作，缩短名称可以减少原文体积。重命名不生成实例身份，不修改对象或素材登记，也没有跨文件事务或跨视图历史。

该动作使用独立可选 Rust 重命名能力；旧核心没有它时，仅关闭重命名按钮，原新增、复制和未引用删除继续可用。提案仍为原有八字段、空 `targets`，普通保存负责磁盘冲突和持久化。验证分别记录于[重命名专题](test-results/scene-composition-fragment-rename/results.json)，该能力已纳入 0.0.10 源码，专题验证保留当时的 0.0.9 条件。

## 管理片段放置

**0.0.10 源码**另有独立的“管理片段放置”入口。在源码模式打开已登记配方的场景预览后，从工具栏进入；不用先选择演员。它管理整个放置，与“编辑片段结构”的共享演员增删、单份偏移和局部覆盖编辑分开。

- **新增放置**：选择已声明片段和偏移，追加一份放置。也可选尚未放置的片段；首次展开会实际检查它的投影和图片依赖。
- **复制放置**：选一份已有放置，保留片段引用、偏移和局部覆盖，追加独立副本。新放置及其中的所有实例、组织组使用新的稳定身份；对象定义和素材引用仍复用原数据，不复制素材文件。原偏移或覆盖字段缺失时继续缺失，显式零与图片 `null` 不变成缺省值。
- **移除放置**：只删所选放置及其身份映射、局部覆盖；片段声明、定义文档、素材与其他放置保持。每份配方必须保留至少一个放置，不能移除最后一份。

一次操作分配的新身份在检查和语言切换期间保持固定。审阅列出全部受影响实例、组织组及覆盖字段，并显示完整候选原文。检查通过后只应用到当前源码草稿，再由主编辑器普通保存；取消、过期来源或失败检查均不改原文。新增和复制只追加，不重排原有绘制顺序。

所有放置仍最多 128，展开后的演员与组织组也各最多 128，完整原文及候选最多 128 KiB。放置数没有到上限时，复制多演员片段也可能超过展开预算。此入口不新增空间变换、批次结构操作、跨文件保存或后端执行；配方仍须另行生成并登记 Scene2D 才能构建。

原生与 WASM 共用独立可选 `sceneComposition.addPlacement`、`copyPlacement`、`removePlacement` 补丁接口。复制基于原放置字节范围，仅替换身份；移除精确删除数组项，其他作者字节保留。纯提案复核完整来源、影响身份及精确补丁，候选验收核对整个场景，不要求被移除的原选中演员继续存在。验证范围见[放置结构记录](test-results/scene-composition-placement-structure/results.json)。

## 编辑共享片段的组织分组

当前 0.0.10 源码新增 **编辑组织分组**。在源码模式打开已登记配方的场景预览，从工具栏进入，选择一个片段；没有放置的片段也能编辑声明。组只表达组织关系，改组不会移动演员、改变尺寸、绘制顺序或引入父组空间变换。

- **新增组**：填写片段内唯一的组标识、显示名称和可选父组。每个引用放置生成一个独立组 UUID；本次操作反复检查或切换语言时，身份保持固定。
- **修改组**：修改显示名称，或选择其他父组／根层级。组标识和已有 UUID 保持；不能选择自己或后代形成循环，层级最多 16 层。显示名称与原文相同时，保留原来的字符串写法。
- **调整演员归组**：选择已有演员，再选择组织组或“取消归组”。一次检查处理一个演员，全部引用放置同步改变组织关系；实例身份、位置和局部覆盖保持。
- **移除空组**：只能移除没有直属演员、没有直接子组的组。先调整演员归组或子组父级，再删除；不会隐式转移成员。允许删除片段的最后一个组，保留空 `groups` 数组与空 `groupIds` 映射。

审阅显示全部关联放置、演员和组织组的身份、名称及父级／归组关系，完整候选检查同时核对实际分组语义和来源。检查成功后应用到当前原文草稿，再在主编辑器普通保存。取消、过期来源、迟到响应或失败检查保留作者输入；同值操作不生成新的源码修改。未放置片段仅编辑声明，没有有效实例可供渲染验收。

原文与候选仍最多 128 KiB，声明和展开后的组织组各最多 128；一个片段被多次放置时，新增一个组可能同时增加多个展开组。新增、改名／改父级、演员归组和移除使用独立可选 Rust 组能力与纯提案接口，界面不直接写文件。此入口不修改局部组标识、不重排组，不执行批量结构操作、空间变换或跨文件事务。验证范围见[组织分组记录](test-results/scene-composition-group-authoring/results.json)。

## 配方契约

顶层必须只包含：

```json
{
  "format": "viento-scene-composition",
  "schemaVersion": 1,
  "scene": {
    "title": "组合场景",
    "viewport": [800, 480],
    "background": "#0d1829"
  },
  "fragments": [],
  "placements": []
}
```

上面只展示字段位置；有效配方至少需要一个片段及一次放置。`scene` 的标题、视口和背景沿用现有场景规则：标题为 1–160 个 UTF-16 单元，不能为空白或含控制字符；视口宽高为 64–4096 的整数；颜色为六位或八位十六进制值。

| 部分 | 必需字段 | 可选字段与含义 |
| --- | --- | --- |
| 片段 | `fragmentId`、`actors`、`groups` | 无嵌套、外部引用或脚本字段 |
| 片段演员 | `key`、`objectId`、`position` | `groupKey`、`size`、`color`、`speed`、`controls`、`imageResourceId`、`useProjectionDefaults` |
| 片段组 | `key`、`name` | `parentKey` 指向同一片段的组；省略表示根组 |
| 放置 | `placementId`、`fragmentId`、`actorIds`、`groupIds` | `offset`、`overrides` |
| 单演员覆盖 | `actorKey`、`values` | `values` 仅允许 `position`、`size`、`color`、`speed`、`controls`、`imageResourceId` |

`fragmentId` 及局部 `key` 匹配 `[a-zA-Z][a-zA-Z0-9_-]{0,63}`。片段 ID 在配方内唯一；演员键与组键分别在片段内唯一，两个命名域可以使用同一键。`objectId` 引用现有定义的 UUID，不能被放置覆盖。片段演员只有 `useProjectionDefaults: true` 时才可省略尺寸、颜色、速度和控制方式；它保留投影继承声明，实际有效值由现有场景规划器读取已登记投影后解析。

`actorIds` 和 `groupIds` 是局部键到小写 UUID 的完整映射，不能缺项或多项。例如：

```json
{
  "placementId": "11111111-1111-4111-8111-111111111111",
  "fragmentId": "pair",
  "actorIds": {
    "lead": "22222222-2222-4222-8222-222222222222",
    "support": "33333333-3333-4333-8333-333333333333"
  },
  "groupIds": {
    "cast": "44444444-4444-4444-8444-444444444444"
  },
  "offset": [240, 0],
  "overrides": [
    { "actorKey": "support", "values": { "controls": "none", "speed": 0 } }
  ]
}
```

此示例要求 `pair` 已声明 `lead`、`support` 两个演员和 `cast` 一个组。配方明确持有每个生成实例与组的身份；标题、数组下标和位置不参与 UUID 生成。重排片段或放置不会改变映射中的 UUID；新增局部演员或组时，应在每个使用该片段的放置中补上新的身份映射。每个放置的 `placementId` 唯一；所有生成的演员和组 UUID 也须全局唯一，两个生成身份域不得碰撞。

## 展开与覆盖

输出始终为 `viento-scene2d`、`schemaVersion: 3`，仅包含既有场景字段。演员顺序为放置数组顺序，再按对应片段的演员顺序展开；这个顺序继续决定叠放顺序。组按相同规则展开，`groupKey` 和 `parentKey` 转为该放置的组 UUID。组织分组不产生空间变换、运行节点或额外 World 对象。

每次放置先复制演员声明，再应用该演员的覆盖，最后把 `offset` 加到位置上。覆盖位置是片段内的位置，偏移后才是生成场景中的绝对坐标。未给 `offset` 等同 `[0, 0]`；越界会拒绝整次展开，不做裁剪。组本身不接受位置偏移。

覆盖不修改共享片段，也不影响其他放置。它不能更换定义、身份、分组归属或继承开关；覆盖声明本身不含删除指令，编辑器恢复继承通过上述独立原文补丁处理。省略 `imageResourceId` 保留原声明，`imageResourceId: null` 只在启用投影继承时表示明确去图；两者不能互换。保留省略和局部覆盖后，已有场景规划器仍负责投影默认值和资源依赖校验。

所有片段都会验证，包括未被放置引用的片段。未知字段、解码后重复 JSON 键、重复覆盖、无效引用和循环分组均拒绝，失败不输出部分场景。

| 预算 | 限制 |
| --- | --- |
| 配方原文与紧凑生成场景 | 各最多 128 KiB UTF-8 |
| JSON 结构 | 64 层、100000 个值节点；严格 JSON 和有效 Unicode |
| 片段 | 1–32 个 |
| 声明总量 | 所有片段合计最多 128 个演员和 128 个组；每个片段至少一个演员 |
| 放置 | 1–128 次 |
| 展开总量 | 1–128 个演员、0–128 个组，组层次最多 16 层 |
| 坐标 | 原位置、覆盖位置、偏移和最终位置各轴在 ±100000 内 |

## 来源结果与写回边界

`--emit bundle` 返回 `viento-scene-composition-result` v1，包含 `sourceRevision`、`scene`、`sourceMap`。修订号基于输入的原始 UTF-8 字节，包括 BOM 和换行，因此内容相同但编码写法不同的配方有不同修订。

`sourceMap` 是独立的 `viento-scene-composition-map` v1；`actors` 和 `groups` 与生成数组同序。每条记录给出生成 UUID、`placementId`、`fragmentId`、`localKey`、`templatePath`、`placementPath`、`identityPath`，以及字段到贡献来源的映射。路径都是该配方中的 JSON Pointer，不是文件系统路径。

位置来源指向模板位置或覆盖位置；显式偏移还会追加 `/placements/.../offset`，表示两项数值共同得到结果。演员所属组的来源同时指出模板的 `groupKey` 与该放置的组 UUID 映射；组的父身份来源同样指出模板父键与父组 UUID 映射。每条记录自身的身份由 `identityPath` 单独表示。映射不提供字符范围、不标记可直接替换的源码跨度，也不授予现有 `sceneEditing` 或 World 保存权限。投影继承仍由后续场景模型提供有效字段来源。

CLI 的这份 sidecar 用于检查展开来历。编辑器的只读配方预览另外使用当前原文的 CST 为真实贡献项补充 UTF-16 范围，不改变 sidecar 格式。多贡献字段的主范围标为 `exact: false`；`contributors` 分别携带原文位置及 `template`、`override`、`offset` 或 `identity` 角色。派生场景的 `/actors/N`、`/groups/N` 位置和摘要不会泄露为作者来源。无法索引范围时不沿用生成文本范围，也不伪造精确位置。

来源定位不等于反向写入许可。单实例覆盖使用独立的稳定目标和原文校验流程，不直接把贡献位置当作替换授权。需要改变共享片段演员的六类值时，可使用下述独立共享编辑表单；结构变化仍修改配方并重新查看结果；保留自己需要继续编辑的生成场景副本，避免把两份内容误认为自动同步。

## 在临时工程中验证生成场景

先复制整个 `examples/scene2d` 到临时目录，保留它的正文、登记和素材。配方输出的 v3 可以作为 **新场景** 交给现有 [`scene.create`](PROJECT_BUILD.md#创建场景)：读取该临时工程当前 World 修订，提供一个新的场景 UUID、工程已有的文档类型、尚不存在的正文路径及生成内容。先用 `mode: "preview"` 检查，再以同一基线和身份使用 `mode: "apply"` 保存。命令入口是 `scripts/world.mjs --root <临时工程> --request <请求文件>`，完整字段见[场景创建命令](PROJECT_BUILD.md#场景创建命令)。

`scene.create` 会核验定义、投影和图片，并按生成场景派生依赖登记；它共同创建新正文与登记，不能用直接覆盖旧场景文件替代。创建完成后，使用[已有计划／构建命令](PROJECT_BUILD.md#运行样例)检查新场景，运行后仍得到 plan/runtime v2。图形编辑和保存只作用于这份已登记的生成场景。

生成场景进入资源包与完整工程包时沿用现有依赖规则。配方作为独立普通文档走自己的保存与迁移链路；预览派生模型不进入资源包，也不替代原文。生成场景的导出不会自动替代或更新配方。单实例覆盖、恢复、两个位置画布、共享片段字段、演员结构、整份放置、组织分组及片段定义管理可按上面的专用流程修改当前原文草稿；嵌套／跨文件片段及多文件创作事务仍是后续工作。

## 实现与验证

下列开发专题保留各自的版本和执行条件，涉及 0.0.9 工作树的记录不重标为新版本验收。当前操作能力已纳入[0.0.10 源码交付](RELEASE_0.0.10.md)。

共享核心提供无状态 `sceneComposition.expand`，原生与 WASM 共用实现；宿主通过可选 `viento_core_scene_composition_version()` 能力导出识别支持范围。旧核心缺少此能力时拒绝组合操作，原有几何、草稿、保存和源码补丁操作保留。组合不占用布局草稿会话，也不访问文件、World 或渲染器。

`engine/scene-composition.mjs` 提供同步 `expandSceneComposition(content)`；`engine/studio-core.mjs` 校验核心响应形状，并核对贡献指针确实属于该模板、演员覆盖、放置偏移或组身份映射；不能仅因指针在配方中存在就接受它。`engine/scene-composition-document.mjs` 在 Rust 校验后提供只读文档识别与全部声明依赖；Node CLI 负责受限文件或已登记快照读取、原始字节摘要和输出。资源包目录、读取器和导入计划分别重新检查当前源码与依赖清单。测试入口及环境边界见[验证指南](TESTING.md#场景片段组合实验)。

`resolveSceneCompositionPreview(observed, recipeId, { digest })` 位于 `engine/scene-composition-preview.mjs`。它接受 workspace v2／v3 中 recipe v1 的已登记 JSON 观察；草稿先由既有只读覆盖器应用同一保存基线。接口返回 `{ recognized, ok, model, diagnostics, composition }`，内部临时观察合并派生关系与原有手工关系，复用完整场景模型校验，不返回这份合成观察或构建快照。模型的 World 修订、场景来源摘要和全部配方位置绑定实际输入原文；投影来源保持不变。`composition` 只包含格式版本、配方身份／路径／修订及片段／放置数量。宿主在同一次读取守护内冻结并验证图片字节，返回独立预览身份；Scene2D 的原构建捕获入口保持独立。


局部覆盖另用独立可选能力 `viento_core_scene_composition_patch_version() === 1` 和无状态 `sceneComposition.patchOverrides`。请求只含协议版本、操作、原文、`placementId`、`actorKey` 及非空的六字段 `values` 子集；成功回执为 `compositionPatch: { afterContent, changedPaths }`，路径按 position／size／color／speed／controls／imageResourceId 固定顺序指向真实覆盖字段。输入与输出原文各限 128 KiB UTF-8，前后均由原组合规则完整校验。数值 token 与现有源码补丁使用同一 JavaScript 数字拼写规则，没有新 recipe 或 World 协议。

恢复操作使用另外的 `viento_core_scene_composition_edit_version() === 1` 及 `supportsStudioCoreCompositionEdit()`。新 `sceneComposition.editOverrides` 在上述请求中增加 `resetFields`，允许空 `values` 配合非空恢复集合；字段来自同一六字段白名单，不得重复或与 set 重叠。响应形状不变，`changedPaths` 按六字段固定顺序，使用输入源码中覆盖条目的索引；删除条目后不改用后续条目的索引。纯提案调用 `draft.propose(fullFormValues, { resetFields })`，自动排除恢复字段的 set 候选，只提交其他实际改值；没有恢复的请求继续使用原 `patchOverrides`，旧请求和提案形状保持。

桥接的 `supportsStudioCoreCompositionPatch()` 与 edit 探针分别检查能力；只缺少 edit 时隐藏恢复入口，旧 set／展开／源码／几何仍可用。`dispatchStudioCoreCompositionPatch(request)` 核对回执只能改变指定覆盖值、来源路径及顺序真实正确，并在补丁调度结束后通过核心严格展开输入与候选原文；非法回执禁用运行时，普通输入错误不禁用。`scene-composition-overrides.mjs` 提供 `createSceneCompositionOverrideDraft` 与 `prepareSceneCompositionOverrideApply`，在异步摘要前分离输入快照，检查预览身份、来源修订、局部坐标和提案。主编辑器在内存应用前再次核对当前会话；Rust、提案助手和预览服务都不保存作者文件。

### 共享演员结构的本轮验证

独立可选 `viento_core_scene_composition_structure_version() === 1` 经 `supportsStudioCoreCompositionStructure()` / `dispatchStudioCoreCompositionStructure()` 调用 `sceneComposition.addFragmentActor` 和 `sceneComposition.removeFragmentActor`。新增请求严格包含 `content`、`fragmentId`、完整 `actor`、作者顺序的 `{ placementId, instanceId }[]`；移除包含 `content`、`fragmentId`、`actorKey`。两者还需既有 `protocolVersion` 与 `operation`。Rust 对原文和完整候选重验，保真修改数组、身份成员与覆盖项；桥接核对精确结构变化及路径，旧域不接受新结构操作。

纯 `createSceneCompositionStructureDraft(model, source, { digest })` 绑定全预览及原文，公开冻结目录、私有快照生成一次 add／remove 提案。`prepareSceneCompositionStructureApply` 重算完整 edit、受影响 UUID／覆盖字段、源摘要、保存基线和精确字节回执。父控制器从实际候选展开核对全部演员／组身份及来源，不要求被移除的打开入口演员继续存在；宿主最后核对 owner／token 后仅应用内存，普通 Save 持久化。
