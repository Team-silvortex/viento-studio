事件接口属于项目会话，订阅属于当前场景访问。切场景后历史记录仍可查看，旧订阅自动撤销；新场景不会补收先前事件。需要跨场景保留的结果应明确写入共享状态。事件不是存档、网络消息或持久任务队列。

## 编辑器路径

1. **新建脚本 → Godot / 项目事件**，审阅起始内容，创建原文草稿并普通保存。
2. 将脚本登记并绑定到已保存的组装成员实例，再检查、构建并运行组装。起始内容订阅 `checkpoint`，延迟发布 `hello`，接收后写入 `last_event`。
3. **构建与运行 → 项目事件记录** 查看发布序号、事件名、载荷，以及每个订阅的等待／已处理／已跳过状态。没有订阅者会单独显示，不能据此推断有行为完成了处理。
4. 按事件名称筛选；使用 **打开发布来源** 或 **打开订阅来源** 分别返回冻结构建对应的行为声明。修改脚本后需重新构建。此面板只读，不发布或修改事件。

面板与共享状态观察各自独立，中英日界面不翻译作者事件名与载荷。切场景保留历史和筛选，新任务清空。新增记录不会打断已有发布来源的读取；任务、当前访问、目标记录或作者草稿变化时，过期导航失效。

## 行为接口

项目运行给绑定行为注入 `viento_project`。普通单场景运行不注入该接口；起始内容在这种情况下直接返回。

```gdscript
extends Node

var _project

func _ready() -> void:
    if not has_meta("viento_project"):
        return
    _project = get_meta("viento_project")
    _project.subscribe_event("checkpoint", _on_checkpoint)
    call_deferred("_publish_checkpoint")

func _publish_checkpoint() -> void:
    _project.publish_event("checkpoint", "hello")

func _on_checkpoint(value) -> bool:
    return _project.write_state("last_event", value)
```

| 方法 | 返回和限制 |
| --- | --- |
| `subscribe_event(name, callback)` | 返回本会话正整数订阅编号；旧访问或失败返回 `0`。同一行为重复登记同名、同一回调返回已有编号 |
| `unsubscribe_event(id)` | 只能撤销当前行为自己的订阅；成功返回 `true`，不存在、其他行为的编号或旧访问返回 `false` |
| `publish_event(name, value)` | 发布请求接收成功返回 `true`，此时尚不表示回调处理成功；旧访问或失败返回 `false` |

回调必须属于当前绑定的行为实例，接受一个载荷，并同步返回布尔 `true`。无返回值、`false`、运行错误、失效回调和异步回调均使本次运行失败，并产生对应订阅行为的诊断。异步回调不受支持。失败不会回滚之前已经写入的共享状态或作者脚本的其他副作用；没有成功回执的投递仍保留为等待状态，具体错误见任务问题列表。

## 顺序与场景生命周期

发布时捕获当前同名订阅，按订阅编号排序；后来登记的订阅不会补收。事件延迟分发，以发布顺序处理，每份消息先处理完自己的全部收件者。回调中新发布的事件排到队尾，不递归调用。

如果某订阅在轮到它之前被撤销，该次投递记录为 **已跳过**；已经开始执行的回调自行撤销订阅，仍以本次返回结果判定处理是否成功。不同事件不能复用同一订阅身份，返回同一场景会创建全新的订阅编号。记录为跳过的编号不得被后续新发布重新捕获；此前已捕获它的排队消息仍可正常记为跳过。

场景切换请求在当前事件队列及随后声音、动画请求队列全部处理完后执行，之后撤销旧场景订阅并关闭旧场景。普通窗口关闭也按此顺序排空后结束；宿主的显式取消可以中断，不能把取消时尚未完成的记录标为已处理。循环发布仍受预算限制，超限明确失败。

启动时可以先在 `_ready` 注册，再延迟发布，避免其他行为尚未完成订阅。有限无头测试保证已接收事件的顺序处理，仍只进行原有两步场景测试；它不模拟任意作者异步任务，也不保证切入新场景后所有 `call_deferred` 工作都已执行。需要确定性的有限验收时，明确安排先订阅后发布；正常窗口运行遵循 Godot 的调度。

## 有界数据与中间层

事件名遵从共享状态键规则：1–64 个 ASCII 字符，字母开头，后续允许字母、数字、下划线、点和连字符，区分大小写，拒绝保留名称。载荷支持布尔、绝对值不超过十亿的有限数字，以及 UTF-8 至多 4096 字节的有效 Unicode 字符串；不接受对象、数组或 `null`。

| 每次项目运行的预算 | 上限 |
| --- | --- |
| 当前活跃订阅／累计新订阅 | 64／1024 |
| 发布次数／预留投递次数 | 128／1024；跳过的投递也计入 |
| 有收件者的待处理消息 | 64 |
| 待处理消息的名称与载荷 | 16384 字节 |
| 累计发布的名称与载荷 | 524288 字节 |

名称计 ASCII 字节，布尔计 1 字节，数字计 8 字节，字符串按 UTF-8 计。发布前一次性检查并预留全部收件者与容量；拒绝不消耗序号。无订阅者的发布仍占累计预算，因无需投递而不占待处理队列。原有项目帧数、输出和时间限制继续适用。

纯事件账本、协议准入和查询位于可移植核心；Godot 的订阅、回调和队列实现独立于根场景协调器，界面只消费已校验快照。项目协议 3 引入发布与投递结果记录，协议 4 保留这些语义并独立追加声音命令；发送方和订阅方来源均从冻结绑定派生，事件不能提供任意文件路径。通用层校验身份、预算和回执顺序；它不独立证明引擎实际执行了某段作者代码。

声音控制接入时，Godot 适配器 `0.11.0` 声明 `project.events` 与独立 `project.audio-control`，生成 `assembly.json` 为 schema 5。作者组装和项目计划仍为 1，旧单场景协议保持，纯读取器保留显式项目协议 1／2／3。适配器升级后本机旧构建仍需重新构建，不绕过生成字节及来源指纹。独立导出的工程携带事件模块、声音控制模块、协调器、成员、脚本和素材，接收方使用 Godot 启动后从空事件会话开始。

0.1.7 已发布源码中，含动画项目使用协议 5，含命名片段的项目使用协议 6；各自的适配器及生成格式见[动画运行边界](SCENE_ANIMATION.md#命名动画片段)。这些版本延续同一事件接口，本轮起始内容没有升级协议。

项目事件首轮实际验证见[项目事件验收](test-results/project-events/README.md)。Bevy 项目事件、事件留存重放、跨启动存档、异步处理和连续调试分别作为后续能力接入。

事件回调也可使用[行为声音接口](PROJECT_AUDIO_CONTROLS.md)请求播放／停止已声明音轨。事件投递的“已处理”只表示回调同步返回 `true`；声音接口返回 `true` 则表示请求受理，实际执行另在声音控制记录中呈现。声音请求不调用订阅回调、不制造新的事件投递，也不改变事件预算。

## 事件驱动动画起始内容

**Godot / 事件动画片段**（`godot-project-animation-event`）沿用普通 TXT 创建与保存、行为绑定及文本参数。`event_name` 默认 `checkpoint`，空值禁用订阅；`clip_id` 为已保存片段 UUID，可按名称选入，空值表示完整动画。就绪时仅订阅，不发布事件、不暂停或选择动画，因此保留场景默认自动播放。作者另行安排同名事件的发布与订阅顺序，详见[完整配置步骤](SCENE_ANIMATION.md#用项目事件触发动画片段)。

同步回调忽略合法标量载荷，依次提交选择和播放请求；重复事件从所选范围 0 秒重播。只有两个请求都受理才返回 `true`，任一失败返回 `false` 并交既有诊断处理。事件记录的“已处理”在这里表示命令已提交，实际执行须另查动画控制记录，不代表播放完成。

模板检查有效项目对象及订阅、取消订阅、选择片段、播放端口；旧项目缺少选择方法时不订阅、不控制动画。退出时先清空本地订阅身份，再对有效端口主动取消订阅，忽略旧访问返回的 `false`；项目本身仍负责场景离开时撤销订阅。这只是已有接口的脚本组合，不增加事件载荷类型、模块能力或协议。

## 与动画自然完成组合

0.1.7 后工作树的新含动画项目使用 protocol 7，并保留已有事件接口。攻击可由 `checkpoint` 事件启动，再由独立[动画完成订阅](SCENE_ANIMATION.md#动画自然完成与片段衔接)接续待机。自然完成来自场景动画，不借用某个行为作为事件发布者；它不自动发布名为 `animation.completed` 的通用事件。需要游戏事件时，作者可在自己的完成回调中明确调用既有 `publish_event`，由真实行为承担发布来源与预算。
