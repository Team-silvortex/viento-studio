# 项目事件发布与订阅

Godot 项目行为可以发布带有一个标量值的事件，由当前场景内明确订阅的其他行为处理。例如，拾取行为发布 `item.collected`，任务行为处理后更新[共享状态](PROJECT_SHARED_STATE.md)，再请求进入下一个[组装成员场景](PROJECT_ASSEMBLY.md#运行中切换场景)。

事件接口属于项目会话，订阅属于当前场景访问。切场景保留历史并撤销旧订阅，新场景不会补收先前事件；要跨场景保留的结果需明确写入共享状态。事件不是存档、网络消息或持久任务队列。

[发布与观察](#编辑器路径) · [投递与动画进入回看](#按事件回看投递与动画进入) · [当前项目协议选择](PROJECT_BUILD.md#当前项目协议选择)

逐实例动画范围由动画文档[显式保存](SCENE_ANIMATION.md#为正式运行选择播放范围)，不从消息或参数名推断。事件回看读取协议 10／11 的进入来源；动画命令与完成记录另核对目标身份。

源码范围、安装版本与平台验收以[当前状态](STATUS.md)为准；旧版本前言见[历史归档](history/runtime-guides-2026-10-25.md#项目事件)。

开发工作树中的[角色起跳／落地脚本](SCENE_PHYSICS2D.md#用角色运动事件驱动动画与声音)可作为普通发布者：真实运动信号经绑定脚本发布实例 UUID，继续使用这里的队列、来源和订阅规则。事件名本身不证明物理来源，观察界面以冻结的作者绑定为准。

## 编辑器路径

1. **新建脚本 → Godot / 项目事件**，审阅起始内容，创建原文草稿并普通保存。
2. 将脚本登记并绑定到已保存的组装成员实例，再检查、构建并运行组装。起始内容订阅 `checkpoint`，延迟发布 `hello`，接收后写入 `last_event`。
3. **构建与运行 → 项目事件记录** 查看发布序号、事件名、载荷，以及每个订阅的等待／已处理／已跳过状态。没有订阅者会单独显示，不能据此推断有行为完成了处理。
4. 按事件名称筛选；使用 **打开发布来源** 或 **打开订阅来源** 分别返回冻结构建对应的行为声明。修改脚本后需重新构建。此面板只读，不发布或修改事件。

面板与共享状态观察各自独立，中英日界面不翻译作者事件名与载荷。切场景保留历史和筛选，新任务清空。新增记录不会打断已有发布来源的读取；任务、当前访问、目标记录或作者草稿变化时，过期导航失效。

## 按事件回看投递与动画进入

在 **构建与运行 → 项目事件记录** 中，点击某条消息的 **回看此事件**。回看面板显示该消息的原始标量值、发布来源及发布时捕获的全部订阅；也可用事件下拉框选择另一条消息。同名消息仍按各自序号区分，事件列表的筛选不会隐藏已打开的回看内容。

每条订阅的投递结果与动画关联分别显示：

| 记录 | 含义 |
| --- | --- |
| 等待处理 | 尚未收到成功或跳过回执；可能已经采集到动画进入 |
| 已处理（回调成功） | 同步回调返回成功，不保证发生状态转换或完成动画播放 |
| 已跳过（已取消订阅） | 此次捕获的订阅在轮到它前已撤销 |
| 已采集关联进入 | 协议10／11明确记录此消息和此订阅触发的进入，可继续回看控制器 |
| 未采集动画进入 | 当前快照没有这次投递对应的进入记录，不判断具体原因 |
| 旧协议未记录进入来源 | 协议3–9仍能查看事件与来源，但无法关联动画进入 |

点击关联进入按钮可打开已有 **控制器状态回看**，查看同一绑定、同次场景访问的完整进入顺序、后续命令及终止快照。初始化、自然完成或直接调用产生的进入不会被归到这条事件下；跨场景重入、同名事件与共享脚本的不同绑定也不会混用。进入记录说明脚本接受了请求，后续命令是否执行仍查看独立执行记录。

**打开发布来源** 与 **打开订阅来源** 各自使用构建时冻结的声明位置。界面正在读取自己的来源时可继续完成读取；编辑器草稿、所选事件、运行任务、当前访问或来源身份变化会使过期读取失效。切换场景保留事件选择并撤销旧导航，新运行清除选择；轮询更新、追加事件和语言切换保留仍然有效的选择与焦点。关闭回看返回原事件按钮；该行被筛选隐藏时返回搜索框。

这一步不会发布事件、切换运行状态或修改文件；没有记录条件逐项值、命中转换边或未进入原因。界面仅根据已验证的 `eventSequence + subscriptionId` 关联，不能把“已处理但未采集进入”说成条件失败。完整范围见[事件回看验收](test-results/project-event-review/README.md)。

## 行为接口

项目运行给绑定行为注入 `viento_project`。普通单场景运行不注入该接口；起始内容在这种情况下直接返回。

```gdscript
extends Node

var _project

func _ready() -> void:
    if not has_meta("viento_project"):
        return
    _project = get_meta("viento_project")
    _project.subscribe_event("checkpoint", _on_checkpoint)
    call_deferred("_publish_checkpoint")

func _publish_checkpoint() -> void:
    _project.publish_event("checkpoint", "hello")

func _on_checkpoint(value) -> bool:
    return _project.write_state("last_event", value)
```

| 方法 | 返回和限制 |
| --- | --- |
| `subscribe_event(name, callback)` | 返回本会话正整数订阅编号；旧访问或失败返回 `0`。同一行为重复登记同名、同一回调返回已有编号 |
| `unsubscribe_event(id)` | 只能撤销当前行为自己的订阅；成功返回 `true`，不存在、其他行为的编号或旧访问返回 `false` |
| `publish_event(name, value)` | 发布请求接收成功返回 `true`，此时尚不表示回调处理成功；旧访问或失败返回 `false` |

回调必须属于当前绑定的行为实例，接受一个载荷，并同步返回布尔 `true`。无返回值、`false`、运行错误、失效回调和异步回调均使本次运行失败，并产生对应订阅行为的诊断。异步回调不受支持。失败不会回滚之前已经写入的共享状态或作者脚本的其他副作用；没有成功回执的投递仍保留为等待状态，具体错误见任务问题列表。

## 顺序与场景生命周期

发布时捕获当前同名订阅，按订阅编号排序；后来登记的订阅不会补收。事件延迟分发，以发布顺序处理，每份消息先处理完自己的全部收件者。回调中新发布的事件排到队尾，不递归调用。

如果某订阅在轮到它之前被撤销，该次投递记录为 **已跳过**；已经开始执行的回调自行撤销订阅，仍以本次返回结果判定处理是否成功。不同事件不能复用同一订阅身份，返回同一场景会创建全新的订阅编号。记录为跳过的编号不得被后续新发布重新捕获；此前已捕获它的排队消息仍可正常记为跳过。

场景切换请求在当前事件队列及随后声音、动画请求队列全部处理完后执行，之后撤销旧场景订阅并关闭旧场景。普通窗口关闭也按此顺序排空后结束；宿主的显式取消可以中断，不能把取消时尚未完成的记录标为已处理。循环发布仍受预算限制，超限明确失败。

启动时可以先在 `_ready` 注册，再延迟发布，避免其他行为尚未完成订阅。有限无头测试保证已接收事件的顺序处理，仍只进行原有两步场景测试；它不模拟任意作者异步任务，也不保证切入新场景后所有 `call_deferred` 工作都已执行。需要确定性的有限验收时，明确安排先订阅后发布；正常窗口运行遵循 Godot 的调度。

开发工作树的[平台端点脚本](SCENE_PHYSICS2D.md#用平台端点事件驱动动画与声音)也沿同一发布接口：两个默认事件名区分起点与终点，载荷是本平台实例UUID，来源是作者行为绑定。原生端点信号每端每步合并一次，转为项目事件后仍受下表累计预算；循环运动不会自动重置预算。

## 有界数据与中间层

事件名遵从共享状态键规则：1–64 个 ASCII 字符，字母开头，后续允许字母、数字、下划线、点和连字符，区分大小写，拒绝保留名称。载荷支持布尔、绝对值不超过十亿的有限数字，以及 UTF-8 至多 4096 字节的有效 Unicode 字符串；不接受对象、数组或 `null`。

| 每次项目运行的预算 | 上限 |
| --- | --- |
| 当前活跃订阅／累计新订阅 | 64／1024 |
| 发布次数／预留投递次数 | 128／1024；跳过的投递也计入 |
| 有收件者的待处理消息 | 64 |
| 待处理消息的名称与载荷 | 16384 字节 |
| 累计发布的名称与载荷 | 524288 字节 |

名称计 ASCII 字节，布尔计 1 字节，数字计 8 字节，字符串按 UTF-8 计。发布前一次性检查并预留全部收件者与容量；拒绝不消耗序号。无订阅者的发布仍占累计预算，因无需投递而不占待处理队列。原有项目帧数、输出和时间限制继续适用。

纯事件账本、协议准入和查询位于可移植核心；Godot 的订阅、回调和队列实现独立于根场景协调器，界面只消费已校验快照。项目协议 3 引入发布与投递结果记录，协议 4 保留这些语义并独立追加声音命令；发送方和订阅方来源均从冻结绑定派生，事件不能提供任意文件路径。通用层校验身份、预算和回执顺序；它不独立证明引擎实际执行了某段作者代码。

声音控制接入时，Godot 适配器 `0.11.0` 声明 `project.events` 与独立 `project.audio-control`，生成 `assembly.json` 为 schema 5。作者组装和项目计划仍为 1，旧单场景协议保持，纯读取器保留显式项目协议 1／2／3。适配器升级后本机旧构建仍需重新构建，不绕过生成字节及来源指纹。独立导出的工程携带事件模块、声音控制模块、协调器、成员、脚本和素材，接收方使用 Godot 启动后从空事件会话开始。

0.1.7 已发布源码中，含动画项目使用协议 5，含命名片段的项目使用协议 6；各自的适配器及生成格式见[动画运行边界](SCENE_ANIMATION.md#命名动画片段)。这些版本延续同一事件接口，本轮起始内容没有升级协议。

项目事件首轮实际验证见[项目事件验收](test-results/project-events/README.md)。Bevy 项目事件、事件留存重放、跨启动存档、异步处理和连续调试分别作为后续能力接入。

事件回调也可使用[行为声音接口](PROJECT_AUDIO_CONTROLS.md)请求播放／停止已声明音轨。事件投递的“已处理”只表示回调同步返回 `true`；声音接口返回 `true` 则表示请求受理，实际执行另在声音控制记录中呈现。声音请求不调用订阅回调、不制造新的事件投递，也不改变事件预算。

## 事件驱动动画起始内容

**Godot / 事件动画片段**（`godot-project-animation-event`）沿用普通 TXT 创建与保存、行为绑定及文本参数。`event_name` 默认 `checkpoint`，空值禁用订阅；`clip_id` 为已保存片段 UUID，可按名称选入，空值表示完整动画。就绪时仅订阅，不发布事件、不暂停或选择动画；整场景范围保留默认自动播放，逐实例范围初始停止，等待事件或其他行为启动。作者另行安排同名事件的发布与订阅顺序，详见[完整配置步骤](SCENE_ANIMATION.md#用项目事件触发动画片段)。

同步回调忽略合法标量载荷，依次提交选择和播放请求；重复事件从所选范围 0 秒重播。只有两个请求都受理才返回 `true`，任一失败返回 `false` 并交既有诊断处理。事件记录的“已处理”在这里表示命令已提交，实际执行须另查动画控制记录，不代表播放完成。

模板检查有效项目对象及订阅、取消订阅、选择片段、播放端口；旧项目缺少选择方法时不订阅、不控制动画。退出时先清空本地订阅身份，再对有效端口主动取消订阅，忽略旧访问返回的 `false`；项目本身仍负责场景离开时撤销订阅。这只是已有接口的脚本组合，不增加事件载荷类型、模块能力或协议。

## 与动画自然完成组合

动画完成从 protocol 7 接入，当前含动画项目按[冻结内容选择协议](PROJECT_BUILD.md#当前项目协议选择)，事件接口保持。攻击可由 `checkpoint` 事件启动，再由独立[动画完成订阅](SCENE_ANIMATION.md#动画自然完成与片段衔接)接续待机。自然完成来自场景动画，不借用某个行为作为事件发布者；它不自动发布名为 `animation.completed` 的通用事件。需要游戏事件时，作者可在自己的完成回调中明确调用既有 `publish_event`，由真实行为承担发布来源与预算。


## 逐实例动画目标与事件回看

项目事件仍按发布时捕获的订阅逐个投递，不会因启用逐实例动画而变成按实例隔离的事件总线。同一消息可交给多个角色；各角色的动画请求随后由登记端口及已保存的 `playbackScope` 选择目标。不同角色复用同一脚本、收到同名消息或选择同一片段，不能据此合并其进入和执行记录。

协议11继续用明确的 `eventSequence + subscriptionId` 关联成功进入，发布者、接收绑定、访问及来源校验保持。控制器进入说明脚本接受了转换，不能当作该目标已经播放成功。动画命令记录另列scene／instance目标；完成记录同时列目标最后命令序号与全局命令截止，只有同目标的新命令会使该目标旧完成通知过期。完成不自动发布通用项目事件，也没有新的事件载荷类型。

协议3–9的事件仍可查看，但不补造进入来源；协议10保持整场景来源证据及原格式。协议11仅由含显式instance范围的项目组装生成，普通整场景控制器／动画／无动画项目分别保持协议10／7／4。公开动画端口的身份约束不把GDScript变成沙箱，详见[行为边界](SCENE_BEHAVIORS.md#逐实例动画端口的身份边界)。

0.2.4已收录 **Godot / 角色移动碰撞** 起始脚本；本轮开发工作树同时支持自由平面停止／滑动和重力／跳跃角色，按本步移动阻挡集合变化发布开始／结束事件，载荷为对方实例UUID，自身保留在发布来源中；可显式填写 `other_instance_id` 过滤。它不是触发区进出或几何分离通知，设置及生命周期见[物理指南](SCENE_PHYSICS2D.md#用角色移动碰撞驱动项目事件)。
