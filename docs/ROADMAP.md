# 演进路线与验收

整理日期：**2026-11-13**。当前源码 **0.2.10**，本机已安装 **0.2.0**；本版新增能力尚未进入新安装验收。本页负责开发顺序和阶段出口；已实现范围与证据由[当前状态](STATUS.md)负责，操作从[完整工作流](PROJECT_WORKFLOW.md)进入，长期模型见[下一代架构书](NEXT_ARCHITECTURE.zh-CN.md)。阶段号是产品规划，不代表本轮升版、已发布或日期承诺。

## 方向与边界

Viento 提供 **设定 → 多用途投影 → 场景实现 → 组装打包 → 工程交付** 的内置创作链。近期以两款小型 2D 游戏验证整条链路，优先消除作者完成任务的阻碍；每轮新增模板或适配层只解决可复现的真实需求。

原生目标是 **ns-nova／yalivia runtime／Nuislang**。JS／Node／Web／Tauri 是当前实验承载；保留作者语义、稳定身份、来源修订、受限命令、构建、会话、归档和恢复合同，后续替换实现。Godot 是近期游戏主验收后端；Bevy 的两个受限通道按共享需求独立跟进，不承诺功能对等。

作者原文、登记和素材是权威数据；工具、缓存、运行存档、会话和生成工程分别管理。图形操作形成可审阅的原文提案，普通保存保持明确。基本编辑在 Studio 内完成；外部 IDE／LSP 是可选接入，不是完成游戏的前置条件。

## 0.5.0 的明确出口

[0.5.0 验收门槛](MILESTONE_0.5.0.md)负责最终判断：俯视收集与平台跳跃两款游戏主要在内置编辑器完成，具备胜负、重开、暂停、HUD、跨启动进度；各实际交互至少 30 分钟，作者工程能换根恢复，独立游戏能在无引擎工具的目标环境运行，并在当期 Studio 候选安装中重复整条流程。首个发行目标为 **Linux x86_64**，其他平台另行验收。

依赖顺序是 **第一款游戏 → 重启／暂停与输入生命周期 → 持续运行＋持久存档 → 第二款游戏与独立发行 → 候选安装全链验收**。第一款游戏先用已有能力形成可运行初稿，随后补缺口达到 0.3 出口；发行工具、模板和字体的可行性应提早验证，不拖到最后一阶段才探索。

### 接下来的三项开发工作

1. **把已有游戏初稿变成可顺畅复建的作者任务。** [晶石庭院](../examples/topdown-collect/README.md)已形成可迁移作者工程，真实收集、计分、开门、伤害、胜负与重试通过原窗口和离线工程验证。接下来按工程内指南从空白在 Studio 逐步复建，记录重复操作、参数查找和来源交接的阻碍；已存在样例的保存／构建检查不替代从空白复建。玩法继续保留普通行为文本，不修补生成工程。
2. **减少寻找编号和重复接线。** 0.2.10 新增[参数参考](SCENE_BEHAVIORS.md#按名称填写成员实例与输入动作)：从当前场景选择实例，显式选择组装后选择成员／已保存输入动作，核对来源后填入普通String，再沿原有审阅保存。多个实例或组装分别显示身份，不推断参数用途。本版另补[官方重试参数起始项](SCENE_BEHAVIORS.md#官方重试脚本的参数起始项)：明确补齐三行原始默认值，再按名称接线；已从初始化的空白结构通过界面创建八文档的两场景试点，真实窗口Enter切换和HUD初始状态另验。接下来继续完整关卡复建及重复实例配置、脚本创建返回和诊断交接；没有跨绑定自动接线或隐式关系。
3. **接通同场景重启与暂停／恢复。** 分别定义重建场景和暂停会话：共享状态复位范围、物理与行为时间、音频／动画、菜单输入、失焦与长按、排队请求和旧访问失效都须明确；Escape 当前结束运行的行为不能直接当成暂停。随后完成鼠标／键盘菜单，收口第一款游戏。

每项先完成一条可独立审阅和实测的纵切，再推进下一条。各开发增量可以继续用 patch 版本交付，阶段版本只在对应出口满足时收口。

## Studio 核心与界面解耦

共享 Rust 核心已承接布局、位置草稿与历史、保存状态、严格声明及若干保真补丁；Web 使用同源 WASM。大部分 World／构建规划、完整场景语义、依赖与投影继承仍在 JS，不据此宣称全 Rust 化。

近期按完整作者任务保留便携样例和结果，随功能需要沉淀领域规则。渲染负责绘制、命中、视图坐标、焦点和输入法；宿主负责文件、进程、设备及回执。身份、命令、来源／修订、依赖、构建、会话与恢复是迁移资产；HTTP 路径、DOM owner、JS 对象防护和控制器组织不是永久接口。

现有物理空间编辑的纯提案、临时绘制、字段更新、审阅和普通保存继续分别负责；配方与 3D 编辑区保持独立写入边界。跨区选择先传递来源和受限命令，不合并各区未保存草稿、权限或历史。原生替换使用同一组语义样例验证，不以全面 Rust 迁移、JS Provider、通用 RPC 或永久双 GUI 为近期前置工程。详见[当前架构](ARCHITECTURE.md)和[模块边界](STUDIO_MODULES.md)。

## 文本驱动场景的实施顺序

1. **沿用定义与实例分离。** 稳定身份、显式依赖和来源继续复用；当前 128 实例及组织组 128／16 层的上限，扩容前建立解析、索引、选择和预览基准。
2. **先明确空间与复用语义。** 区分组织、空间变换、放置和叙事顺序，确定共享声明与局部覆盖的写回目标，再做嵌套和跨文件引用。
3. **视图共享来源与受限命令。** 文本、大纲和画布指向同一身份；错误保留输入与最后有效预览，构建继续读显式保存版本。跨视图历史和多文件事务另行定义。
4. **剧本按实际玩法推进。** 复用项目事件、共享状态、声音、动画和物理触发；对白、出场和时间轴需要独立的时间、顺序、条件及后端合同。

作者格式、构建计划和执行协议分别演进；workspace v4 仍是候选，不因接入新能力自动迁移作品。近期行为路径是 GDScript 与 Bevy Rust；C# 暂缓，Nuislang 不作为当前闭环的前置条件。

## 原生执行与 GPU 能力

这条路线可按真实工具可用程度独立试验，不阻塞 0.5.0 的 Godot 主验收，也不以现有后端结果代替原生执行证据。

| 阶段 | 进入条件 | 完成证明 |
| --- | --- | --- |
| 原生最小执行器 | 真实可调用的 ns-nova／yalivia 工具与版本合同 | 独立样例构建、运行、诊断和取消；保留对象身份并拒绝缺能力计划 |
| 同设计双后端 | 一项真实且可移植的场景行为 | 分别验收时间、事件顺序和数值容差；不要求源码互译或逐像素相同 |
| GPU 纵切 | 真实并行工作量及资源所有权／同步规则 | 记录设备、GPU 时间、传输量、峰值内存及失败释放；设备句柄不进入作者包 |
| 原生 Studio／内嵌视口 | 已可用的选择、命令、草稿、资源和会话端口 | 实际作者任务与三语、输入法、焦点、可访问性和关闭保护通过目标宿主验证 |

窗口、离屏、内嵌视口和 GPU 计算分别声明。现有 WebGL 或软件图形证据不替代原生 GUI、硬件 GPU 或计算通道的验收。

## 后续能力及进入条件

| 方向 | 进入条件与边界 |
| --- | --- |
| Bevy 跟进 | 由一项真实共享需求驱动中立合同，分别补生命周期、资源或运行能力并实测；不要求先追平 Godot |
| 更广作者事务 | 明确混合写入的权威与恢复模型；中断只得到完整旧版或新版，外部冲突保留现场 |
| LSP 与跨区工作流 | 文档 URI、版本、来源范围、诊断、受保护的草稿应用；内置编辑可独立完成任务，迟到响应与冲突有测试 |
| Live Build／内嵌运行 | 后端先提供补丁、安全点、会话与恢复合同；不支持的变更明确要求重建 |
| 类型化工程包 | 至少两种真实工程证明共同语义，再定义版本锁定、未知类型保留与显式升级 |
| 规模与磁盘 | 隔离大工程、明确预算和产物归属，再处理大量对象、空间不足、缓存失效及可重建输出清理 |

## 每个阶段共同的完成条件

- **作者任务闭环**：有隔离样例、内置操作步骤、实际后端结果和可迁移工程；生成目录中的临时修补不能冒充作者能力。
- **失败可恢复**：缺资源、错误版本、过期来源、外部冲突、取消、超时与进程结束均可观察；新增持久数据先定义归档与恢复。
- **来源与归属清楚**：原文、稳定身份、关系和素材经导出恢复核对；作者数据、存档、工具、缓存、会话和产物不混用。
- **证据对应交付**：源码、浏览器、原生窗口、独立发行和候选安装分别记录；按改动范围执行检查，保留历史报告与原始摘要。
- **文档有单一职责**：操作更新专题／工作流，当前事实更新状态，实施边界更新架构，顺序更新本页，最终门槛更新里程碑；图谱评分依据证据，不随规划自动提高。
