# 演进路线与验收

本页维护下一阶段的工程范围、依赖和完成条件，不承诺日历排期。已实现范围和平台验证以 [当前状态](STATUS.md) 为准，模块与调用链路见 [系统架构](ARCHITECTURE.md)；长期模型和关键决定保留在 [下一代架构书](NEXT_ARCHITECTURE.zh-CN.md)。本页中的工作项均不代表已发布能力。[当前功能图谱](FUNCTION_ATLAS.md) 将本页目标与已接入实现分开评分，可沿依赖和工作流选择下一条迁移或验证链。

## 方向与边界

Viento 的方向是设计优先的 IDE，也是未来 ns-nova 的官方 GUI 编辑器。原生执行采用 Nuislang、ns-nova 和 yalivia runtime，自身 GUI 未来迁到 ns-nova；GUI 宿主与作者工程的执行后端保持独立。原生体系仍处早期，场景文本与行为开发不以 Nuislang 就绪为前提。Godot 4 当前承接受限 Scene2D 的早期执行需求，近期优先在它上面接入 GDScript 行为，可长期保留为副引擎；Bevy／Rust 是第二候选，尚未接入。副引擎总量按 1–2 个控制，不以支持所有引擎为目标。

允许产品和依赖快速实验迭代，以窄适配接口、版本记录和真实验证控制变动。ns-nova 的异构计算能力可以直接通过原生扩展开放，不受副引擎共有功能限制；作者正文、素材、UUID、恢复及完整迁移的保护持续适用。

## Studio 核心与界面解耦

Studio 自身的设计规则向独立 Rust 核心逐步迁移，执行后端优先 GDScript／Rust；两者是不同层次。核心不依赖 DOM、Canvas、Tauri 或某个游戏引擎，通过版本化输入输出连接 GUI、CLI 与运行适配器。现有 Web 界面使用同一 Rust 代码的 WASM 编译目标，高频编辑保持本地同步；未来原生 GUI 可直接调用原生库。

布局移动、吸附、六向对齐与原子位置批次校验已接入共享核心；位置草稿、初始基线、100 步批次撤销／重做与 dirty 判断也已下沉。检查／保存／核对的状态转换、错误分类和请求归属已接入独立 Rust 保存工作流；宿主继续校验回执正文与修订并执行 I/O。Scene2D 的来源范围、语义模型和计划生成已在 JS 层拆开，精确原文定位及 v2 稳定实例已接入；源码布局所需的严格 JSON、稳定身份／位置／组检查和精确数值补丁已迁入 Rust 无状态接口。接下来在这个有界切片上推进完整场景语义与展开来源 → 字段、投影和 World 变更规划 → 统一构建及行为契约。每次迁移一条可验证的链路，删除被替代的规则实现，保留原文保真、身份及事务恢复边界。渲染端继续负责绘制、命中测试、视图坐标、焦点和输入法；宿主负责文件、进程与设备权限。当前大部分语义规划仍在 JS，不能据此宣称已完成全 Rust 化。

## 下一阶段：把文本驱动的场景接入现有构建链路

现有起点是文档对象命令、可恢复的受限变更，以及 Linux 本机的 Scene2D 计划、Godot 生成工程、运行与诊断。下一阶段优先打通设计到执行之间的实际使用缺口，同时准备原生接入。2026-10-03 用户进一步明确：随着场景对象增多，主要创作入口应是结构化、类似剧本的场景文本。实例身份、来源定位及平面画布已贯通；后续处理文本组织、场景树和共享草稿，让各视图消费同一份设计。现有拖动与对齐作为局部修改工具继续保留。

## 文本驱动场景的实施顺序

稳定实例与持久组织分组已接入当前源码；单场景原文草稿可驱动大纲和画布，错误保留最近有效结果，布局坐标可经精确补丁应用回当前源码草稿。空间变换、片段语法、事件语义、多文件提交与跨视图统一撤销仍待定案。

1. **定义与实例已分开。** OC 保存自身背景和设定，投影定义一种用途；Scene2D v2 的平面实例引用所选定义，持有独立 UUID、位置和局部覆盖。同一投影可多次实例化，重排保留身份；来源、选择、位置历史、构建节点与运行事件已区分实例和定义。新场景默认 v2，旧 v1 经显式预览保存升级；上限仍为 128。
2. **组织可解析的场景文本。** 结构可表达场景、空间分组、实例、可复用片段及其参数；叙事段落与明确声明的事件流程可关联到这些对象。空间层次和剧情顺序分别表达。文本可拆分为受版本管理的场景文件和引用片段，解析后形成可移植模型，原文件保持作者数据权威。具体语法通过小样例确定，先用现有结构化格式验证场景模型和现成引擎的行为绑定；不把新编程语言或 Nuislang 工具链作为前置条件。
3. **让编辑视图共享来源。** 文本、大纲／场景树和画布使用同一场景身份与来源映射。树支持折叠、检索和按需加载；选中实例能定位到原文声明或生成片段。图形修改形成明确的实例覆盖或原文修改，保留注释、行尾和版本检查。有效草稿可更新设计预览；文本尚未写完或有错误时保留输入和最后有效预览，构建继续只使用明确保存的版本。
4. **再接剧本事件与规模验证。** 出场、交互、对白、音频等行为逐项定义时间、顺序、条件和运行能力，再交给后端实现。批量声明与片段展开须可重复，并让生成实例保持稳定身份和来源；模板修改与单实例覆盖的写回目标须明确。按逐级扩大的样例记录解析、展开、索引、选择和预览成本，再调整现有数量上限与可见范围处理。

前置拆分与首个实例切片已接入：`json-source.mjs` 提供严格 JSON 与来源，`scene-model.mjs` 解析 v1／v2 语义及投影继承，`build-plan.mjs` 发射相应版本的计划；“同一定义多个实例 → 精确定位 → 独立位置修改／历史 → 保存重开 → 构建／运行与资源包往返”使用同一实例身份。完整场景模型、依赖与投影继承仍在 JS；Rust 几何与历史继续接收实例 UUID 作为不透明选择键，新增源码操作独立检查严格结构、身份／位置及分组。本轮 v3 已增加可嵌套组织分组，预览／布局共享大纲、搜索和后代选择，组来源与原文保存贯通。单场景文本草稿预览已接入：只读覆盖原样正文、保留最后有效画面和修订守护定位；登记依赖及构建仍读保存版本。当前已接通“有效源码草稿 → Rust 严格结构检查 → 共享位置历史 → Rust 精确坐标补丁 → 主编辑器内存应用 → 普通保存”；只支持当前已登记场景的源码模式，保留 128 KiB 预算与原保存基线，不调用 World 命令，没有跨视图统一撤销。下一步先以隔离样例确定可复用片段的确定性组合、稳定身份、来源映射和局部覆盖，优先产出已有 v3 场景再接作者工作流；文件内复用与跨文件依赖分开验收，不直接引入未经验证的 v4 或多文件事务。组织大纲仍不是剧本系统。

作者文本格式、构建计划和运行协议分别管理兼容版本。v1 的扁平 `actors`、对象唯一规则、计划 DTO 及原 Godot 生成器保留；v2／v3 同样限制 1–128 个实例，使用独立 `instanceId`；v3 另有 0–128 个组织分组、最多 16 层，编译到 plan v2，坐标与绘制顺序不因归组变化。显式升级保持作者原文和稳定身份，当前拒绝反向降级。场景格式变化不升级整个 workspace；现有 `scene.update` 仍只守护场景正文和登记，跨文件片段修改需另定原子提交与恢复边界。

文本结构描述作者设计，并引用明确登记的行为及参数。近期行为实现使用 Godot GDScript，后续按独立验收引入 Bevy Rust；Nuislang／ns-nova／yalivia 留作原生接入目标。可移植部分是实例、参数、事件和来源契约，行为源码仍按后端实现，不承诺自动互译。归档应保留场景原文、引用片段、行为源码与依赖声明、定义和素材，解析树、编译缓存与引擎产物可重新生成。

2026-10-03 的 [行为绑定预研](PROJECT_BUILD.md#行为绑定选型预研尚未接入) 已用独立 Godot 样例验证 GDScript 元数据、两个实例、参数、方法与信号；它还不是产品接口。下一步在已接入的实例模型上，将这个绑定过程纳入冻结快照、能力校验、来源诊断和运行生命周期；C# 因额外工具链与维护成本暂缓，不进入近期交付依赖。Bevy 的 BRP、反射注册和代码热补丁可供第二后端复用，但不替代作者文本保存和跨引擎适配。

## 原生执行与 GPU 能力

原生接入可与工作台完善并行，但必须以 Nuislang／ns-nova／yalivia 当时真实可调用的接口为依据。Godot 的结果、协议模拟和本机示例文件都不能替代原生验收。

| 顺序 | 交付范围 | 完成条件 |
| --- | --- | --- |
| 原生最小运行契约 | 固定输入、工具链／适配器标识、产物、会话、诊断和取消；只声明已支持的能力 | 用真实原生工具链构建并运行一个独立样例；事件与源对象身份可核对，缺能力和版本不匹配能准确拒绝 |
| 对齐设计样例 | 同一受限 Scene2D 设计分别生成原生与 Godot 产物；后端专属能力显式扩展 | 约定时间、事件顺序及数值容差，分别验收输入和状态；不要求画面逐像素相同，也不承诺转译任意引擎源码 |
| GPU 纵切 | 选择一项真实的并行计算或渲染工作量，贯通资源上传、执行、预览消费和释放 | 记录设备、执行结果、GPU 时间、传输量与峰值内存；取消／失败能释放资源；设备句柄与同步对象不进入工程或迁移包 |

控制命令与大块资源传输分开。纹理、缓冲区和计算结果通过有所有权、使用期限与同步约定的资源通道交换；共享资源和减少回读以真实支持为前提。无头逻辑测试、正常窗口、离屏渲染、内嵌视口和 GPU 计算分别声明与验证。

## 每个阶段共同的完成条件

1. **调用链路可复现。** 有可运行的隔离样例、入口和真实后端结果；Mock 只证明其覆盖的协议。
2. **作者数据有明确归属。** 正文、登记、素材、工具、本机配置和生成物分别管理；运行结果须显式提交才成为设计值。
3. **失败可观察。** 缺资源、错误版本、冲突、取消、超时和进程结束有明确状态与诊断，不能把未验平台标为支持。
4. **迁移仍完整。** 原文和素材字节、稳定身份、关系及模板经过导出／恢复核对；有新持久数据时先完善归档契约。
5. **文档与交付一致。** 更新 STATUS、使用契约及适用的架构边界；保留既有 ADR、发布记录和原始验证证据，不用新结果改写历史。
