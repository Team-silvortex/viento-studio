# 演进路线与验收

截至 **2026-10-25**，当前源码为 **0.2.4**，已收录有界物理步与碰撞观察、角色重力／跳跃、作者运动与移动碰撞事件、静态单向平台；本机安装仍为 **0.2.0**。能力与平台证据统一见[当前状态](STATUS.md)，操作见[物理指南](SCENE_PHYSICS2D.md)。本页列待推进的工作及进入条件，逐轮完成记录迁入[路线历史快照](history/roadmap-2026-10-25.md)。

## 方向与边界

Viento 面向通用 OC 设计与场景工程创作，提供 **设定 → 多用途投影 → 场景实现 → 组装打包 → 工程交付** 的内置工作流。原生目标是 ns-nova／yalivia runtime／Nuislang；Godot 与 Bevy 用于验证真实运行需求和中间层粒度，后端能力分别声明，行为源码按后端实现。

作者原文、登记和素材持续作为权威数据。工具链、缓存、运行会话与生成工程分开管理；图形操作产生可审阅的原文提案，运行状态只有经过明确的作者操作才进入持久数据。保留基本内置编辑能力，外部 IDE／LSP 通过标准端口接入，避免让工作流依赖某一前端或引擎。

## 内置创作到交付的推进顺序

| 优先方向 | 已有起点 | 下一步可独立交付的范围 | 验收出口 |
| --- | --- | --- | --- |
| 二维物理与玩法 | Godot 角色碰撞、静态障碍、触发区；首次创建、字段与空间图偏移／尺寸编辑，角色可选停止／滑动 | 物理观察、基础角色重力／跳跃、起跳／落地事件、静态单向平台及运动角色移动碰撞开始／结束已收录 0.2.4；接着按玩法独立定义自由平面／持续接触生命周期、移动平台、向下穿透或动态刚体，材质与关节另行设计 | 作者配置经检查保存后产生可复现运动／接触结果；错误、取消、旧工程兼容和事件来源可核对 |
| 创作工作流 | 独立设定、投影、配方、场景、行为、声音、动画与物理编辑区 | 用完整二维样例补缺少的交接和问题回源，减少重复选择；分别设计跨区选择、草稿和历史契约 | 从空白工程到保存重开、构建运行、迁移恢复与工程交付，无隐式写入或来源丢失 |
| 工程与发行 | 已保存场景组装、运行观察、生成工程目录及 `.viento-build.zip` | 为明确目标平台设计独立发行预设与工具模板管理 | 在未安装目标引擎的独立环境运行发行物，保留构建输入／工具／产物摘要 |
| 后端扩展 | Godot 执行与两个独立 Bevy 通道 | 用一项共同需求验证中立契约，再分别补 Bevy 的生命周期、资源或运行能力 | 同设计、独立工具与运行证据；拒绝未支持计划，既有通道保持兼容 |
| 文本与外部工具 | 原文辅助、查找替换、行列跳转和当前任务诊断 | 标准文档 URI、语言、版本、范围、诊断及受守护的草稿应用端口，再接 LSP | 同步、冲突、关闭与迟到响应覆盖；内置编辑器继续独立可用 |

这不是一次性升级所有模块的清单。每轮选择能形成作者输入、实际运行和交付证据的一条链路；二维映射入口见[功能对接表](FUNCTION_MAPPING_2D.md)，原始成熟度与缺口见[功能图谱](FUNCTION_ATLAS.md)。

## Studio 核心与界面解耦

共享 Rust 核心已承接布局、位置草稿与历史、保存状态、严格声明及若干保真补丁；Web 使用同源 WASM。大部分 World／构建规划、完整场景语义、依赖与投影继承仍在 JS，不据此宣称全 Rust 化。

后续迁移沿 **完整场景语义与来源 → 字段／投影／World 规划 → 构建和行为契约** 逐条进行。每次建立原生与 WASM 同一输入输出、保留原文字节与失败恢复，验证后移除被替代的重复规则。渲染端负责绘制、命中、视图坐标、焦点和输入法；宿主负责文件、进程、设备权限及回执校验。

物理空间编辑提供当前拆分实例：纯提案复用 Rust 数值规则，渲染器只显示临时形状，控制器更新现有字段，检查／审阅／普通保存继续独立。配方和 3D 的专用编辑区保持独立权限，不为了统一界面合并审批回执。架构细节见[架构](ARCHITECTURE.md)和[模块](STUDIO_MODULES.md)。

## 下一阶段：把文本驱动的场景接入现有构建链路

该方向的首段已经完成：稳定实例、组织分组、原文草稿预览、位置回写、单文件配方与显式生成运行场景均已接入。当前应扩展未定义的语义和规模，避免把已完成入口反复列作新目标。

| 表示 | 当前可用链路 | 仍需独立设计 |
| --- | --- | --- |
| Scene2D | 保存态 v1／v2／v3；稳定实例、局部覆盖和组织组；行为、声音、动画、物理与组装 | 空间变换层级、大规模按需处理、更多玩法与运行观察 |
| 片段配方 | 文件内定义／放置／覆盖与结构编辑；明确生成独立 Scene2D | 嵌套／跨文件引用、多文件提交及生成结果同步；组织组不等于空间变换 |
| Scene3D | 独立方块声明、环境／粒子、编辑与预览、Godot 工程导出 | 模型素材、层级变换、OC 投影、行为与项目组装的完整接线 |

## 文本驱动场景的实施顺序

1. **沿用定义与实例分离。** 同一 OC 或投影可重复实例化；新结构继续使用稳定身份、明确依赖和来源。当前 Scene2D 上限 128 实例，组织组上限 128／16 层；扩容先建立解析、索引、选择和预览基准。
2. **先定义空间与复用语义。** 区分组织、空间变换、放置和叙事顺序，明确共享声明与局部覆盖的写回目标，再处理嵌套和跨文件来源。
3. **让视图共享来源与受限命令。** 文本、大纲和画布引用同一身份；错误保留输入与最后有效预览，构建继续读取显式保存版本。跨视图历史和多文件事务分别设计。
4. **逐项建立剧本和玩法事件。** 已有项目事件、共享状态、声音提示、动画状态转换及物理触发；对白、出场编排和更完整剧本时间轴仍需独立定义时间、顺序、条件和运行能力。

作者格式、构建计划、执行协议分别演进。workspace v4 仍是候选设计，现有格式能表达的能力不为功能扩展自动升级作品。GDScript 和 Bevy Rust 是近期行为路径；C# 暂缓，Nuislang 成熟前不作为此链路的前置条件。

## 原生执行与 GPU 能力

| 阶段 | 输入条件 | 完成证明 |
| --- | --- | --- |
| 原生最小执行器 | ns-nova／yalivia 的真实可调用工具链与版本契约 | 独立样例实际构建、运行、诊断、取消；稳定对象身份和缺能力拒绝 |
| 同设计双后端 | 已定义的一项可移植场景行为 | 原生与现有后端分别验收时间、事件顺序和数值容差，不要求任意源码互译或逐像素相同 |
| GPU 纵切 | 一项真实并行计算或渲染工作量，以及资源所有权／同步约定 | 记录设备、GPU 时间、传输量、峰值内存及失败释放；设备句柄不进入作者包 |
| 原生 GUI／内嵌视口 | 可用的对象选择、命令、草稿、资源和会话端口 | 原生界面操作已有后端；中英日、输入法、焦点、可访问性和关闭保护在目标宿主验证 |

窗口、离屏、内嵌视口和 GPU 计算是分别声明的能力。当前 3D WebGL 预览与粒子参数不能替代原生引擎或物理 GPU 通道的验收。

## 后续能力及进入条件

| 方向 | 进入条件 | 验收重点 |
| --- | --- | --- |
| 更广作者事务 | 明确新增、删除、关系和资源混合操作的权威及恢复模型 | 中断只得到完整旧版或新版；外部冲突保留现场；旧归档继续读取 |
| Live Build | 后端有明确补丁、安全点与恢复能力 | 会话／版本／基线校验，设计与运行版本分别展示；不支持的变更要求重建 |
| 类型化工程包 | 至少两种真实工程需求证明共同语义 | 版本锁定、未知类型保留、实例独立维护和显式升级 |
| 长期规模与磁盘管理 | 隔离的大工程样例、预算和产物归属清单 | 大量对象、长期运行、空间不足、缓存失效及可重建输出清理 |
| Windows／macOS／Android | 对应系统的工具链、权限和宿主实现 | 目标环境的安装、交互、设备与签名验证；纯模块移植不替代设备证据 |

## 场景声音的下一步

已有非空间音轨、时间提示、素材选择试听和行为播放／停止。空间声音、混音总线、暂停／定位的正式运行控制、自然完成通知及更完整声音运行观察各自定义能力后推进；Godot 的实现不自动授予 Bevy 相同支持。声音复用资产、原文保存与组装路径，见[声音指南](SCENE_AUDIO.md)。

## 每个阶段共同的完成条件

- 有隔离作者样例、实际入口和适用的真实后端结果；替身只证明其覆盖的接口。
- 作者数据、工具、缓存和运行资源归属明确，普通保存与跨文件事务边界可审查。
- 缺资源、错误版本、过期来源、冲突、取消、超时与进程结束可观察。
- 原文／素材、稳定身份、关系和模板经导出恢复核对，新持久数据先补归档契约。
- 更新操作指南、状态、图谱和适用架构；历史报告、失败与原始摘要保持原时点。
