# 演进路线与验收

本页维护下一阶段的工程范围、依赖和完成条件，不承诺日历排期。已实现范围和平台验证以 [当前状态](STATUS.md) 为准，模块与调用链路见 [系统架构](ARCHITECTURE.md)；长期模型和关键决定保留在 [下一代架构书](NEXT_ARCHITECTURE.zh-CN.md)。本页中的工作项均不代表已发布能力。

## 方向与边界

Viento 的方向是设计优先的 IDE，也是未来 ns-nova 的官方 GUI 编辑器。原生执行采用 Nuislang、ns-nova 和 yalivia runtime，自身 GUI 未来迁到 ns-nova；GUI 宿主与作者工程的执行后端保持独立。Godot 4 当前承接受限 Scene2D 的早期执行需求，可长期保留为副引擎；Bevy 是第二候选，尚未接入。副引擎总量按 1–2 个控制，不以支持所有引擎为目标。

允许产品和依赖快速实验迭代，以窄适配接口、版本记录和真实验证控制变动。ns-nova 的异构计算能力可以直接通过原生扩展开放，不受副引擎共有功能限制；作者正文、素材、UUID、恢复及完整迁移的保护持续适用。

## 下一阶段：把现有构建链路做成可连续使用的工作流

现有起点是文档对象命令、可恢复的受限变更，以及 Linux 本机的 Scene2D 计划、Godot 生成工程、运行与诊断。下一阶段优先打通设计到执行之间的实际使用缺口，同时准备原生接入；不要求先完成通用插件框架或整体 GUI 重写。

| 工作方向 | 范围 | 可审查验收 |
| --- | --- | --- |
| 场景创建与类型模板 | 已接入场景表单、OC 子模板与多份投影，复用已有类型；投影配置编辑与换图已接入，继续补模板演进操作 | 从空白作品创建并登记场景、角色和图片依赖；完成计划、构建、预览、保存重开及完整迁移；生成的 Godot 工程始终是派生输出 |
| 场景属性与诊断 | 创建与既有场景编辑已接入，支持位置、画布和逐字段继承／覆盖；已增加保存状态的场景预览、缩放与对象检查；继续完善空间编辑与更丰富的诊断交互 | 未保存草稿、外部改文、引用缺失和无效字段均保留输入并给出对应诊断；UI 与 CLI 使用相同身份和版本前置条件 |
| 本机工具配置 | 补齐工具发现、配置和实际可用性反馈，保持工具链与工程分离 | 工具路径只存宿主配置；缺工具、错误版本和工具替换明确反馈；构建记录仍可追溯实际二进制；旧工程不自动改选后端 |
| 构建记录与磁盘管理 | 明确跨编辑会话的产物发现、保留、失效和清理；补齐意外终止后的检查策略 | 只清理本应用拥有的派生输出，保留需要审阅的诊断；失效产物不能运行；宿主异常终止后的残留可识别，不触碰作者数据和用户自行管理的引擎 |
| 独立发行产物 | 为明确的平台目标增加导出预设和对应工具模板管理 | 在未安装 Godot 的独立测试环境运行导出物；保留源快照／工具／产物摘要和失败记录；发行导出与 `.viento.zip` 作品迁移分别验收 |

场景行为按已定义语义逐项扩大。触发器、音频行为和状态机需要独立字段规则、能力声明及源映射；当前固定移动状态不能被改称通用状态机。每项先验证正确运行、错误定位、取消与恢复边界，再扩大模板和界面。

## 原生执行与 GPU 能力

原生接入可与工作台完善并行，但必须以 Nuislang／ns-nova／yalivia 当时真实可调用的接口为依据。Godot 的结果、协议模拟和本机示例文件都不能替代原生验收。

| 顺序 | 交付范围 | 完成条件 |
| --- | --- | --- |
| 原生最小运行契约 | 固定输入、工具链／适配器标识、产物、会话、诊断和取消；只声明已支持的能力 | 用真实原生工具链构建并运行一个独立样例；事件与源对象身份可核对，缺能力和版本不匹配能准确拒绝 |
| 对齐设计样例 | 同一受限 Scene2D 设计分别生成原生与 Godot 产物；后端专属能力显式扩展 | 约定时间、事件顺序及数值容差，分别验收输入和状态；不要求画面逐像素相同，也不承诺转译任意引擎源码 |
| GPU 纵切 | 选择一项真实的并行计算或渲染工作量，贯通资源上传、执行、预览消费和释放 | 记录设备、执行结果、GPU 时间、传输量与峰值内存；取消／失败能释放资源；设备句柄与同步对象不进入工程或迁移包 |

控制命令与大块资源传输分开。纹理、缓冲区和计算结果通过有所有权、使用期限与同步约定的资源通道交换；共享资源和减少回读以真实支持为前提。无头逻辑测试、正常窗口、离屏渲染、内嵌视口和 GPU 计算分别声明与验证。

## 后续能力及进入条件

| 方向 | 开始前需要的边界 | 完成条件 |
| --- | --- | --- |
| 原生 GUI 与视口 | 稳定对象选择、命令、草稿、会话和资源接口；先做独立视口原型 | ns-nova GUI 能操作已有后端；中英日文字、输入法、键盘焦点、可访问性、窗口关闭和草稿保护逐项验收 |
| 第二副引擎 | 第一后端已有可复用的输入、输出与诊断契约；明确比较需求 | 以 Bevy 候选原型对比构建、输入、对象映射、停止重开、资源重载、崩溃与磁盘成本，再决定支持级别 |
| 类型化工程包 | 至少两种真实工程需求证明哪些语义需要共享 | 版本和依赖锁定、能力检查、未知类型保留、实例独立维护及显式升级；声明模板不自动获得脚本执行权限 |
| 更广的作者事务 | 定义新增／删除／关系／资源内容等混合操作的权威及恢复模型 | 任一发布点中断后只得到完整旧版或新版；外部冲突保留现场；旧编辑、构建读取和归档保持一致 |
| Live Build | 运行后端明确支持的补丁能力、安全点和恢复条件 | 校验 session／epoch／基线；过期补丁拒绝；设计版本与运行版本分别展示；不支持的变更要求重建 |
| 软件工作流与协作 | 软件工程类型及远程 Artifact／Task／Run／Review 的最小版本契约 | 指定输入版本执行；重复请求不重复启动；诊断与审阅指回正确快照；一个执行步骤只有一个所有者 |
| 其他宿主 | 相应系统的工具链、权限、进程和资源传输实现 | Windows、macOS、Android 各自在目标环境验收，不继承 Linux 的执行能力声明 |

workspace v4 仍是候选设计。当前 Scene2D 使用已登记 v3 文档可以完整表达和迁移，增加运行功能本身不要求升级作品格式。只有现有格式确实不能表达新的权威数据时，才定案新格式、归档清单、旧程序拒绝写入和独立副本迁移；验证通过前保留原作品。

## 每个阶段共同的完成条件

1. **调用链路可复现。** 有可运行的隔离样例、入口和真实后端结果；Mock 只证明其覆盖的协议。
2. **作者数据有明确归属。** 正文、登记、素材、工具、本机配置和生成物分别管理；运行结果须显式提交才成为设计值。
3. **失败可观察。** 缺资源、错误版本、冲突、取消、超时和进程结束有明确状态与诊断，不能把未验平台标为支持。
4. **迁移仍完整。** 原文和素材字节、稳定身份、关系及模板经过导出／恢复核对；有新持久数据时先完善归档契约。
5. **文档与交付一致。** 更新 STATUS、使用契约及适用的架构边界；保留既有 ADR、发布记录和原始验证证据，不用新结果改写历史。

长期阶段 V0–V6 与初始施工编号 V-M0–V-M5 保留在 [下一代架构书第 10 节](NEXT_ARCHITECTURE.zh-CN.md#10-分阶段施工路线与首批里程碑)，用于解释依赖和历史决策；日常开发范围按本页推进，避免重复执行已完成的仓库迁移或第一条语义纵切。
