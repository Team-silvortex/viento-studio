## 方向与边界

Viento 的方向是设计优先的 IDE，也是未来 ns-nova 的官方 GUI 编辑器。原生执行采用 Nuislang、ns-nova 和 yalivia runtime，自身 GUI 未来迁到 ns-nova；GUI 宿主与作者工程的执行后端保持独立。原生体系仍处早期，场景文本与行为开发不以 Nuislang 就绪为前提。Godot 4 承接受限 Scene2D 的早期执行需求，已接入显式 GDScript 参数／信号绑定；Bevy／Rust 的首条接入只运行无图场景的冻结数据计划，以真实 ECS 实现比较中间层粒度。两者可保留为副引擎，总量按 1–2 个控制，不以支持所有引擎为目标。

允许产品和依赖快速实验迭代，以窄适配接口、版本记录和真实验证控制变动。ns-nova 的异构计算能力可以直接通过原生扩展开放，不受副引擎共有功能限制；作者正文、素材、UUID、恢复及完整迁移的保护持续适用。

0.0.8 源码已抽出[执行后端中间层](BACKEND_MIDDLEWARE.md)：纯数据描述符明确区分构建、无头逻辑、窗口、截图、离屏、内嵌视口和 GPU；可信宿主注册表与通用执行器不携带具体引擎参数和文件约定。Godot 与 [Bevy 无头后端](BEVY_BACKEND.md)各自实现同一宿主契约，冻结回放核对执行适配器与工具指纹，作者格式和既有 plan／runtime 保持。旧 Bevy 数据通道不扩展动态编译或作者代码；当前工作树另以独立 Rust 源工程适配器接入受限行为，渲染接口仍未增加。现有共同能力已增加[运行对象观察](RUNTIME_OBJECTS.md)：从既有事件保留稳定实例、来源及明确采样阶段，再按实际需求扩大契约；替代测试夹具仍不算引擎验收。

当前再接[有限控制回放](RUNTIME_CONTROL.md)：全局 schema 1 与冻结 plan 2 的按实例 schema 2 在两个后端执行固定步骤，每步未列实例释放，返回完整身份／位置／状态样本。输入独立于作者计划，宿主与适配器继续保持粒度；仅有限无头、无作者行为 plan 1／2，后续实时采样与运行修改仍需独立定义。

0.0.9 源码的[运行验收用例](RUNTIME_CASES.md)已把有限输入、逐步实例样本和显式容差检查组合成可重跑验收；先覆盖无行为 plan 2、位置／状态。工程内用例登记、版本冲突保存、选择式资源包及完整迁移已接入同一稳定身份；同场景有序[批量运行验收](RUNTIME_CASE_SUITES.md)已接入纯组准入、宿主调度与独立界面；作者行为检查、嵌套／并行验收与更多运行观察仍分别定义，不从本轮推导通用脚本测试或 Android 执行。

## 内置创作到交付的推进顺序

主路径是 **设定 → 投影 → 场景实现 → 组装打包 → 工程交付**。先把常用创作操作放在 Studio 内完成，专用编辑区通过独立中间层与作者保存、预览和执行器衔接。当前已登记 Scene2D 可沿此路径形成需要工具的生成工程包；不同场景表示仍分别接入，不把目录里出现一个入口当成完整工作流验收。

1. **扩展已接入的实例行为创作。** 内置脚本创建已提供 GDScript 与 Bevy Rust 的空行为、参数／信号以及 Rust 固定步移动起始内容，经完整预览进入 TXT 草稿，再普通保存登记；已保存场景的首次创建现扩展为有界多绑定／多脚本清单及去重关联，三文件仍由单次可恢复事务保存；新清单初始参数和信号为空。已有绑定文档继续使用独立实例／脚本选择、带类型参数和信号映射表单，审阅、依赖重验、草稿应用与普通保存分开。已有清单引入新脚本现可独立审阅并保存 `references`，此事务只改登记，后续绑定编辑只改原文草稿。目录候选至多 256 份、单份 TXT 至多 64 KiB；关系缺失或歧义阻止操作。下一步单独设计引用移除、已有声明迁移与更多规模验收。Bevy Rust 执行能力独立登记，现覆盖无图就绪／固定步自身位置回调、标量参数、信号事件和 Cargo 源工程交付；不把起始模板或中立声明推断为 LSP、热更新或完整游戏运行支持。
2. **逐类衔接场景与组装。** 当前多 Scene2D 成员、启动场景与运行时切换已形成 Godot 工程组装，运行观察按访问次数隔离；下一步单独设计跨场景状态／事件、连续调试与玩法验证。Composition 和 Scene3D 先明确输入表示、依赖、后端能力、来源与失败诊断，再接入构建目录、冻结工程和交付。保留各自编辑模块，不把展开结果或生成文件变成作者权威；独立发行另按目标平台验收。
3. **提供外部工具标准接口。** LSP 尚未实现。后续独立定义文档 URI、语言、版本、范围与诊断，以及受来源和版本守护的 `applyDraft`，再接外部 IDE／语言服务。先验证同步、冲突、关闭与迟到响应，保持内置编辑器可独立完成基本工作；不让外部工具接口直接取得构建缓存的作者写入权。

## Studio 核心与界面解耦

配方原文创作现已抽出纯候选验收、独立入口工作流和浏览器适配层，九个编辑区不共享审批回执或读取兄弟能力，见[场景创作工作流](SCENE_AUTHORING.md)。后续人机工程优化应分别验证来源、审阅、应用与导航接口，再调整面板、键盘与焦点；跨区统一历史、普通场景事务和执行任务仍需独立设计与验收，不能据此次接口拆分宣称已有统一工作流。

Studio 自身的设计规则向独立 Rust 核心逐步迁移，执行后端优先 GDScript／Rust；两者是不同层次。核心不依赖 DOM、Canvas、Tauri 或某个游戏引擎，通过版本化输入输出连接 GUI、CLI 与运行适配器。现有 Web 界面使用同一 Rust 代码的 WASM 编译目标，高频编辑保持本地同步；未来原生 GUI 可直接调用原生库。

布局移动、吸附、六向对齐与原子位置批次校验已接入共享核心；位置草稿、初始基线、100 步批次撤销／重做与 dirty 判断也已下沉。检查／保存／核对的状态转换、错误分类和请求归属已接入独立 Rust 保存工作流；宿主继续校验回执正文与修订并执行 I/O。Scene2D 的来源范围、语义模型和计划生成已在 JS 层拆开，精确原文定位及 v2 稳定实例已接入；源码布局所需的严格 JSON、稳定身份／位置／组检查和精确数值补丁已迁入 Rust 无状态接口。接下来在这个有界切片上推进完整场景语义与展开来源 → 字段、投影和 World 变更规划 → 统一构建及行为契约。每次迁移一条可验证的链路，删除被替代的规则实现，保留原文保真、身份及事务恢复边界。渲染端继续负责绘制、命中测试、视图坐标、焦点和输入法；宿主负责文件、进程与设备权限。当前大部分语义规划仍在 JS，不能据此宣称已完成全 Rust 化。

## 文本驱动场景的实施顺序

稳定实例与持久组织分组已接入当前源码；单场景原文草稿可驱动大纲和画布，错误保留最近有效结果，布局坐标可经精确补丁应用回当前源码草稿。文件内片段已有 recipe v1 实验，输出既有 v3，已接配方保存态／当前原文的只读预览和贡献来源导航；当前源码配方已支持单实例六字段覆盖、恢复继承、独立单实例位置画布、多实例移动／对齐批次及共享演员六字段显式设置／允许的声明恢复、整组放置偏移，精确补丁应用到原文草稿后普通保存；片段演员增删、整份放置新增／复制／移除及组织分组编辑已形成独立原文创作链；空间变换、嵌套／跨文件片段、事件语义、多文件提交与跨视图统一撤销仍待定案。

1. **定义与实例已分开。** OC 保存自身背景和设定，投影定义一种用途；Scene2D v2 的平面实例引用所选定义，持有独立 UUID、位置和局部覆盖。同一投影可多次实例化，重排保留身份；来源、选择、位置历史、构建节点与运行事件已区分实例和定义。新场景默认 v2，旧 v1 经显式预览保存升级；上限仍为 128。
2. **组织可解析的场景文本。** 结构可表达场景、空间分组、实例、可复用片段及其参数；叙事段落与明确声明的事件流程可关联到这些对象。空间层次和剧情顺序分别表达。文本可拆分为受版本管理的场景文件和引用片段，解析后形成可移植模型，原文件保持作者数据权威。具体语法通过小样例确定，先用现有结构化格式验证场景模型和现成引擎的行为绑定；不把新编程语言或 Nuislang 工具链作为前置条件。
3. **让编辑视图共享来源。** 文本、大纲／场景树和画布使用同一场景身份与来源映射。树支持折叠、检索和按需加载；选中实例能定位到原文声明或生成片段。图形修改形成明确的实例覆盖或原文修改，保留注释、行尾和版本检查。有效草稿可更新设计预览；文本尚未写完或有错误时保留输入和最后有效预览，构建继续只使用明确保存的版本。
4. **再接剧本事件与规模验证。** 声音已提供独立有限时间提示；出场、交互、对白及事件触发音效仍需逐项定义时间、顺序、条件和运行能力，再交给后端实现。批量声明与片段展开须可重复，并让生成实例保持稳定身份和来源；模板修改与单实例覆盖的写回目标须明确。按逐级扩大的样例记录解析、展开、索引、选择和预览成本，再调整现有数量上限与可见范围处理。

前置拆分与首个实例切片已接入：`json-source.mjs` 提供严格 JSON 与来源，`scene-model.mjs` 解析 v1／v2 语义及投影继承，`build-plan.mjs` 发射相应版本的计划；“同一定义多个实例 → 精确定位 → 独立位置修改／历史 → 保存重开 → 构建／运行与资源包往返”使用同一实例身份。完整场景模型、依赖与投影继承仍在 JS；Rust 几何与历史继续接收实例 UUID 作为不透明选择键，新增源码操作独立检查严格结构、身份／位置及分组。本轮 v3 已增加可嵌套组织分组，预览／布局共享大纲、搜索和后代选择，组来源与原文保存贯通。单场景文本草稿预览已接入：只读覆盖原样正文、保留最后有效画面和修订守护定位；登记依赖及构建仍读保存版本。当前已接通“有效源码草稿 → Rust 严格结构检查 → 共享位置历史 → Rust 精确坐标补丁 → 主编辑器内存应用 → 普通保存”；只支持当前已登记场景的源码模式，保留 128 KiB 预算与原保存基线，不调用 World 命令，没有跨视图统一撤销。文件内片段的首个隔离实验现由 Rust `sceneComposition.expand` 实现：recipe 内嵌片段，放置声明显式 UUID 映射及局部覆盖，输出已有 v3 与 JSON Pointer 来源 sidecar；CLI 只读并输出，完整范围见[片段组合](SCENE_COMPOSITION.md)。配方现在复用普通已登记 JSON 文档和源保存，当前模板／覆盖中的全部声明依赖以只读派生边进入资源包闭包；不新增类型或 World 事务，不写元数据。完整备份保留未完成原文，选择式迁移要求有效配方及完整或已锁定的依赖。已接当前配方的只读预览：保存版与未保存原文共用完整 v3 模型，模板／覆盖／偏移／身份贡献分别精确定位，合成值不伪装为单一可写位置；构建与布局写入入口保持独立。单实例覆盖现已通过独立 Rust 补丁按稳定放置与局部键定位，检查候选完整模型后仅应用到当前源码草稿，保留其余原字节和原保存基线；共享模板与其他放置保持原样。当前 0.0.10 源码已接通六字段恢复继承与原子 set／reset，位置／尺寸成对处理，候选完整检查后普通保存；另接固定一个实例 UUID 的位置画布，场景坐标转为局部 position-only 覆盖，复用 Rust 几何／100 步历史与原文审批；未动轴保留原局部小数，局部和场景越界在几何修改前拒绝。此切片不编辑共享片段、偏移或其他属性，不开多选／对齐，不使用生成场景坐标补丁。当前另接独立配方批次画布，全部实例共用一个 Rust 位置历史，以大纲／搜索／分组后代建立独立选择集；多放置移动、吸附与按有效尺寸六向对齐可一步撤销，净变化目标经新可选 Rust 无状态补丁原子写回，完整候选及目标列表检查后普通保存。局部／场景边界在历史更新前整批检查，共享片段、偏移、其他属性及作者身份保持；旧单实例路径保留。当前另接共享片段演员六字段 SET-only 编辑；raw 原文声明与有效实例值分离，未声明字段明确设置同一有效值仍新增声明，全部引用的局部覆盖继续优先。独立 Rust 能力原子保真修改模板并复查所有放置，完整候选、关联实例和图片检查后应用原文草稿并普通保存。共享声明恢复另用新可选 fragment_edit 能力，source 启用投影继承才可删尺寸／颜色／速度／控制，图片任一继承状态可删、位置不可删；原始输入保持，局部覆盖仍优先，设置与删除原子生成完整候选后普通保存，旧 SET 保持。另接独立 placement 能力设置／删除可选 offset，以全演员及组映射绑定一份保真候选；局部覆盖后统一加偏移，不为组织组增加空间变换。完整检查后应用原文草稿／普通保存，原位与缺省零声明分开。不改结构或继承开关。现另接共享演员结构创作：新增显式演员及全部放置稳定 UUID，移除同步清理对应映射／覆盖，完整候选检查后普通保存，未放置片段也可编辑；保留现有分组、其他身份和原文。共享组织组的新增、名称／父组修改、演员归组和空叶组移除已独立接入；下一步分别定义空间层次和跨视图历史；生成场景的直接编辑不反向修改配方。嵌套／跨文件依赖、多文件事务分别验收，不直接引入未经验证的 v4。组织大纲仍不是剧本系统。

共享字段设置和可选声明恢复的当前闭环已由[本轮结果](test-results/scene-composition-fragment-inheritance/results.json)分别验证 raw 意图、原子补丁、全引用掩蔽、真实投影／图片、普通保存和旧路径回归。共享演员增删已由独立结构能力处理；组织组创作另有独立验证；下一切片仍须定义空间层次或跨视图历史各自的作者契约和权限，不把声明删除的验收扩大为结构编辑或跨文件事务。

作者文本格式、构建计划和运行协议分别管理兼容版本。v1 的扁平 `actors`、对象唯一规则、计划 DTO 及原 Godot 生成器保留；v2／v3 同样限制 1–128 个实例，使用独立 `instanceId`；v3 另有 0–128 个组织分组、最多 16 层，默认编译到 plan v2，显式行为场景另组合为 plan 3；坐标与绘制顺序不因归组变化。显式升级保持作者原文和稳定身份，当前拒绝反向降级。场景格式变化不升级整个 workspace；现有 `scene.update` 仍只守护场景正文和登记，跨文件片段修改需另定原子提交与恢复边界。

文本结构描述作者设计，并引用明确登记的行为及参数。近期行为实现使用 Godot GDScript，以及工作树的独立 Bevy Rust 就绪／固定步自身位置回调。Bevy 的旧数据通道继续负责无行为计划和有限回放，Rust 通道另负责冻结 Cargo 源工程与临时编译。Nuislang／ns-nova／yalivia 留作原生接入目标。可移植部分是实例、参数、事件和来源契约，行为源码仍按后端实现，不承诺自动互译。归档应保留场景原文、引用片段、行为源码与依赖声明、定义和素材，解析树、编译缓存与引擎产物可重新生成。

2026-10-03 的 [行为绑定预研](PROJECT_BUILD.md#行为绑定选型历史预研) 已用独立 Godot 样例验证 GDScript 元数据、两个实例、参数、方法与信号；它还不是产品接口。当前独立实现已把受限的 GDScript Node 参数／信号纳入冻结快照、能力校验、来源诊断、运行生命周期和资源包，见[场景行为](SCENE_BEHAVIORS.md)；它不扩大旧探针的验证范围。工作树已有脚本起始草稿、首次绑定与关联、已有清单的参数／信号表单，下一步完善迁移、关联管理和规模验证；C# 因额外工具链与维护成本暂缓，不进入近期交付依赖。Bevy 的 BRP、反射注册和代码热补丁可供第二后端复用，但不替代作者文本保存和跨引擎适配。

## 原生执行与 GPU 能力

原生接入可与工作台完善并行，但必须以 Nuislang／ns-nova／yalivia 当时真实可调用的接口为依据。Godot 的结果、协议模拟和本机示例文件都不能替代原生验收。

| 顺序 | 交付范围 | 完成条件 |
| --- | --- | --- |
| 原生最小运行契约 | 固定输入、工具链／适配器标识、产物、会话、诊断和取消；只声明已支持的能力 | 用真实原生工具链构建并运行一个独立样例；事件与源对象身份可核对，缺能力和版本不匹配能准确拒绝 |
| 对齐设计样例 | 同一受限 Scene2D 设计分别生成原生与 Godot 产物；后端专属能力显式扩展 | 约定时间、事件顺序及数值容差，分别验收输入和状态；不要求画面逐像素相同，也不承诺转译任意引擎源码 |
| GPU 纵切 | 选择一项真实的并行计算或渲染工作量，贯通资源上传、执行、预览消费和释放 | 记录设备、执行结果、GPU 时间、传输量与峰值内存；取消／失败能释放资源；设备句柄与同步对象不进入工程或迁移包 |

控制命令与大块资源传输分开。纹理、缓冲区和计算结果通过有所有权、使用期限与同步约定的资源通道交换；共享资源和减少回读以真实支持为前提。无头逻辑测试、正常窗口、离屏渲染、内嵌视口和 GPU 计算分别声明与验证。

## 每个阶段共同的完成条件

1. **调用链路可复现。** 有可运行的隔离样例、入口和真实后端结果；Mock 只证明其覆盖的协议。
2. **作者数据有明确归属。** 正文、登记、素材、工具、本机配置和生成物分别管理；运行结果须显式提交才成为设计值。
3. **失败可观察。** 缺资源、错误版本、冲突、取消、超时和进程结束有明确状态与诊断，不能把未验平台标为支持。
4. **迁移仍完整。** 原文和素材字节、稳定身份、关系及模板经过导出／恢复核对；有新持久数据时先完善归档契约。
5. **文档与交付一致。** 更新 STATUS、使用契约及适用的架构边界；保留既有 ADR、发布记录和原始验证证据，不用新结果改写历史。

长期阶段 V0–V6 与初始施工编号 V-M0–V-M5 保留在 [下一代架构书第 10 节](NEXT_ARCHITECTURE.zh-CN.md#10-分阶段施工路线与首批里程碑)，用于解释依赖和历史决策；日常开发范围按本页推进，避免重复执行已完成的仓库迁移或第一条语义纵切。

## 场景声音的下一步

行为面板现可显式读取已保存场景的音轨目录，再将选中 UUID 填入任意文本参数，沿既有审阅、草稿和普通保存完成配置。目录与试听、完整构建及后端执行分别维护，不把参数名当作语义，也不提供后续引用保护；下一步的引用导航／影响检查须另立契约。操作与本轮范围见[行为音轨选择](SCENE_BEHAVIORS.md#将音轨编号填入行为参数)和[专题记录](test-results/scene-behavior-audio-picker/README.md)。

当前切片先接稳定音轨、有限时间提示与 Godot 工程交付；已有声音 JSON 可在独立面板修改音量、循环、用途和提示时间／动作。0.1.3 后工作树已接通首次声音创建：选择已登记 WAV、配置 1–16 轨、审阅并原子保存正文与关系，再回到独立字段编辑。0.1.4 已收录行为声音控制；其后工作树先接入提示添加／移除，再以独立提案接入既有提示换轨和显式上移／下移；旧增删 API 的固定绑定／相对顺序契约保持。运行仍按时间排序，同刻按作者列表执行，均复用普通草稿／保存。此前以独立轨道提案接入同资源复制与有提示引用保护的移除，维持 1–16 轨、旧轨道资源／顺序及 metadata，行为动态 ID 仍由作者维护。此前接通已绑定 WAV 的显式选择：先复用 World 绑定资源，再按完整来源／目录修订审阅资源引用修改、应用普通草稿并保存；目录不验实际 PCM，构建负责字节检查。此前独立试听准备、受限素材读取与 WebAudio 生命周期已接入当前轨道的显式素材试听，本轮补齐当前素材进度、暂停／继续和定位；使用当前音量与循环，不执行场景时间提示。暂停及继续沿用本次验证快照，目录仍未验证，构建继续独立冻结。后续分别设计声音内的新资源导入登记、解绑／清理、行为绑定导航、自然结束反馈、混音总线与空间音频。现有 `music`／`effect` 分类不隐式获得总线或空间语义。Bevy 实现须自行声明并验证声音能力，不能因为共享作者格式就视为已支持；声音与有限控制回放的组合也须单独验收。完整支持边界见[声音指南](SCENE_AUDIO.md)。
