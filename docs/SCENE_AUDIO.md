## 从场景首次添加声音

0.1.4 源码提供 **构建与运行 → 场景声音设置**，当前为 **21 模块／40 项声明能力**。先保存一个 Scene2D schema 2／3 场景，并通过素材库导入 PCM16 WAV，然后：

1. 在构建窗口选择场景，打开 **场景声音设置**。
2. 选择工程已有文档类型和新的 JSON 路径。配置 1–16 条音轨：素材、音乐／音效用途、音量、循环和触发方式。**定时播放** 是默认值，另填 0–60 秒的开始时间；**由行为触发** 不创建定时提示。同一 WAV 可以供多条音轨使用，也可以混用两种触发方式或全部选择行为触发。
3. 点击 **审阅新声音**，核对完整正文、场景关系和去重后的素材绑定。候选目录只是已登记素材；审阅与提交前会读取所选文件，检查实际 WAV 格式、大小和 SHA-256。
4. 点击 **保存声音与关系**，一次提交新声音正文、声音登记和原场景登记三份文件。原场景正文与素材不被改写。**取消创建** 不写入文件。
5. 点击 **打开声音原文**，进入已有字段编辑器与普通保存流程。再次从场景打开设置会定位这份文档，不重复创建。

只有选择定时播放的轨道会初始生成一条 `play` 提示；全部选择行为触发时正文包含 `cues: []`。触发方式是新建表单选项，不增加声音格式字段，也不自动创建脚本或绑定；后续通过[项目行为声音接口](PROJECT_AUDIO_CONTROLS.md)控制轨道，已有时间线也可与行为命令共存。切换方式保留轨道身份，修改后需要重新审阅。0.1.4 后工作树可在 **编辑场景声音** 中添加停止／后续提示、移除提示，或调整目标轨道与列表顺序；还可复制已有轨道或在处理其提示后移除轨道；本轮可在先完成素材绑定后选择音轨的新素材，具体见[替换素材](#替换音轨使用的素材)。新资源导入登记仍走素材管理。新建表单与已有字段编辑器相互独立，能力仍为构建模块的 `scene.authoring.audio-creation`。目录与创建不需要安装 Godot；宿主必须声明 `audio.create`，当前移动存储宿主未接入这一写命令。

场景必须有完整登记和可解析依赖。已有声音关系缺失、重复或无效时会报告错误，不当作空场景覆盖。当前目录最多 256 份可选 WAV，选中资源去重后合计至多 128 MiB；单份限制见下表。资源必须先导入登记，本入口不代替导入或转码。

表单切换中英日保留输入和稳定身份；来源或会话变化后必须重新审阅。保存响应不确定时只重新读取核对同一文档、正文和关联，不自动重试写入。宿主用独立 v10 日志恢复三文件提交；冻结证据不包含 WAV 内容，恢复不会覆盖之后被作者修改的素材。桌面退出与网页离开均检查此表单的未保存／处理中状态。

触发方式扩展的验证见[本轮验收](test-results/scene-audio-trigger-creation/README.md)；最初定时创建的结果保留在[首次创建声音验收](test-results/scene-audio-creation/README.md)。这些触发方式测试执行时为 0.1.3 工作树，功能已收录 0.1.4；该轮未更新安装包。

## 查看音轨使用位置

**0.1.5 之后的工作树**：在 **编辑场景声音** 中点击某条轨道的 **查看使用位置**。面板将两种结果分开：

- **当前表单的时间提示**：按正在编辑的提示目标实时更新，列出提示序号与 UUID。未完成的音量／时间输入不会阻止查看。
- **已保存行为的文字匹配**：读取该场景明确关联的行为文档，按完整小写音轨 UUID 比较所有文本参数，列出文档路径、绑定／实例身份、参数名和字段路径。不根据参数名猜测其用途。

切换轨道使用同一份已读取快照；修改过行为文档后，点击 **刷新已保存行为** 重读。尚未关联行为、已读但没有匹配、读取失败分别显示。新复制的未保存轨道也可以查看当前表单引用。移除当前查看的轨道后收起面板。

读取不会修改表单、撤销已检查的审阅、停止试听或保存文件；失败可重试，也可继续普通编辑。声音草稿可包含尚未保存的修改，读取仍要求磁盘声音与编辑器保存基线一致。关闭重开、切换来源或撤回可选读取能力后，旧回复不能填入新面板。

### 就地定位提示与行为原文

使用位置列表中的 **定位提示** 会滚动到当前声音表单中对应的提示，并聚焦其音轨选择框。定位按提示身份识别；新增、重排或移除之后不会依赖旧行号跳转。它不修改提示，也不撤销已经检查的修改。

行为匹配旁的 **查看参数原文** 在当前面板内展开只读原文，直接选中该绑定、该参数的 JSON 字符串。相同音轨编号在多处出现时，各按钮分别定位自己的字段；原文中的转义写法保持可见。**重新定位参数** 可返回匹配选区，**收起原文** 回到使用位置列表。原文可复制，不能在这个只读框中编辑。

原文来自**上次读取的已保存快照**。查阅不会切换主编辑器的文档、触发保存或增加服务请求，当前普通草稿、声音表单、不完整输入、审阅与试听保持。切换语言保留只读框、选区及内部滚动位置；切换音轨、刷新已保存行为、收起使用位置或关闭面板会清除原文。磁盘行为修改后需显式刷新，重新打开对应匹配；刷新失败不显示旧文本冒充新结果。来源定位的验证见[就地定位专题](test-results/scene-audio-usage-navigation/README.md)。

这是局部检查：行为结果来自上次读取的同场景**已保存**文档，不扫描脚本文本、其他场景或未保存行为草稿。普通参数仍是字符串；没有匹配不证明音轨未被使用，有匹配也不增加删除限制或自动清理。已有时间提示仍须先移除或改接，才能移除其音轨。可以就地定位或查看原文，不自动跳转离开当前草稿。

此入口使用独立只读服务，不依赖素材选择、WAV 可播放性或引擎安装。World 快照仍读取工程文档并检查素材状态，工程登记损坏或读取预算超限会报告不可用。浏览模式和当前 Android 存储宿主不提供此端口；准备副本中的模块不表示设备已支持。实际验证见[使用位置专题](test-results/scene-audio-usage/README.md)。

## 在行为参数中选择音轨

声音声明保存后，可在所属场景的 **编辑场景行为** 中显式读取场景音轨，为任意文本参数选择并填入稳定 UUID，再经行为审阅、应用草稿和普通保存。读取目录不需要试听或 WAV 可用，也不修改声音文档、素材绑定或参数类型；后续删除音轨时仍需作者维护脚本中的引用。操作见[音轨选入文本参数](SCENE_BEHAVIORS.md#将音轨编号填入行为参数)，验证范围见[本轮专题](test-results/scene-behavior-audio-picker/README.md)。

## 先试用示例

复制 [examples/scene-audio](../examples/scene-audio/) 到新的临时工程，再用当前源码编辑服务打开副本。工程内已有声音声明、场景关系、素材绑定和代码生成的 440 Hz PCM 测试音，不需要使用真实作品。

1. 打开 `documents/audio/demo.json`，进入 **编辑 → 原文**，点击 **编辑场景声音**。
2. 修改既有轨道的音乐／音效用途、音量与循环，或播放指令的秒数和播放／停止动作。0.1.4 后工作树还可按下节复制／移除轨道，增删提示、选择目标轨道或上移／下移。
3. 点击 **检查声音修改**，审阅完整修改前后原文。**应用到原文草稿** 只更新草稿，再用普通 **保存** 写入工程。
4. 在 **构建与运行** 选择场景 `documents/scenes/demo.json`，检查计划、构建场景、无头测试；完整场景声音仍通过配置了声音输出设备的 Godot 窗口预览；单份素材可先用[就地试听](#就地试听音轨素材)。
5. 在后端工程详情中核对音频文件，再用 **交付工程** 导出。解包后在 Godot 导入 `project/project.godot`，音频通过工程内相对路径加载。

返回／取消不会应用未提交表单；窗口内可以滚动，操作按钮保持可达。原文或来源切换后旧提案失效。既有字段编辑只修改明确选择的 JSON 叶值；提示增删与重排按稳定身份复用原文片段；目标轨道只有在表单中明确修改时才改变。只有显式选择新素材才修改音轨的资源引用；BOM、换行和未修改原文字节保持，编辑不会自动播放。

当前运行链要求带稳定实例身份的 Scene2D（作者 schema 2／3）；旧 schema 1 不会被自动升级。已有声音面板支持下节的轨道复制／移除、提示编排及已绑定素材选择；新资源导入登记与素材绑定使用既有独立入口。首次创建及关联使用上面的独立入口。源码与旧安装包的支持范围分别核对。

## 替换音轨使用的素材

已有音轨可以保持原 ID，改为使用另一份已登记并绑定给该声音文档的 WAV。

此目录要求已保存且登记完整的 Scene2D schema 2／3，以唯一 `audio` 关系指向当前声音文档；现有演员定义、行为及声音依赖仍须通过场景计划检查。游离声音 JSON 或无效的已保存依赖不能通过此入口修复。候选上限 256 按全工程符合条件的 WAV 计数，再筛选当前声音文档的绑定。宿主须提供 `sceneAudioCreation` 目录读取能力；当前 Android 未接入，不显示读取按钮，原有声音字段编辑保持。

素材登记、绑定和正文编辑各有独立入口：

1. 如素材尚未登记，先在素材库导入 WAV。保存或取消当前正文草稿，再打开 **世界与对象**，选择声音 JSON 对应的文档对象。
2. 点击 **绑定资源**，选择目标素材，填写用途（例如 `audio`），预览后保存绑定。这里选的是声音文档，不是 Scene2D 场景对象；已有同一素材的合法绑定可直接复用，不要求用途恰好是 `audio`。
3. 回到声音 JSON 原文并打开 **编辑场景声音**，点击 **读取已绑定素材**。目录就绪后，在目标音轨的 **WAV 素材** 中选择新素材；只读取目录不会替换当前选择，也不会自动保存或播放。
4. 点击 **检查声音修改**，核对完整修改前后原文，再 **应用到原文草稿** 并普通 **保存**。原音轨 ID 与已有提示引用保持；只有本次明确修改的字段改变。保存并重新构建后，新运行才使用替换后的素材。

目录读取将已保存基线、World、文档及素材目录修订绑定到当前来源；审阅使用这份目录，应用草稿前重新读取并核对完整上下文。来源或登记发生变化时须重新读取和审阅；过期结果不能写入当前草稿。只提供目录中已绑定的 WAV，不能输入任意资源 ID。中英日界面保留当前表单的身份和未完成输入。读取失败会保留输入和当前选择，禁用素材下拉；未更换素材的普通轨道与提示编辑仍可继续。目录不再包含当前素材时，保留其 ID 并标为不可用，不自动换成另一份素材。

绑定保存与正文保存是两次独立操作。绑定已保存后取消声音修改，新增绑定仍会保留；更换或移除音轨也不会删除旧绑定、素材登记或文件。本入口不提供解绑、不创建新的跨文件事务，也不自动导入资源。

目录只检查登记、文件可用性和声明信息，候选仍是 **未验证** 状态；成功读取目录、保存绑定或应用正文草稿都不证明实际 PCM 内容和哈希有效。构建继续独立读取并校验 WAV、登记大小与 SHA-256，只冻结最终音轨使用的去重素材。已经生成的构建与运行快照保持原声明。

实际流程与结果见[素材选择专题](test-results/scene-audio-resource-selection/README.md)和[执行摘要](test-results/scene-audio-resource-selection/summary.json)。旧轨道及提示提案 API、验收日志与范围继续保留。

## 就地试听音轨素材

在已有声音 JSON 的 **编辑场景声音** 中，先点击 **读取已绑定素材**，再在目标轨道选择 WAV，并显式点击 **试听音轨**。试听使用当前表单中的音量（0–1）与循环设置；零音量保持静音，循环覆盖整份素材。一次只试听一条轨道，再试听另一条会停止前一条；可随时点击 **停止试听**。素材选择与播放互相独立，读取目录和更换选择不会自动播放。

播放器显示当前试听位置和素材时长，可用 **暂停试听／继续试听** 控制播放，并用进度条定位；暂停时定位仍保持暂停。非循环素材定位到末尾会停在暂停状态，显式继续后从头播放；循环素材的末尾对应起点。自然播放完非循环素材仍结束本次试听。继续操作处理中暂不能再次暂停或定位，**停止试听** 始终可用。位置表示素材内的秒数，与声音文档的时间提示无关。

暂停持有本次已校验的内存快照；继续和定位复用同一缓冲，不重新读取文件或重复解码。要重新读取并验证当前磁盘素材，应停止后重新点击 **试听音轨**。进度与控制不改动表单、修改审阅或普通草稿。

试听前重新读取目录并核对完整来源、World／对象和候选登记上下文，再通过既有稳定资源地址读取所选文件。验证本次读取副本的登记大小、SHA-256 与 PCM16 单／双声道 8–96 kHz 格式后，才交给浏览器 WebAudio 解码。单份文件仍至多 32 MiB；浏览器解码会按输出采样率重采样，试听额外限制预计 float32 解码缓冲至多 128 MiB，超过时提示不能试听，不改变构建允许的素材范围。

编辑表单、重新读取目录、检查、应用、关闭窗口或页面转入隐藏状态都会停止包括暂停中的试听，并撤销迟到的读取／解码／继续结果；中英日切换保留表单与当前试听状态。播放失败、来源失效或素材不可用时保留输入，不自动选择其他素材。停止操作保持可达；浏览器不支持 WebAudio 或未提供读取能力时，不能试听，原有编辑仍可使用。

它只试听本次选中的完整素材，不执行 `cues`、场景时钟、行为、Godot 或 Bevy；当前表单即使尚未应用或保存，也可按有效音量／循环试听。试听不保存正文、绑定、登记或文件，也不会改变修改审阅和普通保存的归属。验证成功仅证明本次取得的字节副本与读取时目录一致，目录候选继续标为 **未验证**；它不是对磁盘内容的持续监测。保存后构建仍独立读取并验证当时的真实 WAV。

本入口复用前节的已绑定目录，仍要求有效并已登记的 Scene2D schema 2／3 声音关联，候选上限 256 按全工程符合条件的 WAV 计算。当前 Android 没有该目录／素材读取接口，不能据浏览器实现推导移动设备支持。进度、暂停／继续、定位和准备副本的本轮范围见[试听控制专题](test-results/scene-audio-audition-transport/README.md)和[执行摘要](test-results/scene-audio-audition-transport/summary.json)。[基础试听专题](test-results/scene-audio-audition/README.md)保留此前字节校验、真实浏览器与 Godot 指纹回归时点；本轮未改 PCM／Godot，不将旧结果记作重跑，也不把浏览器试听视为引擎播放或物理扬声器／安装设备验收。

## 复制与移除已有声音轨道

在已有声音 JSON 的 **编辑场景声音** 中，点击某条轨道的 **复制音轨**。复制项取得独立 UUID，沿用同一素材以及当前表单中的用途、音量和循环设置，追加到轨道列表末尾。未完成数字会随复制保留，仍须修正并通过完整检查后才能应用；复制不会复制时间提示，也不会自动播放。随后可给新轨道添加提示或在行为中使用它的新 ID。

声音文档保持 **1–16 条轨道**。达到 16 条时不能继续复制；至少保留一条轨道。要点击 **移除音轨**，先将本次表单内指向它的所有时间提示移除或改接到其他轨道；仍有提示引用时该按钮不可用。轨道复制或移除本身保留旧轨道的身份、素材引用及相对顺序，新轨道只追加；素材变化需另行显式选择。可在同一表单中修改允许的字段、编排提示，再统一检查完整原文、应用普通草稿并保存。

没有时间提示引用，不代表行为脚本未使用这条轨道。编辑器不会静态分析脚本或自动改写行为参数；作者需检查 `track_id` 参数以及代码中的播放／停止调用，更新被移除的轨道 ID。若行为实际调用了已移除的 ID，项目运行会报告未知轨道错误；复制生成的新 ID 也不会自动替换原行为引用。修改后保存并重新构建，已有构建或运行快照保持原声明。

轨道复制／移除提案本身仍只复用原文已有资源；本轮另以[已绑定素材选择](#替换音轨使用的素材)独立授权资源引用修改。移除轨道不删除素材文件、资源登记或声音文档中的素材绑定；绑定可保留当前轨道所需集合之外的条目。构建只冻结最终轨道实际使用的音频资源，并按资源身份去重；保留的登记绑定仍参与原有作者工程依赖管理。

轨道结构提案继续保留原文、来源与保存基线守护，不增加 World 写命令或自动播放接口。实际验证见[轨道编辑专题](test-results/scene-audio-track-authoring/README.md)；先前提示增删及换轨／重排的 API、历史日志与验收范围保持。

## 增删已有声音的时间提示

0.1.4 后工作树可在已有声音 JSON 的 **编辑场景声音** 面板中维护 0–64 条提示：

1. 添加提示后，从当前文档已声明的轨道中选择目标，填写 0–60 秒时间及播放／停止动作。新增默认值为 0 秒播放，提示身份在本次表单中保持稳定。
2. 可移除任意提示，也可以移除全部提示。空时间线保留轨道及素材引用，供行为触发；它不会自动创建行为或立即停止正在运行的工程。
3. 提示身份保持稳定；新增项先追加到末尾，已有与新增提示均可选择当前文档内的目标轨道，并用 **上移／下移** 调整列表。运行时仍按时间排序，同刻沿作者数组顺序执行；操作与影响见[调整目标轨道与顺序](#调整提示目标轨道与顺序)。
4. 可同时修改音轨用途、音量、循环和保留提示的时间／动作。点击 **检查声音修改**，审阅完整原文，再 **应用到原文草稿** 并普通 **保存**。任何进一步修改都要重新检查；取消只丢弃本次表单内容。

仅调整提示时，结构变更只重建提示数组，复用保留提示的原文片段；轨道字段仍按叶值修改。原文、文档会话或保存基线发生变化后，旧审阅不能应用。中英日切换保留未完成数字和新增提示身份；达到 64 条时停止添加，仍可修改、移除或调整顺序。

轨道复制／移除见[轨道管理](#复制与移除已有声音轨道)，已绑定素材替换见[素材选择](#替换音轨使用的素材)，新资源导入登记仍使用独立入口；声音格式、Rust 校验／采样、模块／能力和后端版本保持。它不新增保存事务或播放器接口。此前的[提示增删专题](test-results/scene-audio-cue-authoring/README.md)验证固定旧目标轨道、保留旧相对顺序与末尾追加，原 API 和证据范围保留；后续换轨与顺序能力另见下节。

## 调整提示目标轨道与顺序

在 **编辑场景声音** 中，每条提示都可选择当前表单中的目标轨道，包括本次复制的新轨道；已经保存的提示也可换轨。改变目标只更新该提示的轨道引用；轨道自己的 UUID、素材、音量与循环保持，除非本次也明确修改允许的轨道字段。

使用该行的 **上移／下移** 将提示移动一行。第一条不能再上移，最后一条不能再下移；提示的身份和未完成输入随该行保留，切换语言也不重置。新增提示仍先出现在末尾，随后可以移动。同一表单可组合换轨、重排、增删与时间／动作修改，完整检查后应用到普通草稿，最后普通保存；换轨或移动后，之前的审阅必须重新检查。

列表表示作者声明顺序。运行依旧先按时间先后处理，只有时间相同时才按列表顺序执行。例如同一轨道、同一时刻先播放再停止，最终为停止；先停止再播放，最终会从头播放。移动不同时间的提示不会改变时间优先级，也不会自动改秒数或启动声音。构建与运行继续消费已保存快照，修改后需保存并重新构建才能使用新的编排。

换轨但不重排时只修改对应轨道引用的叶值；重排与增删复用原提示片段，保留未修改 token、BOM、换行和其他原文。新提案沿用来源／修订守护，取消不改草稿，异步检查期间来源变化后不可应用旧结果。实际测试、浏览器与后端范围见[换轨与顺序专题](test-results/scene-audio-cue-arrangement/README.md)，不由源码编辑推导安装或声音设备验收。

## 声音声明

独立 JSON 文档使用 `viento-scene-audio` schema 1，示例：

```json
{
  "format": "viento-scene-audio",
  "schemaVersion": 1,
  "sceneObjectId": "dddddddd-dddd-4ddd-8ddd-dddddddddddd",
  "tracks": [{
    "id": "77777777-7777-4777-8777-000000000001",
    "resourceId": "99999999-9999-4999-8999-999999999999",
    "role": "music",
    "volume": 0.25,
    "loop": true
  }],
  "cues": [{
    "id": "66666666-6666-4666-8666-000000000001",
    "trackId": "77777777-7777-4777-8777-000000000001",
    "atSeconds": 0,
    "action": "play"
  }]
}
```

字段全部必填，拒绝未知字段、重复 JSON 键和非法值。场景、轨道、素材及指令使用小写 UUID；轨道 ID 和指令 ID 分别唯一。音乐／音效 `role` 是用途标签，尚不是混音总线。

| 内容 | 第一版规则 |
| --- | --- |
| 轨道 | 1–16 个；每个轨道绑定一份音频，多个轨道可以复用同一资源 |
| 音量 | 线性数值 0–1；0 完全静音，1 为原音量 |
| 循环 | 每轨道独立布尔值，不更改共享资源 |
| 播放指令 | 当前工作树 0–64 条；`play` 从头重新播放，`stop` 幂等停止 |
| 时间 | 场景启动后的 0–60 秒；先按时间排序，同时间保留作者声明顺序 |
| 自然结束 | 取决于素材与后端；纯逻辑采样不推测素材时长或实际播放结束 |
| 声音文档 | 至多 32 KiB；一个场景明确关联一份声音声明 |
| 执行素材 | PCM 16 位 WAV，单／双声道，8–96 kHz；每份至多 32 MiB，全部冻结素材合计至多 128 MiB |

编辑器素材库仍可导入和试听其他受支持音频格式；本轮场景执行仅接入以上 WAV 子集，不自动转码。

## 关联与迁移

声音文档按普通 `viento-document` 登记，类型名称由工程自行决定，解析方式为 `structured`。场景的登记中增加 `kind: "audio"`、`targetId: <声音文档UUID>` 的关系。声音文档登记包含：

- 指向 `sceneObjectId` 的普通引用关系，例如 `kind: "reference"`。
- 每份实际使用音频的 `assetBindings`，例如 `{ "assetId": "<素材UUID>", "role": "audio" }`。

这些双向引用和素材绑定让资源包与迁移保留完整依赖。声音声明缺失、重复关联、引用错误、未绑定素材或素材哈希变化都会阻止构建，并指向原声音文档。尚未关联到场景的普通声音 JSON 保持文档数据，不自动参与运行。

声音跟随场景及生成工程，不写回 OC 的运行状态。实际文件仍在作品素材存储中；程序本体只提供规则、编辑器和后端代码。构建冻结登记哈希与原音频字节；交付清单登记 `project/audio/<UUID>.wav`，接收方不依赖原作者目录。

## 分层与后端

共享 Rust 核心提供 `sceneAudio.inspect` 与 `sceneAudio.sample`：严格检查声明、稳定排序并计算截至指定时间的播放命令和逻辑状态。GUI、宿主和后端通过独立接口使用这些规则；WASM 缺失时明确失败，不使用第二份 JavaScript 语义。

已保存场景显式关联音频后，构建计划附加版本化的 `viento-audio-plan` 和 `audio.nonspatial`／`audio.timeline` 能力要求；原场景计划 2／行为计划 3、演员事件协议与静态布局预览保持。Godot 适配器 0.6.0 组合独立 `audio-runtime.gd`，声音事件走独立 `VIENTO_AUDIO` schema 1，由中间层按冻结身份、声明顺序和结束时间验证。日志不能自行提供作者路径。

Godot 的原生 `AudioStreamPlayer` 负责解码、播放和输出。同资源的循环设置按轨道复制；场景结束统一停止，取消或失败由宿主终止子进程。固定无头测试保持两步、每步 0.25 秒，因此 0.5 秒之后的声音指令不会在该测试中执行；窗口运行继续推进场景时间。它不是逐采样精度的音乐编排时间轴。

无头验收检查播放命令和状态。独立原生混音测试捕获实际 PCM，验证非零输出、零音量、循环及停止后的静音；这不等于物理扬声器或某台设备的听感验收。

尚未接入 Bevy 音频输出、混音总线、音量自动化、流式长音轨、空间声源／衰减、音频与有限控制回放组合，以及 Android 声音运行。需要这些能力时必须显式扩展接口和验收，不能把任意行为事件回传当成已经播放声音。

本轮验证见[声音链路验收](test-results/scene-audio/README.md)。通用构建与交付见[构建工作台](PROJECT_BUILD.md)和[后端工程管理](BACKEND_PROJECTS.md)。
