# 0.5.0：可完成并交付小型 2D 游戏

这是 2026-11-11 确立、2026-11-13 整理的产品门槛，**不是当前已完成的能力声明或发布日期承诺**。应用源码为 0.3.0，本机安装为 0.2.0。以两款参考游戏从空白工程到独立发行的完整结果判断成熟度；[路线图](ROADMAP.md#内置创作到交付的推进顺序)负责开发顺序，本页负责验收，功能图谱负责定位实现与证据缺口。

## 两款参考游戏

- **俯视收集关卡**：移动、碰撞、收集、计分、开门与通关，另有伤害／失败；使用开始／关卡／结果场景、屏幕 HUD、声音、动画和重开。
- **平台跳跃关卡**：重力跳跃、静态与移动平台、触发伤害／死亡、检查点与过关；复用开始／结果、HUD、声音和动画，验证已有物理与实例身份的组合。

两者都必须能主要在 Studio 内置编辑器中完成。允许在内置文本编辑区编写 GDScript 等后端行为；外部 IDE／LSP 可选，不要求任意脚本可视化。不能靠手工修补生成工程完成验收。每款保留可迁移的作者工程、从空白创建的操作步骤及对应构建和运行记录。

## 实施顺序

基础起点已经接通：[场景相机](SCENE_CAMERA2D.md)、[只读 HUD](SCENE_HUD2D.md)、[动作／事件导航](SCENE_NAVIGATION.md)、[不同成员间关卡重试](SCENE_RETRY.md)。它们无需重新立项，但仍须参与组合验收。0.3.0 新增同场景重启及可选暂停／恢复，暂停作者链与Chrome已通过，原生／离线与完整应用回归已通过；本轮基础菜单在参考副本另验，同一访问冻结与松键恢复不等于从空白创作、持续运行或里程碑出口完成。

1. **0.3 阶段**：先形成俯视收集游戏初稿，减少寻找成员／实例／动作编号的重复操作；补实际胜负、同场景重启、暂停恢复与鼠标／键盘菜单，完成第一款游戏全流程及换根恢复。
2. **0.4 阶段**：分别接通持久存档和有界持续运行，完成平台跳跃参考游戏；形成首个独立发行候选与字体闭包，两款各完成 30 分钟交互。导出工具／模板可行性提早验证。
3. **0.5.0 收口**：对当期候选做完整回归、失败恢复、作者迁移、干净环境发行和实际安装验收，重新核对全部门槛后决定发布。

阶段拆分和下一轮具体交付统一查[路线图](ROADMAP.md#接下来的三项开发工作)。本页门槛不会因单项专项通过而自动完成。

地图放置与复用必须在参考关卡证明可用，但不预设整套 TileMap／自动地形。动态刚体、旋转平台、骨骼动画、联网及 Bevy 全能力对等不作为默认硬门槛；样例确需时，先定义合同和后端支持再调整范围。3D 与原生 Studio 保持独立边界。

## 可替换的实现

长期资产是作者语义、稳定身份、来源修订、受限命令、构建计划、运行观察、归档与恢复合同。JS／Node／Web／Tauri 当前验证工作范式，未来由 ns-nova 原生实现接替。界面负责编辑和呈现，宿主负责存储／进程，Godot／Bevy 各自声明实现能力；全面 Rust 迁移、通用 JS RPC、全局工作流框架和永久双 GUI 不是本里程碑的前置条件。

0.3.0 另收录[基础鼠标／键盘运行菜单](PROJECT_MENU.md)，与只读HUD分离。场景页导航／重试／重开和暂停页恢复／结束有独立合同，专项原窗口、标准ZIP离线和场景重开长按释放已验证，具体来源与应用回归见[回执](test-results/project-menu/README.md)；完整从空白作者任务、暂停中重开和里程碑组合出口继续分别验收。
