# 单文件片段组合样例

这是尚未发布的实验 CLI 样例。`recipe.json` 在一个文件里定义片段，再通过多个放置复用；每次放置显式保存演员与组的 UUID，并可单独覆盖配置或偏移位置。输出使用已有 Scene2D v3，版本仍为 0.0.7。

在仓库根目录运行：

```sh
npm run scene:compose -- --input examples/scene-composition/recipe.json
npm run scene:compose -- --input examples/scene-composition/recipe.json --emit bundle
```

两条命令只读取样例，结果写到标准输出。默认只输出场景，bundle 另含配方原始字节 SHA-256 和 JSON Pointer 来源映射。机器读取可使用 `npm run --silent scene:compose -- ...`。命令不会创建工程文档或启动引擎；初次运行会准备共享 Rust/WASM 核心。

样例中的 `party` 片段有 `leader`、`companion` 两个演员和两层逻辑组，放置两次后得到 **4 个实例、4 个组**，四个实例仍共用一份角色定义和图片。第二次放置偏移 `[360, 80]`，只把本队 `leader` 的片段内位置覆盖为 `[100, 140]`，最终为 `[460, 220]`；它同时覆盖颜色、速度与控制，第一队仍保留方向键控制。另一成员的最终位置为 `[560, 260]`。两个放置各有独立的演员和组身份，移动或覆盖其中一个不会改动另一个。

配方引用[Scene2D 合成工程](../scene2d/README.md)已有定义与图片的 UUID。若要验证构建，先复制该完整工程到临时目录，将生成内容交给现有 `scene.create`，使用新场景 UUID 和新路径，经过预览后保存；由命令派生引用登记，再使用 `project:build` 检查、构建和运行。不要覆盖样例工程的已有场景文件来代替登记。

生成场景可在原有编辑器中正常编辑，但修改不会回写 `recipe.json`，重新展开也不会合并场景中的后续修改。配方也可作为普通已登记 `.json` 文档进入临时工程，沿用原文保存与完整备份；选择式资源包从当前模板和覆盖派生依赖，保留正文及 UUID，不自动改写元数据。未完成配方可保存，但须修复后才能选择式打包或展开。登记后可运行 `npm run --silent scene:compose -- --root <临时工程> --object <配方文档UUID> --emit bundle`，同时检查定义／图片依赖并返回文档来源；它不登记生成场景。已登记配方可在场景预览选项卡查看保存版或当前未保存原文，并分别定位模板、覆盖、偏移与身份来源；预览不提供布局编辑或构建／运行。当前源码编辑中的同一配方还可通过“编辑此实例覆盖”调整六类局部字段，检查完整结果后应用到原文草稿，再普通保存；未改字段保留继承，不改共享片段或其他放置。共享片段编辑、删除覆盖／恢复继承和画布拖动回写仍未接入。完整配方字段、覆盖顺序、稳定身份与来源边界见[片段组合指南](../../docs/SCENE_COMPOSITION.md)。
